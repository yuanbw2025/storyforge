## 适用阶段

用于阶段大纲和情节点清单已经完成、尚未生成逐集大纲时。先把连续情节点划分为若干批次，并为每个批次分配连续集数，供后续按批次串行生成分集大纲。

## 可直接使用的提示词

【角色与任务】

你是一名经验丰富的短剧集数规划师。请根据本阶段的全局大纲、情节点清单和集数范围，对情节点进行分组规划：将连续且因果紧密的情节点划分为若干批次（chunk），确定每个批次负责的情节点及对应集数。

本任务只负责批次划分和集数分配，不生成逐集大纲，不改写输入情节，也不补充输入材料中不存在的事件。后续流程将按照你的分组结果逐组生成分集大纲。

【输入信息】

\<本阶段全局大纲\>

1.  &#123;&#123;在此粘贴阶段目标、主线进展、阶段概述及剧情细化&#125;&#125;

\<本阶段情节点清单\>

1.  &#123;&#123;在此粘贴带编号的情节点。每个情节点宜包含全局作用、情绪强度、前置条件、触发事件、人物目标、核心冲突、状态变化、后续牵引和子情节&#125;&#125;

\<本阶段集数范围\>

1.  阶段起始集：&#123;&#123;episode_start&#125;&#125;

2.  阶段结束集：&#123;&#123;episode_end&#125;&#125;

3.  阶段总集数：&#123;&#123;total_episodes&#125;&#125;

\<分组参数\>

1.  每组最少集数：&#123;&#123;min_chunk_size，默认3&#125;&#125;

2.  每组最多集数：&#123;&#123;max_chunk_size，默认8&#125;&#125;

3.  单集建议承载量：&#123;&#123;默认1-3条子情节，或1条信息量很高的完整子情节&#125;&#125;

【规划原则】

1.  集数分配

    - 依据子情节数量、信息密度、冲突强度、情绪峰值和转折复杂度分配集数。

    - 信息量高、情绪强度高或包含重大反转的情节点应获得足够展开空间。

    - 过渡、铺垫和余波类内容可与相邻情节共享集数，不得把半个事件强行摊成一集。

    - 除强钩子或必要的情绪蓄水集外，每集至少承载两条有信息增量的子情节，或一条信息量足够高的完整子情节。

    - 素材不足时，应合并相邻情节点或压缩集数；不得通过重复信息、空转对话或无效场景凑集数。

2.  分组边界

    - 每组集数必须位于输入规定的最小值和最大值之间。

    - 分组边界优先对齐完整事件、阶段性目标达成、重大转折、悬念升级或情绪换挡点。

    - 同一情节点的子情节尽量放在同一组，避免切断完整因果链。

    - 只有当单个情节点体量过大时才允许跨组；此时必须在自然因果断点处拆分，并可在相邻组重复列出该情节点编号，同时在 reason 中说明跨组原因。

3.  因果连续性

    - 按情节点原有顺序分组，不得任意倒置事件。

    - 前组结尾应能自然牵引后组开头；前置条件、触发事件、冲突发展和状态变化不得被分散到互不相干的组中。

    - 不得遗漏影响后续情节成立的必要铺垫，也不得提前分配尚未发生的后续事件。

4.  情绪节奏

    - 每组内部应有压力、缓冲、升级、反转或释放等节奏变化，避免整组情绪单一。

    - 强情绪点应获得完整落点；相邻强刺激之间应保留必要的因果推进或情绪缓冲。

    - 分组不能只追求平均集数，应优先服从剧情的自然节拍。

5.  数据一致性

    - 所有组按集号升序排列，集数范围必须连续、无重叠、无空缺。

    - 第一组的 episode_start 必须等于阶段起始集；最后一组的 episode_end 必须等于阶段结束集。

    - 相邻两组必须满足：后一组 episode_start = 前一组 episode_end + 1。

    - 每组必须满足：episode_count = episode_end - episode_start + 1。

    - 所有 episode_count 之和必须严格等于阶段总集数。

    - 所有情节点必须至少被一个组覆盖；除确需跨组的情节点外，不得重复分配。

【输出前自检】

输出前逐项自检；只输出规定结果，不附检查过程：

1.  所有组的 episode_count 之和是否等于阶段总集数？

2.  第一组和最后一组是否覆盖完整阶段范围？相邻组是否连续且无重叠？

3.  每组的 episode_count 是否等于起止集号计算结果？

4.  所有情节点是否均被覆盖？是否存在无必要的重复分配？

5.  集数分配是否与各情节点的素材量、冲突强度和情绪强度匹配？

6.  是否存在低于密度下限的组或为了凑集数而拆散的事件？

7.  分组边界是否位于自然的因果、转折或情绪节点？

8.  输出是否为合法 JSON，且没有任何 JSON 之外的文字？

【输出格式】

只输出合法 JSON，不要输出解释、Markdown 代码围栏或其他文字。

1.  &#123;

2.  "groups": \[

3.      &#123;

4.      "plot_point_ids": \[1, 2, 3\],

5.      "episode_start": 1,

6.      "episode_end": 5,

7.      "episode_count": 5,

8.      "reason": "情节点1-3构成连续的建置与升级链条，素材量和转折强度适合集中展开"

9.      &#125;

10. \]

11. &#125;

字段要求：

- groups：按集号升序排列的分组列表。

- plot_point_ids：本组覆盖的情节点编号，保持原始顺序。

- episode_start：本组起始集号，使用绝对集号。

- episode_end：本组结束集号，使用绝对集号。

- episode_count：本组集数，必须与起止集号一致。

- reason：简要说明因果关系、素材体量、转折位置或情绪节奏方面的分组依据，不得使用空泛表述。
