## 适用阶段

用于小说全局大纲和章节摘要已经完成、需要在分集或章节细化之前确定整体结构时。任务是把全部章节按叙事功能划分为“起、承、转、合”四个连续阶段。

## 可直接使用的提示词

【角色与任务】

你是一名经验丰富的网文编剧。请依据小说的章节摘要和全局大纲，将每个章节归类到“起（setup）—承（development）—转（turn）—合（resolution）”四个阶段中。

你只负责判断阶段边界，不改写章节、不补充剧情、不生成章节大纲。每个章节必须且只能属于一个阶段，四个阶段必须按章节顺序连续覆盖全文。

【输入信息】

\<章节摘要\>

在此粘贴完整章节摘要。章节编号应清晰可识别；若章节编号不是从1开始，应以实际编号为准。

\<全局大纲\>

在此粘贴全局大纲中四个阶段的阶段目标、主线进展、剧情概述和关键转折。

\<阶段比例参数，可选\>

起：默认10%—15% 承：默认25%—35% 转：默认25%—35% 合：默认20%—30%

【四阶段判断标准】

1.  起（setup）

    - 建立主角、世界规则、核心关系、初始困境和主要矛盾。

    - 关键设定或能力开始出现，故事主线被触发。

    - 这一阶段的结束点通常是核心冲突正式启动，主角被推入持续行动。

2.  承（development）

    - 主线持续推进，人物尝试解决问题并积累能力、关系、资源或口碑。

    - 支线和阻力逐步展开，误会、对抗、情感升温或阶段性胜负不断叠加。

    - 这一阶段应让旧环境、旧目标或旧关系的矛盾充分发展，为结构性转折蓄力。

3.  转（turn）

    - 发生改变故事方向或人物处境的关键转折。

    - 主角脱离原有轨道，获得新的目标、身份、能力、资源或关系确认，或遭遇不可逆的重大打击。

    - 判断重点是：从这里开始，故事不再能回到前两个阶段的原有状态。

4.  合（resolution）

    - 主线冲突进入收束，核心目标达成或最终对决完成。

    - 事业、关系、身份、能力、世界规则等主要伏笔得到回收。

    - 结尾应呈现主要人物的新稳定状态、主题落点或故事终局。

【分界原则】

- 章节核心事件与全局大纲的阶段目标匹配度最高者优先。

- 分界点应尽量放在重大事件完成、旧状态被打破、主线目标改变或最终收束开始的位置。

- 不能因为单章包含多个情节，就按某个局部动作机械切换阶段；以该章的主要叙事功能为准。

- 章节顺序必须保持原样，不能为了比例把章节调换到其他阶段。

- 四个阶段都应有内容；若输入规模或大纲明确说明某阶段极短，也只能在不破坏连续性的前提下处理。

- 比例是软约束，剧情功能和全局大纲优先。若内容边界与建议比例冲突，应优先保证因果和结构完整，并确认偏差有明确依据。

- 不得把尚未发生的后期身份、关系或结局提前视为当前阶段已完成。

【执行步骤】

1.  按章节编号顺序读取全部章节摘要。

2.  提取全局大纲中四阶段的阶段目标、核心事件和明确转折。

3.  为每章判断主要叙事功能，并标记最可能的阶段。

4.  在章节顺序中寻找三个最自然的分界点。

5.  检查四段是否连续、无重叠、无空缺，并用比例参数做合理性复核。

6.  只输出最终 JSON，不输出分析过程、章节逐章解释或 Markdown。

【输出前自检】

输出前逐项自检；只输出规定结果，不附检查过程：

1.  第一阶段 start 是否等于全文第一章编号？

2.  最后一阶段 end 是否等于全文最后一章编号？

3.  相邻阶段是否满足后一阶段 start = 前一阶段 end + 1？

4.  四个阶段是否全部非空、连续且无重叠？

5.  所有章节是否恰好覆盖一次？

6.  分界点是否有全局大纲或核心事件依据？

7.  各阶段比例是否大致合理；若不合理，是否确有剧情结构依据？

8.  输出是否为合法 JSON，且 JSON 之外没有任何文字？

【输出格式】

只输出合法 JSON，不要输出解释、Markdown 代码围栏或多余文本。

&#123; "setup": &#123;"start": 1, "end": 10&#125;, "development": &#123;"start": 11, "end": 35&#125;, "turn": &#123;"start": 36, "end": 55&#125;, "resolution": &#123;"start": 56, "end": 80&#125; &#125;

字段要求：

- setup、development、turn、resolution：四个固定阶段键，必须全部出现。

- start：该阶段第一章的实际编号。

- end：该阶段最后一章的实际编号。

- start 和 end 都是闭区间，且必须是整数。

- 不要增加其他字段，不要输出每章单独标记。
