# 小说 Prompt 在 StoryForge 中的调用方式
::: tip 迁移来源
本页由原始 Word Prompt 资产迁移为 Markdown，尽量保留原文结构、术语、表格和示例。这里的 Prompt 是创作资产/方法资料，不等同于当前 StoryForge 代码中的唯一运行模板；实际产品行为以当前仓库和界面为准。
:::




本指南说明如何把小说 Prompt 体系用于 StoryForge 的实际创作流程。每个阶段都遵循“准备材料 → 运行 Prompt → 检查结果 → 选择采纳”的方式，避免一次生成覆盖全部创作决策。

## 一、开始前确定三个项目参数

1.  **篇幅模式**：长篇、短篇或中短篇。

2.  **交付方式**：完整稿、分卷创作或持续连载。

3.  **主要类型承诺**：选择一个主要类型，其他类型作为辅助，不同时加载全部规则。

这三个参数决定后续需要调用哪些 Prompt、需要准备多少上下文，以及哪些规则不应进入当前作品。

## 二、阶段与工作区对应

|                 |                                |                                |                                |
|-----------------|--------------------------------|--------------------------------|--------------------------------|
| **阶段**        | **在 StoryForge 中准备**       | **Prompt 主要产物**            | **采纳前检查**                 |
| P00 创作简报    | 项目想法、篇幅、题材、禁区     | 创作任务简报、待决策问题       | 是否准确表达作者目标           |
| P01 灵感整理    | 灵感笔记、参考材料、意象和片段 | 原创灵感卡、组合方向           | 是否保留机制并去除专有指纹     |
| P02 作品定位    | 题材、目标读者、期望体验       | 读者承诺、差异化机制           | 承诺是否具体且能够兑现         |
| P03 故事核心    | 候选概念、人物想法、世界设想   | 核心冲突、故事前提、主题问题   | 是否能持续产生选择和后果       |
| P04 创作考证    | 研究问题、世界规则、事实要求   | 事实边界、可用条件、剧情影响   | 确定事实与创作假设是否分开     |
| P05 世界构建    | 故事核心、地理、制度、能力规则 | 世界因果链、生活纹理、限制     | 设定是否真正影响人物选择       |
| P06 人物系统    | 故事核心、世界压力、人物草案   | 人物动力、关系、弧线和阶段状态 | 人物设定是否有行为证据         |
| P07 剧情发动机  | 人物目标、冲突条件、故事线     | 升级阶梯、信息矩阵、复线碰撞   | 升级是否来自选择而非巧合       |
| P08 全书结构    | 故事核心、人物弧、结局方向     | 全书转折、高潮和兑现路线       | 结构是否服务于具体故事         |
| P09 篇幅分轨    | 全书结构、交付方式             | 长篇卷纲、短篇压缩或连载计划   | 是否只启用对应篇幅规则         |
| P10 章场规划    | 本章任务、人物状态、伏笔和情绪 | 章节任务、场景卡、章节标题     | 每场是否产生明确变化           |
| P11 正文写作    | 章纲、细纲、连续性信息和文风   | 首章、续写、对白、动作与叙述   | 是否遵守正文事实和人物状态     |
| P12 连续性维护  | 本章正文和既有事实             | 摘要、交接、状态差分、时间线   | 每项变化是否有正文证据         |
| P13 宏观修订    | 全书大纲、摘要、正文和事实     | 结构诊断、优先级和重构路线     | 是否先确认问题再改写           |
| P14 语言修订    | 选定正文、修订目标、文风规则   | 场景、对白、视角和节奏改写     | 是否越过允许改动范围           |
| P15 读者验证    | 首章、片段、类型承诺           | 理解轨迹、期待落差和阅读风险   | 是否把模拟判断当成风险而非事实 |
| P16 包装交付    | 故事核心、大纲和章节摘要       | 书名、简介、梗概、标签         | 是否准确承诺且控制剧透         |
| P17 Prompt 管理 | Prompt、输入输出、采用稿和反馈 | 运行复盘、版本比较和测试       | 是否有多类样例支持版本升级     |

## 三、正文写作需要的最小信息包

章节正文生成时，优先准备与本章直接相关的内容：

1.  本章任务与细纲。

2.  上一章结尾、章节交接和上一章计划对账。

3.  近期章节摘要及与本章相关的远距正文片段。

4.  出场人物、关系、当前状态和已确认事实。

5.  本章涉及的世界规则、地点、物品和能力限制。

6.  需要推进或避免提前回收的伏笔与故事线。

7.  时间位置、行动顺序和重要物品归属。

8.  作者文风要求及必要的角色语言示例。

信息过多时，按照“与本章的相关性、事实确定性、出错后的影响”排序，不简单只保留最近文本，也不把整部作品无差别塞入一次调用。

## 四、四类 Prompt 的处理方式

### 生成型

先生成候选结果，再检查结构、事实和格式，最后由作者选择采纳。适用于故事核心、世界观、人物、大纲和正文。

### 抽取型

要求每项结果能够回查正文证据，冲突项单独列出。适用于章节摘要、人物状态、物品、时间线和伏笔。

### 诊断型

默认只输出问题、证据、影响和修复方向，不直接修改故事事实。适用于结构审校、连续性检查和读者验证。

### 修订型

保留原稿，明确修订目标和允许改动范围，比较修订前后差异后再确认写回。适用于宏观重构、场景改写和语言修订。

## 五、推荐调用路线

### 新建长篇

P00 → P02 → P03 → P05/P06/P07 循环 → P08 → P09L → P10/P11/P12 循环 → P13/P14/P15 → P16

### 连载长篇

在长篇路线中启用 P09R。连载参数只影响阅读回报、断点和生产节奏，不覆盖人物逻辑、世界规则和正文事实。

### 短篇

P00 → P01/P03 → P09S → P10（精简）→ P11 → P14/P15 → P16

### 已有正文修订

P13 宏观诊断 → P12 连续性审计 → P14 定向修订 → P15 阅读验证 → P16 包装

## 六、结果采纳原则

1.  已确认正文事实优先于旧计划和类型惯例。

2.  作者明确决定优先于 AI 候选建议。

3.  结构化结果按人物、关系、伏笔、时间线等目标分别确认，不用一段自由文本同时修改多个区域。

4.  冲突、缺失和不确定项先进入复核，不自动补成事实。

5.  正文与重要设定写回前保留原版本，确保能够比较和撤回。

6.  多世界、多时间线或多视角作品必须确认结果属于正确的世界、时间和人物范围。

## 七、常见错误

- 在故事核心尚未稳定时直接批量生成章节。

- 把所有世界观、人物和历史资料无差别塞入每次正文调用。

- 同时运行多个会修改同一人物或同一章节的任务。

- 把诊断建议直接当成事实写回项目。

- 长篇、短篇和连载规则同时启用。

- 只检查文案是否好看，不检查因果、连续性和字段归属。

- 修订正文后不更新人物状态、时间线和后续计划。

## 八、完成标准

一次 Prompt 调用只有在以下条件满足后才算完成：输入范围清楚，输出格式完整，事实没有被越权改动，冲突得到标记，结果属于正确的项目范围，作者已经决定采用或放弃，并且后续依赖的信息已经同步更新。
