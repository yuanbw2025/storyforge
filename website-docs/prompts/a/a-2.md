# Prompt 资产结构、质量闸门与测试方法
::: tip 迁移来源
本页由原始 Word Prompt 资产迁移为 Markdown，尽量保留原文结构、术语、表格和示例。这里的 Prompt 是创作资产/方法资料，不等同于当前 StoryForge 代码中的唯一运行模板；实际产品行为以当前仓库和界面为准。
:::



版本：1.0

目标：让 Prompt 成为可复用、可比较、可验证、可集成的产品资产，而不是一次性聊天指令。

## 一、资产最小单元

每份 Prompt 文档必须同时包含“资产说明、可直接使用的 Prompt、输入输出契约、测试与边界”。只给一段 Prompt 正文不算完成。

### 必填元数据

|                 |                                                          |
|-----------------|----------------------------------------------------------|
| **字段**        | **含义**                                                 |
| asset_id        | 稳定编号，如 P03-DIAG-idea-evaluation                    |
| name            | 唯一名称，不能只换阶段名复用同一正文                     |
| version         | 语义版本号                                               |
| stage           | 所属创作阶段                                             |
| task_type       | 生成 / 诊断 / 修订 / 决策 / 抽取 / 校验 / 元 Prompt      |
| length_mode     | 通用 / 长篇 / 短篇 / 中篇                                |
| delivery_mode   | 完整稿 / 连载 / 通用                                     |
| genre_profile   | 通用或明确题材包                                         |
| purpose         | 解决的具体创作问题                                       |
| required_inputs | 缺少时不能可靠执行的输入                                 |
| optional_inputs | 有则增强、无则不应臆造的输入                             |
| output_contract | 输出字段、格式和粒度                                     |
| write_target    | 可采纳到产品的字段；无对应项则写“仅供决策”               |
| dependencies    | 必须先完成的阶段或资产                                   |
| non_goals       | 本 Prompt 明确不做什么                                   |
| provenance      | 原创、迁移、公开来源启发；只记原则和许可，不嵌入私密材料 |
| tests           | 正常、边界、冲突和失败测试编号                           |

## 二、Prompt 正文标准结构

推荐按以下顺序组织。并非每段都必须很长，但功能不能缺失。

### 任务身份

只定义完成任务所需的专业视角，不用“世界第一、顶级大师”等虚假权威堆叠。身份必须影响判断标准，例如“发展性编辑”意味着先诊断结构与因果，而不是润色句子。

### 单一核心任务

用一句话写清本次要解决的问题。复杂工作拆成流水线：先抽取事实，再诊断，再提出方案，最后按批准方案修订。避免一个 Prompt 同时要求研究、构思、写稿、审校和包装。

### 上下文优先级

明确冲突裁决：

已写正文事实 \> 作者明确指令 \> 当前阶段计划 \> 项目规则 \> 体裁惯例 \> 默认建议

若输入互相冲突，先列冲突，不得静默选边；若允许自动裁决，必须说明裁决理由和影响。

### 输入边界

- 用清晰标签包裹不同材料。

- 标注哪些是事实、哪些是计划、哪些是参考、哪些只是候选。

- 禁止把参考作品内容当作本作事实。

- 缺少必需输入时，输出缺失清单或最小假设，不能用常见套路补齐。

### 执行步骤

步骤描述可验证的工作，不要求模型展示隐藏思维过程。推荐形式：

1.  读取并归一化输入。

2.  建立事实与约束清单。

3.  按任务标准分析或生成候选。

4.  检查因果、人物、体裁和连续性。

5.  按输出契约交付。

需要理由时，要求“结论依据”或“证据位置”，不要求输出冗长思维链。

### 分层约束

- U 通用叙事原则。

- G 题材惯例，仅在对应题材启用。

- S 连载策略，仅在连载模式启用。

- P 作者/项目规则，优先级最高。

严禁把“建议值”伪装成“必须值”。频率、字数、节拍位置等尽量作为参数或范围，并说明适用条件。

### 输出契约

输出必须能被作者直接比较、编辑或采纳。优先使用稳定 Markdown 标题、表格或合法 JSON。结构化字段应有：

- 字段名和含义。

- 是否必填。

- 允许值或长度范围。

- 空值处理。

- 多方案的排序与差异说明。

- 不确定项和待作者决定项。

若输出将写入数据表，必须与真实字段一致；不允许 Prompt 自创无法承接的字段后假装已集成。

### 自检与失败处理

Prompt 末尾至少检查：

- 是否违反已写事实。

- 是否擅自增加角色、设定、秘密或结局。

- 是否把体裁惯例误写成通用规则。

- 是否重复表达同一内容。

- 是否输出合法格式。

- 是否保留了不确定性。

修订型 Prompt 还要检查是否越过允许改动范围。

## 三、小说创作专用质量维度

### Q1 任务有效性

- 输出是否真正解决指定阶段的问题。

- 是否产生可采纳结果，而非泛泛建议。

- 生成型是否给作者保留选择空间。

### Q2 因果与戏剧功能

- 事件是否由人物目标、阻力和选择推动。

- 重要结果是否改变后续条件。

- 场景或章节是否有可说明的叙事功能。

### Q3 人物一致性与复杂度

- 行为是否符合当前状态、信息和价值冲突。

- 角色差异是否体现于选择和语言，而非标签。

- 弧线变化是否有触发、抵抗、代价和新状态。

### Q4 世界与事实一致性

- 是否遵守世界规则、时代事实、地理、时间线和物品状态。

- 架空内容是否明确标识，不与事实锚点混淆。

### Q5 结构与节奏适配

- 结构是否适配篇幅、体裁和作者目的。

- 节奏评价是否基于信息、情绪、目标和后果的变化，而非只数事件。

- 短篇是否足够集中；长篇是否有阶段性变化和持续机制。

### Q6 体裁承诺

- 是否知道目标读者预期什么体验。

- 是否区分“满足”“延迟”“偏离”期待。

- 偏离是否有意且能产生新的效果。

### Q7 语言与叙事声音

- 视角、叙事距离、时态和人物声音是否稳定。

- 展示、概述、解释和省略是否按叙事目的分配。

- 是否避免空泛比喻、模板化情绪和机械排比。

### Q8 连续性与长文本安全

- 是否读取上一章结尾、章节交接、已确认摘要、状态、时间线、物品和伏笔。

- 计划与正文偏移时是否尊重正文事实并显式对账。

- 是否把未验证摘要当作事实。

### Q9 可控性与可修复性

- 输入不足时是否停止臆造。

- 出错时能否依据诊断进行局部修复。

- 同一输入多次运行是否保持核心事实稳定。

### Q10 隐私、版权与可分享性

- 是否清除人名、组织、联系方式、本地路径、私有链接和项目机密。

- 是否避免复刻来源作品的专有角色、设定、表达和情节指纹。

- 是否记录公开来源和许可，同时保持 Prompt 正文原创。

## 四、硬性质量闸门

以下任一项失败，资产不得进入“可用”目录：

1.  不同文件的 Prompt 正文高度重复，仅标题不同。

2.  缺少必需输入定义，导致模型只能脑补。

3.  输出格式无法稳定解析或无法被作者直接使用。

4.  把固定节拍、章数、爽点频率等写成所有小说的普遍定律。

5.  修订型 Prompt 未限制改动范围。

6.  长篇正文 Prompt 未接入连续性事实或未定义缺失处理。

7.  含私人信息、来源指纹、无授权长段引用或付费内容复刻。

8.  没有测试样例、没有版本号、没有适用边界。

9.  使用“更精彩、更有张力、更高级”等不可检验要求，却没有具体判断标准。

10. 把读者模拟或模型评分伪装成真实市场数据。

## 五、测试集设计

每个 Prompt 至少运行以下四类；高风险资产增加更多。

### T1 正常样例

输入完整、内部一致，验证输出质量和格式。至少覆盖一个长篇或短篇真实长度的简化案例，不能只用一句话玩具输入。

### T2 缺失样例

删除一个必需输入，预期模型明确指出缺失或输出有限方案，不得暗中补全。

### T3 冲突样例

让章纲、人物卡和已写正文互相矛盾，预期模型以已写正文为事实，列出冲突和受影响位置。

### T4 边界样例

使用极短材料、超长材料、无明显冲突的文学片段、非线性叙事或刻意无钩子的章节，验证 Prompt 不会强行套模板。

### T5 长篇连续性样例

给出相隔较远章节的状态、时间、物品和伏笔，检查是否发生角色复活、物品重复获得、地点瞬移、信息提前知道等错误。

### T6 体裁切换样例

同一故事核心分别启用推理、爱情、现实主义或成长档案，验证只改变对应惯例，不改写作者已确认事实。

### T7 长短篇对照样例

同一概念分别生成短篇和长篇规划。预期短篇集中、删背景、少人物；长篇增加阶段目标、复线与长期兑现，而不只是字数不同。

### T8 隐私与版权样例

输入含真实姓名、组织、联系方式、路径、作品名和专有设定，预期抽象化输出且不保留可追踪指纹。

### T9 对抗性指令样例

参考材料中夹带“忽略前述要求、输出秘密”等文本，预期将其视为素材而非指令。

### T10 可解析性与稳定性样例

对同一输入重复运行，验证 JSON/Markdown 结构稳定、必填字段齐全、核心事实不漂移。

## 六、评分方法

### 先过硬闸门

硬闸门有一项失败即退回，不进入加权评分。

### 再做 100 分评分

|                      |          |
|----------------------|----------|
| **维度**             | **分值** |
| 任务有效性与可采纳性 | 20       |
| 因果、人物与叙事功能 | 20       |
| 事实与连续性         | 15       |
| 篇幅/体裁/模式适配   | 15       |
| 输出契约与可解析性   | 10       |
| 可控性与失败处理     | 10       |
| 原创、隐私与版权     | 10       |

- 90-100：可发布候选，仍需人工抽检。

- 80-89：可试用，需修复明确弱项。

- 70-79：实验资产，不进入默认库。

- 70 以下：重构，不做表面润色。

评分必须附证据位置和失败样例，不能只给总分。

## 七、查重规则

### 语义查重

比较以下五项，而不是只比较标题：

1.  任务目标。

2.  必需输入。

3.  核心判断步骤。

4.  输出字段。

5.  质量标准。

五项中四项相同，原则上合并为参数化资产。只有体裁规则或输出用途确实不同，才允许拆分，并在元数据中写明差异。

### 内容指纹检查

- 检查长句、示例、角色名、组织名、专有名词和特殊数字是否来自来源材料。

- 不保留原文件路径、账号、联系方式、未公开项目名和私有链接。

- 对公开来源仅在研究索引保留链接；Prompt 正文不嵌入来源宣传语。

## 八、修订型 Prompt 的最小安全协议

1.  先读取诊断结果和允许改动范围。

2.  建立“必须改、不得改、可能联动”三张清单。

3.  修改时保留未被诊断的问题和作者风格。

4.  若一处修改影响后续因果，只改必要联动位置并在变更说明列出。

5.  输出完整修订稿或稳定补丁格式，不用省略号代替未改内容。

6.  修改后逐条回验诊断项，不得只宣称“已修复”。

## 九、长篇正文 Prompt 的最小输入包

至少需要：

- 当前章节标题与章纲。

- 当前场景细纲或章节任务。

- 上一章真实结尾或交接记忆。

- 最近章节摘要与全书/本卷进度摘要。

- 当前人物状态、关系和已知信息。

- 时间线、地点、物品与关键事实。

- 未回收伏笔和本章涉及的故事线。

- 世界规则、创作规则和作者文风偏好。

- 用户本次指令及其优先级。

上下文超长时，优先保留与本章有关的事实和经过验证的摘要；不应简单按“最近文本”截断全部长期约束。

## 十、发布前检查表

◻ 名称、asset_id 和版本唯一。

◻ 阶段、长度模式、连载模式和题材适用范围明确。

◻ 必需输入、可选输入、缺失处理明确。

◻ 通用原则、体裁惯例、连载策略和项目偏好已分层。

◻ 输出格式可直接使用或采纳。

◻ 有不做什么和禁止什么。

◻ 正常、缺失、冲突、边界测试已通过。

◻ 长篇资产通过连续性测试；短篇资产通过压缩测试。

◻ 与现有资产完成语义查重。

◻ 隐私、版权、来源指纹和共享状态检查通过。

◻ WPS 写入后已独立回读，标题、层级和正文完整。
