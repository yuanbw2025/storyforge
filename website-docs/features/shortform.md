# 短篇小说

面向约 5,000～25,000 字、3～8 章的独立故事。入口：“短篇 → 作品库 → 新建短篇”。当前已形成创作、审校、定向重写、版本与导出的工程闭环。

## 准备什么

准备一句话故事、目标读者、篇幅、核心冲突和希望读者感受到的结尾效果。无需先建立独立世界。

## 完整流程

1. **创作意图**：明确目标、篇幅和约束。
2. **故事设计**：确定人物选择、冲突升级和结局，确认 AI 候选。
3. **章节卡**：检查每章职责与承接，避免短篇被拆成重复的情节。
4. **正文**：逐章生成、编辑和采纳；检查实际保存的正文。
5. **全篇审校**：查看带章节依据的问题，选择需要定向重写的部分。
6. **版本与导出**：完成检查通过后保留冻结版本，导出 Markdown、TXT 或 JSON。

## 怎样判断可以交付

检查章节是否齐全、实际字数与目标的差距、待处理候选和严重问题。正文改变后，原来的审校报告可能不再适用于新版本，需要重新核对。

发布是保留本地冻结版本，不等于自动发布到公共网站。

## 修订与派生

定向重写用于修正具体章节，保留其他章节已经确认的内容。在“扩展与派生”中可以显式派生世界；后续世界修改不会自动改写原短篇。

## 常见问题

**实际字数与目标不一致？** 先核对完成检查和各章长度，调整章节任务后定向补写或压缩。目标字数不是模型精确计数保证。

**生成结束却无法发布？** 检查缺章、未采纳候选、过期审校和未解决的严重问题，按提示逐项处理。
