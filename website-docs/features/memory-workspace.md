# 本地记忆工作区

本地记忆工作区把浏览器 IndexedDB 中的确定内容投影为用户硬盘上的可读文件。它既是可核对映像，也支持在安全边界内由作者从项目侧或硬盘侧修改受支持内容。

## 项目位置

- 新建项目时可选择项目存储位置，也可以之后在“设置 → 项目存储工作区”绑定、更换或重新授权。
- 选择文件夹本身不会立即写文件；同步由作者主动检查和确认。
- 未绑定文件夹时，项目仍可在浏览器数据库中使用。

典型目录：

```text
我的小说/
├─ storyforge.workspace.json
├─ worlds/
├─ works/
│  └─ <WORK-CODE>/
│     ├─ chapters/
│     └─ memory/
│        ├─ story-core.yaml
│        └─ creative-rules.yaml
└─ .storyforge/
   ├─ manifest.json
   ├─ recovery/
   ├─ runs/
   ├─ history/
   └─ trash/
```

## 日常同步

1. 绑定或重新授权项目文件夹。
2. 点击“检查记忆与本地文件”。检查只做本地读取、解析、哈希、作用域和依赖检查，不调用模型。
3. 查看项目改动、本地改动、双方冲突、缺失、额外或损坏。
4. 项目内改动由作者确认写入硬盘；本地改动先形成候选和影响计划，再由作者确认采纳。
5. 冲突必须由作者明确选择哪一侧为准；覆盖或删除前保留恢复证据。

## 可编辑与只读范围

当前可直接编辑 Workspace、World、Work、章节 Markdown，以及每个 Work 下的 `story-core.yaml` 与 `creative-rules.yaml`。Harness 运行记录、候选、作者决定、采纳和验证证据等进入恢复胶囊，其中高风险账本和回执保持只读。

## 恢复

- 浏览器数据仍在：重新授权原目录，先检查差异再同步。
- 浏览器数据库丢失：可从工作区校验 identity、manifest、恢复胶囊和文件 hash，再重建正式内容和引用。
- 不支持 File System Access API 的环境：使用工作区包导出/导入。
- 重大迁移或删除前仍建议保留完整 JSON 备份。

## 隐私与费用

文件扫描、差异检查、结构校验、影响计划、哈希、同步和恢复均在本机完成，不需要模型调用，因此不消耗 AI token。只有作者另行启动 AI 生成、文风学习或语义复核时，才会调用用户自己配置的模型服务。

当前不包含云同步、多人协作、Git 自动提交或 StoryForge 服务端托管。
