# 长篇：连续性、章后整理与改稿

长篇连续性依靠原文、已确认事实、摘要和检索共同维护。模型仍可能漏看或误解，所以每一章都需要作者核对。

## 写完一章之后

检查章后整理提出的候选：人物关系与状态、物品变化、事件时间、伏笔、事实和主支线进度。只确认正文有依据、且应作为后续创作依据的内容。

角色的猜测不一定是客观事实；作者知道的秘密也不代表所有角色都知道。

## 各工具怎样配合

| 工具 | 适合检查 |
| --- | --- |
| 伏笔看板 | 是否已经埋设、回应、回收；关联章节是否正确 |
| 事实库与认知 | 事实依据、角色知道什么、异常或过期记录 |
| 状态表与物品栏 | 角色状态、物品获得和消耗是否承接 |
| 故事年表 | 剧情时间顺序 |
| 主支线与进度 | 当前章节是否推动既定故事线 |
| 改稿与影响检查 | 修改影响了哪些未来规划和资料 |

## 状态字段异常时如何恢复

分步骤稳定性修复开发版会在正文页指出异常状态卡，正文仍可手工编辑和保存。相关生成会先暂停，避免漏掉状态后继续写；不会自动清空或改写异常记录。当前主干与发行状态见[开发记录](/updates/development-status)。

1. 点击“修复状态字段”，进入“状态与物品”。
2. 可先“导出原始字段”留档，再展开需要修复的卡。
3. 逐项填写字段名和文本值；不需要的异常项可明确移除。“编辑原始内容”供需要核对原始格式时使用。
4. 点击“保存修复”。校验或写入失败时，原记录与当前输入保留；修正后可以重试。
5. 刷新确认字段仍在，再回到正文继续生成。

另一窗口已经修改同一张卡时，旧修复会被拒绝。先保留当前输入，重新打开并对照新状态，避免覆盖别人的修改。完整备份仍从[备份与恢复](/guides/backup-restore)进入；状态文本导出不能代替完整备份。

## 保存候选修改后再刷新

正文候选可先“保存候选修改”，再刷新或继续编辑。保存只更新候选，正式正文仍需明确“采纳”。切换步骤前会尝试保存候选修改；保存失败会阻止离开并保留输入。直接刷新或关闭前，请先确认“候选已保存，尚未采纳”。 手机窄屏的正文工具栏随页面滚动，可滚动到候选区域保存、采纳，再返回正文保存。

清空候选后仍可重新输入；空白候选不能保存或采纳。上述候选保存能力与状态修复一同处于开发版验证范围。

## 修改早期章节的推荐顺序

1. 保存版本或完整备份。
2. 修改正文，确认实际保存结果。
3. 检查旧摘要、事实或审校是否已过期。
4. 阅读影响列表，逐项决定后续章纲、伏笔和设定要怎样调整。
5. 更新需要处理的内容，再继续生成下一章。

系统不会因为一次改稿自动重写整本小说。已确认历史、当前候选和未来规划需要分别处理。

## AI 没想起早期细节时

先检查细节是否写在当前作品、是否已经确认、是否属于本章之前，以及原文和摘要是否仍有效。查看本次生成依据，必要时在本轮要求中明确提醒相关事件。

重复生成不一定能补足遗漏，还会增加费用。可把问题和对应章节整理后提交[反馈](/feedback/bug)。

硬盘中的记忆文件如何核对，见[本地记忆工作区](/features/memory-workspace)。
