# 长篇：大纲、细纲与正文

## 百科引用异常与正文入口

正文中的百科名称和摘要用于只读引用预览。[PR #231](https://github.com/yuanbw2025/storyforge/pull/231) 已修复异常百科名称或预览值阻断正文入口的问题：不合法的名称不参与引用，非文本预览按空内容处理，原百科记录保持不变。进入章节后可继续编辑、保存并刷新核对正文。若仍报错，保留原记录，提供版本、错误文本和操作步骤；此修复没有查明异常值的写入来源，也不代表其它原生退出已解决。

## 先分清三个层次

| 层次 | 回答的问题 | 推荐内容 |
| --- | --- | --- |
| 卷纲与章纲 | 故事如何推进 | 本卷目标、本章事件、转折和承接 |
| 场景细纲 | 这一章怎样发生 | 人物行动、冲突、场景变化和退出状态 |
| 正文 | 读者实际读到什么 | 叙述、动作、对白与具体细节 |

## 推荐操作顺序

以下可选场景任务、全章评审与范围修订适用于包含 [PR #141](https://github.com/yuanbw2025/storyforge/pull/141) 的源码版本，已于 2026-10-20 合入 main。

1. 在“大纲与章纲”选择卷或章节，先确定当前层级。
2. 手工填写或生成大纲候选，检查是否接续已经写完的内容，再确认。
3. 进入“场景细纲”，检查人物、地点、冲突、转折和章节结尾。
4. 进入“正文”，选择正确章节；生成前检查本轮要求与可见的生成依据。
5. 查看候选，修改不合适的段落，再确认写入。
6. 核对实际正文和保存状态，处理[章后整理](/features/longform/continuity)。

## 正文生成前补充本章要求

点击正文生成或续写后，在“正文生成提示”中填写本章重点、节奏、视角或篇幅要求；输入与本章自定义指令同步，留空则使用已有资料。确认后才进入原保存、预算与生成流程；取消会保留本章临时输入，不发起模型请求。

切换章节后先核对弹窗中的章名和要求。生成结果仍需审阅和明确采纳，自定义模板没有写入提示变量时也会补送本轮要求。依据：[PR #209](https://github.com/yuanbw2025/storyforge/pull/209)。

## 细纲与本章任务

在“大纲与章纲”选中本章，进入独立的“场景细纲”。展开“场景任务（可选，可留白）”，按需记录进入状态、本场目标、关键选择、行动后果、退出状态、场景功能与读者期待。日常、缓冲和收尾也可以使用；不要求每场都有惩罚、敌人或奖励。

通过“编辑本章细纲”“写本章正文”“查看本章细纲”在同一章节间跳转，先等待当前输入保存。生成前核对本轮要求、资料和目标字数；字数要求不是精确长度保证。

## 全章评审与定向修订

1. 保存正文，在工具栏打开“质量审校”，选择“审校”“表达与重复”或“追读力”。按需填写“本轮评审补充要求”，点击“开始检测”。无法完整送审时会阻止检测；完整送审仍可能漏检或误判。
2. 核对问题引用，勾选本轮要改的问题。默认只允许修改问题所在段落，也可展开“选择其它可改段落”；在“保护原句”中每行填写一句原文，须完全相同且在原稿只出现一次。
3. 按需填写“本轮修稿要求”，说明要保留的动作、人物表达或收尾。点击“生成修订并复核”，本轮最多一次修订、一次复核，新增最多两次模型请求。
4. 等待正式候选和完整复核，比较原稿与修订稿，再选择“确认采纳修订”或“放弃修订”。未通过复核只保留只读预演，原稿不被覆盖；模型认为改善仍需作者判断。
5. 刷新后可以回读报告、要求与决定，不会自动重发。正文或相关资料变化后，旧报告和候选可能过期；核对变化后再明确开始新一轮。

节点模式调用同一流程：连接“全文评审与修订”和“定向修订与复核”，选择问题、范围、Prompt、温度、输出上限及 AI 配置，等待正式输出后确认采纳或拒绝，再回到分步骤核对同一正文与格式。确认上游后继续下游会重读当前资料；改变目标、资料或连线仍会使旧候选过期。节点模式整体仍为预览。

这些操作改善资料交接与作者控制，不保证故事更吸引人或达到平台标准。本轮独立读者盲评与作者计时转为后续自愿评测，不需要填写问卷才能使用。

## 续写与改写

续写应承接已写正文的结尾；润色侧重表达；重写可能改变事件和人物表现。调用前明确处理范围，保留原稿或版本记录。

如果改变了重要事实，不要只看这一段是否顺畅，还要检查后续章纲、伏笔和角色状态的影响。

## 续写准备或拒绝细纲失败

点击续写后，若保存当前编辑、准备连续性资料或组装生成依据失败，正文区域会显示具体原因。先保留当前文字，按提示处理保存、资料或配置问题，再明确重试；不要把没有开始生成当成已经保存或完成。

拒绝场景细纲或批量细纲候选时，若拒绝操作保存失败，界面会提示错误并保留待确认候选，方便检查后重试。候选只有在拒绝成功后才清除，失败不会被当作已经拒绝。遇到提示时先保留内容，不必清空作品。

这两项修复见 [PR #166](https://github.com/yuanbw2025/storyforge/pull/166)。

## 故事线提示阶段数据格式异常

遇到“阶段数据格式异常”时，原始数据会保留，先暂停该故事线的 AI 生成并导出完整备份。切换到对应故事线，展开“检查并修复阶段数据”，对照原始 JSON 核对每个阶段及关键事件。

保留合法阶段 ID、已有事件和其它内容；仅在原本没有关键事件时使用空数组，不用清空事件来消除错误。确认内容正确后点击“确认保存阶段修复”。保存失败或原文已变化时，按错误提示重新核对，不能视为已修复；“放弃编辑稿”可回到原始内容。删除阶段会解除相应进度引用，应先确认影响。格式无法判断时保留原件再反馈。

这项修复处理异常读取与作者显式恢复，尚未确定坏值的原始写入来源，也不等于原生退出或全部长篇故障已解决。依据：[PR #226](https://github.com/yuanbw2025/storyforge/pull/226)。

## 大纲调整后检查什么

移动或修改章节后，检查章节顺序、正文对应关系、伏笔关联与故事年表。已有正文是重要依据，重新生成大纲不应让你忽略已经写完的故事。

## 为什么生成没有直接保存

正式 AI 结果通常先进入候选确认。流式输出结束只说明生成结束，是否进入正式内容要看采纳结果。遇到失败或过期提示，先保留可用文本并阅读原因。

详见：[AI 候选与恢复](/guides/ai-workflow) · [导出与交付](/guides/export)。

## 场景细纲生成后仍在保存候选

“一键拆场景”或“完善细纲”的文字输出结束后，界面可能仍显示“正在校验并保存候选”或“正在建立可恢复候选”。此时先等待，编辑、采纳、忽略和重试入口尚未开放；候选成功保存后再审阅并确认。不要把文字已经显示完整当成可以关闭页面的保存凭据。

这项等待保护已随 [PR #107](https://github.com/yuanbw2025/storyforge/pull/107) 于 2026-10-05 进入主干；不会替作者自动采纳候选。

## 保存、拖动和切章提示

作品概况与故事核心的编辑会保留当前草稿，按界面保存后核对正式内容。拖动章节靠近列表边缘时可自动滚动；跨卷移动后仍要检查归属。快速切换章节时，生成状态和恢复候选应对应当前目标，避免把上一章结果当成本章内容。

流式输出可逐步阅读；正文候选可先编辑再采纳，并保留修订依据。生成完成、采纳完成和数据保存是不同状态，退出或刷新前以保存提示为准。

2026-10-04 主干修复了资料已存在却被误判为缺少必读资源的问题，并减少把可并存事件误判为单一状态冲突的情况。真实缺失或冲突仍需处理；请勿通过删掉事实记录绕过阻断。

## 大纲 Agent 候选的采纳与过期提示

在主 Agent 中输入大纲目标，先“讨论与规划”，检查待确认计划，再“确认计划并开始”。生成后审阅标题与内容，点击“采纳”才正式写入；刷新后应回到仍待确认的候选，不会自动再次生成或采纳。

2026-10-16 的 [PR #158](https://github.com/yuanbw2025/storyforge/pull/158) 修复了自动编排卷章大纲时，生成与采纳使用的策略身份不一致、导致有效候选被误报为过期的问题。真实的来源、权限或内容变化仍会使候选过期；遇到提示先保留可用文字、核对原因，不要通过清空作品或关闭过期检查来绕过。


## 查找、批量替换与保存

正文的查找替换和工具中的全局替换使用同一套界面：“文字替换”处理当前章节或全书，“智能实体改名”同步角色、地点和词条引用，“跨设定字段”处理选定范围的描述文字。

跨设定替换先预览每条记录的修改前后内容，再确认创建快照并替换。正文标签、实体名称、词条引用、数值与选项字段不会作为普通文字修改；同一词条的多个文本字段一起保存。预览后资料变化会停止本次替换，重新预览即可。撤销不会覆盖替换后的新编辑；关闭页面后，可在版本历史找到替换前快照。

场景细纲与情绪节拍的协调操作以实际保存结果为准：等待期间不提前显示成功；失败可重试，原稿保留。

生成前的预览与运行详情可展开“提示词与文风来源、覆盖关系”，查看本次模板、参数及创作规则、文风画像等实际是否纳入。显示“未提供本次证据”时，不代表该来源已被读取。

## 精细章纲中断后怎样继续

在“大纲与章纲”分块生成精细章纲时，先保留已经生成的候选。遇到前序候选快照或来源提示，阅读错误、核对目标章节及相关内容，处理原因后从原入口明确重试；不要清空作品或通过关闭校验继续。生成完成后仍需审阅并确认采纳。

[PR #171](https://github.com/yuanbw2025/storyforge/pull/171) 保留分块生成所需的前序候选原文，修复内容截断后快照缺失导致的中断。候选内容或来源真正变化时仍会阻断，修改后应重新核对。
