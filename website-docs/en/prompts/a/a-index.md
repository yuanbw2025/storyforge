## 2. Project definition and story core

## 4. Length and delivery branches

- Longform: [Volume promises, subplots, and middles](/en/prompts/c/c-10), four Prompts.
- Short fiction: [Single effect, compression, ending](/en/prompts/c/c-11), four Prompts.
- Serial add-on: [Reader rewards, breaks, production](/en/prompts/c/c-12), four Prompts, enabled only for serials.

Choose longform or short fiction as the main architecture. Serialization is an added production layer, not a third story structure.

## 5. Chapters, prose, and continuity

1. [P10 Chapter function, scene turns, emotion](/en/prompts/c/c-13): five Prompts, including chapter titles.
2. [P11 Openings, continuation, dialogue, action, narration](/en/prompts/c/c-14): six Prompts.
3. [P12 Memory, facts, states, timeline, foreshadowing](/en/prompts/c/c-15): six Prompts.

Cycle: chapter task → scene cards → prose → memory/state diff → plan reconciliation → next chapter. Maintain continuity after each confirmed chapter, not only after finishing the book.

Genre packages cover only their genres. Author project rules always take priority. Mixed genres need one main promise and a few optional supporting packages.

## 9. Shortest usable routes

- Complete longform: P00 → P02 → P03 → P05/P06/P07 → P08 → P09L → P10/P11/P12 cycle → P13/P14/P15 → P16.
- Serial longform: above + P09R; organize/judge reader feedback before changing outlines.
- Short fiction: P00 → P01/P03 → P09S → simplified P10 → P11 → P14/P15 → P16.
- Existing-manuscript revision: P13 → P12 continuity audit → P14 → P15 → P16.

## 10. Usage principles

1. Do not run multiple generation Prompts concurrently against the same fact target.
2. Authors confirm diagnoses before revision Prompts.
3. Genre/serial rules cannot override written facts or explicit author choices.
4. Extract mechanisms from references, not proprietary names or expression fingerprints.
5. Before writeback preserve original draft, Prompt version, input snapshot, and adoption record.
