# 插件故障与恢复

优先保留作品、原始安装包和报错。不要清空网站数据或删除 IndexedDB，也不要直接在真实作品上尝试未知迁移。完整备份见[备份与恢复](/guides/backup-restore)。

| 现象 | 先检查 | 下一步 |
| --- | --- | --- |
| 没有工坊入口 | 应用版本是否包含预览、是否打开正确应用路径 | 打开该应用的 `/workshop` 并开启开发预览；旧版本参见[当前状态](./) |
| 安装后没有功能 | 安装与启用是分开的；作品／世界是否选对 | 在“已安装”确认信任启用，再去工作台或相应历史页面 |
| 内容包没有自己的按钮 | 它没有执行代码的界面 | 查看“保存的插件内容”；专属界面需相应功能插件 |
| 缺少依赖或版本不一致 | 插件要求的是准确版本，不是任意新版 | 安装作者声明的依赖；不要自己改清单假装兼容 |
| 提示目标已被替换 | 同一作用域、同一模块已有替换插件 | 先停用原替换者，再启用新插件 |
| 目录下载失败 | 地址是否 JSON／原始包，HTTPS、CORS、重定向、摘要 | 让作者修复分发；也可取得可信原文件后从文件安装，不关闭浏览器安全设置 |
| 同版本文件冲突 | ID 和版本相同但文件字节不同 | 作者发布新版本；不要覆盖已有版本 |
| 保存发生冲突 | 另一标签页或操作已更新记录 | 先复制未保存文字，重新读取最新记录，再手动合并，不强制覆盖 |
| 换浏览器后数据不见 | 是否更换域名、端口、浏览器或配置 | 回到原环境导出完整备份，再导入新环境；不自动跨地址同步 |
| AI 没有生成或不能确认 | 模型配置、作者是否开始、候选是否已过期 | 查看“AI 任务历史”；过期或结果未知时先核实，不反复盲点重试 |
| MCP 工具不可用 | 服务是否运行、地址／协议／工具名、认证、浏览器网络限制 | 按插件说明检查本机桥或外部服务；未支持的 Apps 等能力不能靠修改提示词开启 |

## 插件导致页面报错

先使用工坊的 **安全模式**。如果页面无法正常打开，在当前应用的工坊地址加上 `?safe-plugins=1`；已有查询参数时用 `&safe-plugins=1`。例如 `http://localhost:5173/storyforge/workshop/installed?safe-plugins=1`，请换成自己的地址。

安全启动会在模块求值前跳过插件。停用故障插件后退出安全模式，再单独检查可信插件。若页面已经被插件死循环卡住，先关闭该标签页，在新标签直接打开安全启动地址；它不能终止已经卡死的主线程。

## 升级失败或需要旧内容

1. 保存完整备份、旧包与新包，记录插件 ID、版本和报错。
2. 迁移校验或事务失败时，原数据代应保留。不要通过删除数据或改 schema 版本绕过错误。
3. 在“已安装”的 **数据恢复与操作记录** 选择可用旧数据代；缺少对应包时重新安装那个准确版本。
4. 恢复将旧内容复制成新的数据代，不删除恢复前较新的编辑。恢复后再检查内容并决定是否启用。
5. 停用或缺包时，在“插件工作台 → 保存的插件内容”检查原始记录。看得到记录不代表仍有专属编辑界面。

导入的历史 AI 候选和工具结果是只读历史，不恢复旧任务的写入或查询／取消权限。在新作品继续创作需要明确开始新任务。

## 怎样提交有用的反馈

记录熔炉版本或提交、插件 ID／版本／摘要、浏览器与操作系统、作品或世界归属、从哪一步开始出错、预期与实际结果、是否能在独立测试作品复现。附脱敏截图或最小示例。

不要附真实私稿、整个浏览器数据库或 API key。代码问题优先联系插件作者；宿主接口、安装或数据恢复问题可通过[反馈中心](/feedback/)提交。作者修复后仍应递增版本，不让用户安装来源不明的替换文件。
