# 保存、备份与恢复

作品主要保存在当前浏览器、当前站点的本地数据库中。自动保存方便日常编辑，但不能替代独立备份。

## 先分清四种文件

| 文件 | 用途 | 注意事项 |
| --- | --- | --- |
| Markdown / TXT 等正文导出 | 阅读、投稿、外部编辑 | 不包含完整项目关系和运行记录 |
| 产品发布 JSON（例如短篇发布版本） | 保存某个产品的冻结交付清单 | 不是完整项目备份，不能直接使用项目 JSON 导入入口 |
| 完整项目 JSON 备份 | 恢复项目、注册数据及其引用关系 | 使用数据管理的项目 JSON 导入入口，必须匹配当前支持的备份格式 |
| 本地记忆工作区 / `.storyforge.json` 工作区包 | 可读文档、恢复胶囊与校验信息 | 使用工作区恢复或工作区包导入入口；不是普通正文 ZIP |

不能仅凭 `.json` 扩展名判断文件用途。短篇的发布 JSON 是冻结的作品版本清单；完整项目备份由数据管理导出；工作区包虽然也是 JSON，却有自己的包格式和恢复入口。

## 第一次备份

![当前数据管理界面：导出导入与版本历史](/assets/current/data-current.png)

1. 打开“首页 → 数据与备份”并选择工作区；也可从对应产品的“版本与导出”或“通用设置”进入数据备份。
2. 选择完整项目 JSON 导出，确认下载文件已经存在。
3. 在另一处保留副本，文件名记录作品与日期。
4. 重要正文另存一份阅读格式。

## 图片、附件与运行记录是否包含

完整项目 JSON 会导出纳入项目备份范围的注册数据，并把已登记的共享媒资对象转换成可携带的数据：读取实际文件、校验大小与 SHA-256，再内嵌为带 MIME 类型的 base64 内容。因此，正式登记并就绪的图片等媒资不只是导出一个本地路径；文件较大时，备份 JSON 也会明显增大。

这不意味着任意外部 URL、未纳入项目的硬盘文件或未完成的下载都会自动打包。媒资未就绪、内容缺失或校验失败时，完整备份可能被拒绝；应先修复文件，再重新导出，不要把失败下载当成成功备份。

恢复胶囊可保留运行记录、候选、作者决定和采纳证据。它们可能包含私稿和上下文，不宜把完整备份当成公开分享包。

## 工作区包与硬盘目录的区别

数据管理中的“导出工作区包”从**当前浏览器项目**生成可读文档和完整恢复胶囊，下载为 `.storyforge.json`。它不会自动把尚未采纳的硬盘编辑合并进来。若硬盘上有最新修改，先检查差异、确认采纳，再导出包。

硬盘目录依赖浏览器对目录的授权；可读 Markdown 并不等于完整恢复材料。跨设备搬移时，应保留包括 `.storyforge/` 在内的完整目录，或使用工作区包，而不是只复制章节文件。工作区恢复会校验身份、清单、恢复胶囊及文件哈希；不要手动删改校验文件来绕过错误。

## 恢复之后核对什么

先保留原备份和原目录，不要在确认恢复结果之前删除旧环境。恢复完成后核对：

- 当前项目、作品与章节数量，正文开头、结尾和最近修改。
- 人物、设定、世界引用，以及当前使用的方案或版本。
- 关键图片和其他素材是否能实际打开，而不只是列表中有名字。
- 需要继续使用的候选、运行记录与发布版本是否存在。
- 工作区绑定和授权是否需要重新建立；先检查差异，再决定同步方向。

工作区导入会为本地对象重新绑定身份；部分历史运行回执可能因此标为“待复核”。这是对引用变化的明确提示，不代表历史证据被删除，也不要把旧的成功状态直接当作当前项目已验证。

当前完整项目备份使用版本 **14**，导入要求支持的精确格式；并非所有旧 JSON 都能自动升级。被拒绝时保留原件和错误信息，参见[版本与兼容](/updates/compatibility)。不要手改版本号、补空表或删字段强行导入。

## 换浏览器、设备或运行地址

在线版、本地 localhost、另一个端口以及另一个浏览器可能使用不同的存储空间。先在原环境导出，再在目标环境按导入提示恢复；恢复后核对作品、章节和关键素材，再处理旧环境。

浏览器隐私模式、清除站点数据或浏览器配置丢失可能导致本地作品不可访问。

## 使用硬盘工作区

在“设置 → 项目存储工作区”绑定目录，再进入数据管理检查差异。绑定文件夹不会自动写盘，模型任务完成也不会自动同步硬盘。

详见[本地记忆工作区](/features/memory-workspace)。

## 数据突然看不见

先确认地址、端口、浏览器和浏览器配置文件是否与原来一致。不要立即清理站点数据或覆盖原目录。

有 JSON 或工作区包时按支持的恢复入口操作；旧备份被拒绝时保留原件，查看[兼容说明](/updates/compatibility)并提交反馈。
