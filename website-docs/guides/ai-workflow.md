# AI 生成、候选确认与失败恢复

## 一次生成的正常过程

1. 选择正确作品、章节或场景，明确这次要做的事。
2. 检查输入、已有资料、模型与任务参数。
3. 开始生成，等待结果或明确的错误提示。
4. 阅读候选，核对事实与范围；可编辑、拒绝或按允许方式采纳。
5. 检查正式内容是否写入，并处理后续影响。

正式流程保存运行记录与版本依据，帮助解释失败和恢复。不同入口的恢复能力仍有差异，以当前页面提示为准。

## 候选状态怎样理解

| 提示 | 建议操作 |
| --- | --- |
| 可以采纳 | 仍需阅读，确认内容符合你的意图 |
| 可用但有警告 | 检查警告，按界面允许的方式编辑或接受 |
| 需要手工修复 | 保留可用文本，修正具体问题 |
| 阻断或版本过期 | 先处理来源、范围、权限或版本问题 |

模型返回完整文本不代表通过了保存条件。候选等待期间修改了原文，旧候选可能会被阻止采纳。

## 失败后先做什么

先保留当前结果，查看失败阶段和原因，再决定恢复或重试。余额、认证、权限、网络结果未知等问题不适合连续点击重发。

如果页面提供同一次运行的恢复入口，先检查它是否已有结果和待确认内容。不要默认重新运行整个流程就是恢复。

## 怎样写有效要求

说明目标、范围、必须保留的内容、允许改变的内容与输出形式。例如：“只润色这一段对白，保留人物决定和事件顺序”，比“全文优化”更容易核对。

[Prompt 资料库](/prompts/)提供方法参考；外部 Prompt 不会自动获得读取整个项目或写回正式内容的权限。

## 文学质量仍需作者判断

规则与结构检查可以发现一部分问题，但不能保证人物动机、因果、语气和文学效果。先用小任务验证模型，再扩展工作量。
