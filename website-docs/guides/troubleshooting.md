# 故障排查

先记下当前版本、访问地址、产品、操作步骤和完整错误文本。下面的检查顺序尽量保留你的作品与候选。

| 现象 | 先检查 | 下一步 |
| --- | --- | --- |
| 看不到旧作品 | 地址、端口、浏览器和配置文件是否变化 | 回原环境导出备份 |
| AI 认证或权限错误 | Key、服务商、模型权限 | 在服务商侧确认，避免重复发送 |
| 余额不足或限流 | 账户额度、并发、返回的限流提示 | 等待或调整账户后再试 |
| 连接测试成功但生成失败 | 模型能力、输入长度、输出限制 | 以小任务验证，保留错误文本 |
| 浏览器提示跨域 | Base URL 与代理配置 | 按设置页指引使用本地代理 |
| 输出中断或为空 | 当前运行状态、模型返回、网络 | 先检查是否已有可恢复结果 |
| 候选过期、不能采纳 | 等待期间源内容是否变化 | 核对当前版本后重新生成或编辑 |
| 无法发布 | 缺失章节、未采纳候选、严重问题、素材 | 按检查列表逐项处理 |
| 不能选择硬盘目录 | 浏览器能力、权限、运行环境 | 重新授权或使用工作区包 |
| 导入旧 JSON 被拒绝 | 备份格式与当前支持窗口 | 保留原件，查兼容说明 |
| 界面与文档不同 | 固定 Release、在线部署、当前 main | 查看版本说明与更新日志 |

## 不要用清空数据作为第一步

刷新、清缓存、清站点数据是不同操作。清站点数据可能删除本地数据库。先确认备份和原环境，不要为了修 UI 直接删除作品存储。

## 提交有用的 Bug 报告

通过[Bug 报告](/feedback/bug)提供版本、系统、浏览器、模块、步骤、期望与实际结果。可以附截图和脱敏日志；不要上传 API Key 或私稿。

如果没有可靠复现，说明“发生过一次”和当时条件，比猜测原因更有帮助。

继续阅读：[升级与兼容](/updates/compatibility)。

## 下载版的问题与故障反馈

包含此功能的构建可从“首页 → 通用设置 → 问题与故障反馈”进入；页面渲染报错或启动被阻断时，也有不依赖项目数据库的反馈入口。旧 v4.0.0 固定下载包不会自动增加这些功能，此入口适用于 v4.0.1 及之后的便携构建，正式附件以[最新发行页](https://github.com/yuanbw2025/storyforge/releases/latest)为准。

1. 点击“查看故障摘要并反馈”，先在本机检查摘要。内容限应用构建号、系统/浏览器类别、最近错误的类型和代码位置，以及可读取的启动器故障类型和时间；不带错误正文、手稿、提示词、API Key、完整网址、硬盘路径或整库内容。
2. 点击“带摘要打开官方反馈表单”。摘要通过浏览器片段带入，读取后移除片段；不会自动提交。
3. 补充标题、问题描述和复现步骤，检查“补充信息”并删除不想公开的内容，再提交。反馈进入项目公开 Issue；截图和附件也应先自行检查。
4. 网络不可用时保留本机记录，稍后重开反馈入口；不会在后台无限重试或偷偷补发。也可直接打开[Bug 报告](/feedback/bug)手动填写。

浏览器仅保留最近 7 天最多 20 条错误，摘要最多带最近 5 条、每条 3 处位置；刷新后仍可查看。“清空本地错误记录”仅清除浏览器诊断，不删除作品或模型配置。“数据与备份”中的完整诊断 JSON 仍单独下载，不会自动上传。

便携启动器在用户目录 `.storyforge/diagnostics/` 保留一份最近故障和会话状态。启动失败时，可手动打开官方反馈页并选择附上 `last-failure.json`。端口占用、权限错误和可捕获的进程异常会留下有限类型记录；重新启动发现上次会话未正常结束时只标记“异常中断待核对”。强制结束、断电、浏览器自身崩溃或诊断代码加载前的失败不保证可捕获，不能把中断一律当成程序崩溃。诊断不替代作品备份。
