# 故障排查

先记下当前版本、访问地址、产品、操作步骤和完整错误文本。下面的检查顺序尽量保留你的作品与候选。

| 现象 | 先检查 | 下一步 |
| --- | --- | --- |
| 看不到旧作品 | 地址、端口、浏览器和配置文件是否变化 | 回原环境导出备份 |
| AI 认证或权限错误 | Key、服务商、模型权限 | 在服务商侧确认，避免重复发送 |
| 余额不足或限流 | 账户额度、并发、返回的限流提示 | 等待或调整账户后再试 |
| 连接测试成功但生成失败 | 模型能力、输入长度、输出限制 | 以小任务验证，保留错误文本 |
| 浏览器提示跨域 | Base URL 与代理配置 | 按设置页指引使用本地代理 |
| 输出中断或为空 | 当前运行状态、模型返回、网络 | 先检查是否已有可恢复结果 |
| 候选过期、不能采纳 | 等待期间源内容是否变化 | 核对当前版本后重新生成或编辑 |
| 无法发布 | 缺失章节、未采纳候选、严重问题、素材 | 按检查列表逐项处理 |
| 不能选择硬盘目录 | 浏览器能力、权限、运行环境 | 重新授权或使用工作区包 |
| 导入旧 JSON 被拒绝 | 备份格式与当前支持窗口 | 保留原件，查兼容说明 |
| 界面与文档不同 | 固定 Release、在线部署、当前 main | 查看版本说明与更新日志 |

## 不要用清空数据作为第一步

刷新、清缓存、清站点数据是不同操作。清站点数据可能删除本地数据库。先确认备份和原环境，不要为了修 UI 直接删除作品存储。

## 提交有用的 Bug 报告

通过[Bug 报告](/feedback/bug)提供版本、系统、浏览器、模块、步骤、期望与实际结果。可以附截图和脱敏日志；不要上传 API Key 或私稿。

如果没有可靠复现，说明“发生过一次”和当时条件，比猜测原因更有帮助。

继续阅读：[升级与兼容](/updates/compatibility)。
