# 故障排查

## 启动时资源加载中断

应用尚未打开时，已识别的模块或样式加载失败最多自动重载一次。持续失败会保留错误与明确的重载入口，不循环刷新；普通错误不会触发这条自动恢复。应用打开后的模块失败仍按下方保存屏障处理，由作者明确点击重试，不自动发起模型任务，也不清理作品数据。[PR #215](https://github.com/yuanbw2025/storyforge/pull/215) 的恢复保护不等于所有 Crash 或内存问题均已解决。


先记下当前版本、访问地址、产品、操作步骤和完整错误文本。下面的检查顺序尽量保留你的作品与候选。

| 现象 | 先检查 | 下一步 |
| --- | --- | --- |
| 看不到旧作品 | 地址、端口、浏览器和配置文件是否变化 | 回原环境导出备份 |
| AI 认证或权限错误 | Key、服务商、模型权限 | 在服务商侧确认，避免重复发送 |
| 余额不足或限流 | 账户额度、并发、返回的限流提示 | 等待或调整账户后再试 |
| 连接测试成功但生成失败 | 模型能力、输入长度、输出限制 | 以小任务验证，保留错误文本 |
| 浏览器提示跨域 | Base URL 与代理配置 | 按设置页指引使用本地代理 |
| 输出中断或为空 | 当前运行状态、模型返回、网络 | 先检查是否已有可恢复结果 |
| 候选过期、不能采纳 | 等待期间源内容是否变化 | 核对当前版本后重新生成或编辑 |
| 无法发布 | 缺失章节、未采纳候选、严重问题、素材 | 按检查列表逐项处理 |
| 不能选择硬盘目录 | 浏览器能力、权限、运行环境 | 重新授权或使用工作区包 |
| 导入旧 JSON 被拒绝 | 备份格式与当前支持窗口 | 保留原件，查兼容说明 |
| 界面与文档不同 | 固定 Release、在线部署、当前 main | 查看版本说明与更新日志 |

## 模块加载失败时怎样重试

若报错含 `Failed to fetch dynamically imported module`、`Importing a module script failed` 或 CSS 预加载失败，先确认网络与访问地址，再点击错误页的“重试”。应用会先保存待保存编辑，再重新加载页面；正在运行的任务可能中断，回来后先查看原运行与候选，不连续点击生成。

若显示“编辑尚未保存成功，未重新加载”，请保留当前页面，处理保存错误后再试。不要清站点数据，也不要把保存失败当作已安全刷新。其他渲染错误仍从错误页重试。

## 不要用清空数据作为第一步

刷新、清缓存、清站点数据是不同操作。清站点数据可能删除本地数据库。先确认备份和原环境，不要为了修 UI 直接删除作品存储。

## 提交有用的 Bug 报告

通过[Bug 报告](/feedback/bug)提供版本、系统、浏览器、模块、步骤、期望与实际结果。可以附截图和脱敏日志；不要上传 API Key 或私稿。

如果没有可靠复现，说明“发生过一次”和当时条件，比猜测原因更有帮助。

继续阅读：[升级与兼容](/updates/compatibility)。

## 下载版的问题与故障反馈

v4.0.2 可从“首页 → 通用设置 → 问题与建议”进入。页面渲染报错或启动被阻断时，也提供不依赖项目数据库的反馈入口。

### 在应用内提交问题或建议

1. 选择“报告问题”或“功能建议”。不需要先发生崩溃，按钮无反应、显示错误或改进需求都可以提交。
2. 填写标题和问题描述；Bug 可补充复现步骤、期望结果。应用会附带版本、操作系统类别和客户端类型。
3. 若需要诊断信息，先点击“查看故障摘要并反馈”，检查内容，再勾选“附带下方预览的脱敏错误记录”。这是可选项，没有错误记录也可提交。
4. 勾选“我已检查填写内容，确认发送给维护者”，再点击“提交反馈”，等待提交结果。应用内反馈进入维护者私有收件箱，不会自动公开到 GitHub；提交失败时保留输入并按提示重试。

### 使用备用网页表单

“直接反馈问题”以及“带摘要打开官方反馈表单”会打开网页反馈。v4.0.1 的带摘要反馈也使用这条路径。摘要通过浏览器片段带入，读取后移除片段；表单不会自动提交。

补充标题、问题描述和复现步骤，检查“补充信息”后再提交。**网页表单创建公开 GitHub Issue**，不要附上不想公开的手稿、凭证或截图。可直接访问[Bug 报告](/feedback/bug)或[功能建议](/feedback/feature)。

摘要只包含应用构建号、系统/浏览器类别、错误类型和代码位置，以及可读取的启动器故障类型和时间；不包含错误正文、手稿、提示词、API Key、完整网址、硬盘路径或整库内容。

浏览器仅保留最近 7 天最多 20 条错误，摘要最多带最近 5 条、每条 3 处位置；刷新后仍可查看。“清空本地错误记录”仅清除浏览器诊断，不删除作品或模型配置。“数据与备份”中的完整诊断 JSON 仍单独下载，不会自动上传。

已同意错误上报时，同一次原生故障不会仅因本地摘要轮换或刷新而重新进入上报队列；不同时间的新故障仍分别记录。关闭错误上报或执行删除会清除相应的本机去重记录。此改进处理重复记录，不意味着原生崩溃原因已经修复。

便携启动器在用户目录 `.storyforge/diagnostics/` 保留一份最近故障和会话状态。启动失败时，可手动打开官方反馈页并选择附上 `last-failure.json`。端口占用、权限错误和可捕获的进程异常会留下有限类型记录；重新启动发现上次会话未正常结束时只标记“异常中断待核对”。强制结束、断电、浏览器自身崩溃或诊断代码加载前的失败不保证可捕获，不能把中断一律当成程序崩溃。诊断不替代作品备份。
