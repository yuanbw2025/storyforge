## 3. 优先处理的实现模式

| 模式 | 已确认表现 | 修复重点 |
|---|---|---|
| 使用展示缓存决定正式写入 | Codex 删除漏新子项；灵感两次成功却只存一条；状态差异把 B 私域字段合进 A（049/059/062） | 在同事务内读当前目标数据、校验 owner/CAS，再合并和写入 |
| 读/核对与写分离 | 切集旧 revision 双成功；媒资 version 并发唯一键失败；Brief/Canon 与收据断裂（024/036/056） | 事务、幂等与部分提交恢复；不能用扩大 stale 容忍掩盖竞态 |
| 生命周期只处理常见形状 | 非 `id` 主键漏删；更新跳过 FK；合法备份丢重映射（014/035/037） | 由现行登记和产品 codec 派生，补真实 reader 与跨 owner 对照 |
| 恢复重建了错误意图/状态 | 作者剧本改动被原模型提案覆盖；主大纲来源过期仍补写；健康媒资因临时 I/O 永久不可用（017/055/064） | 保留作者 payload，区别临时失败/真实损坏和已写/未写，不隐藏或自动重做结果 |
| 入口选择了另一套规则 | 节点/批量候选缺确认按钮；主 Agent 热态细纲选错 parser；普通与专业漫画入口审查失效不同（039/057/063/066） | 同一能力登记和校验被真实调用，分别覆盖热态、刷新和恢复 |
| 原始证据留存晚于可能失败步骤 | 多产品只留 hash/规范 payload，或来源更新时先抛错（002） | 每次 attempt 的原文先留存，再做解析/来源/候选校验；保存失败不触发模型重发 |
| 聚合时提升了来源权威 | 已知过期摘要被 continuity-tail 标为“已验”并强制输入；作者关闭的资料仍自动纳入（086/087） | 每个派生字段分别验来源，自动选择落实作者策略，必读冲突显式处理 |
| 同批操作相互破坏与错误投影 | 多卷采纳因自身写入 stale、拒绝失败却清界面、已 AI 会谈却显示零调用（089/094/095） | 区分批次内合法前进和外部变化，界面成功以持久回执为准 |
| dirty 编辑与实时数据没有独立基线 | 小镇借新 revision 覆盖其它窗口稿件；无效可见候选采纳旧文；空地理组新增写入旧组地点；状态卡 live 更新冲掉本地稿（112/118/122/126） | 分清持久数据、编辑缓冲和确认快照，保留冲突两份稿，采纳只对应可见有效输入 |
| finally 没覆盖全部锁内步骤 | 在线备份异常永久占住当前实例串行锁；HTTP 响应头后取消/超时提前失效（110/114） | 最外层生命周期覆盖准备、执行、正文、回滚和清理，故障逐边界验证 |
| 顺序正确掩盖并发/数值边界 | 并发单值事实变双当前；Float32 成本与 double 队列比较丢合法地图前沿（119/124） | 在原子约束内维护单值不变量，数值存储/比较共用精度合同，保留顺序/整数正例 |
| 磁盘与数据库之间缺最终校验 | 元数据缓存掩盖外稿；异步归档后并发新正文仍被删（092/093） | 正式覆盖读真实字节；最终 DB 事务内验证正文/owner，沿既有生命周期执行 |
| 可读标签替代稳定身份 | 同名或规范化碰撞的不同项目目录备份互相覆盖（127） | 稳定 workspaceUid 决定归属；可变名称仅作标签，覆盖前核相同 owner |
| 边界校验与真实消费者脱节 | tags 内层形状通过备份信任门却让地点 UI 崩溃；内置发布逐资源 hash 不实（129/132） | 严格领域 codec 与真实冻结来源进入现行注册门，往返后验证实际 reader |
| 只测局部逻辑遗漏真实宿主 | 直接移动的单位方向被当距离上限；移动遮罩选择器与根 DOM 不符；SVG 全局 style 影响宿主（128/130/131） | 分别补实际 scene loop、生产构建移动 DOM、清洗后真实浏览器隔离对照 |
| UI 预览与正式读取各用一套选择器 | 正文状态卡勾选/数量变化，而 Gateway 必读输入不变（136） | 从实际 manifest 投影预览，明确必读与控件用途；保留本章/章后整理的合法选择 |
| 异步成功清理了当前草稿 | 反馈提交旧快照成功后，把等待期间新写文字/新附件一并清空（138） | 按发送快照核对清理或冻结在途编辑，失败与未知保留新稿，成功提示对应已发送版本 |
| 续批防重只检查一个目录 | judge 子批 A 失败后，从同一父批换子目录 B 再次分派同输入（137） | 父批原子认领与全部已尝试身份继承；保留正常同目录 resume 与旧失败回执 |
| 声明身份未绑定真实执行对象 | SAM 核对 checkout，却从其它目录或修改模块导入并自报固定 codeRevision（135） | 导入前核实际代码/配置字节及模块路径，不能仅增加一个 Git 状态判断 |

这些反例使用隔离数据，不表示已发生线上事故；同根问题按共同机制组织整改，具体入口仍分别验收。

## 4. 测试质量

本批已逐段读完共享生产工作台 2,653 行。它协调多产品修订、未知费用、逐图验收、实际试玩和性能门，是需要按状态、副作用和产品适配职责拆分的维护热点；首页共 50 行，其中第 46 行的大段 JSX 也说明“行数少”不代表结构清楚。拆分之前应保护已有的开始授权、暂停 control epoch、冻结候选和人工发布门。

已有测试覆盖新库、作用域、预算、冻结证据、失败和导出等多种约束，不能把发现缺陷解释成项目没有测试。需要修正的是“绿灯到底证明了什么”。

- **断言逻辑**：注册表与玩家 recipe/vendor 字段集合排除写成整体 `not.arrayContaining`，单个禁止项仍通过；新增 12 种逐字段污染也复现，当前真实集合的严格检查正常（054）。
- **拒绝断言**：JSON 深冻结/克隆测试自行抛出的 unexpected success 被同一 catch 吞掉，直接返回 mutant 仍通过（139）。三个真实 validator 当前均正确拒绝，邻近严格 toThrow 正例保留；要求抛错与 getter 零执行应分开断言。
- **生成器完整性**：AI 手册与同一生成器输出相等，也可能一起漏掉来源。实际173项只生成171项；常量预算等值字面量控制才暴露缺口（141）。应独立比较运行时完整 key 集合，并对不支持表达式明确失败。
- **夹具真实性**：部分图片 happy path 使用仅有签名/尺寸的不可解码字节；它可以验证工程协议，不能证明最终图片可交付。真实 PNG/坏图解码对照已执行（042）。
- **往返深度**：行数、表存在、顶层引用正确，不能代替嵌套字段和真实恢复后 reader 正确。TTRPG 媒资导入反例由 owner 检查正确拒绝旧 ID，结果是不可用，不是越权（037）。
- **增改对称性**：新增 FK 拒绝测试无法保护 `recordId`/CAS 更新；需同一字段在各实际入口的对照（035）。
- **边界组合**：分别测 24 条上限和禁止删除版本来源，无法发现第 25 条静默裁掉被引用片段（060）。
- **真实入口**：源码包含文案或函数名不等于按钮能采纳；单章测试不替代批量，旧 generic 聊天不替代当前 v3（057/058/063）。
- **测试分支**：普通 Vitest 会跳过高危确认；必须另测实际 adapter。100 在显式验证普通分支后，通过真实弹窗和公开删除复现第二步 X 仍继续，不能让测试便利分支代替作者授权的交互验收。
- **作者原稿与选择**：CAS 正确也不能保护被模型漏句副本重建的摘要；单个模板保存测试不能覆盖激活后旧 metadata 回写、AI 晚到覆盖手改和自己的导出往返（099/106/107/108）。
- **证据来源**：实际 H4 面板用估算 token 填补 provider 缺失 usage，导致 40 次全部被当作已计量；估算金额本已明确标注，仍应区分实测/估算/缺失并核证据门（120）。逐字唯一性还需覆盖重叠出现，不能只测分离重复（113）。
- **删除与异常所有权**：开发评测名称前缀不能证明项目属于评测；需要普通同前缀作品保护与真实评测清理对照（111）。UPDATE 返回 0、拒绝后立即重试等异步状态也需经过实际组件验证（121/125）。
- **完整时序与宿主**：保存成功不能代替同目录多项目备份；source hash 非空不能代替逐资源核对；导航 helper 正常不能代替直接移动 loop。SVG 测试需有合法 XML/命名空间正例，避免危险样本仅因 XML 本身无效而整体被拒；脚本拦截也不能证明 CSS 已隔离（127/128/131/132）。
- **长用例与阶段依赖**：已读 AVG 声音返修测试含按序共享 production/publication/portable 结果的多阶段用例。它解释依赖步骤失败的传播，尚不证明首轮超时根因；可按公开阶段结果拆分并测量耗时，不能删严密正反例或提高超时掩盖问题。
- **断言前置状态**：Harness H9 的候选在来源变更前已经不可采纳，变更后仍为 false 不能单独证明 true→stale；H24 对 stale 分类的期望与已确认默认重规划问题（067）需按现行合同裁决，不能用测试期望替代合同。

- **覆盖率口径**：当前统计门排除了部分 Harness、产品生产/runtime；它们有测试，仍需单列关键业务层和失败分支覆盖（008）。
