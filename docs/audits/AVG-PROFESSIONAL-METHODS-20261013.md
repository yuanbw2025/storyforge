> 检索代码基线：`516a98bff7cb03eab2414aecfcd0ce92102cbf9e`。

> 状态：已读取主创访谈、生成方法的一手论文/项目说明、参考图接口与许可；从三个官方宣传视频提取 47 帧，实际视觉查看 24 帧。未聆听音频、通玩商业作品、运行本项目正式生成或进行真人验收。

本轮把质量要求进一步落到岗位方法：**作品先决定怎样叙述和表现，再通过专业场景、规则、导演、图像和声音工件生产；最后在同一可玩版本里修订和验收。** 每场戏需要体现人物行动、信息或关系变化；媒资和系统要消费这些变化。专业方法的有效性仍需真实产物与作者/玩家验证。

研究属于 AVG 产品研发。未来制作先经过 S2 定向，正式生产在用户明确开始、Brief 和 SourcePlan 冻结后进入 S3 执行。AVG Work 拥有剧本、规则、演出、媒资、Build 和 release；WorldRelease 只供版本化语义读取。以下 Skill、字段、工件与例子均是研究提案，尚未成为注册 Skill、数据库数据或作品发布。

## 2 主创制作经验对研发路线的修正

| 来源及版本 | 主创陈述的要点（归纳） | 本地化设计判断 |
|---|---|---|

| [2021 月姬制作访谈](https://www.famitsu.com/news/202109/11232354.html)，奈须、武内 | 第一人称与第三人称作品的演出方针不同；扩大素材量与控制细节的计划仍受实际质量要求和返工影响 | 叙事视角与视觉镜头分别建模，允许作品声明例外；按连续场景的实际返修记录预算，不能依据素材数量推定工期 |
| [2022 魔法使之夜配音访谈](https://www.4gamer.net/games/612/G061285/20221220053/)，奈须、小林裕介 | 角色试音重视日常表现；指导包含情绪原因和表里差异；已有表情/音乐帮助表演，原演出也预先考虑了对白节奏 | 配音合同加入角色说话动机、潜台词、上下句和舞台参考；艺术表演方向与运行时语音结束事件分别治理 |
| [2009 STEINS;GATE 系统访谈](https://dengekionline.com/elem/000/000/212/212275/index-3.html)，松原、林直孝 | 邮件选择嵌入故事物件；时间、回复及历史的一致性成为大工作量；操作响应与读取时机经过细致调整 | 选择不局限于菜单形态；任何特定交互都需要正式状态、可见记录及重放。先让一个作品确实需要的交互成立 |
| [2011 STEINS;GATE 制作访谈](https://news.mynavi.jp/article/20110602-steinsgate/)，松原 | 程序与演出落地时仍会暴露剧本中的信息记录矛盾；统筹、编剧与视觉设计有真实交接 | 审校同时查看剧本与确定性运行投影；实际出现的消息、证据、知识和变量比纸面梗概更接近最终作品 |
| [2026 Key 主创访谈](https://game.watch.impress.co.jp/docs/feature/2097950.html)及[后半部分](https://game.watch.impress.co.jp/docs/feature/2097950-2.html)，魁、佐雪隼；谈 anemoi/Summer Pockets 制作方法 | 路线可保留不同作者的特点，但主题与最终整合需要统筹；日常趣味及后续回响是情绪积累的基础；音乐选择与世界氛围相连 | 统一作品不变量，保留角色/路线声音；检查前后回响与共同主题，避免用统一润色抹掉差异。该访谈用于方法研究，不据此给新作质量排名 |

这些经验给出明确的研究方向：S2 增加作品视角与演出语法；内容线增加日常/冲突/回响的方法；系统线增加导演与运行信息一致性；媒资线增加构图、角色家族和表演合同。具体实现仍须进入 AVG 专项 L2 契约。

## 4 生成方法研究能支持到哪一步

| 一手研究 | 已读取的方法/限制 | AVG 可取的方法 | 本项目必须另证的部分 |
|---|---|---|---|
| [Re3](https://arxiv.org/abs/2210.06774) | 结构计划、随故事状态补上下文、重排及修订 | 当前场景读取相关计划、角色状态及此前决定；按场景推进和审校 | AVG 路线、可玩规则、中文对白和媒资；不能复用论文成绩为本项目结果 |
| [DOC](https://aclanthology.org/2023.acl-long.190/) | 详细分层大纲与生成控制器分别工作 | 场景计划先充分细化，写作过程核对具体场景目标与发生的变化 | 控制忠实度可能损伤创意，须连同人物/语言评审；形式化规则仍由确定性系统负责 |
| [Dramatron 官方项目](https://github.com/google-deepmind/dramatron)与[论文](https://arxiv.org/abs/2209.14958) | 分层生成角色、剧情拍、地点和对白；十五位专业人士参与共写研究；作者明确没有评估自主创作，公开舞台例子经过大量人类改写 | 专业工件分解与作者修改流程有依据；评审应涉及专业创作者和实际表现 | 编译成功、提示词岗位化不证明文学成熟；需实测原始采用率与编辑工时 |
| [MAST v2](https://arxiv.org/abs/2503.13657v2) | 研究一般多 Agent 系统的职责/系统设计、协调、验证与终止失败 | 每岗位独占工件；问题回到 owner；稳定版本交接；冻结预算和终止条件 | 不是 AVG 文学实验；须比较同预算通用路径、专业生成和加入独立编辑后的收益 |
| [ConsiStory 作者代码](https://github.com/NVlabs/consistory) | 共享注意/特征，使用锚点与缓存促进多图主体一致 | 资产按身份锚点、连续家族和上下游 hash 管理，单张与家族分别评审 | 二次元人物、表情/裁切对齐、透明分层和实际硬件表现均未实测；代码的商业使用还有限制 |

[ConsiStory 代码许可 §3.3](https://github.com/NVlabs/consistory/blob/main/LICENSE)将该代码及衍生工作限制为研究/评估用途并限定 NVIDIA 处理器使用。因此本研究将它列为方法参照，不把该公开代码选作商业生产底座。相关商业服务或独立实现须按各自条款和实际效果重新核对，不能沿用代码仓库的能力或许可结论。

### 4.1 参考图与编辑接口的实际接入方向

当前 AVG 通用[媒体请求](../../src/lib/product-production/media-adapters.ts)只有 prompt、尺寸、时长等输入，没有参考图片输入。解决一致性问题需改实际合同与传输；延长人物文字描述不足以填补该缺口。

| 路线 | 当前证据 | 研发取舍 |
|---|---|---|
| 一致素材导入与人工制作 | 本产品已有导入、采用、Blob、版本和消费路径 | 可作为第一场真实演出验证与人工质量基准；记录制作/修订投入，不能冒充自动生成采用率 |
| BFL 输入图编辑 | [FLUX.2 编辑文档](https://docs.bfl.ai/flux_2/flux2_image_editing)给出真实输入图/多参考输入与异步结果接口；Kontext 已列为较旧系列 | 可列入 adapter 及采购候选。按准确 endpoint/model 声明参考数量、尺寸与能力，冻结实际路由；不把厂商展示当作本作品的稳定性成绩 |
| Gemini 输入图编辑 | [图像生成文档](https://ai.google.dev/gemini-api/docs/image-generation)明确文字加图像输入及连续编辑，区分不同模型的多参考能力 | 同样是待验证候选。按实际模型传入字节、保存参考消费与产物证据，不以模型系列名统一能力 |
| 研究型一致性算法 | ConsiStory 方法与公开实现 | 可用于理解锚点、家族和一致性/姿态变化的取舍；进入商业实现前须取得独立可用的许可与硬件/效果证据 |

BFL 的[API 条款](https://bfl.ai/legal/flux-api-service-terms)与自托管代码许可分开，API 条款还涉及输入/输出使用；Gemini 的[服务条款](https://ai.google.dev/gemini-api/terms)区分免费及付费数据处理。实际采购仍需明确服务、账号/地区、数据类别、费用、输入素材授权和输出使用依据。本轮未调用这些生成服务，没有实测排名或报价。

新增请求的逻辑合同应包括：参考素材的 owner/ref/hash、用途（身份/姿态/构图）、允许变化与保留项、可选编辑区域、消费槽、准确 provider/model、数据类别和能力约束。input hash 必须覆盖实际参考字节、方向和上游版本；transport receipt 证明真正消费了对应输入。

世界 SourcePlan 负责语义读取；角色图片属于 AVG Work 媒资，应经产品媒体投影与独立输入合同读取。不能把图片塞回世界，也不能用“参考过该人物”元数据替代实际图像传输。共享媒体协议升级先形成兼容的基础单元，再集成 AVG 使用方。

## 5 可供专业岗位校准的七张方法卡

以下是 Skill 方法草案。每张卡需补齐注册输入、输出 schema、预算与真实评测后才能正式执行；属于专业方法设计，不是已经验收的 Skill。各岗位及核心 Skill 的完整提案见主研究 §7。

### M01 日常行为与后续回响

- 岗位：场景设计、分场写作分别拥有场景卡与剧本；故事架构岗位拥有上游回响计划。
- 输入：角色欲望/顾虑、关系初态、指定事件、已规划回收与场景资源范围。
- 步骤：选择一个具体的小行动；让双方回应产生人物差异；标出本场关系变化；为后续回响保留准确动作/物件及语境。
- 输出：场景动作与对白、回响锚点及后续用途引用。作者可改写笑点/措辞，修改锚点时通知相关后场。
- 反例：只有日常寒暄；用旁白宣布两人关系很好；高潮临时创造从未出现的习惯；每个小物件都机械变成伏笔。
- 评审：读者可解释为何在意人物；回响在本场也自然成立；不得以伏笔数和感动词数量评分。

### M02 路线价值、信息揭示与行动后果

- 岗位：路线设计产出语义计划，系统设计产出执行规则候选，确定性编译器负责约束。
- 输入：故事/角色不变量、人物和玩家的已知信息、结局候选、允许的交互模式。
- 步骤：从结局回推此前行动的因果；为每个分叉定义合理代价；指定即时回应与后续消费；保留汇流后的差异；标出独有信息及允许揭示时点。
- 输出：路线/揭示计划、选择意图、回响与规则需求。菜单或故事物件是表现方式，正式后果不能只存在于文案。
- 反例：选项同义、任意奖励“正确答案”、分支之后失忆、隐藏条件导致作者也无法解释结局、人物凭空得知另一条路线的信息。
- 评审：语义上各路线值得阅读；执行上覆盖条件、汇流与终态。线性作品不强制添加分支。

### M03 人物声音、潜台词与独立对白编辑

- 岗位：分场作者写候选，独立对白编辑只修改表达，连续性编辑提出事实/知识问题。
- 输入：人物说话目的、惯用/避免的表达方式、对象关系、本人知道什么、玩家知道什么、场景动作。
- 步骤：逐句确定言语行动（试探、回避、协商等）；检查对方的回应；删除重复解释；用具体行为/措辞表达表里差异；核对知识和事实是否被润色改变。
- 输出：保留稳定句标识的修订差异、表达问题和必须交由上游处理的问题。
- 反例：仅更换姓名仍像同一个人；双方轮流念设定；全部人物用同一种文艺腔；为了漂亮句子泄露秘密或变更动机。
- 评审：在提供语境的条件下辨识人物声音；作者确认自然度和潜台词。审校不能自己改规则、世界或路线。

### M04 叙事视角、构图与事件时序

- 岗位：场景导演拥有演出候选；系统设计与编译器拥有运行语义；美术岗位生产符合镜头的资产。
- 输入：定稿场景、叙事视角、镜头规则及允许例外、人物空间/视线、视觉/声音方向、消费槽和当前 runtime 能力。
- 步骤：逐拍确认注意目标；确定人物相对关系、景别与文字区；选择必要动作、留白或转场；绑定文字/语音/动作完成与手动打断；在当前能力之外的需求必须明确报告。
- 输出：分镜/布局与事件依赖候选，声明预期效果、素材需求、允许降级和恢复策略。
- 反例：每句换背景；无目的震屏；仅按角色数组排位置；把所有停顿写成 500ms；自动播放不等重要语音；第一人称叙述与镜头形态被错误当作同一开关。
- 评审：准确 Build 的连续场景与手动/自动阅读；恢复后构图及规则一致。角色旋转/独立裁切等不能凭现有 camera Cue 推定已支持。

### M05 角色家族、空间基准与关键画面

- 岗位：美术总监拥有视觉圣经；角色/环境/关键画面岗位拥有各自制作 Brief；视觉审校独立观察图片及场景合成。
- 输入：已确认身份基准、衣着/比例/色彩、姿态/表情目的、镜头/画幅/锚点、空间光照和允许变化。
- 步骤：先验角色基准，再产生场景需要的连续变体；每次实际消费参考；把基准与候选并排比较；再把资产放回多人及关键画面检查；返修限定字段和依赖范围。
- 输出：明确的家族/变体需求、参考消费、真实候选、逐项问题与作者采用记录。
- 反例：每次靠同一文字重画；角色脸/服装漂移；单张漂亮但替换时跳位；以尺寸/alpha/hash 代替艺术评审；只产生完整 PNG 却声称有可动层/模型。
- 评审：身份、比例、动作、表情、空间、风格与用途；记录所有失败、淘汰及人工修图费用，不只展示精选成功图。

### M06 配音表演、音乐用途与混音

- 岗位：声音导演与配音导演分别拥有声音计划和逐句表演包；音频审校接收真正音频或人工试听记录。
- 输入：定稿文本/句标识、人物声音、言语行动、情绪原因/表里差异、上下句、画面与音乐参考、播放模式。
- 步骤：用日常/冲突/安静句校准演员或音色；指导行为和潜台词；确定台词之间的留白与声音进出；在连续对话及场景中试听；最后核对播放同步和恢复。
- 输出：逐句表演方向、音乐/环境/SFX 的用途与消费点、实际片段和版本绑定、试听问题。
- 反例：每句只有“悲伤/愤怒”标签；音色正确但人物说话方式错误；音乐覆盖对白；字数代替实际时长；文本已改而沿用旧配音。
- 评审：专业表演与技术播放分别取证。响度门不能证明情绪，能导入 voice 不能证明 TTS，尚未试听不得标声音质量通过。

### M07 从整段体验反查跨线问题

- 岗位：独立体验评审提供问题单；内容/系统/媒资各 owner 返修；作者决定高影响修订和最终采用。
- 输入：准确 Build、接受的剧情/规则/导演/媒资、实际路径与消息/知识状态、各工件版本和已有问题。
- 步骤：无指导阅读与操作；检查玩家看到/听到的信息；分别试静音、自动、快进和读档；定位具体拍/选项/声音/素材；判断问题源头，再展开最小依赖闭包。
- 输出：位置、证据、严重性、owner、允许变化、受影响工件及重验条件；不直接修改各部门产物。
- 反例：各部门自评都通过便标作品通过；图很漂亮抵消动机矛盾；用 fixture 通关替代真实生成；大量重生成仍不定位问题。
- 评审：作品整体意图成立、玩家可理解、操作与恢复可靠；对应准确版本，未知事项保留未知。

## 6 原创微场景与正反例

下列文字由本次研究撰写，用于讨论方法；没有经过专业作者或目标玩家验收，不是 StoryForge 正式生产结果，也不计入真实模型对照成绩。它们不是完成的三至五分钟可玩场景。

统一设定：两名档案员林汐、沈祈在雨夜值班。林汐习惯核对细节，担心误伤别人；沈祈话少，保护亲人但不愿坦白。叙事采用贴近林汐的第三人称；本场不得进入沈祈内心。邮戳和此前说法是公开证据，寄信人身份仍为秘密。

### D01 日常：一个当下成立的小行动

待返修写法：“林汐看见沈祈给自己泡茶，感到十分温暖。两个人关系很好，约好以后一起面对困难。”它直接宣布关系，缺少双方行动与声音差异。

方法候选：

> 林汐拎着湿透的外套进门。沈祈把杯盖扣上，又将杯柄转向她。
>
> “给我的？”
>
> “占桌子的。拿走。”
>
> 她摸了摸杯壁：“占得还挺热。”
>
> 沈祈把写坏的标签翻了个面，没有接话。

当下用途是两人熟悉而克制的相处；杯柄动作可以成为后续候选回响，但是否保留由故事计划及作者决定。候选需要继续检查人物辨识与自然度，不因存在动作便自动评为优秀。

### C01 冲突：证据、回避与可理解的决定

冻结事实：沈祈此前说信是上个月捡到的；林汐看到当天邮戳；封口尚完整，玩家和林汐都没有读到信内文。本场目标是决定如何处理这封信，不提前解决寄信人秘密。

待返修写法：“林汐知道那是沈祈妹妹的求救信，非常愤怒，决定惩罚他。”它越过知识边界，并替玩家作决定。

方法候选：

> 信封从文件夹里滑出来，停在她手边。
>
> 林汐点了点邮戳：“上个月捡到的？”
>
> 沈祈伸手。她压住信封，没用力。
>
> “先还我。”
>
> “邮戳是今天的。”
>
> 他收回手：“明早之前，别登记。”
>
> “登记之后会发生什么？”
>
> 沈祈看向她。林汐等着，没有再问。

两个行动候选：登记并留下公开记录；暂不登记，要求私下说明。前者让后续正式核对有依据，但可能增加同伴压力；后者给坦白机会，同时承担没有公开记录的风险。代价需在此前语境建立，不能只在研究备注里存在。

邮戳构成需要解释的证据冲突，尚不足以确定沈祈说谎、信内文或投递全过程；内容和审校须保留这项未知，不能把合理疑问偷换为已经证实的秘密。

选择即时回应与延迟回响分别写作。系统以有限 `letterHandling` 状态记录决定；作者必须能查看后场何处消费该状态。内容作者不直接往 DB 写 flag，导演也不能通过 Cue 偷改规则。

### H01 回响：复用行为，改变关系含义

候选后场发生在 C01 之后。若此前登记，林汐通过正式记录继续核对；若此前私下保留，沈祈需要在约定时点给出解释。两路都遵守同一封信的已确认事实，不能把事实换掉以制造分支。

微片段候选：

> 杯子还在昨天的位置，杯柄朝着空椅。
>
> 林汐没有坐下。她将签收簿放在杯子旁边。
>
> “这次写清楚。”
>
> 沈祈翻开簿子。她松开压着页角的手，等他写完。

这里的关系变化候选是双方重新建立可承担的信任边界。本片段只是候选汇合段，两路如何走到这里、此前决定怎样被消费以及不同的即时回应尚未写成，不能算作已完成两条分支。回响依赖 D01 的动作与 C01 的决定；若上游换掉动作、约定或选择后果，本场必须重新审查。它不能凭几句文字完成整条情感弧，也不能被拿来证明达到 Key 水平。

### 6.1 C01 同一场戏的三线交接

| 拍 | 内容及知识 | 系统/导演意图 | 实际媒资要求与复核 |
|---|---|---|---|
| 进入 | 林汐发现信，尚不知道来源 | 建立人物位置和桌面关系，焦点从对方转到物件 | 同一室内空间、两人既定服装/比例；桌面近景须能容纳后续文字 |
| 证据 | 当天邮戳与此前说法冲突，封口保持完整 | 展示必要细节；信息取得由正式事件处理 | 可读而不过度剧透的信封/手部 CG；不能生成包含信内文的画面 |
| 回避 | 沈祈想取回，林汐暂压住，双方暂不说破 | 一次有目的的动作/表情变化，保留对方反应；静默与音量变化为导演候选 | 表情/姿态依赖同一人物基准；配音包包含回避、请求与等待，不仅标“愤怒” |
| 决定 | 两种可理解行动，尚未揭开秘密 | 停止自动推进，等玩家；状态变化只来自正式选择 | 清楚的交互与已预加载关键资源；两路状态和恢复分别测 |
| 回响 | 即时态度变化，后场继续消费决定 | 冻结有限状态与下一场入口；提供合法存档/重放 | 保留无关角色/背景/声音，修改相应对白时使语音和时序失效 |

上述导演描述需要被编译为本产品已支持的 Cue 与有限规则；缺能力时提供阻塞或明确替代。当前类型没有独立角色裁切/朝向等完整布局字段，音频也缺逐句推进协调，不能将本表当作现有 runtime 已能自动播放的脚本。

## 7 下一轮真实评测的固定任务

先用方法卡形成明确评分锚点，再运行正式或已登记的有限评测入口。以下任务尚未执行。

| 任务 | 控制条件 | 原始记录及判断 |
|---|---|---|
| 视角与知识 | 同一事实/人物，分别在声明的叙事视角下写场景；保持结局和允许信息不变 | 哪一句越界、空间是否可理解、人物声音是否保留；第一人称与电影镜头不强制绑定 |
| 日常与回响 | 三场连续原创片段，冻结人物习惯和关系/信息变化 | 日常是否当下有趣、后场是否回收、回收是否靠解释；由专业作者及目标读者判断 |
| 专业内容方法 | 三类 Brief × 通用/专业生成/加入独立编辑三条件 × 三次采样，得到二十七份最终候选 | 相同来源、目标长度和总预算；全部原始响应、问题、拒绝、人工改稿与调用费用。二十七份候选不等于二十七次模型调用 |
| 参考图一致性 | 同一被接受角色及明确表情/姿态槽，比较文字生成、实际参考/编辑和一致素材基准 | 每次输入参考的真实证据；身份/衣着/裁切/锚点/多人合成；淘汰及返修进入成本分母 |
| 表演与同步 | 同一人物的日常/回避/冲突/安静句，固定对白与舞台用途 | 实际试听与上下句对比；手动、自动、点击打断、重访、无语音、失败与读档；无试听不计通过 |
| 导演与整体效果 | 同一被接受剧本和素材，对比默认组装与明确导演编排，再试玩整段 | 画面/声音/选择是否共同表达意图；记录前情、时长、播放方式与品牌熟悉度，问题定位到准确 Build |

机器检查负责结构、版本、作用域、引用、条件与预算。文学、表演和艺术评审记录具体位置和理由；制作岗位不能复用自己的 Run 自审。模型辅助评审和专业/玩家评审分别记录，出现硬矛盾或关键运行错误时不得用平均分抵消。

## 8 对 AVG-00～04 的具体补充

| 工作包 | 新增的设计与验证要求 |
|---|---|
| AVG-00 | 冻结叙事视角、视觉镜头规则及例外、主体/空间、信息边界、角色/路线声音、三线交接与方法卡；明确实测基准而非仅列游戏名 |
| AVG-01 | 专业场景方法与独立对白/连续性审校；验证日常、冲突、回响和跨路线知识；作者保留修改和独特声音的权利 |
| AVG-02 | 具备构图与事件依赖的导演合同；显式报告现有 Cue 不支持的布局；形式化消息/证据/知识状态和作品选用的特定交互 |
| AVG-03 | 将配音表演方向与播放器同步区分；逐句 ID/文本版本/音色/片段绑定、持续声音/一次性音效恢复和实际试听 |
| AVG-04 | 参考图/编辑输入真正传输；角色家族/空间/构图共同校准；准确供应商能力、许可、数据类别、可用率、失败成本与人工修图记录 |

建议的下一交付单元是 **AVG-00 专项契约与受治理的校准方案**，并完成至少一项连续场景参考取证。基准文本、正式生成、连续媒资和联合 Build 的证据取得后，才能决定方法/模型、作者效率与制作经济性。不得因本研究文档可读、方法可描述或公开视频可采样而提升 E-AVG-01 成熟度。

## 9 交付验证与证据边界

本轮只验证文档权威登记、链接、表格、原始采样索引的计数/hash、工作树与差异。不运行产品 CI 或作者浏览器，不产生 ProductRelease，不调用付费生成服务。媒体观察来自可读取的官方公开视频帧；音频、完整场景与人类意见继续保持未验证。

原始源与研究推论分开引用；方法卡及原创文字仍需校准。后续实现按现行总纲、上层产品契约、三注册表及 Harness 施工，本文件不替代 L2 产品契约。
