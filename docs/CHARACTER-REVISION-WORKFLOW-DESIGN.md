# STORY-1 / CF-12 角色变更影响分析与中途重规划

> 状态：CF-12 产品边界已完成；HARNESS-36 主入口治理已完成（2026-08-09）
> 入口：创作区 → 角色驱动 → 中途重规划
> 核心边界：AI 只提出带真实节点 ID 的未来大纲 patch；正文、已写保护区和
> `storyCore.mainPlot` 永远不自动写回。

## 一、问题与产品裁决

开书阶段的角色驱动工作台可以从弧光生成新大纲，但不能安全处理“已经写了正文以后新增
角色、调整弧光或改变结局”。CF-12 保留原“开书规划”，新增“中途重规划”，把一次变更
拆成三个明确区域：

```text
规范章序 + 真实正文状态
  → 已写保护区：只分析，不生成可应用 patch
  → 近期过渡区：只允许自然切入和小修
  → 未写规划区：可按轻量 / 中度 / 深度方案重规划

AI 结构化建议
  → 本地解析与边界过滤
  → 作者选择方案并逐项预览
  → 作者确认
  → adopt(target=outlineNodes；已有空正文行仅同步 chapters.title)
```

本能力不新增业务表；修订候选、作者选择、运行状态和回执复用现有 durable Agent 账本。角色驱动
active 方案只是输入之一；没有方案时仍可依据角色卡、Canon、故事线和现有大纲分析。

## 二、真实进度与保护边界

`buildCharacterRevisionSnapshot()` 使用规范大纲遍历和最佳章节映射建立章序，不根据数组
位置或标题猜测：

- 正文经标准化后非空才算“已写”；
- 最后已写章自动形成最低保护边界，用户不能把保护值调低；
- 已写章之后的空 Chapter 行仍属于未写区；
- 章节记忆缺失时，界面和解析结果都会明确警告只能做有限证据分析；
- 大纲异常会传入分析上下文，不静默假定章序正确。

分析开始时会把快照、保护边界、锚点、目标角色、变更要求和方案 ID 冻结进 durable plan。即使
用户在模型执行期间修改表单，旧分析也不能降低保护范围；正式基线变化会使旧候选 fail closed。

## 三、AI 读取与输出契约

所有资料都通过 `assembleContext()` 和登记的 `CONTEXT_SOURCES` 读取。确定性施工边界作为
`manualText` 输入，包含真实 `outlineNodeId`、规范章序、卷章标题、摘要、正文状态、区域
和锚点；其余输入复用：

- 故事核心、角色、关系、故事线及动态进度；
- 现有大纲、当前事实、连续性交接与计划对账；
- 角色事实/正文片段、伏笔、Canon 断言；
- 世界规则、Codex，以及作者明确激活的角色驱动方案。

大纲 Agent 的 `outline.character-revision` Skill 使用 `plot.character-revision` Prompt，必须输出轻量、
中度、深度三档严格 JSON。事实与冲突必须带证据，证据
不足要明确说明。主线只能给只读建议，不是写回命令。

本地解析器不信任 AI 提供的当前值，会从捕获快照重新附加当前标题和摘要，并拒绝：

- 未出现在输入闭集中的节点 ID；
- 重复节点；
- 有正文或处于保护边界内的节点；
- 试图改名的用户锚点；
- 没有实际变化的 patch。

被拒绝项会留下可见 warning，而不是悄悄消失。

## 四、预览、写回与并发保护

候选持久化时 `decision` 必须为空，通用候选入口不能直接采纳。作者先选三档方案之一，再逐项勾选
patch；选择先固化为候选修订事件，之后才允许二次确认并重新读取项目现状：

- 节点已删除、跨项目或已进入正文保护区时跳过；
- 分析后标题/摘要有手工变化时判定为过期，要求重新分析；
- 锚点标题仍受保护；
- 合法 patch 只通过 `adopt(target=outlineNodes)` 写标题和摘要；
- 若历史上已经存在空 Chapter 行，只同步标题；绝不写 `content`；
- 不创建或修改 `storyCore`，不自动补写已完成正文。

确认后中断时，恢复逻辑只补齐候选明确选择且尚未写完的 patch；已写入项不会重复写，其它作者变化
仍会阻断。terminal verifier 会回读全部选中大纲字段与已有空正文行标题。刷新页面后，待确认候选仍可恢复。
