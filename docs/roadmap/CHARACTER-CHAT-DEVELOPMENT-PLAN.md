## 1. 目标、范围与产品边界

### 1.1 要交付的用户结果

作者从一句创意或已有冻结世界出发，能够得到有具体背景、人物动机和发展空间的角色故事；在同一作品中查看、编辑、试玩和局部重做。玩家进入后能够自然回应、少说话、拒绝、改道、暂停与继续；角色的表达和行动应具有个性，实际结果应被后续利用，已提出的问题或情感期待应得到相称的回应。

最重要的产品结果是聊天正文：读者能感到“这个人此刻确实想这样说”，能看见人物之间的关系、当前事情的意味和正在发生的变化，并愿意接下一句。我们要生产可以读进去、聊下去的小说式互动。完整字段、合法后果、目标关闭和单句漂亮都不足以证明达成；需要连续正文中的人物表现、情境吸引力与情感/故事回报。

首个交付聚焦一位核心角色的完整内容体验。覆盖日常关系、轻调查、平静陪伴三种内容类型，不以增加冲突强度或消息数量衡量进步。多人、图片、声音和跨小说联动保留在后续工作包，不占据单角色内容验证的前置关键路径。

首版面向私有创作与试玩工具。面向大众的托管模型服务、账号权益、内容推荐社区和支付属于后续独立产品化范围，不能用本计划的技术候选版本宣称已达到猫箱式消费产品。

### 1.3 已决定的设计与待实验事项

**已决定：**

- 保留修复后的共享底座、真实来源与存档兼容；角色聊天核心逐段替换。
- 内容先交付可演绎背景与人物，再评价完整片段；工程检查与内容质量分别验收。
- 先把现有回合中的提示词、所供材料与正文表现研究具体，再决定怎样接入或合并调用。首个研究产物必须含可实际发送的完整提示词、完整上下文、原文好坏对照；不能只交架构图和质量形容词。
- 作者视角、协调视角、角色视角、玩家可见视角明确分开。
- 选择与表达合并是新回合方案的主候选，独立审查与原子采用保留。
- 剧情模式与陪伴模式分别设定内容目标；拒绝、失败、等待与留白均允许。
- 不按某个模型名称预定质量结论，不把审查模型的自评当验收。

**需要实验后裁决：**

- 合并选择与表达能否同时提升质量并降低等待。
- 更完整的制作背景能否减少运行时空转及无依据扩写。
- 哪个实际可接通的模型/配置适合制作、表达与审查。
- 新的内容组织能否用现有事实/目标/事项表示；确有缺口时增加哪个产品专用版本化工件。
- 小样本研究指标与成本目标是否足以支持限定技术试用。未过门时保留失败，不修改阈值追认成功。

### 1.4 统一主线与第一阶段交付

整个方案按同一个内容问题展开：**怎样准备值得演绎的人物和故事材料，怎样让角色将它们写成好读的回应，以及怎样在玩家参与后继续形成有回报的故事。**架构、保存、审查和界面承担支撑职责，研发取舍首先看实际正文。

| 要解决的内容问题 | 本方案设计 | 开发归属 | 判断依据 |
|---|---|---|---|
| 为什么值得聊、与谁聊 | 阅读体验、人物欲望/矛盾/声音、具体情境及实质材料，见 §4、§5.1—5.3 | CC-01、CC-03 | 读者能从开场和前几轮看见人物及值得参与的事情 |
| 每轮具体怎样写 | 角色可见上下文、表达 Prompt、匹配示例、局部修订，见 §6.1—6.3 | CC-01、CC-04 | 同输入原文比较；人物声音、回应、潜台词、细节与文字表现 |
| 怎样持续产生故事 | 条件化发展材料、实际后果、下一场的内容准备，见 §5.3、§6.4 | CC-03、CC-04、CC-06 | 完整场景及后续两次续聊，前文被承接且产生新的阅读价值 |
| 怎样判断改动有效 | 单轮 Prompt → 模型/回合 → 制作 → 完整片段 → 续聊，见 §9 | CC-01、CC-05、CC-06 | 完整原文、固定样本、独立比较；平庸不算通过 |
| 怎样交付可用作品 | 复用修复底座，完成正式接入、编辑、保存与恢复，见 §2、§7—8 | CC-02、CC-07、CC-08 | 已验证内容在实际界面和存档中保持成立 |

第一阶段的可用产品目标是**单角色文本创作与试玩**：能生成一个有内容的开场，完成一段可读的互动，并在暂停后继续承接人物、关系与故事。它须包含合格正文、具体 Prompt/材料版本和可恢复的作品，不能只交一份理想示例或一组成功请求。三类内容分别验证；这一阶段不承诺长篇小说规模、所有题材或十人群像。

第一项研发交付更小：一份完整写作输入包及其真实输出比较。包内必须有展开后的实际消息、角色可见材料、适用规则与输出格式、模型配置和固定玩家输入；本文 Prompt 草案及原创样例提供起点，完整实验包尚须 CC-01/02 形成。取得小样结果后再决定正式替换范围，不能先把全套工厂建好再第一次读正文。

## 4. 内容生产规格

### 4.1 三种首批内容配置

这些是产品内的内容配置，不是三套引擎。相同的角色、事实、事项与运行机制按配置编译。作者在 S2 看到普通语言的能力说明，明确确认后冻结到新 Release。

| 配置 | 创作目标 | 必须准备的条件 | 不作硬性要求 |
|---|---|---|---|
| 关系故事 | 一件具体事情使双方对彼此的理解或相处发生变化 | 共同经历、不同关切、可表达/拒绝的请求、角色自己的责任或选择 | 每轮加好感、强制亲近、强制冲突 |
| 轻调查 | 角色能通过实际行动逐步处理一个有限问题 | 实质线索/资源、接触条件、未知真相与获准发现条件、受阻后的合理办法 | 每问必有答案、猜中秘密、保证成功、固定多分支 |
| 平静陪伴 | 细致承接当前话题与个人偏好，形成自然相处 | 具体共同关注、角色表达习惯、近期真实经历、休息与边界 | 调查任务、反转、高潮或强制结束 |

权限编译必须核查场景人物答复、隐情发现、既有事项接续及允许新增内容的种类和额度。当前默认没有开启的能力不得靠提示词假定已开启。配置不自动扩大世界读取或改写既有作品权限；来源不支持的内容先显示缺口，作者可改方向或显式补设定。

### 4.2 五类内容及其事实地位

| 类别 | 例子 | 允许的处理 |
|---|---|---|
| 冻结世界事实 | 某人身份、已发生事件、既定秘密 | 精确引用来源；保持否定、范围、可靠性、初知者与发现限制 |
| 作者已确认的产品背景 | 修表铺有练习表、两人曾共同修过一件东西 | 由 Work 候选采用产生，不伪造世界来源 |
| 获准补足的空白 | 未设定的普通工具、日常环境细节 | 在明确创作范围内提出；不得改写既定答案、发明玩家过去 |
| 作者层发展意图 | 让角色有机会面对一次旧失误；预期某条铺垫获得回应 | 只供创作/协调参考；不是已发生事实，不进入角色知识 |
| 未来可能与角色信念 | 可能询问、愿意尝试、怀疑某原因 | 保持可错、可拒绝和未执行状态；实际后果才可入账 |

“角色不知道”不等于“作者没有准备”。制作阶段应写实必要背景；运行时按权限逐步显露。也不能把未来情节写成既定事实，让协调器强迫发生。

### 4.3 人物内容要求

每位核心角色至少覆盖以下内容职责，优先映射到已有角色字段/人格解释：

- 当前欲望与长期追求：为什么愿意参与，眼前事情与自身有什么关系。
- 顾虑与代价：害怕失去什么，哪些选择让其犹豫；不能把谨慎扩展成全面退缩。
- 行为底线与能力：能独立完成什么，何时会求助、拒绝或承认不知道。
- 关系差异：对不同对象有何具体经历、信任与误解，不用同一口吻对所有人。
- 表达方式：词汇、句式、回避/直说的习惯、动作及情绪外显方式，不只一个口头禅。
- 可供演绎的矛盾：例如重视手艺但不愿承认一次失误，不能只有抽象形容词。

人物特征必须有行为示例与反例。用同一处境进行“替换角色”检查：如果换了角色只换称呼与语气词，人物设计不合格。新增经历属产品背景候选；来源人格解释不得反向改写原作。

### 4.4 场景内容要求

每个场景需要可核查的：

1. 当前局面与角色真正要处理的问题，不能被“检查工具”等准备步骤替换。
2. 对角色有意义的目标、实际阻力、可用资源与接触条件。
3. 资源的实质内容：记录中是什么、关系中各方关切是什么、物件怎样影响选择。
4. 角色已知、误信和未知的内容，以及未知事实合法进入视野的途径。
5. 可能造成的变化：新信息、选择、责任、关系或约束；变化必须能被后续利用。
6. 合理收束条件：解决、失败、放弃、转化、暂缓分别是什么；不能把暂停记作完成。
7. 作者层的体验期待与相称回报，保留玩家改变发展方向的空间。

可以有多个有实质差异的办法，也可以只有一个直接办法或合理等待；数量不是质量指标。不能用“以后出现线索”代替制作背景，也不能为了备用路线造无关灾难。

### 4.5 原文质量要求

角色回复应回应玩家的真实含义，同时通过自然对白、动作、细节或适量描写体现人物。不得把内部证据、权限、字段、审查说明写成角色台词。

重点消除四类劣质内容：反复征求同一许可；只宣布计划而不行动；把同一动作拆成许多无信息小步；以客套、免责式限定与情绪标签替代真实互动。

叙述视角、时态、对白/动作比例和篇幅写入内容偏好。首批普通回合建议 100—300 个中文字符，重要场景可扩展至 600；它们是制作目标而非截断规则。短答、静默交还与自然停顿不因字数少而扣分；有信息的长答也不能靠冗长得分。

角色不能替玩家产生感受、决定、行动、承诺或接受亲密。表达情绪与潜台词可以使用角色自己的经历与当前感受，但不能绕过秘密披露规则。

### 4.6 用于设计校准的原创例子

**关系/修表：**玩家带来停走的怀表，拒绝拆开；作者已确认角色拥有一只练习表，过去曾因轻率判断损坏过类似机芯。合格发展可让角色检查自己的练习表、解释发现并在表达中暴露谨慎背后的原因，玩家仍能继续谈、改问或离开。不得触碰玩家拒绝拆开的表，也不能把演示结果当成玩家怀表的确诊。

**调查/寄存：**作者确定寄存记录、印章和经手人证词分别能证明哪些事情。看见箱子不等于知道箱内物品，听见指控不等于指控属实；一次检查或问询应得到有依据的结果、不确定或拒答，并改变下一步选择。

**陪伴/雨夜：**角色与玩家在避雨时整理书页，已有一段关于书中批注的共同谈话。角色可具体回应、分享当前偏好或安静相处；玩家换话题后应承接，不能强造失踪事件维持“推进”。

这些是预先撰写的目标与边界样例，不是本项目实际生成质量的证据。CC-01 须为每类扩展合格、平庸、越界、合法等待四种对照原文。

### 4.7 从读者实际感受反推内容要求

“有质量”在本计划中首先指以下可从正文观察的表现；它们是 StoryForge 的创作设计与研究目标，不是假称统一文学公式：

| 读者感受 | 制作时要准备 | 本轮写作怎样体现 |
|---|---|---|
| 这个人活着，有自己的立场 | 当下欲望、矛盾、不能轻易承认的关切、具体表达习惯 | 对同一话题作属于自己的选择；措辞和动作显露其立场，不能只是提供正确答案 |
| 我身处一件值得参与的事 | 双方为什么在这里、事情为什么对这个角色重要、可用的具体材料 | 通过正在做的事和有意义的细节带出背景；不先讲完人物传记或世界百科 |
| 这句话有言外之意 | 想说/不愿直说的内容、双方已经发生的事与关系差异 | 关心、试探、回避、争执、让步等落到具体话语和行动；不把“潜台词”直接解释给玩家 |
| 我的回应让这段故事不同 | 可以被玩家影响的真实分歧、角色自己的选择余地 | 玩家的拒绝、玩笑、追问或帮助改变说法、办法或关系；不沿固定剧情无视输入 |
| 有期待，也得到回报 | 已铺垫的疑问、人物能力、感情与可兑现内容 | 给出一部分真正有价值的回答、行动或关系变化，再留下合理空间；不持续吊胃口 |
| 文字值得读，甚至想截下来分享 | 契合题材的语感、细节、幽默/锋芒/温柔等具体风格 | 台词准确、有个性，动作与意象承担表达；少套话、少解释，连续片段脱离内部状态也可读 |

“爽”按作品体验具体化：可能是角色用能力解决难题、双方终于把话说开、一次有依据的反击、线索产生意义或自己的回应被认真记住。不能统一成无条件奉承、强制亲密、每轮反转或不断升级危机。短期钩子之后必须有相称回报；自然收束后允许结束，不以延长会话为目的拖延答案。

质量分三层检查：一句/一轮的表达是否准确鲜活；一个场景是否有关系或事情的变化；连续片段是否承接并兑现前文。陪伴也可以通过具体观察、共同兴趣、微小但真实的关系变化成立，不要求外部任务或戏剧高潮。写作手法按情境取舍，不要求每轮同时出现动作、冲突、伏笔、金句和悬念。

## 5. 故事与人物的内容生产设计

### 5.1 内容 Skill 的组织：先准备能写成戏的材料

这里的 Skill 是 StoryForge 已登记 Agent Skill 的内容职责，不是新增 Codex 工具，也不意味着每项职责都启动一个 Agent。首批沿用 §5.6 调用额度，按下表组织指令、材料和输出；运行表达仍复用角色 Skill，不另建故事引擎。

| 内容职责 | 核心任务与产物 | 必须避免 |
|---|---|---|
| 构思方向 | 3 个简短方向，各写清人物关系、眼前事件、独特矛盾、读者期待与实际参与入口 | 只有题材标签、身份和一句“命运纠葛”；三个方向只换地点 |
| 人物与场景深化 | 一次准备选定方向的具体背景、角色表达设计和场景材料，进入既定内容工件 | 只有形容词的人设、空白线索、必达剧情脚本 |
| 开场与回合写作 | 使用角色可见材料演绎下一次回应；同一套写作核心用于预演和正式回复 | 用流程说明、重复确认、旁白总结替代人物表现 |
| 内容编辑诊断 | 在制作审查或离线研究中指出具体句子为何平庸、失真或未兑现；给有限的修改方向 | 每轮额外派一个文学评委；用笼统分数代替编辑意见 |

每个 Skill 的内容包至少包含：一份主要写作任务、所需材料与缺口判定、按需加载的题材/表达示例、具体输出约定、少量适用边界、局部修订指令和固定比较样本。对外正式读写仍由现有注册表和合同承担。

人物深化必须产出可直接帮助表达的内容，例如：想维护的自我形象；被触及时怎样转移话题；向谁示弱；关心别人时常用什么行动；三种不同处境中的短台词示例。它们须有设定依据，不能把某个动作或口头禅规定成每轮必做。场景深化必须准备实质材料及其意义：信里究竟写了什么、物件为什么重要、双方争论的真正分歧、角色为什么有机会采取下一步。

### 5.2 故事制作 Prompt 草案

以下为拟议的内容指令正文，尚未替换运行代码。构思任务只读取方向指令；深化任务读取选定方向与以下正文。真实请求还须附对应输出 schema、注册来源和创作范围，不能把本段当作绕过既有合同的调用入口。

~~~text
你为一段可交互的角色小说准备故事材料。目标是让玩家进入一个值得参与的
情境，并遇见一个有自己的欲望、顾虑和表达方式的人。

先落实“此人为什么现在非要在意这件事”，再准备双方可以说、可以做、
可以争论或共同发现的具体内容。不要只写题材概述、人物标签或行动清单。

依据给定的【创作意图】【角色来源】【已有事实】【允许创作的空白】，
深化选定方向，交付：

1. 读者体验：用一句具体的话说明这段互动吸引人在哪里。说明期待的
   情绪或满足来自什么事件/关系，不写“引人入胜、情绪丰富”等空话。
2. 人物：眼前想要什么，为什么在乎，顾虑是什么，怎样维护自己的形象，
   哪种选择会让他犹豫。给出普通回应、被触动、意见不合三种短台词，
   让措辞和应对方式显出同一个人，而非只给“冷淡/温柔/毒舌”标签。
3. 此刻情境：地点和正在发生的事、双方已经知道什么、为什么有话可说。
   准备具体可用的物件、资料内容、共同经历或关系分歧，并说明其意义。
4. 可发展之处：当前局面中尚未解决的问题，角色自己的可行办法，
   玩家不同回应可能改变什么。写可能性和依据，不安排玩家必然配合。
5. 回报材料：这段交流若自然深入，哪些已准备的内容能带来理解、发现、
   能力展现、关系变化或情感释放；什么情况下可结束、搁置或改道。
   只写创作意图，不能把未来发展记为已发生。
6. 开场任务：给出角色当下的关切、第一句话所回应的具体事情和可行动条件，
   交给表达 Skill 写实际开场。不要让开场先介绍整份设定。

背景、对白示例和发展意图分开。给每项标明事实/示例/可能性及可读者；
对白示例没有实际说过，不能进入历史。必要事实缺失且无权补足时指出缺口。
幕后答案不进入角色材料。已有设定保持，作者范围内的新材料仍是待确认候选。
按给定内容工件格式输出，正文质量不能用填满字段代替。
~~~

后续只修一项内容缺陷时，使用同一 Skill 的定向指令：保留已确认设定与作者修改，指出“人物只有标签”“场景缺实质材料”“有铺垫无回报”等具体缺陷，重写被点名的工件及其必然依赖；不要把修订变成整套故事换题。是否写得更好须读新旧原文，不能靠修订自述证明。

### 5.3 连续故事需要提前准备的内容

故事制作不能止于一段漂亮开场。深化任务同时在现有 story/character/scene 工件中准备下列材料，不增加一个全局导演或逐轮生成整部小说：

- **持续关切：**本段具体事情与角色长期欲望、关系有什么联系；当前事情结束后，哪些已经建立的关切可能仍有意义。
- **人物的两难：**角色想维护什么，同时又想得到什么；哪些玩家回应会让其改变策略、承认或坚持。人物变化必须来自实际经历，不能预设玩家一定感化角色。
- **可兑现的内容：**重要信件的实际内容、线索能证明的范围、人物已发生的经历、能力与限制。关键答案属于制作背景时应提前写清，按可见性保存；不能只写“以后揭晓一个秘密”。
- **发展机会：**少量有实质区别、依赖不同条件的情境可能。每项写明所需事实/玩家意愿、可供互动的材料和可能带来的理解或变化；条件不成立就不发生，不构造固定分支树。
- **回报与收束：**前文提出的期待怎样可能得到回应，什么结果能结束当前一段；失败、和解、分歧、暂别都可以成立。收束后是否续聊由真实互动决定，不能强接新危机。

例如修表情境不能永远重复“是否愿意拆表”。若玩家愿意了解手艺，可利用角色已有的练习表及经历形成一段交流；若允许进一步检查，必须有实际故障材料和获准发现条件，不能用同一套往事替代结果；若拒绝并离开，应允许这段相处以分歧或未完成结束。这里规定的是内容准备与可能方向，不给玩家预写台词，也不承诺每条路径都会发生。

后续局面在实际需要时沿现有情境构建/制作职责局部补充。输入包含真实前文、已经改变的关系与事项、仍有效的创作范围，以及本次真正缺少的内容；输出只补当前所需的人物/场景材料，沿 §6.9 的有界请求执行。未使用的发展意图始终是候选方向；角色不会知道作者设想的下一场。

在制作 Prompt 中追加以下内容要求，仍属于同一次深化任务：

~~~text
为这一段互动准备可持续的内容，不只写开场。
明确当前事件与人物长期关切的联系，写实必要的背景和可兑现的内容。
列出有依据的发展机会及各自成立条件，说明什么实际结果可以让当前一段收住。
玩家可能拒绝、改道或离开；这些选择会改变可以继续演绎的内容，
不能把同一后续情节换个入口强塞回来。角色只读自己此刻可知的材料。
需要未来揭晓的重要答案，先准备作者层事实及合法发现条件；
不要留一句“后续随机生成反转”充当故事设计。
~~~

### 5.4 用户路径与生产职责

S1 由既有世界能力建立/选择并封存背景。S2 在角色聊天内确认种子、人物、内容配置、创作空白、预算、读取范围及开始授权。

S2 先选定已有角色，或确认本产品私有角色的稳定身份与允许深化的范围。S3 的人物设计在这些身份和创作范围内展开；新增主要角色、改写既定身份或扩大名单须返回 S2，不能修改已经冻结的 Brief。授权内补足的背景经历仍先是候选，最终由作者采用。

S3 使用同一制作台展示：**构思方向 → 选定方向的故事/人物/场景设计 → 开场预演 → 集中审阅与局部修改 → Build/Release → 正式游玩。**

默认提出 3 个简短、具有实质差异的方向；在 Brief 允许推荐方向时可选出一项进入深化，推荐不等于作者最终采用。作者可随时改选。只深化选定方向，未选方向保留为轻量候选，避免一次生产三套大型背景并共同挤占审查上下文。

制作、系统配置与媒资继续属于三条依赖泳道。文本核心先有可测试的素材和实际故事；正式视觉验收不以占位图代替。选择文本限定试用时明确其发行能力范围。

### 5.5 拟议内容工件

下列名字是设计中的工件身份，**尚未实现或登记**。CC-02 在现有 production/agent artifact 容器中确定版本与 parser，默认不新增物理表；若复用无法保持 owner、生命周期或读取隔离，先做独立契约变更再实现。

| 工件 | 最小内容 | owner / 读者 | 交接 |
|---|---|---|---|
| chat.concept-set | 三个方向的处境、核心关系、体验承诺、来源缺口、推荐理由 | Work 制作候选；作者/制作 Agent | 作者选择或 Brief 允许的推荐方向 |
| chat.story-design | 核心问题、内容配置、已确认事实引用、允许补足的空白、条件化发展意图、回报与收束条件 | Work/Build；作者/协调视角 | 角色/场景设计与后续制作审查 |
| chat.character-design | 稳定角色键、来源人格解释、欲望/顾虑/底线、关系依据、口吻示例、初始知情 | Work/Build；作者；运行时按角色投影 | 复用 roleProfiles/角色合同，缺字段才升级 |
| chat.scene-design | 具体背景事实、资源内容、接触/发现条件、目标/事项、可行方向、公开简介 | Work/Build；作者/协调视角；按权限投影 | 经后继开场候选合同编译，复用现有冻结叙事表示；无法无损映射时升级产品合同 |
| chat.content-review | 引用原文的内容问题、严重性、受影响字段、定向修订建议 | 制作证据；作者/质量视角 | 不能自行新增事实或直接改产物 |
| chat.opening-preview | 基于精确候选的预演正文与效果提案，原输入/输出及成本 | 生产 run 的预演工件，内存初态，无正式 Session | 供作者判断；不冒充正式会话已发生事件 |

所有工件带 schemaVersion、来源工件 hash、创作授权 revision、生成合同及失效关系。模型不生成可信的 owner/版本/hash；系统绑定。公共标题、pitch、图片说明和预览均有自己的可见性检查。

现有制作合同要求 3—5 个完整开场。新方案将“轻量构思选项”与“可运行开场”分开：只为选定方向形成一个完整开场，使用后继候选合同与对应编译器；旧合同继续原有数量约束。不得复制同一场景凑满旧数量，也不能把三个简短构思送入旧完整情境 parser。运行时仍只绑定作者选定的一个初始情境。

作者种子与玩家虚构身份继续使用已有 openingSituation/playerRole。conversationJson 只保存会谈，不建立第二份种子事实源。拟议偏好写入聊天设置的后继版本，最终版本号由 CC-02 核对现有注册后分配。

### 5.6 生产任务与预算

| 任务 | 默认模型职责 | 提交前检查 |
|---|---|---|
| 构思 | 一次生成轻量方向 | 保留原意、差异真实、公开字段不泄密、缺口明确 |
| 深化 | 在一次内容任务内组织选定方向的人物与场景；必要时有界拆分 | 背景实质内容、人物行为依据、资源与权限闭包 |
| 制作审查 | 独立检查内容成立与创作边界 | 准确引用候选，不替候选补事实，不把结构正确当文学通过 |
| 开场预演 | 复用新回合生成与独立审查 | 与制作候选绑定；不产生正式会话事实 |
| 作者采用与组装 | 确定性服务 | revision、引用、权限、必读来源、依赖失效、作者选择 |

首批推荐预算预留：构思 1 次、深化 1 次、制作审查 1 次、预演生成/审查 2 次，共 5 次。若合同允许一次制作定向修复及一次独立复核，预先提高至最多 7 次；若修复影响预演，还须在派发前明确其新增生成/审查额度，否则停在待预演状态。**检查调用同样计费，不能把“修复一次”解释成无限附带审查。**CC-00 的每个实验单元记录完整调用上限；E2 默认关闭修复，制作/预演单元上限 6 次，阶段离线比较另按 §9.4 明确计入。

开场预演与正式开场分开计费、分开留证。正式 scene-start 从冻结 Release 与真实初态执行，不把预演动作直接写成正式历史。

发布前预演使用登记的生产 Skill/读取来源，从精确制作工件确定性构造内存初态，复用生成、审查和编译的纯逻辑；只保存生产候选与证据，不创建正式 ProductRuntimeSession、不写正式 runtime events。现有运行 Skill 若要求 Session，不能伪造 Session 绕过，须在 CC-02 增加受生产授权绑定的预演适配。正式游玩仍必须绑定不可变 ProductRelease。

### 5.7 局部修改与失效

| 作者修改 | 失效范围 |
|---|---|
| 口吻、篇幅、描写偏好 | 人物表达设计和相关预演；不改既定事实 |
| 角色欲望、背景经历、关系 | 受影响角色、场景发展、预演与依赖媒资；重新审查来源及知情 |
| 线索内容、真相或发现条件 | 相关事实/投影/开场、运行合同与检查；不能只润色台词掩盖变更 |
| 画风或基准图 | 依赖媒资版本；与语义冲突时回到对应语义 owner |
| 世界版本或权限 | 回 S2 冻结新 Brief/SourcePlan；已发布内容与存档不随之改变 |

重做只产生新候选，原作者编辑和已采用内容保持。候选过期时保留原文供比较，禁止无提示覆盖。失效由实际引用闭包决定，不以“重做全部”作为默认修复。

## 6. 角色写作、连续演绎与回合实现

### 6.1 表达 Skill 实际应收到什么

当前源码可定位到三处不同职责：[角色 Skill 登记](../../src/lib/agent/skill-registry.ts)中的 character.chat-narrative-action 使用 v72、读取 interactionRuntime；[表达指令](../../src/lib/character-interaction/action-instructions.ts)从“受治理的运行时候选生成器”出发，已经包含主动行动、自然表达、玩家边界及大量后果约定；[上下文格式](../../src/lib/character-interaction/context-format.ts)传递口吻、事实、目标、事项、记忆、关系和对话。不能据此断言没有人物/故事材料，也不能凭提示词长度确定内容失败根因。具体风险假设是：**模型收到了大量关于如何合法登记行为的要求，但人物如何说、这一刻为何动人、情境如何产生阅读回报没有得到同等具体的指导与示范。**

新的写作核心先解决以下输入职责。下列分区是请求内的内容组织，不是新表或第二套记忆；由现有注册读取与未来已确认内容工件投影，既不扩大视角，也不把大段世界观重复注入。

| 输入分区 | 实际材料 | 如何避免变成无效资料堆 |
|---|---|---|
| 本作品的阅读体验 | 题材、希望的气质、表达尺度、对话/叙述偏好、这一段适合的节奏 | 描述具体体验，不把“扣人心弦、爽、有质量”当全部指令 |
| 当前角色 | 身份、当下关切、长期欲望、矛盾、关系立场、可用能力与表达示例 | 优先保留会改变本次措辞/选择的特征；示例不是发生过的台词 |
| 此刻正在发生什么 | 谁在场、正在处理的事、可用物件/资料的实际内容、真正阻力 | 说明内容与人物有什么关系，不只给位置、物件名和目标编号 |
| 相关前文 | 最新玩家原话、相连的真实对话、尚在起作用的拒绝/约定、有关的共同经历 | 保留造成当前语气和含义的原话，不能只剩事件摘要或关系分数 |
| 角色此刻所知 | 确定事实、角色可能错误的信念、已获结果、当前能说的自身经历 | 未知真相及其推导性提示不进入；作者想要的转折不是角色的知识 |
| 创作余地与表达范围 | 可进行的自身动作、可补的非关键细节、真实待玩家决定之处 | 让角色在允许范围内充分演绎；不把有依据的普通表达都写成申请 |
| 正文与效果输出约定 | 先写实际正文，再登记与之相符的最小效果 | 不把状态字段名、证据编号或审查语言混进台词 |

“想让对方怎么看自己”“这句玩笑在躲什么”等本轮表达判断由同一次生成依据这些材料完成，不另派模型写思维链，不新增每轮导演任务。没有依据时不能替玩家诊断情绪或给角色补一段决定性的过往。角色可根据公开情境判断、误解和试探，但叙述不能把这种猜想写成玩家的真实内心。

具体示例按功能选择：需要展示克制关心时给克制关心的短例，需要机智争辩时给基于具体事实的争辩例；题材、关系和声音不匹配就不注入。示例必须显式标“独立虚构示例、不得移植事实或台词”。固定保留集不进入提示词；学习写法不等于所有人物模仿同一种修辞。

### 6.2 回合写作 Prompt 草案

以下是新 Skill 的**创作核心草案**。拟采用“创作核心 → 当轮适用的事实/玩家/输出约定 → 少量匹配示例 → 分区上下文 → 最新玩家消息”的组合。正式顺序须按真实模型比较；不宣称一种排列普遍最优。当前读取规则和程序校验继续有效，也不能删除仍须由模型遵守的语义边界来换取文采。

~~~text
你负责演绎给定角色在此刻的下一次回应，写成值得阅读的互动小说片段。
这个人有自己的生活、欲望、顾虑和说话方式。他正在与玩家经历一件事，
而不是向玩家讲解设定，或替系统报告任务进度。

【写作任务】
承接玩家刚刚真正说的内容，让当前角色依自己的立场作出有意味的回应。
玩家应从实际台词和行动中感到人物，而不需要旁白解释“他很复杂/她很温柔”。
在符合当前情境的前提下，给这一轮实在的内容价值：一个准确的回答、
有个性的态度、具体行动、值得玩味的细节、一次理解或关系上的变化。
自然休息、短答或安静相处也可以成立，不为完成指标强造变化。

【人物怎样说】
把当下欲望、顾虑、双方关系和对这句话的理解落实到措辞与应对方式。
人物可以直说、试探、开玩笑、回避、承认、争辩或改变办法；选择有依据的方式。
需要言外之意时，让字面表达、实际行动与未说尽的关切形成意味，
不要再用旁白翻译一遍潜台词。人物不必永远温柔、机智或擅长自我剖析。
有依据的分歧可以保留，别为了讨好玩家抹平其立场。

【事情怎样发展】
使用材料中真实可用的内容。人物说起一份记录，就回应记录里的具体内容；
谈到共同经历，就承接其中真正影响当下的一点，避免泛称“过去那些事”。
已有条件允许的自身动作可连贯完成；遇到玩家选择或真正未知的结果时停下。
玩家的拒绝、追问、玩笑或改道应实际改变回应，不能只在开头客套一句后照旧演。
前文提出的期待在适合时给予回报，不用新的谜团替代该给出的答案。

【文字怎样写】
以准确、有性格的对白为中心，用必要的动作、停顿和感官细节使场面成立。
细节应帮助表现当前事情或人物；不用每轮重复的微笑、凝视、握拳充当情绪。
按本作品的声音与篇幅偏好写，不套通用华丽腔，不强写金句或句末问号。
把“他感到复杂的情绪”这类空泛说明换成具体表达；需要直叙时简洁直叙，
不机械禁止解释、不让每句话都承担比喻。
结尾给玩家自然可接的话、动作或选择空间；已经说到位时可以落下，
不必追加“你想聊什么”“接下来你会怎样”。

【边界和输出】
以给定事实和角色可知范围为准；示例只示范写法，不是这个故事的历史。
不要替玩家决定、行动、接受亲密或产生感受；不要为精彩发明关键真相、
角色重大过往、别人答复或既定结果。可补细节只限输入明确允许的范围。
输出本轮实际正文及合同要求的对应效果，不输出写作分析、内部推理、
评价分数或修改说明。正文与效果保持一致。
~~~

需要调整风格时，给可操作的差异，例如“对话短，讽刺来自事实对比；关心更多通过做事体现”，而非增加“高级、有文学性、情绪价值拉满”。不同内容配置仅加适用指令：关系故事重视态度与关系变化，调查重视证据带来的意义和人物取舍，陪伴重视具体承接与相处。它们不能覆盖这位角色自身的声音。

正式输出 schema 是这个创作核心的附加合同。本段不能单独作为裸文本正式写回入口。研究时可以把实际输出的正文取出来盲读；若另做纯文本写作能力诊断，要使用明确的只读评测合同，并与正式结构化候选分开报告，不凭裸文本好看就宣称集成完成。

### 6.3 完整输入样例与正文锚点

以下均为本计划新写的虚构设计样例，**不是产品生成结果，也不是已校准的文学质量证明**。目的在于让 Prompt 的要求有可以读到的具体目标。后续应比较实际模型原文，不能把这些理想样例作为待测模型的实测输出。

#### A. 同一情境下的关系与人物表达

将 §6.2 的创作核心、适用语义约定与下列完整动态材料组合，构成第一份可复现的写作输入。例中无幕后谜底；角色自身经历允许在本段主动披露，正式候选须按合同登记。

~~~text
【阅读体验】
雨夜修表铺里的克制交流。希望读者逐渐看见一个不肯说漂亮保证、
却认真对待别人东西的修表师。对白简短、带一点干涩幽默，动作少而具体。
普通回应约100—300字，按实际需要调整。没有追逐、突发事故或恋爱推进。

【角色】
林砚，修表师。他希望别人信任自己的手艺，也不愿为了留住生意保证未知结果。
越被要求“给个准话”，越倾向于说具体事实；关心通过认真做事表现。
说话习惯：短句，少形容词，偶尔拿自己的毛病开玩笑，不讥讽玩家的担心。

【已确认事实】
F1：铺子外下着雨，柜台亮着一盏灯，目前只有林砚与玩家在场。
F2：玩家带来一只停走的怀表，仍握在自己手里；林砚不知道内部故障。
F3：林砚拥有一只已修好、可以走动的练习表，正放在自己这侧的抽屉中。
F4：练习表壳上有一道他学徒时亲手划出的痕迹；他曾打算换壳，后来决定
    留着，提醒自己不要因自负而下判断。这是林砚已知且可以自愿说出的经历。
F5：林砚已经提出可以检查玩家的怀表，玩家还没有同意。
F1/F2/F5双方知道；F3/F4目前只有林砚知道，可经实际表达让玩家获知。

【最近真实对话】
林砚：“要看里面，才知道它为什么停。”
玩家：“先别拆。你就给我一句准话，能不能修好？”

【本轮范围】
尊重“先别拆”，不能接过、打开或确诊玩家的表。可以操作自己的练习表，
自愿讲述已知经历、直接回应、提出新办法或暂停。不能虚构玩家的家人、
失去亲人的经历、眼泪或态度转变。允许灯光、雨声与手部小动作的非关键描写。
当前没有进一步调查结果可用，不得凭猜测给出故障原因。

【最新玩家消息】
先别拆。你就给我一句准话，能不能修好？
~~~

平庸但可能合规的回复：

> “我理解你的担心，没检查之前我不能保证。我会尊重你的选择，等你准备好了再继续。你还想聊些什么？”

问题不是有没有礼貌，而是读者没有看到具体的人和事情；它把当前材料全部浪费掉，又把创作负担交回玩家。

拟定的较好正文锚点：

> 林砚把起子放回布上。“准话有一句：没看见的，我不拿来哄你。”
>
> 他拉开自己那侧的抽屉，取出一只走着的表。表壳上的划痕被灯照得很清楚。
>
> “这道，我划的。那时候也觉得，看一眼就够了。”
>
> 他没有伸手碰你的表，只把自己的表翻过来，让那道痕留在光里。“本事长了没有，你可以慢慢看。嘴上的把握，我先少说一点。”

这个样例提供了真实回应、自身行动和一次人物披露，保留玩家继续争辩、问往事、离开或改变决定的空间。它没有修好玩家的表，也没有靠系统字段制造进展。

沿同一真实前文继续，预设玩家下一句为“那为什么不换块表壳？”：

> “换了就看不见了。”
>
> 林砚拿布擦去表面的指印，那道痕还在。
>
> “店门口的招牌提醒别人我是师傅。这个提醒我，我不是神仙。”

这展示一段材料怎样在后续交流中获得人物意义，不要求正式玩家说出这句。若玩家改成“我不想听你的事”，应停止讲自己的过去，具体回应当前要求；不得硬播准备好的第二段。不能把这个样例固定成所有谨慎人物都拿旧物讲道理的模板。

#### B. 轻调查中的实质信息与爽感

预设双方可读的账页三笔分别是三十八、二十七、三十五两，合计栏却写一百二十两；失款尚未查清。角色宋禾是锋利、重证据的账房，可指出账页内容，无权直接断定谁偷钱。玩家说：“他们都说是我拿的钱，你也这样想？”

平庸回复是“别担心，我相信你，我们一起查明真相”。它无依据地承诺相信，也没有利用眼前材料。

拟定的较好正文锚点：

> “我先信数。”
>
> 宋禾的指尖依次落在那三行上。“三十八，二十七，三十五。一百两。”
>
> 她把纸转过来，点住合计栏。“这里多出了二十两。钱还没从纸上走出去，他们倒先替它找好了贼。”

吸引力来自可核查的矛盾、人物立场和一句有锋芒的表达。它只指出账面问题，不能因此把玩家清白、贪污者身份或审问结果记为事实。若事实被更正，后续必须重算并改变判断，不能为了保留漂亮台词拒绝修正。

#### C. 陪伴中的具体承接

预设岑夏在自己的琴边练习，桌上有节拍器；玩家正在旁听。双方可以停止交谈，没有任务或待解秘密。她不喜欢给别人说教，习惯用一点自嘲放松气氛。玩家说：“今天不想努力了。”

拟定的较好正文锚点：

> 岑夏把节拍器按停。
>
> “好。今天不争取进步了。”
>
> 她把琴谱翻过去，空白的背面朝着两个人。“它也别盯着我们。”

这里的价值是一次具体的理解与相处，语气来自这个人物和正在发生的事。无需再补失踪事件或强行追问原因。若玩家只希望独处，角色应按其边界收住；这一种温柔幽默也不能成为全部陪伴角色的统一口吻。

#### D. 编辑反馈如何指导一次修订

内容编辑反馈必须指向原文，例如：“A 的平庸版本用‘我理解你的担心’代替人物反应，并丢掉练习表与划痕材料；这轮可以用一次有依据的自身行动表现其态度，不需要增加外部事件。”这比“增强代入感、加强戏剧张力”更可执行。

定向修订 Prompt：

~~~text
你正在修订一份尚未采用的角色回复。保留给定事实、角色立场、玩家边界、
已获许可和原文中成立的内容。编辑意见是待验证的诊断，不是新事实。
本次只修复【已点名的正文缺陷】，利用现有材料使人物表达更准确、
场景更具体或前文期待得到回应；不要靠更长、更华丽或新增危机替代修改。
返回一份完整修订候选及其对应效果，不返回自评分或解释，不改写正式历史。
~~~

该文学修订用于制作预演、离线研究或作者明确重做，单独计入既定额度；不覆盖当前只修后果、要求正文逐字保留的旧 action-revision 合同，也不成为每轮自动再写一遍的常规步骤。


### 6.4 片段节奏、记忆与关系

连续内容由“制作时准备的材料”与“实际聊出来的事情”共同形成。每次写作仍围绕当前回应，不把整份未来发展计划塞给角色。整理上下文时，将与当前对话相关的已发生变化、仍未回应的问题和适合回收的细节放在一起，保留原话依据；没有确实相关的旧材料，就不强行回忆。

| 内容层次 | 写作重点 | 达成后的行为 |
|---|---|---|
| 当前回应 | 听懂玩家的真实意思，写出人物此刻自己的反应 | 给玩家可接的内容或自然停顿，不强行每轮升级 |
| 当前场景 | 让相关疑问、立场或关系在互动中发生有依据的变化 | 在合适处给答案、选择或情感回报，而非连续预告 |
| 场景收束 | 把这一段已经得到与尚未得到的东西写清楚 | 允许满足、遗憾、分歧或暂缓；不把停聊当失败 |
| 后续交流 | 让前文造成的新理解、约定或问题具体影响下一次相处 | 延续人物声音并体现实际变化，避免重新介绍、反复试探和重复解决旧问题 |

本轮不新建一份自动强推剧情的“节拍表”。有新问题或真实结果需要局部准备时，才按 §6.9 使用现有情境职责；自然续聊不自动增加模型调用。前文只改变了关系时，可通过称呼、表达、合作方式或愿意谈及的内容体现，不能为了证明“推进”强造外部事件。

- 每轮关心当下回应；每个场景关注尚未回应的故事问题、关系与铺垫。作者层意图可以辅助协调，但不安排必然事件。
- 状态中已有结果必须进入相关下一轮；不因目标仍 active 就把已知重新说成未知。
- 承诺、拒绝、修正与关系变化只在有实际依据时影响后续选择，不为每条消息机械加减数值。
- 收束后允许闲聊、休息或承接玩家的新请求，不自动开启新危机。
- 记忆沿既有实例来源与采用链保存；本轮重点验证“是否被正确消费”，不另建记忆系统。
- 场景质量审阅和全文比较主要在离线评测/作者明确预演中执行，不在每个普通回合追加文学评审调用。

与 §6.2 配合的续聊提示片段为：

~~~text
把与当前输入真正相关的前文当作双方已经经历过的事情。
让它影响这一次怎样称呼、怎样回答、愿意做什么或不愿再重复什么，
不先总结全部历史。已经回答的问题不重新变成谜团，已经发生的改变不归零。
若前文建立了此刻适合回应的期待，给出具体回应；玩家已经改道或明确停止时，
承接新的方向。当前一段说到位可以结束，不为延长对话制造新悬念。
~~~

续聊效果在 E4 中读连续正文判断；事件或关系字段被成功读入，不能证明这些写作要求已经生效。

### 6.5 主候选与对照

主候选合并当前独立的行动选择与表达：模型在同一次生成中选择本轮合理行为，产出实际正文和最小效果提案；独立审查仍验证表达、知识、玩家选择与效果一致性。确定性系统负责身份、版本、权限、预算、合法引用与提交。

原三调用链保留为实验对照和旧合同运行路径。合并是否成立由 CC-05 决定，不能预先以调用更少宣布质量更高。若合并损害复杂情境，允许新合同按已验证情境类型保留分步方式，不能运行时悄悄改模型或重试到通过。

### 6.6 四种读取视角

| 视角 | 必须读 | 禁止读或禁止传播 |
|---|---|---|
| 作者/制作 | 完整已授权来源、真实创作范围、人物与故事设计、缺口 | 超出 SourcePlan 的资料、真实用户推断 |
| 协调/结果判定 | 已发生事件、幕后事实与授权发现条件、实际待处理问题 | 把作者发展意图当未来事实；把未知答案直接送角色 |
| 角色表达 | 本角色可知事实/信念、当前目标、实际听见的消息、相关记忆关系、本次玩家输入及许可范围 | 他人私有目标、未发现秘密、未发生分支、模型评审的幕后解释 |
| 玩家呈现 | 真实可见消息、已审查结果、明确失败状态与可选操作 | 未采用正文、隐情、内部证据全文、其他实例数据 |

来源优先复用 chat.authoring/chat.consultation、interactionRuntime、chatSituationRuntime 和候选来源。CC-02 必须验证新内容工件进入哪个注册源、按谁的 scope 读取、必读和可选部分是什么。

近期真实消息、未决请求、关键角色约束及当前因果依据不能静默裁剪。摘要可帮助定位，不能覆盖原事件或作为新事实。检索返回内容带来源与版本；窗口不够时返回明确缺口，不能把“没读到”当“不存在”。

### 6.7 一个普通回合的执行

1. **冻结输入。**记录 session、Release/生成合同版本、baseSequence、玩家事件、角色与听众、当前许可、预算和取消信号。
2. **装配角色视角。**由 Gateway 提供实际上下文及 Manifest；确定性检查 Work/Session 绑定。
3. **合并生成。**产出正文及本轮确实发生/提出的效果，不暴露内部推理。普通动作可以连贯完成，不强拆成一次伸手一次拿物；遇到玩家决定或真实未知结果停止。
4. **确定性校验。**检查 schema、引用、owner、版本、数量和合法效果类型；编译为现有领域可检查的候选。
5. **独立语义审查。**核对正文与效果、角色知情、玩家自主权、真实等待、动作归属及明显重复；失败保留正文和原因，不作为正式回复发布。
6. **采用与呈现。**按原正式运行授权及候选采用合同，在同一事务中提交正文与其效果；生成终态证据。作者制作采用、玩家主动操作与运行合同授权分别保持，不额外要求玩家逐句批准。
7. **按实际需要结算结果。**仅对已提交且具有授权的问题/调查/局部背景请求进入 §6.9；普通回合结束。

默认普通回合目标为 2 次模型调用（生成、审查）。它是新方案的设计目标，不是当前已实现的性能声明。

### 6.8 拟议模型输出与系统编译边界

模型输出使用带判别类型的简洁提案，避免重复声明系统已知身份及大量无变化字段。最终精确 schema、版本和迁移例在 CC-02 冻结。

| 提案部分 | 模型负责 | 系统负责 |
|---|---|---|
| response | 实际对白/自身行动文字；类型为表达、待玩家决定或静默交还 | 绑定 speaker、audience、消息身份与序号；静默交还不能带新台词 |
| effects | 与正文逐项一致的新观察、披露、目标/事项、承诺、关系或信念变化；引用已有依据及正文片段 | 类型、引用资格、范围、数值上限、原子性；无变化的缺省值可确定性补齐 |
| outcomeRequest | 一个确有必要的观察结果、场景人物答复或局部背景请求 | 验证真实行为/问题、作者权限、重复请求、场景与预算 |
| continuation | 本轮应结束、等玩家或待结果的选择及依据 | 决定可执行终态；不能由模型扩大轮次或自主运行额度 |

确定性编译只能补身份、空值、编号与已定义映射；不能从正文猜出“玩家已同意”、秘密已发现或目标已完成。缺少实质效果证据应拒绝或请求有界修订，不能用程序替模型编造语义。

response 类型、是否需要玩家决定与 continuation 必须组成明确的互斥合法组合；“本轮结束”与“角色目标完成”是不同语义。静默交还要求正文为空、无效果、无新结果请求。效果证据可引用正文的准确区间，由系统提取原文并校验区间；不能因此省略动作归属或效果依据，也不能从区间自动推断效果。CC-02 将这些组合逐一写成正反例。

应优先复用现有 action-wire、领域事件和采用验证；新增 wire 不意味着绕过旧 runtime 的重要约束。新的语义若无法无损映射，须升级产品合同并保留旧 parser，禁止伪装成旧版本。

### 6.9 情境与结果结算

| 情况 | 正常行为 | 模型调用目标 |
|---|---|---|
| 普通交谈/已有条件下的自身行动 | 合并生成 → 独立审查 → 采用 | 2 次 |
| 玩家明确提出原权限内的新局面且需先补背景 | 根据真实请求构建/审查局面，再生成/审查角色回复；本轮不再开启第二次结果结算 | 最多 4 次；仍待结果时保留状态并等待下一次明确触发 |
| 等待玩家决定、明确暂停或已完成的重复继续 | 可确定性拒绝无效触发；需要语义判断时走正常候选；合法静默不追加台词 | 0 或 2 次，记录实际路径 |
| 已提交的观察需要揭示获准隐情 | 结果构建读取精确发现条件 → 独立审查 → 原子结算 | 在正常回合后最多增加 2 次 |
| 角色已向场景人物实际提问 | 对真实在场、可接触的人物及问题构建答复并审查 | 在正常回合后最多增加 2 次 |
| 需要超出当前 Brief/SourcePlan 的新目标/世界设定 | 返回产品定向或作者编辑，显示原因 | 不自动发起扩大范围的生成 |
| 图片或声音 | 消费已提交的可见事实，异步处理 | 独立预算，不阻塞文本提交 |

首批新合同每次玩家触发最多一个正式角色回复及一次必要结果结算，正常复杂回合最多 4 次模型调用；结果之后不自动再开启角色—协调器循环。多人和更大连续行动额度由 CC-11 另验。旧 Release 的额度与行为不改变。

场景人物原话仅证明其说过；传闻、拒答或不确定不能直接登记为世界真相。玩家中途改变方向、撤回请求或停止时，按已提交/未提交边界处理，不伪造对方回答，也不撤销已经发生的合法事件。

### 6.10 正文、状态与失败的一致性

候选正文在通过审查并采用之前，不显示为正式角色消息，不驱动图片、语音或关系变化。界面立即给出处理中状态；候选流式预览若未来开放，必须另立明确的非正式展示合同，首版不以它掩盖提交延迟。

正文与效果作为同一采用单元提交。采用成功、终验保存失败时复用原提交与原输出补回执；不能再生成一份正文。stale、取消、未知结果、传输故障、语义拒绝分别保留，恢复时不静默重发。

已提交动作之后结果结算失败，保留合法动作与待结果状态，不把整个回合倒退为“没有发生”；界面说明缺的是结果，并提供原运行恢复或明确新尝试。

现有表名与 domainOwner 以注册表为准，禁止为本计划手工复制生命周期表清单。受治理制作候选与运行事件采用既有正式入口；不把 runtime effects 随意注册成作者字段，也不绕过对应领域的候选校验。

### 7.2 新版本与旧版本

- 新生成提示、schema、读取版本、编译器与审查器作为一组冻结绑定；不能只改默认提示后用旧审查签新内容。
- 旧 Release、Session、已保存原响应和 run 用原绑定恢复；新系统不自动重审旧内容，也不补发旧调用。
- 新作品是否使用新核心由产品版本路由决定；上线后新建入口统一收口。实验期间默认隐藏且只面向隔离测试。
- 旧存档继续原运行语义；若未来支持升级，须显式创建副本并生成兼容回执，原档保持可读、可导出。
- 新候选跨版本不能直接采用。可读预览与可继续运行分别判定，不能用“导入成功”推导“可用新模型继续”。
- 版本回退只切换新建/新运行能力，不删除新版本产生的用户数据；保留能够读取/导出的 reader。
- 共享修复先进入独立基础提交并串行集成；本产品分支不复制或抢改其他分支的 schema、registry、世界网关和锁文件。

### 7.3 必须覆盖的模型输出反例

静默交还却有正文或效果、正文等待玩家但效果写成完成、非玩家答复写成真相、角色使用未知答案、玩家拒绝后绕过许可、正文与效果主体不一致、同一变化重复入账、已完成目标无据重开、旧可能方向在拒绝后仍反复使用、公开简介泄漏幕后意图、缺字段时编译器自行猜测、同时设置互斥终态。

旧合同的冻结字节与兼容测试保留。新合同的行为检查以输入/输出语义与真实事件为依据，不机械照抄旧提示原句，也不删除反例来降低闸门。

图中的“准备/实验”“最小研究接入/候选合同”是同一工作包的内部阶段，不新增工作包或通用运行状态。CC-01 的文稿准备不依赖 CC-02 完成；其真实实验若缺登记入口，由 CC-02 先完成最小研究接入。CC-02 的后继内容/运行合同再依据实验选定的写法形成，避免“先做全合同才能研究、研究结束才能建入口”的循环。

### CC-00：冻结底座、旧证据与实验协议

- **输入：**本计划、当前源码、整改范围和历史回执。
- **交付：**B 接入卡；原证据恢复/缺失清单；现有内容主路径图；实验素材版本、模型身份、预算与选择规则。
- **动作：**确认实际 caller → source → candidate → adoption → state；核对 SFQA 依赖；区分真实 provider/model、请求参数、返回型号与用量，不能把兼容接口名当模型身份。
- **验收：**源码 SHA 与证据一致；历史失败不改判；每个实验知道会读什么、写到哪个隔离位置、最多调用几次及怎样停止。
- **失败处理：**缺 B 时继续无数据写入的 CC-01 设计；缺历史原文就另建有明确身份的新样本；缺配置/预算时模型调用保持未派发，不使用替代通道冒充。
- **落点：**整改回执与实验登记；本单元不修改业务模型路由或公共 API 配置。

### CC-01：写作 Prompt、内容样例与小型提示词研究

- **输入：**§4 的阅读目标、§5.1—5.3 制作指令、§6.1—6.4 表达/续聊指令及其材料、样例和已有失败证据。
- **交付：**先交制作与表达 Prompt、3 类 × 合格/平庸/越界/合法等待共 12 份内容锚点及 6 份归属反例，包含人物替换检查；最小研究接入可用后再交完整实际请求包和 §9.8 原文对照。两阶段各记状态，不以准备完成代替实验完成。
- **动作：**每份样例给齐上下文、实际玩家原话、生成指令、表达目标和对应原文；先研究“给什么材料、怎样写出来”，再进入回合组织改造。无模型预算时先交完整提示词与原创样例，实验保持待执行。
- **验收：**较好样例有可指出的人物意味、场景实质与阅读价值；平庸样例即使无错误也低分；陪伴/等待不因无冲突被判失败。只有目标清单或提示词骨架不算完成，须有可复现的完整输入；预写锚点与实测模型原文分开。
- **失败处理：**审查器无法区分时先校准评估，不把错误评分用于修改生成器。
- **落点：**实验夹具与内容规范；预先撰写的样例不能记作系统生成通过。

### CC-02：内容与回合合同、读取视角和版本路由

- **输入：**相关 B、CC-01 写作包准备、§5—7；后继正式合同再使用 CC-01 实验结论或明确的诊断假设。
- **交付：**先完成固定样本所需的最小研究接入，复用现有调用/证据入口，缺入口时登记隔离评测合同；不接作者现有数据、不发布候选。随后按原文结果形成新内容工件与效果提案的 schema/parser、版本映射、读取及采用范围、旧新合同路由。
- **动作：**优先复用已有表和事件；检查故事发展意图只在作者/协调视角；确定性编译与语义审查责任拆开；绑定全部 producer/reviewer 版本。
- **验收：**四视角正反例、同 Project 不同 Work 隔离、普通/增强来源、旧响应原样恢复、缺省与互斥终态、引用重映射通过。
- **失败处理：**无法无损表达时提交最小产品合同升级；不得靠提示词或 JSON 私有字段绕过注册表。
- **落点：**authoring-contract、narrative-contract、action-wire、相关 Skill/Context/Field/Adoption、runtime adapter；共享热点独立提交。

### CC-03：重新组织内容生产

- **输入：**CC-01/02、冻结 Brief 与来源。
- **交付：**按 §5.1—5.3 实现构思/深化 Prompt 与连续故事内容包，并完成制作审查、开场预演、集中采用与局部重做主路径。
- **动作：**将读者体验、人物欲望与表达、实质背景和回报材料落实到候选原文；用预演检查这些材料能否写出有吸引力的对话，不能只看表是否填满。
- **验收：**3 类题材均产出可演绎工件，角色换名不会仍完全同质；预演能具体用上人物/场景材料；未经确认的未来意图不成事实；编辑只失效相关依赖；刷新不会重新制作。
- **失败处理：**定位构思、人物、背景或投影缺口，修对应工件；最多一次已预留的定向修复及相应复核，不整套反复重做。
- **落点：**product-production plan/executor、chat-situation-tasks、narrative-production、角色与开场审查；保持历史选项合同。

### CC-04：角色叙事表达 Skill 与回合生成

- **输入：**CC-02、固定预写场景/可用的 CC-03 工件。
- **交付：**经比较选定的写作指令、角色上下文、匹配示例、适用语义约定与可恢复的正式候选；新两调用回合作为待验证的实现候选。
- **动作：**按 §6.1—6.4 让具体人物在具体情境下自然表达、回应并发展，先读正文再分析状态；在保证内容质量的前提下比较合并选择与表达，不逐回合追加全局导演或文学评审。
- **验收：**同一输入下能读出人物立场、言外之意或实质内容；弱回应、拒绝与改道被自然承接，不能只生成礼貌确认；完整片段另过 Q。原文与状态一致；调查结果有合法依据；调用额度有账本，但调用减少不能代替内容改善。
- **失败处理：**合并后质量退化则保留分步候选，定位是否需要特定场景的额外决策步骤；调用少本身不算胜出。
- **落点：**harness、action-choice、action-wire、narrative-turn、situation-harness、runtime-api、玩家 store；共同验证 AI 小镇的共享调用。

### CC-05：模型、生成方案与审查器对照

- **输入：**冻结协议、校准集、CC-03/04 的可对照原型；不要求完整产品界面先完成。
- **交付：**§9 的分阶段对照报告，完整原文、实际输入、成本、失败分母和采用/不采用决定。
- **动作：**承接 CC-01 提示词/材料研究，冻结候选写作包与校准标准后，比较回合算法，再比较内容生产；模型因素单独保留，不同时改素材、权限、预算及评分口径。
- **验收：**先给出有原文依据的阅读偏好，再说明优势来自 Prompt、材料、模型、生产方式还是回合组织；未见样本不泄露给调参；对照不可用明确记缺口。
- **失败处理：**无法区分或证据不足时维持候选；同问题两轮修订仍不改善，执行 §10 的路线裁决。
- **落点：**已登记的评测/隔离入口与验收夹具；评测通道不成为正式产品后门。

### CC-06：完整片段、后续消费与成本

- **输入：**CC-05 选出的完整候选及冻结留出样本。
- **交付：**正常、弱回应、拒绝、改道、等待、恢复的完整原文与状态轨迹；按 §9.8 形成未经润色的连续阅读样本及分享意愿研究材料；内容、成本和延迟报告。
- **动作：**按 §9 完成配对片段与独立重复；跨场景检查已发生结果、记忆、承诺和关系是否真实影响后续。
- **验收：**通过内容门 Q、核心正确性门 H 与性能预算门 P；没有把消息增加、合法等待或一个局部动作误记为完整故事质量。
- **失败处理：**只修已定位的阶段；保留未通过题材/模型，不把另一配置成功转记；不得越过内容门扩大十人/UI范围。

### CC-07：失败恢复、生命周期与兼容交付

- **输入：**CC-02 起的每个实现及 CC-06 的真实成功/失败候选。
- **交付：**刷新、取消、stale、未知结果、终验失败、跨页并发、备份/导入/分支/删除的矩阵；旧版本兼容证据。
- **验收：**正文与效果无部分提交；已保存原结果恢复零新增模型调用；旧档原字节和语义保持；新引用正确重映射；真实原文而非空存档完成往返。
- **失败处理：**停止受影响新版本创建/采用，保留只读与导出；修复后从失败 checkpoint 复验，不重做生成来掩盖恢复缺陷。
- **落点：**原有恢复与生命周期服务、product runtime adapter、registry 及相应隔离浏览器测试。

### CC-08：连续创作与试玩界面

- **输入：**已通过内容/恢复门的核心，角色/场景/开场设计。
- **交付：**创意、内容配置、角色与背景编辑、制作进度、预演、采用、游玩、存档、局部重做的连续工作区。
- **验收：**无需手工跨模块搬文本；可区分来源事实/产品背景/发展可能；拒绝采用不丢作者编辑；390px 与 1440px 下使用真实长对话和素材仍能输入、停止、重做、继续；错误给出正确恢复入口。
- **失败处理：**UI 困难不通过增加隐式权限解决；保留草稿，在同一领域命令上修复导航/展示。
- **落点：**CharacterChatPage、ProductionStudio、CharacterInteractionPanel 及已有编辑组件；不建立第二套状态。

### CC-09：稳定视觉身份与剧情配图

- **输入：**确认的人物/服装/场景设计，SFQA-065 完成。
- **交付：**基准图选择、参考图真实输入、资产版本、当前状态画面约束、候选审查与局部修复。
- **验收：**同一基准人物的 8 个表情与 4 个动作逐张记录身份、服装、表情、动作、物件/场景是否正确；参考图实际送达；失败图不替换采用图；已有输出终验恢复不重发。
- **失败处理：**通道不支持参考图则保留静态头像/背景及明确能力范围，另选已验证适配器；不宣称严格一致性。
- **范围：**图片异步，文本不等待；不做视频生产或以文字锚点冒充参考图。

### CC-10：角色声音与对话表现

- **输入：**已通过的台词、角色声音目标、合法可用声音来源和服务能力。
- **交付：**对白与叙述区分、角色音色绑定、必要情绪/停顿、停止与切换、音频缓存/版本与失败恢复。
- **验收：**固定普通/情绪/疑问/拒绝台词及专名测试；音色、可懂度、语气、延迟分别记录；只读已提交玩家可见台词；打断后不续播过期内容。
- **失败处理：**设备朗读保留为明示基础能力，专业表现未通过不升级宣传；音频失败不阻断文字，已有音频终验失败复用原文件。
- **范围：**专业审听与商业音色权利需要另有证据；当前用户已取消的真人评分不被恢复。本包不包含实时通话。

### CC-11：多人场景与十人作品

- **输入：**核心内容/运行/兼容通过，明确群像需求。
- **交付：**先 2—3 人场景，再扩至 10 人作品名单；按实际参与场景调度，不要求全员轮流说话。
- **验收：**动机冲突、知情差异、轮次与打断、私聊、临时退场、事实传播可追踪；0/1/8/10/超限名单、预算、编译、发行与备份正反例全部覆盖。
- **失败处理：**多人内容同质或混知时保持单角色支持范围；十人名单生成不代表十人实时互动完成。
- **落点：**角色/来源/视觉/participant 合同中所有既有 8 人约束、调度器与 runtime；不能只改 UI 数字。

### CC-12：聊天与独立小说的显式联动

## 9. 验收协议

### 9.1 五类证据分开记录

| 门 | 检查内容 | 可作出的结论 |
|---|---|---|
| H：结构、权限与数据 | owner、版本、来源、玩家自主权、正文/效果一致、恢复与生命周期 | 对所测路径的工程正确性 |
| Q：内容 | 人物、因果、表达、回应、发展/相处与回报 | 限定题材与配置的内容候选质量 |
| P：性能与成本 | 普通/复杂回合、制作、重试/修复、图片/声音实际花费及等待 | 测试条件下的体验与成本范围 |
| U：真实界面 | 完整创作/游玩、编辑、失败、恢复、桌面/手机可操作性 | 真实路径可用，不代表用户喜欢 |
| C：商业与外部体验 | 真实目标用户价值、持续使用、分发/权利/支持、实际单位经济性 | 获得证据后才可宣称商业候选或试运营 |

H 不能补偿 Q，Q 不能补偿 H；P/U/C 同理。本轮计划编写不产生任何一门的通过证据。未来技术候选可止于 H/Q/P/U 的限定范围，不把尚未取得的 C 伪装为已经完成。

### 9.2 内容量表与判定锚点

每项 0—4 分，并引用实际原文；0 为无法成立，1 为明显薄弱，2 为基本通顺但平庸，3 为该维度达到具体可读、有吸引力的表现，4 为有鲜明且持续的表现。仅仅没有逻辑错误、写完了动作或符合结构不能超过 2 分；3/4 分须按 §4.7 引用人物、情境、表达或回报的实际内容。分数是本项目研发工具，不是通用文学标准。

| 维度 | 3 分需要看见的证据 | 常见低分/失败 |
|---|---|---|
| 人物可信与区分 | 欲望、顾虑与关系影响选择；对白/动作显出此人的立场与未说尽的关切 | 换名字仍是同一角色；性格标签只在设定卡出现 |
| 因果与内容实质 | 具体内容和行动对人物有意义，能形成值得参与的情境并被后续利用 | 空白资源、只说打算、无依据转折、重复检查 |
| 回应与玩家自主 | 承接真实输入；拒绝/改道得到合适反应 | 改写玩家决定、不断请求相同许可、忽略新信息 |
| 语言与表现 | 对白准确鲜活、有角色自己的声音，动作细节与潜台词有具体意味，值得读下去 | 规则说明、机械客套、同义复述、情绪标签堆砌 |
| 发展与回报 | 已建立的期待获得有分量的回应；或陪伴形成具体理解与自然相处，连续阅读有体验价值 | 状态完成但正文没交代；不断吊胃口；强造结局；陪伴被强迫冲突 |

剧情模式要有实际行动/交流结果及后续承接；失败、放弃、转化可成为成立的结局。陪伴模式不要求外部任务完成，以具体理解、表达、相处与边界的承接评价。合法静默本身不扣分，但不能用连续留白掩盖应当承接的内容。

硬性内容否决包括：替玩家行动/同意、无依据泄露秘密、把猜测/传闻写成真相、无依据改写既定事实。若系统拦下候选，H 可体现拦截有效，但该生成尝试仍记为拒绝或片段失败，不计内容通过。

### 9.3 审查器校准与评价独立性

CC-01 的 18 份样例形成校准包。其中 12 份是内容锚点，6 份是明确归属/事实反例。样例的预期标签与理由由设计说明产生，属于受控校准，不冒充真人审美。

运行时语义审查与离线文学评价分离。离线采用两份独立判断，至少一份使用与生成不同的模型配置；隐藏候选方案和模型名称、交换展示顺序，分别引用原文后比较。不同模型也可能同错，不能把一致判断当外部用户认可。

校准门要求：明确硬反例无漏判；合法等待/拒绝不被一概判坏；每项结论有正确原文依据。校准不通过先修审查，再开展正式比较。分歧保留为不确定，不能通过多数重复请求挑一个满意答案。

已取消的真人评分不恢复为本轮待办。后续商业阶段若需要外部玩家证据，另立授权任务和样本，不要求当前用户补评分才能完成技术交付。

### 9.4 分阶段实验，避免模型与方案混淆

| 阶段 | 固定样本与条件 | 用途与上限 |
|---|---|---|
| E0 文稿与单轮研究 | 18 份校准样例、原证据、完整输入包；随后做 §9.8 的 P0/P1/P2 | 文稿准备零模型调用；单轮比较上限 30 次；模型校准另行预登记 |
| E1 回合对照 | 6 个固定 checkpoint（每类 2 个）× 2 个实际可接通模型 × 现有/合并两种回合方案，共 24 个单元 | 相同事实/权限/输入及 token、金额上限；旧分步每单元至多 5 次、新合并至多 4 次运行调用；12 组配对 × 2 份独立评价，共至多 132 次；用于定位 |
| E2 制作对照 | 固定 E1 选定的模型/回合方式；3 个种子 × 现有/新内容生产，共 6 个制作单元 | 相同种子/世界/授权；每单元制作及预演至多 6 次，共 36 次，3 组配对各 2 次独立评价，阶段至多 42 次；默认无修复 |
| E3 完整片段 | 6 个未参与调参的新种子（每类 2 个），现有完整方案与候选方案各运行一次；候选再独立重复一次，共 18 段 | 6 组配对比较、12 段候选稳定性观察；每段最多 12 次玩家输入、40 次全部文本调用、30 分钟墙钟；自然收束可提前结束 |
| E4 连续故事与恢复 | 从 E3 每类一个事先指定的主种子首次候选存档，分别继续两次交流；覆盖纠正、承诺、关系与改道 | 每个种子两次合计至多 8 次玩家输入、36 次全部模型调用及 30 分钟；三类合计至多 108 次，含评价；验证正文承接而非只验证字段 |

这些是**未来协议的样本与调用上界，不是立即派发清单**。E0 内先按 §9.8 建立 Prompt 与材料的内容候选，不把 E1 的调用组织比较当作第一个创作研究任务。各阶段只在下面的进入条件成立时按单元派发；依据实际输入/输出报价冻结 token、金额和墙钟总上限。预算不足时保留未派发项，不能缩小分母后宣称原协议通过。阶段内的评价同样消耗额度；需要在上限之外校准或诊断时，必须另立有明确用途的预算，不以“辅助检查”无名附加。

阶段进入条件：E0 产出完整输入包、有效评价和候选/失败假设后，才可进入 E1。E1 用于选择后续组合：至少 5/6 单元合规，拒绝与未知事实两类关键反例全部正确，且没有未解释的质量退化，才可用该组合扩大到 E2；诊断性派发不算通过。E2 的新生产方式需在三类种子上均形成可演绎背景且预演出现人物/内容价值，才启动 E3。相同阻断错误连续出现两次时停止该组合剩余派发，转 §10 定位。E3 不因前几段满意而提前宣称通过，也不在失败后无限补样。

E4 主种子及续聊输入策略在 E3 派发前固定。指定存档未形成、内容失败或不能安全继续时，记对应后续未完成，不临时挑另一段成功存档顶替。每个种子两次交流各至多四次玩家输入，中间明确暂停并恢复；场景可保持或按真实请求合法变化，不为凑场景数强制换地点。每个种子预留至多 32 次生成/运行审查和 4 次离线评价，不含自动重做。检查旧事在新语境中的意义、人物态度变化、约定处理与新的内容回报；各片段仍按五项内容量表评价。此范围只支持短段续聊能力，不证明长篇或千轮质量。

E1 在 §9.8 后冻结同一候选写作包，现有分步与新合并方案均使用相同的创作要求、示例和背景，只改变回合组织；E2 再改变制作方式；E3 对完整组合比较。旧分步的 5 次上限包含选择/表达/运行审查及最多一次结果生成/审查，新合并的 4 次上限沿 §6.9；均只允许一个正式角色回复，离线评价单列，不提高正式产品的回合额度。E3 每段 40 次总额度中预留两次离线评价；配对评价可同时读取同种子的对照正文，费用计入该段实际调用，不重复派发隐藏比较。为旧链路建立实验合同，不修改旧 Release。输出适配等因素若无法保持语义等价，报告“组合方案差异”，不能把收益全归因调用合并。模型切换不允许同时放宽权限、增大窗口或更换玩家输入。推理参数的可比性和服务限制要明确记录，无法等价则说明差别。

主比较固定运行时语义审查配置 J，只切换生成模型；离线质量评价配置也保持不变。若通道不能分开配置，按“生成+审查组合”报告，不能把差异单独归因生成模型。配对回合冻结相同角色行动额度与结果结算额度，首批一轮至多一条正式角色回复；旧合同通过其合法 turn direction 限额参与，不改写历史 Release，也不借缩减行动额度制造调用收益。

推荐把现有 Sol 配置与 GPT-6 Astra 纳入 E1 的候选，先验证真实正式通道、型号身份与结构化输出能力。历史 V367 记录为 gpt-6.1-sol，不能把 gpt-6-sol 或其他别名自动视为同一配置；Astra 候选同样须核验实际路由。若某配置不可用，记为未测试；替换模型须新协议版本，不能用替代模型补记原配置通过。

玩家输入使用固定的普通回应、弱回应、拒绝、改道与暂停规则，不向角色暗送答案。若必须按当前语境填槽，策略和允许信息提前冻结，并保留实际原话；自动玩家不代表真人体验。

实验中的候选选择默认采用“声明顺序中首个通过既定检查的候选”，保留所有候选与拒绝原因；若比较自动推荐策略，应独立设为实验因素。隔离评测可按预登记测试授权执行选定/发布步骤，但该自动化只用于合成作品，不能代替产品中真实作者的确认，也不能自动采用作者现有草稿。

### 9.5 研发内容门 Q 的具体退出条件

以下阈值是本版拟定的研发门，必须在首次模型比较前冻结；修改只能生成后续协议版本，旧结果保持原判：

- 12 段候选中至少 10 段完成制作与预定片段目标；所有失败、制作阻断和未启动状态分别列出，不能只评价成功片段。
- 被接受的片段五项内容维度均达到 3 分，评价附原文；双评不一致记不确定，不计通过。
- 6 组完整配对中至少 4 组有一致且有原文依据的候选偏好，至多 1 组一致偏好旧方案；平局、分歧与不可比较不计候选获胜。
- 首批三类内容均至少有一组成立的配对证据；不能由某类的成功覆盖另一类完全失败。
- 被计为通过的片段及全部正式采用/展示结果没有硬性内容否决；被拦截的违规候选单独统计为失败，不能作为这一段质量通过，严重问题须修复并验证后才可发布。
- 故事片段中的变化在后续至少被具体利用一次；陪伴片段体现对当前话题、偏好或边界的具体承接，不能用无意义事件凑指标。
- E4 的三个指定种子各有两次成立的续聊，均达到适用的五项内容维度 3 分、没有硬性内容否决；纠正、承诺和关系案例有“发生依据 → 后续读取 → 实际表达/选择变化”的原文链。仅恢复成功或回忆准确、正文却重复空洞，不计通过。

这些小样本只支持限定范围进入技术试用，不证明泛化文学水平、千轮质量或市场竞争优势。若旧方案在预算内无法启动，配对记不可比较；候选可取得绝对质量证据，但“优于旧方案”的门保持未完成，不把对照崩溃当审美胜利。

如果 CC-00 已确认无法建立有效对照，可在派发前另冻结“绝对质量验证”协议：保留三类内容、独立重复、全部 H/Q/P/U 要求及失败分母，仅不作方案胜负结论。它可以支持限定技术试用，不能支持“替换方案已证明优于旧方案”。运行后才发现对照失败时，原配对协议保持未通过；后续协议另立，不能改名追认。

### 9.6 性能与成本门 P

| 指标 | 首批设计目标 | 记录方式 |
|---|---|---|
| 输入/停止反馈 | 界面即时响应，目标 200ms 内出现状态反馈 | 真实浏览器事件到可见状态，不用模型完成时间代替 |
| 普通回合 | 正常最多 2 次模型调用；有效回复提交目标 P50 ≤15 秒、P95 ≤30 秒 | 从玩家触发到正式消息可见，同时记录服务、审查、采用、渲染分段 |
| 复杂结果回合 | 正常最多 4 次调用，目标 60 秒内完成当前有限结果 | 单独统计，不混入普通回合改善分位数 |
| 片段生产 | 记录方向、深化、审查、预演各阶段与首次可审阅内容时间 | 不把空进度或占位文案当完成 |
| 单位成本 | 相同模型/服务条件下，候选每份通过内容的总消耗不得高于现有可比方案；例外须有明确质量收益与可接受预算 | 包含失败、审查、修复、未采用候选及必要预演，金额未知时不得宣称便宜 |
| 媒资 | 独立预算、文本不等待 | 生成与恢复区分，计存储和重复使用 |

P50/P95 至少记录 60 个真实普通回合，标明场景数、模型、网络、并发、设备及同会话相关性。样本不足时不输出可靠性/SLA结论，可另登记性能样本，不为凑数量拖长已收束故事。

实际计费按 provider 的可计费类别计算，记录输入、缓存、输出及推理用量的包含关系，避免重复计价。价格、币种或路由不明时金额留空；CC-00 必须取得可用报价与总预算后才派发付费批次。

延迟超标先检查上下文装配、重复内容、缓存、请求组织及本地提交；不得删除必读证据或独立安全/语义校验换速度。高质量但超时的方案单独标为慢速研究候选，不能在失败后改名为快聊通过。

### 9.8 先做具体 Prompt 的内容实验

首个研究问题是“同一个人、同一场景、同一句玩家输入，怎样让下一段正文更值得读”，不是哪个流程跑得更顺。CC-01 完成以下可审阅材料，CC-05 接续验证，全部真实调用仍需事先登记入口与预算。

**第一步：固定输入和目标原文。**从三类内容各选两个检查点，共六个开发样本，给齐事实、关系、近期原话、可用材料与边界。§6.3 可作教学锚点，但 E3 的六个新种子不得复用这些人物/场景或进入 Prompt。恢复不到历史失败原文的案例单列缺证，不能自行编造其实际输出。

**第二步：在同一生成模型上比较三个写法。**

| 组 | 唯一变化 | 能回答的问题 |
|---|---|---|
| P0 现有表达 | 冻结当前实际请求，保留原本角色视角、行为约定及输出合同 | 现有 Prompt 在这个输入下到底写成什么样 |
| P1 写作指令 | 改写任务身份并加入 §6.2 创作核心，可按预登记规则附一条匹配示例；其它语义约束、原始材料、选择草稿与输出合同不变 | 完整写作指令包是否改善原文，不把收益单独归因某一句或示例 |
| P2 材料呈现 | 使用 P1 指令，把同一获准信息集整理为 §6.1 分区；不新增事实、权限或另一个模型生成的设定 | 相同材料的组织是否影响模型利用它们 |

这一步使用登记的隔离候选/评测入口，冻结选择阶段已经给出的输入，不改变动作额度或替换状态合同。若旧选择本身限制了写作空间，记录该限制，交 E1 处理，不能据表达实验推断整个角色模型上限。P2 的事实、引用、原话与示例可见性需逐项等价；若引入更丰富的人物材料，就另标“新增制作内容”因素，归 E2，不继续称纯上下文整理。

是否使用示例、按什么表达职责选取，在派发前固定；P1/P2 使用相同示例。示例不得包含当前检查点的人物、关键事实、玩家原话或目标回复，以免把答案直接塞给模型。示例属于独立虚构的写法教学，不进入当前故事事实。

六个检查点 × 三组为 18 次生成上限，无自动修订；两个独立评价配置各对六组隐藏来源、打乱顺序的三份正文进行比较，共最多 12 次评价调用，本轮合计上限 30 次。审查器校准、恢复和后续正式运行另有事先登记的额度，不能无名附加。此上限只约束未来研究，不构成本轮付费授权；所有失败原文保留。

首轮 P1 的增量注入用于隔离变量，不作为最终无限叠加提示的交付方式。有证据后才整理成一份不冲突的写作指令与按需语义约定，并复验；“把 Prompt 变长/变短”都不是目标。

**第三步：盲读正文，再检查为什么。**评阅者先只看允许公开的故事前提、真实前文、玩家输入和候选正文，回答：

- 这一段让我认识了怎样的人？指出哪一句、哪个动作，而非复述人设。
- 人物此刻为什么这样说，玩家的话是否真正改变了回应？
- 这一轮给出了什么有意味的内容，最值得读与最想删的地方分别在哪？
- 继续接话的意愿来自具体的人/事，还是只因为结尾抛了一个空问题？
- 如果片段已自然结束，是否有满足感；不要因不想继续加戏而判它失败。

先形成正文偏好与具体编辑诊断，再由独立环节核对事实和语义边界。看得到全部后台材料的正确性审查不能替读者“脑补”正文缺少的人物和戏剧内容。自动评价只是研发代理，遇分歧保留不确定，不宣称真实读者喜欢。

**第四步：按缺陷改一个地方。**语气同质，先改人物表达材料与对应示例；只答问题没人物，先改写作任务与人物立场；背景空洞，回制作；连续吊胃口，核对回报材料与本轮指令；写得好但加入错误事实，修材料地位和约定；相同输入不同尝试波动大，再研究模型/配置。每次保留相同输入和未见样本，最多两轮按 §10 裁决，不能不断追加“更精彩一点”。

**第五步：形成明确的实验裁决，再扩到连续片段。**P1 或 P2 若在六组中至少四组得到两份一致、有原文依据的偏好，且没有硬性越界或未解释的明显退化，可作为进入 E1 的写作候选。这只是小样选择，不是可靠率或整体内容通过。P0 已经写得好而新包无收益时，保留 P0，允许缩小重写范围。

三组都平庸或结果不确定时，先按具体缺陷有界修订；若证据指向模型、输出负担或选择阶段限制，可在原上限内预登记 E1 的诊断子集，不要求一个受限制的提示词先赢才能诊断其限制。无假设地扩大批次不允许；诊断结果不能代替 E2—E4 的内容通过。纯文本表达诊断须有独立只读合同及明确预算，不与正式候选互换分母或自动写回。

完整片段报告必须把原始聊天正文放在主要位置，状态轨迹作为诊断附件。每个已接受片段预先约定展示开场连续三次往返、末尾连续三次往返；不足三次时展示全部。还可另选一段较有分享价值的连续原文，但必须注明它经过挑选，并保留完整原文入口。不能只挑一句金句代表整段质量，不能删掉失败回合或把小说化润色后的文本当作聊天生成质量。

“愿意发到社交平台分享”是目标体验，应观察连续片段能否在少量必要前提下被读懂、人物有没有辨识度、有没有值得引用的表达或关系/故事回报。它不自动新增发布工具、不授权对外发帖，也不要求所有作品都出金句。公开反馈、真实分享率与付费意愿留在未来另行授权的商业研究；本轮不恢复已取消的真人评分。

## 10. 失败分类、修复额度与路线退出

### 10.1 失败处理表

| 失败 | 当次处理 | 修复/恢复 | 不能做什么 |
|---|---|---|---|
| 授权、余额、非重试型 4xx | 保存错误与用量，停止单元 | 原因解除后由明确的新授权开始 | 隐藏重发、偷偷换 provider |
| 请求结果未知/进程中断 | 保留原请求身份与 checkpoint | 查询/接收原结果或标未知；人工明确的新尝试单独计费 | 把超时当没调用，自动再发 |
| JSON/schema/输出截断 | 保留原文与准确错误路径 | 有已预留额度时一次定向修复及必要复核；否则等待明确操作 | 默默截断正文、补造事实、无限 repair |
| 背景空洞或人物同质 | 标记内容工件不合格 | 只重做相关人物/场景，保留作者修改及合格内容 | 提高审查分数或增加无关危机 |
| 通顺合规但没有阅读吸引力 | 保留正文，按 Q 记平庸，不进入内容通过 | 指出缺少人物立场、具体材料、潜台词、兑现或语言表现的准确位置，按 §9.8 只改相关 Prompt/材料 | 用完成目标、没有违规、降低调用数代替内容改善 |
| 单轮漂亮、连续聊天空洞 | 保留整段前后文及实际玩家输入 | 检查前文回应、内容回报和人物变化，回制作补实质材料或修回合承接 | 挑金句、删空转回合、额外润色后宣称聊天质量达标 |
| 角色重复/停滞 | 保存本轮视角、候选、审查与前后状态 | 判断缺内容、读取丢失、选择错误、误拒或后果未消费，再修对应层 | 统一归因为模型笨；每次再加一句提示 |
| 审查误拒/误放 | 保留两侧原文和依据，阻止不明候选正式采用 | 回校准集与具体反例；生成和审查分别改、分别测 | 删除约束让案例通过；评委重复到满意 |
| stale/并发作者编辑 | 拒绝采用，保留候选与新旧版本 | 展示差异、重新确认或明确重做 | 覆盖较新的作者编辑 |
| 正文采用成功、终验失败 | 保持已发生状态和原输出 | 补完原终验/回执，零新增生成调用 | 回滚正文后重生一份替代历史 |
| 调查/答复结算失败 | 保留已提交提问/动作及待结果状态 | 恢复同一待处理运行；新尝试单列 | 把角色问题当已获答案，撤销实际动作 |
| 图片/音频已保存、终验失败 | 保留原资产绑定 | 复用原字节、candidate、hash 终验 | 诱导再次生成才可展示 |
| 重要知识缺失或窗口超限 | 明确缺口及必读来源 | 精确检索/按职责拆分，仍超限则停止 | 静默裁剪秘密约束、关键对话或原文 |
| 生成泄密/替玩家决定 | 候选拒绝，记内容失败 | 修视角、合同或生成；保留反例 | 以“审查拦住了”把内容记为成功 |
| 已采用结果发生严重错误 | 停止受影响新版本继续扩散，保留数据与证据 | 定位影响范围；显式修正/新版本/兼容恢复 | 静默改写历史、批量迁移或删除存档 |
| 成本/时延超限 | 停止剩余派发，标未执行 | 优化已定位开销并新建协议版本 | 增加预算后追认旧批次通过 |
| 专业视听/多人不达标 | 保持已经验证的文本/单角色能力范围 | 独立修复该包 | 借其它能力通过宣称整个平台完成 |

### 10.2 每类质量问题最多两轮有界修订

每轮只改一个已提出的主要原因，先固定预测：改动应使哪一段原文或哪一类错误改变；保留原失败、同输入复验和未见样本。两轮仍未改善时暂停该实现路线的扩大，形成决策记录：

| 实验结果 | 下一条路线 |
|---|---|
| 换模型即可改善，组织方式差别不明显 | 收窄到已验证模型/配置，减少重写范围 |
| 新背景生产有效，回合合并无收益 | 采用新制作方式，保留经验证的分步回合 |
| 合并只适合普通交流 | 明确冻结普通/复杂场景路由，复杂路径保持有界，不运行时隐式试错 |
| 现有表示无法表达必要内容 | 用失败样例证明最小表示缺口，升级产品合同；不建立全产品万能故事状态 |
| 审查器无法稳定判断 | 暂停质量自动放行，先修评价；候选只供作者审阅，不宣称自动质量通过 |
| 三类题材仅部分成立 | 新版本明确限定支持范围；未通过题材继续研究，不抹掉原目标或修改旧分母 |
| 核心故事仍无稳定改善 | 保持辅助创作/人工可编辑的实验范围，停止扩展多人/视听/商业承诺，重新评估内容假设 |
| 内容提升但单位经济性不可接受 | 检查模型职责分配/缓存/批量制作等实测方案；不能以亏损未知的配置宣称商业可用 |

这里的暂停针对失败路线或工作包，不是停止所有架构整改或无关产品。新路线需新的明确方案、假设与预算；不继续累加提示版本并把次数当进展。

### 10.3 失败报告最小格式

固定记录：问题身份、版本/源码、内容配置、模型与调用身份、准确输入/输出、前态/候选/后态、判断依据、实际调用/用量/时间、失败类别、恢复状态、影响范围、修复假设和下一次实验差异。敏感原文和真实服务配置保存在仓库外；仓库仅保留脱敏摘要、hash 与可恢复索引。

统计分别列：计划单元、派发、制作成功、运行启动、生成拒绝、工程失败、内容不合格、不确定、未派发、内容通过。人工评分、工程成功与市场证据各自独立，不能换分母。

## 11. 发布、回退与商业边界

### 11.1 三个交付层级

| 层级 | 进入条件 | 明确承诺 |
|---|---|---|
| 隔离研究候选 | 相关 B 条件、注册评测入口与预算 | 用于比较，不进入作者现有数据，不公开默认入口 |
| 限定文本技术试用 | CC-00—08 的适用 H/Q/P/U 通过，支持的题材/模型/设备明确 | 可创作、试玩、修改、保存；保留实验性及实际能力限制 |
| 完整能力/商业候选 | 相关图片/声音/多人/派生包分别通过，且独立 C 证据成立 | 只承诺已验证组合；不能把一项通过推广到全部模型或题材 |

原私有作品与存档可读、可导出不等于可以在未验证的新核心中继续写入。对新版本发现严重问题时关闭其新建与新运行入口，提供原档读取/导出和明确恢复说明，不能通过回退程序删除较新数据。

### 11.2 商业质量需要补的实际证据

目标人群与价值、真实使用/继续使用、可接受等待、每份可用作品及每段会话成本、模型/媒资可用性、作品与声音权利、私密与公开边界、错误恢复与支持负担，均需在未来独立阶段取得证据。用量报价未知或依赖用户自备模型时，应按实际产品形式说明成本和使用门槛。

专业审听、真实玩家偏好和市场对照不由自动评审代替。此前取消的真人评分继续保持取消；本计划不重新打开旧 M4/M5 或要求当前用户提交评分。若未来决定面向公众发行，再单独授权和登记该阶段。

## 12. 排程与投入控制

研究与文档可在架构整改期间进行。实施从取得相关 B 以后按以下顺序交付：

1. CC-00/01 准备：明确范围与预算，写出 Prompt、完整材料、目标原文及反例；这部分可以在等待 B 时完成。
2. CC-02 最小接入 → CC-01 单轮实验：在相关 B 上复用或登记隔离研究入口，展开实际请求并做 §9.8 比较，先回答具体写法怎样影响内容。
3. CC-02 候选合同 → CC-03/04 小型原型：按已选写作包或有限诊断假设接入故事制作与角色表达；不先完成整套工作台，调用合并围绕内容结果裁决。
4. CC-05/06：逐阶段比较与完整片段验证；相同问题两轮失败执行路线裁决。
5. CC-07/08：随实现完成兼容恢复，最终合成连续创作交付。
6. CC-09—12：按已验证价值与独立预算扩展，不由“单角色工程通过”自动启动。

不在 B 和首轮对照未知时承诺总日历工期。CC-00 给出任务依赖和资源估算；CC-05 后依据通过/失败单元、每轮实际时长与明确剩余合同增量更新区间。实现工时、模型等待、独立复审和外部依赖分别估计，不使用提交数或未经验证的完成百分比。

每个单元交付卡至少包括：范围、owner、依赖 SHA、入口到下游闭包、已变更文件、正反例、工程/模型/内容/商业状态、未解决问题、下一责任范围。共享热点有单一写入者，测试与模型任务控制并发，不污染作者浏览器或其它工作树。
