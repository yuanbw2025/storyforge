# 系统文长篇写作质量优化施工方案

> 版本：1.0.0 · 更新：2026-10-13 · 权威层级：L2
> 对应总纲：§4.1、§4.2、阶段 B · 专项 ID：`B-LF-Q`
> 上位契约：[分步骤长篇与节点模式](../products/LONGFORM-AND-NODE.md)

本专项先改善系统文开篇和连续十章的故事质量。作者选择或修改题材、主角、系统机制、奖励、限制与对抗力量，共用长篇流程把这些元素组织成人物选择、情节因果和阶段兑现。通用技法可以复用，元素变化必须同时改变冲突与成长路径。

第一期交付是可操作、可恢复、可比较的十章写作闭环。是否更好读，由真实文本、目标读者盲评和作者修稿负担判断；平台签约、长期留存和收入需要另有实际结果。十章是本专项的内部验证单位，不是番茄或起点的签约字数要求。

## 3 写作流程与用户操作

作者的主要路径：

```text
选择题材与系统元素
→ 确认人物目标、核心冲突与系统规则
→ 确认本阶段要推进和兑现的事情
→ 卷纲与章纲
→ 章节任务和场景细纲
→ 生成或手写正文候选
→ 全章评审并选择需要修改的问题
→ 定向修订和复核
→ 作者采纳
→ 根据真实正文整理状态并准备下一章
```

这是一条推荐路径。作者仍可留白、自由选写、手动修改或跳过质量建议；缺少某项研究卡不阻止既有合法创作。正式动作自身所需的真实目标、作用域、版本和信息边界继续校验。

### 3.1 用户修改的元素

界面先提供六组常用选择，高级规则按需展开。留白部分可以先产生候选，确认后再进入正式作品。

| 元素 | 用户填写示例 | 系统据此调整什么 |
|---|---|---|
| 题材与阅读感受 | 都市经营，轻松但有竞争 | 冲突类型、表达、节奏与读者期待 |
| 主角处境与目标 | 小店即将关门，想保住父亲留下的店 | 行动动机、失败后果与代入点 |
| 系统机制 | 根据真实顾客反馈改进产品 | 能力触发条件与解决问题的方式 |
| 奖励与成长 | 解锁配方、增加产能、获得认可 | 阶段兑现与未来能力证明 |
| 限制与代价 | 预算、材料、时间、信用限制 | 人物选择、资源取舍与公平性 |
| 对抗力量与人物关系 | 强势竞争店铺、分歧中的合伙人 | 对手策略、关系变化与后续冲突 |

规则不要求每种系统都用倒计时、惩罚、打脸或数值面板。签到、经营、任务、抽取等机制以作者设定为准。修改元素后重新检查未来计划；已经确认的历史正文不被后台改写。

### 3.2 章纲与细纲的分工

- 卷纲确定阶段目标、主要冲突、重要转折与阶段结局。
- 章纲确定本章发生什么、推进什么、进入与退出状态。
- 细纲确定人物如何尝试、遭遇怎样的阻力、做什么选择、产生什么后果，以及各场景应分配的笔墨。
- 正文将场景任务写成具体行动、对白、感受与变化。

细纲页面继续独立存在。章纲提供“编辑本章细纲”，细纲提供“写本章正文”，正文提供“查看本章细纲”。跳转必须携带同一作品和章纲节点身份，并先保存当前编辑；没有已保存正文时进入对应的创建流程。

## 4 技法研究与转成写作任务

先比较公开写作材料、作者经验和经授权文本中的实际作用，再形成适用条件明确的技法卡。每张卡记录适用场景、输入、处理方法、输出、检查问题、原创正反例和限制；同一作品可以选择不同策略。

| 技法主题 | 写作任务与检查方式 | 公开依据 |
|---|---|---|
| 欲望与代入 | 用可观察的处境建立目标；检查主角为什么现在行动、读者为何关心结果 | [番茄开篇课程上篇](https://fanqienovel.com/writer/zone/article/7480087779494346776) |
| 期待与兑现 | 记录已建立的阅读期待、本阶段兑现及新问题；检查奖励是否改变处境 | [番茄开篇课程下篇](https://fanqienovel.com/writer/zone/article/7480089164512247832) |
| 因果与主动选择 | 补足尝试、阻力、选择、结果和余波；检查主角的行动是否影响结果 | [番茄情节与节奏课程](https://fanqienovel.com/writer/zone/article/7625862983972831257) |
| 规则与成长 | 将限制、资源、奖励落实到具体选择；检查能力变化和挑战变化是否相配 | 前述情节课程及[长篇防疲软课程](https://fanqienovel.com/writer/zone/article/7673406206286757950)，具体系统机制由本专项实验校准 |
| 人物与声音 | 给主配角各自的欲望、立场和阶段变化；检查是否只是围观或称赞主角 | [番茄人物课程](https://fanqienovel.com/writer/zone/article/7612544314719076376) |
| 节奏与冲突变化 | 给场景确定功能，安排冲突、释放与余波；检查连续剧情是否重复同一种获胜过程 | [长篇防疲软课程](https://fanqienovel.com/writer/zone/article/7673406206286757950)与[起点作者创作总结](https://www.qidian.com/chapter/1010868264/516065132/) |
| 文笔与修订 | 保留事实、视角和人物声音，减少低功能重复，补足关键过程 | 情节与节奏课程及现有[工坊内容研究](../audits/NOVEL-PROMPT-CRAFT-20260927.md) |

这些材料提供写作经验和问题分类，不保证某个模板能通过平台评估。开篇课程有偏女频的适用说明，起点创作总结是个别作者经验；两者都需经过系统文样本校准。平台质量参考采用[番茄公开签约评估说明](https://fanqienovel.com/writer/zone/help/article?rank1=10189&rank2=10191&rank3=0)，不推断起点未公开的编辑评分或推荐算法。

技法库采用原创示例和抽象方法，不复制商业小说情节或要求模仿特定在世作者。已有模板先做选择与修订；固定“每章必有同一种奖励”“每次升级必须同一种反应”等规则需要按场景功能检查，避免制造重复。

### 4.1 共用方法与元素变化的原创示例

共用方法是“主角有具体目标，能力提供部分机会，限制迫使人物选择，选择带来兑现与后果”。下表只展示工作方法，具体情节仍由作品资料和作者决定。

| 题材样本 | 系统机会与限制 | 主角选择 | 兑现与后果 |
|---|---|---|---|
| 都市经营 | 能发现顾客反馈中的问题，但无法凭空提供原料 | 在临时大订单和常客承诺之间分配有限产能 | 获得信任，同时暴露资金周转问题 |
| 修仙成长 | 能识别功法缺陷，但验证需要稀缺材料 | 决定先验证自己的推断还是抢先公开 | 获得可信的能力证明，同时引来对手的新策略 |
| 末日生存 | 能估算物资风险，但观测范围有限 | 根据不完整信息选择补给路线和合作对象 | 化解当前短缺，同时改变团队信任与下一段风险 |

复用的是选择与因果关系，替换元素后重新推导条件与后果。系统输出、旁观反应和等级变化不能单独证明故事推进。

### Q01 固定样本和验收基线

**目标：**确认质量问题能重复观察，并为后续改动保留公平对照。

1. 准备都市经营、修仙成长、末日生存三个原创系统文设定，每个规划连续十章；样本选择用于覆盖不同冲突，不宣称热门程度排名。
2. 每个设定保存同一初始作品意图、系统规则、人物目标、当前事实、输出长度范围和作者选择规则。保留真实用户失败样例时先确认使用范围，默认留在本地。
3. 使用现版正式入口记录模型和模板版本、有效参数、上下文窗口、输入输出、使用量、时延和失败结果；不会拿模拟响应当现版文学基线。
4. 标记开篇代入、人物主动选择、因果、兑现、重复、声线和连续性问题；Q01 开发分析不填写真人评分，实际作者修稿内容与耗时在 Q10 取得。
5. 在新方案实验前冻结量表、比较方法、调用记录口径与停止条件，见第 8 节。用户已取消 Agnes 本专项总调用/token 封顶；固定样本范围、正式单 Run 合同和有限重试继续生效。

**完成条件：**三个可恢复的样本作品、30 章基线文本、可追溯请求和一份逐项问题清单齐备。外部模型尚未运行时标记“实验未完成”。

**代码关联：**现有正文 Skill、durable Run、评测协议和长篇 E2E；本单元先定义正文实验适配范围，不更改生成默认值。

### Q02 将技法研究转成写作任务

**目标：**让方法直接指导计划、正文和改稿，避免只堆写作口号。

1. 对第 4 节七类主题形成技法卡，每张包括适用条件、输入、输出与检查问题。
2. 为每类至少写两个原创正例和两个反例，补充缓冲章、低冲突日常、签到奖励、强主角等边界案例。
3. 映射现有章节任务单、场景卡、成长审计和局部修订模板，明确保留、修订及缺失内容；模板数量不作为完成目标。
4. 说明每条建议怎样调整人物目标、章纲、细纲或正文，并用小样本检查能否产生可观察的变化。
5. 将经过校准的方法形成版本化策略，不强制每一章使用同一种结构。

Q01 已取得的优先反例为：卖完声明与存货冲突、余额透支、充电收益早于过程、每日合作上限被翻倍，以及末章未兑现阶段任务。终止条件的范围与合理调整保留为作者判断案例。技法卡应先说明如何改变目标、选择、行动和可见收益；人物对白与说明腔需要另外校准。详见 [基线问题与施工优先级](../audits/SYSTEM-FICTION-Q01-BASELINE.md#102-后续施工优先级)。

**完成条件：**七类技法卡、至少 28 个原创正反例、边界案例、阶段映射与实验记录通过复核。仍不清楚是否有效的方法留作可选实验项。

### Q03 元素配置与作品写作合同

**目标：**作者修改少量元素后，得到有根据的故事方案和稳定的本次运行约束。

1. 提供第 3.1 节六组常用元素，保留自然语言补充和高级编辑；有已有作品时先展示实际资料。
2. 元素生成先产生候选，作者确认后落入已有作品资料。题材、简介和文风身份留在 Work；人物目标、冲突和机制分别使用对应故事、角色、设定与创作规则字段。
3. 选择题材包不自动切换全局激活模板。每次 Run 冻结实际选择、规则来源、模型预算与版本。
4. 写作合同由已确认资料形成运行快照，不复制第二份 Canon。奖励、任务进度和成长变化区分计划、候选与实际已发生事实；只有已确认事实进入后续正式状态。
5. 冻结逐字段的读写与 owner 对照。现有字段无法承载的最小结构增量，先补类型、AdoptionSchema、FIELD_REGISTRY 和生命周期，再接界面；不建全产品配置表或游戏运行状态表。

**完成条件：**六组元素可编辑、可恢复；空白起步、已有作品、冲突资料、修改规则及用户模板保留均通过。运行快照可追溯到实际资料，计划奖励不会被当成已有物品。

**主要落点：**作品概况、故事与创作规则入口、`genre-metadata.ts`、Prompt 选择、Skill 输入合同和三注册表。

### Q04 细纲结构和连续操作

**目标：**作者能操作“这一章怎样写”，并在章纲、细纲、正文之间准确切换。

1. 复用 DetailedOutlinePanel 与现有章节身份，增加第 3.2 节的双向跳转；执行前先保存当前输入，切换作品不能沿用旧章目标。
2. 在既有 `DetailedScene` 结构内设计可选的进入状态、目标、关键选择、后果与退出状态；概要、冲突、节奏、预计字数、备注继续保留。读者期待与阶段兑现先随本章任务表达。
3. 将目标和变化检查作为规划建议；作者可以留白、写缓冲场景或明确豁免，不把统一场景公式变成强制通关。
4. 状态区分未规划、有待确认候选、已保存细纲、上游变化待复核。“存在一条空记录”不能显示为细纲已完成。
5. 新字段缺失时按旧细纲读取，保留场景顺序和 sceneId；AI 不后台补写历史记录。必要的 schema 与导入合同变更先做兼容、往返和错误数据测试。

**完成条件：**对应章节跳转、人工编辑、AI 候选、拒绝与采纳、刷新恢复、旧备份、跨作品隔离和窄屏操作通过；旧记录不会丢场景、备注或引用。

**主要落点：**`DetailedOutlinePanel`、`DetailedSceneCard`、`OutlinePanel`、`ChapterEditor`、`WorkspacePage`、细纲类型/store、正式细纲 Skill 与 Adoption。

### Q05 上下文交接与预算

**目标：**实际正文请求能读到作者确认的写作任务，评审知道哪些信息确实被读取。

1. 核对登记的 `detailedOutline` 与正式 Gateway 读取；保留已进入请求的节奏、预计字数和备注，补齐新增任务字段及有证据的资料缺口，按当前作品、世界组和章纲节点解析。
2. 通过既有 Gateway 选择本章规则、人物、前章真实交接、相关奖励状态、已登记伏笔和作者认可的文风资料。
3. 合同、manifest 与最终请求保持一致；正文 adapter 不再自行丢弃已经声明读取的核心任务。必要压缩由预算层记录保留、裁剪和遗漏。
4. 必需信息装不下时显示缺口并停止该正式请求或采用明确的分段方案，不能静默截断再声称完整写作。
5. 核对连续性保护块中要求所有动作在前 40% 落实的现行提示，按章纲规定的事件次序改为合适的执行要求；后段兑现、缓冲与悬念保留有反例。

**完成条件：**真实请求包含预期任务；小窗口、长备注、后段重点、规则更新、未来泄漏、错世界及 stale 均有正反例。正文生成与评审使用正确版本，不凭界面显示判定参数或资料已生效。

**主要落点：**`context-sources.ts`、`prose/gateway-context.ts`、`chapter-adapter.ts`、Gateway/Skill binding 与相关上下文回归。

### Q06 正文生成与文风控制

**目标：**正文完成具体场景任务，人物行动和奖励兑现有过程，表达适合当前作品。

1. 用本章任务、场景顺序、人物立场、系统边界、停笔事件与篇幅范围指导共用正文动作。
2. 第一版优先保留单章调用。仅在长度或可控性实验支持时增加场景分段；分段需共享冻结任务、接续证据和整章预算。
3. 开篇着重人物处境、行动与本书核心吸引点；后续章节按自身功能配置，不重复套用开篇模板。
4. 使用作者确认的文风画像或自有样稿特征，尊重用户 Prompt 和参数。去 AI 味关注重复解释、空泛情绪、同腔对白与无功能细节，不输出未经校准的 AI 概率。
5. 保存初稿、有效模型参数、候选版本和编辑记录。处理篇幅不足、截断、取消或结果未知，不能自动重发或把摘要冒充完整正文。

**完成条件：**开篇、行动、对白、兑现、缓冲与停笔案例通过定向检验；分步骤与节点执行同一领域动作，作者要求及实际参数可以回查。

**主要落点：**正文 adapter、现有章节/场景模板、prose Skill、正文候选、参数路由与节点领域 action。

### Q07 全章评审与问题定位

**目标：**读完整章，指出可以理解和处理的问题，覆盖章节结尾与关键兑现。

1. 移除当前“只看前 4000 字”的隐式评估边界，使用整章或有实际覆盖清单的分段评审；分段加整章汇总共同受预算约束。
2. 评审维度包括开篇代入、人物主动选择、因果、系统规则与兑现、声线、重复、节奏和章际连续性；必要缓冲与有意留白不自动判错。
3. 每个问题绑定候选文本 hash、实际引文、位置、影响、建议和不确定性。代码校验引文真实存在，失效或猜测不得伪装确证问题。
4. 事实冲突继续按既有证据型审修和信息边界处置；阅读质量建议单独标识，不凭偏好或模型分数阻断正式采纳。
5. 保存 reviewer 模型、版本和覆盖证据。同模型评审标明相关性；独立模型评估只辅助筛查，文学认证仍由人完成。

**完成条件：**只在章末出现的问题、跨段重复、长章、无法装入预算、伪造引文、角色有意隐瞒及评分虚高均有反例。覆盖不足时报告不能显示整章已评审。

**主要落点：**`ReviewPanel`、review/readability adapter、证据型语义评审、AI 入口登记及 durable 审查快照。

### Q08 定向修订与复核

**目标：**作者选中的问题得到解决，未授权的情节和事实得到保护。

1. 在已有候选审修机制上增加作者选择问题与可改范围，展示修订前后文本。
2. 本轮冻结问题、原稿版本、受保护事实、目标章节、停笔要求与预算。原稿或上游资料变化后旧修订失效。
3. 一轮最多初审、一次定向修订、一次复核；连同初稿最多四次模型调用。分段模式按预先冻结的整章调用上限执行，不乘上隐藏重试。
4. 复核检查原问题是否改善及是否引入新问题。仍未解决时交给作者决定，禁止循环生成追求某个分数。
5. 默认由作者决定是否启用本轮审修。事实硬规则保持原权限；建议修订不自动覆盖手稿，最终仍经 CreativeArtifact 与 adopt。

**完成条件：**修订只写指定章节；问题解决、误伤、作者取消、断网、预算耗尽、刷新恢复、重复采纳和旧版本拒绝均通过。能回读初稿、修订稿、审查与作者决定。

**主要落点：**`prose-semantic-review.ts`、`prose-semantic-durable.ts`、`prose-generation-durable.ts`、正文 UI、Skill/Run Contract、候选采纳与节点恢复。

### Q09 连续十章与跨模式验证

**目标：**新流程在连续创作、修改和恢复中保持可用。

1. 在隔离数据中完成三个样本各十章的完整路径，阶段性核对任务、能力、奖励、关系与伏笔。
2. 分步骤和节点分别覆盖元素读取、细纲、正文、评审、修订和采纳；两种模式回读同一作品、同一字段与同一版本。
3. 验证后段修改、规则修订、角色状态变化、单章重写和未来影响；已确认历史不被静默同步。
4. 完成备份导入往返、删除隔离、stale、跨标签页执行、保存失败、断网与刷新恢复。测试项目与作者当前浏览器数据隔离。
5. 新结构的 schema、三注册表和生命周期验证在对应实现单元完成；此处验证整条用户旅程，不能用 Git 无冲突替代语义检查。

**完成条件：**三条十章流程及跨模式证据齐全，必要 CI/E2E 通过。模拟模型只证明流程；真实文本进入 Q10 后才判断文学提升。

**主要落点：**既有 `longform-step-quality`、`longform-node-experience` E2E、相关领域回归和新增十章实验适配。

### Q10 真人盲评与版本交付

**目标：**确认质量和修稿负担的收益，并如实确定可发布的范围。

1. 按第 8 节冻结的新旧对照执行，保留失败和持平案例；不能只选最好看的样章。
2. 邀请至少三位对应题材读者或编辑独立盲评，记录偏好、具体理由和弃读位置；参与实现者的评价另列。
3. 记录作者把候选改到可接受文本的时间、改动范围和问题类型，同时报告实际调用、token、时延与费用来源。
4. 再用不同模型与未参与调参的原创设定抽测。收益仅在部分题材或模型成立时，交付说明限定到相应范围。
5. 按实际问题修复、复评；工程与文学证据分别满足后更新用户指南、能力边界和版本记录，经项目协作流程交付。

**完成条件：**盲评、修稿和预算报告齐全，结果达到预先冻结标准，没有未解决的确定性 blocker。平台评估和读者市场表现单独跟踪，缺少结果时不宣称达到签约或商业标准。

## 7 数据与工程实现合同

本期优先复用既有表和动作。下列映射是实施约束；新增字段与 schema 方案须在 Q03、Q04 的合同中明确后才修改代码。

| 信息 | 权威与读取 | 写入与生命周期 |
|---|---|---|
| 作品题材、简介、文风身份 | Work 与既有注册读取 | 原 Work 字段；禁止镜像到 Project |
| 人物目标、核心冲突、系统规则 | 对应故事、角色、设定、creativeRules 的已确认资料，经 Gateway 获取 | 对应既有领域 Skill 与注册字段，候选确认后写入；不在组件散写 |
| 卷章目标与阶段计划 | outlineNodes 与故事线来源 | 既有章纲动作、版本及采纳，计划不冒充已发生事实 |
| 场景任务 | `detailedOutlines.scenes` 与 `detailedOutline` 源 | 最小可选结构扩展，类型、schema、Adoption、导入校验同源；保留旧字段和 sceneId |
| 已发生的奖励与状态 | 已采纳正文、现有事实/物品/故事线来源及章后对账 | 原章后候选确认链；新增谓词或引用须先登记与验证 |
| 正文 | chapters 与登记的正文来源 | 原 prose Skill 写 `content`/`wordCount`，原 adopt、版本与后续影响链 |
| 写作合同与审修证据 | 当前 Run 的 contract、manifest、候选 hash 与审查输出 | 既有 durable 存储与项目生命周期；不另造平行生成或记忆表 |

正式 prose/detail Skill 当前以登记的 `ragSelection`/Gateway 解析资源，不能在组件手工追加另一套来源清单。新增源、AI 可写字段和表分别进入 CONTEXT_SOURCES、FIELD_REGISTRY/AdoptionSchema、PROJECT_TABLES。新引用必须验证备份重映射和删除；不需要新增表时保持现有生命周期。

公开技法包与作者作品数据分开。策略版本可复现，作品事实只以作者确认版本为准；升级不能切换用户全局模板或改写历史稿件。收口旧截断评审入口时直接升级原 adapter，不能保留两个相互矛盾的“整章评审”。

## 8 实验与完成判据

### 8.1 两类对照

**单章对照：**固定同一份作者确认的前文、规则、章纲、细纲、长度和模型，对比现版与新流程。用于判断任务交接、生成和审修各自的作用。

**十章对照：**从同一初始设定、模型和作者选择规则分别运行现版与新流程，各自根据实际采纳正文推进。后续上下文允许随故事分化，不能用单章实验的“输入完全相同”解释连载结果。

调参先用小样本；正式评测前冻结新策略，并增加未参与调参的原创场景。按作品和题材分组报告，30 章来自三个作品，不把章节或多个评审票当成大量独立作品。

### 8.2 人工评价与预算

量表使用 1 至 5 分，并配实际文本锚点：1 为明显妨碍阅读，3 为可读但需要具体修订，5 为当前目标下表现充分。评价开篇代入、因果与主动选择、情绪兑现、人物声音、节奏与重复、连续性；同时记录“更愿意继续读哪版”和原文理由。

Q01 可采用以下首轮目标，在正式实验前结合基线校准并冻结；它们是内部目标，不是平台门槛：

- 30 组成对章节中，至少 20 组获得多数评审对新版的偏好；持平不算新版胜出，各题材至少 6 / 10 组偏好新版。
- 作者修稿时间的中位数较现版降低至少 20%，修稿目标和质量标准保持一致；保留离群和返工案例。
- 受保护事实、目标章节、权限和版本的确定性反例零回归；人物动机与一般语义矛盾仍需人工复核，不能宣称零漏检。
- 报告全部实际调用、使用量及平均和较慢请求的时延；免费或收费取自已确认来源。用户已取消 Agnes 本专项总调用/token 封顶；其他提供商的费用和预算须另行确定。实际支付无账单时保留为空，不把估算标成实际支付。

文字重复率、字数、模型评分可辅助定位问题。验收不能单独依赖某个分数、词频或 AI 检测器。

若质量优势不足，优先分析是哪类问题改善、哪类退步，修订 Q02、Q05、Q06 或 Q08 后使用新版本复测。若只靠更昂贵模型获得优势，应如实归因并给出成本选择。

### 8.3 工程验证与后续发布

代码实施按风险递增验证：先定向回归；涉及结构与引用时做旧数据、损坏数据、跨作品、备份往返与删除反例；涉及真实入口时在隔离浏览器验证。交付单元遵守 AGENTS 和工程质量标准，完成架构、表、AI 手册/入口、类型、相关测试、构建、`npm run ci` 与适用的 `npm run ci:e2e`，提交前 `git diff --check`。

方案初版只执行文档权威、路线图、链接与内容一致性检查。Q01 的配套采纳修复按上述工程门交付。工程门通过、真人质量通过、PR 合并和上线分别有自己的证据；实验样本在隔离浏览器中运行。

## 9 更新和交付记录

每次更新保留固定 ID、依赖和完成标准，在第 6 节填入提交/PR、定向验证及尚未完成的文学证据。不能将“做了界面”“完成代码”或“一次生成满意”直接标成整个单元 DONE。

本专项分支按单元或可解释的里程碑交付。schema、三注册表与共享 AI 热点先形成独立基础提交并串行集成；分步骤和节点随后验证同源调用。纯研究与方案更新保持文档范围，未授权时不启动作品生产、付费实验、发布或模型训练。
