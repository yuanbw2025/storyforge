# StoryForge 写作学院建设方案

> 版本：0.2.0 · 日期：2026-11-27 · 文档定位：L2 建设方案，记录已确认方向与建设设计。逐项施工使用 [首版施工方案](./WRITING-ACADEMY-IMPLEMENTATION-PLAN.md)。首发数量和排期为工作预算，完成状态以实际交付证据更新。

写作学院使用 `academy.storyforge-lab.com`，以中国网文创作经验为特色，为中英文写作者提供方法、作品分析、原创示例、练习和可填写模板。用户既能按路线学习，也能带着具体问题查找资料，最终把学到的方法用于自己的故事，并在需要时进入 StoryForge 创作。

建设先形成一个可重复的内容生产单元，再扩大搜集和出版规模：**一个写作问题 → 一篇教程 → 一组有出处的案例分析 → 一份原创示例 → 一份模板与练习 → 一个真实可用的创作入口。**

## 1 产品定位与职责

### 1.1 已确定的方向

- 名称：StoryForge 写作学院，英文工作名为 StoryForge Writing Academy。
- 域名：`academy.storyforge-lab.com`。
- 官网入口：“写作学院 / Writing Academy”，学院正式可访问后接通。
- 服务对象：希望学习中国网文方法的海外写作者，以及中文新手和已有创作经验的作者。
- 分支范围：本聊天负责写作学院、创意工坊、插件市场及相关作品集议题；当前优先完成学院规划。
- 用户目标：找到方法、看懂案例、完成练习、带走模板并开始自己的作品。

| 入口 | 主要职责 | 与学院的连接 |

## 2 用户与学习路径

| 用户 | 主要困难 | 推荐入口 | 学习结果 |
|---|---|---|---|
| 初学者 | 有想法但不知道如何开始 | 从零开始路线 | 一句话故事、主角目标与第一章草稿 |
| 连载作者 | 开头平淡、中期重复、伏笔失控 | 按问题检索 | 对已有故事形成具体修改方案 |
| 海外类型作者 | 不熟悉中国网文概念和文化背景 | 类型指南与中英术语 | 将方法用于自己的文化、世界与人物 |
| 方法型作者 | 想快速建立可持续写作结构 | 模板库 | 一份经过自己填写的故事设计表 |

两条首发路线建议如下：

1. **从想法到前三章**：读者期待 → 一句话故事 → 主角目标 → 开篇冲突 → 信息释放 → 章节推进与钩子 → 原创练习。
2. **搭建可持续的成长故事**：长期目标 → 能力边界 → 获取代价 → 奖励与后果 → 阶段性对手 → 故事篇章升级 → 中期变化。

每一步明确先修知识、预计阅读与练习时长、要完成的产物、下一步和可选延伸。阅读进度和完成练习分别记录；滚动到底不等于学会。

## 3 资料来源与搜集方法

### 3.1 来源分层

| 来源 | 搜集对象 | 主要用途 | 复核重点 |
|---|---|---|---|
| 官方写作课程 | 平台编辑课、品类指南、作者课堂 | 网文创作经验与选题线索 | 区分写作方法和当期平台签约要求 |
| 作者直接表达 | 本人访谈、公开演讲、创作谈 | 了解具体作者的方法与背景 | 核对作者身份、日期、原始发表处 |
| 合法获得的原作 | 正版连载、授权电子书、纸书 | 建立有章节证据的拆书分析 | 固定版本、范围与定位，不以二手梗概代替阅读 |
| 英语写作教学 | 作者本人课程、写作教育机构 | 对照术语、练习和教学表达 | 记录不同写作传统的差异 |
| 连载平台公开资料 | 帮助中心、作者规则、公开分类 | 理解目标平台和读者问题 | 平台规则标注日期并定期复核 |
| 读者与作者讨论 | 社区提问、评论、经验帖 | 发现真实困难和选题 | 观点作为线索，效果结论另找证据 |

首轮以官方页面和作者原始表达为主。转载站、无出处合集和搜索摘要只帮助发现线索，进入研究卡前回到原始出处。平台课程也代表特定人群和经营模式，整理时保留其适用背景。

### 3.3 搜集按问题立项

每批先确定 10～15 个具体问题，再围绕问题检索。示例：

| 主题 | 中文检索词 | 英文检索词 |
|---|---|---|
| 开篇 | 开篇、黄金三章、代入感、切入点、读者期待 | opening hook, opening promise, first chapter |
| 成长 | 升级、境界、资源、代价、战力膨胀 | progression arc, power scaling, costs and limits |
| 系统 | 系统文、任务、奖励、约束、金手指 | system mechanics, quest design, reward loop |
| 连载 | 章末钩子、追更、篇章节奏、中期卡文 | chapter hook, serial pacing, middle slump |
| 人物 | 动机、关系、对手、人物成长 | character motivation, relationship arc, antagonist |

可使用 `site:fanqienovel.com/writer/zone/ 开篇 期待感`、`site:chinawriter.com.cn 访谈 创作` 等范围检索。搜集记录应写下检索词、时间、筛选理由和缺口，方便补搜与去重。

资料采集采用站点允许的 API、正常网页访问、人工阅读与合法取得的出版物。自动采集先检查访问规则、频率和使用条件；登录或付费内容使用正常授权访问，不绕过限制。

### 3.4 来源记录与研究卡

**来源记录**保存：稳定编号、标题、作者或讲师、发布者、原始地址、原始发表处、发表与访问日期、语言、资料类型、正文是否已读、可访问性、主题标签、权利状态、允许的使用方式，以及编辑备注。私有取证文件使用内部存储引用，公开页面只显示适合公开的书目信息与链接。

**研究卡**保存：一个待解释的问题、来源主张、精确定位、编辑的解释、支持或冲突的其他来源、适用条件、反例、可设计的原创练习、关联教程与审核人。来源主张、编辑推断和原创示例分别标识。

同一观点的多个转载版本合并到原始来源；同一作品的不同版本分别记录。冲突观点并列解释适用条件，例如快节奏开局与渐进式悬念各自如何建立阅读期待。

来源记录、研究卡、公开文章使用不同编号并通过关联连接，避免将研究资料直接当成成品页面发布。

### 3.5 首轮搜集与维护目标

建议先登记 80～120 条候选来源，精读核验其中 30～40 条，形成 20～30 张研究卡，支持第 9 节的首发内容。数量是工作预算；正文访问不足、无法定位或重复的材料不计入已核验。

按主题建立缺口表。平台政策与课程入口每月检查，核心写作内容每季度复核；来源失效时保留书目信息和访问日期，寻找原作者的新地址。变更影响到具体论断时，更新关联教程和译文。

## 4 从资料到公开内容

### 4.1 编辑流程

```mermaid
flowchart LR
  A[确定写作问题] --> B[检索与来源登记]
  B --> C[精读与研究卡]
  C --> D[交叉比较与选题]
  D --> E[原创教程与示例]
  E --> F[模板与练习试用]
  F --> G[事实复核与中英审校]
  G --> H[预览与发布]
  H --> I[读者反馈与版本修订]
  I --> C
```

选题立项时先写出学习目标和要交付的练习产物。资料不足则补搜或缩小论题。初稿完成后检查每个可核实的论断是否能回到来源；编辑的分析以分析口吻表达，作者创作意图仅在有作者直接表达时引用。

AI 可辅助发现资料、去重、初步分类、提出研究问题、整理草稿和翻译候选。原文事实、章节定位、引文、解释质量和发布决定由编辑复核。AI 输出先保存为候选；内容源更新须有审阅和版本记录。实际调用模型时另按仓库外 API 配置与预算执行。

### 4.2 教程统一结构

一篇教程围绕一个能回答的问题组织：

1. 谁适合读、遇到了什么困难、学完能做出什么。
2. 方法及其产生效果的原因。
3. 分步操作和决策问题。
4. 带出处的作品案例或作者经验。
5. 原创正例与反例，并解释差别。
6. 适用条件、局限和替代选择。
7. 可完成的练习、模板和自查清单。
8. 相关课程、拆书、模板与资料来源。

阅读时长、难度和先修内容来自编辑估算并可修订。教程篇幅由任务决定，避免把多个独立问题堆进长文。

### 4.3 拆书的制作标准

拆书分为开篇细读、单一机制分析、故事篇章分析和全书结构研究。页面显示书名、作者、具体版本、实际阅读范围、剧透级别和分析者；只读开篇就以开篇分析发布。

建议观察：读者期待、主角目标、冲突与选择、信息释放、能力限制、代价、情绪变化、关系变化、伏笔回收，以及这些因素如何跨章节推进。以“具体事件 → 叙事作用 → 编辑解释 → 可迁移的写作问题”组织，分析结论能回到章节或页码。

首批候选为《斗破苍穹》的开篇期待与身份冲突、《凡人修仙传》的成长资源与代价、《诡秘之主》的信息披露与谜团组织、《全职高手》的能力展示与团队关系。它们是选题候选；编辑取得对应版本、确定阅读范围后再立项。后续补充言情、悬疑和现实题材，保持方法与读者需要的覆盖。

全书研究须有全书阅读记录；分析中的情节概括、章节定位和引文逐项核对。模板提取一般结构，使用独立的人物、世界和事件设计。页面以合法原作阅读链接供读者延伸阅读。

### 4.4 模板与练习的制作标准

每份模板包含目标、适用人群、必填与选填项、填写指导、原创填好示例、自查问题、可选变体、关联方法和版本。模板以问题帮助作者决策，保留作者修改、删除和偏离结构的自由。

模板的首版交付为在线填写、复制和 Markdown 下载。填写内容在设备上保存，提供清空与导出；刷新恢复要明确，浏览器存储可能丢失的情况下可手动下载备份。结构化 JSON 仅用于有明确版本与用途的模板包，不宣称现有 StoryForge 已支持导入。

练习提供任务、限制条件、预期产物和评价维度；示范答案展示一种选择，不作为唯一答案。初期采用作者自查，后续再评估同伴反馈或指导服务。

### 4.5 资料再利用与出版

公开教程以编辑自己的分析、组织、原创示例和练习为主体。第三方原文、图片、封面、课程录音和译文分别确认使用条件；合法购买、可以浏览或注明出处，都不自动构成公开转载许可。

需要较多引用、完整翻译、转载或课程改编时，记录具体权利人与授权范围。对于开放许可，按该许可处理署名、许可链接、修改说明及其他条件；例如 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 明确规定相应署名与修改说明要求。

引文逐项登记用途、来源、位置与使用判断。各地区的规则需要分别考虑；美国版权局也说明不存在按固定字数或比例自动成立的合理使用规则，因此系统中的长度提醒只能辅助编辑，不能替代具体判断。[美国版权局说明](https://www.copyright.gov/help/faq/faq-fairuse.html)

建立来源更正、权利联系、撤下与修订流程。受影响内容可以先撤下该段或页面，并同步搜索索引和缓存，保留内部处理记录。原始受保护书稿和付费课程文件留在有适当权限的研究环境，不进入公共仓库或站点构建。

## 5 内容分类与关联

### 5.1 内容形式

| 类型 | 回答的问题 | 推荐关联 |
|---|---|---|
| 学习路线 | 我应该按什么顺序学 | 教程、练习、阶段产物 |
| 写作教程 | 这个问题怎么解决 | 案例、模板、术语 |
| 类型指南 | 这一类故事如何组织 | 核心机制、常见问题、案例、路线 |
| 作品拆解 | 具体作品如何产生效果 | 章节证据、写作方法、练习 |
| 创作模板 | 我该填写和决定什么 | 教程、填好示例、自查项 |
| 练习与示例 | 我如何练习和评估 | 学习目标、评价维度、参考选择 |
| 术语与文化解释 | 这个词指什么 | 中英文表达、边界与应用案例 |

### 5.2 按写作阶段分组

一级主题采用写作者的工作过程：读者与题材、故事构思、人物与关系、世界与规则、开篇、场景与章节、长期结构与连载、审校与修订、发布基础。

每个阶段下再组织具体能力，例如开篇包含目标呈现、冲突切入、背景交代、视角、节奏、前三章与章末钩子。发布基础只介绍适用平台和有日期的规则，不承诺签约或收入。

### 5.3 标签分别表达不同维度

| 维度 | 例子 |
|---|---|
| 题材与背景 | 仙侠、武侠、奇幻、科幻、都市、历史、悬疑、言情 |
| 情节模式 | 退婚、重生、复仇、比赛、探索、经营、团队组建 |
| 叙事机制 | 系统、任务与奖励、成长阶梯、循环、信息差 |
| 读者问题 | 开头平淡、主角被动、背景过多、升级重复、中期卡文 |
| 学习属性 | 初学、进阶、阅读与练习时间、语言、剧透范围 |

例如“仙侠题材＋退婚开局＋系统机制＋开篇阶段”，可以指向同一内容。类型与标签由受控词表维护；新增前检查同义词和已有含义，防止每位编辑各建一套分类。

内容之间保存明确关系：某教程使用哪个案例、某模板实现哪些方法、某学习路线依赖哪些条目。页面自动从这些关系生成推荐，避免只靠相似标题猜测。

### 5.4 搜索设计

支持标题、摘要、正文、小节和术语别名检索；按内容形式、阶段、题材、难度和语言筛选。搜索结果显示匹配片段、能解决的问题和内容类型。

建立人工维护的中英别名表，例如“章末钩子 / chapter hook”。“系统文”和 LitRPG 可建立相关关系，但不做完全等同的自动替换；没有同语言结果时提示查看另一语言，并明确其语言。

空结果提供相近术语、相关主题或补充资料的反馈入口。搜索索引只包含已发布内容，内部资料和未审稿件不进入索引。

## 6 中英双语与文化适配

学院默认入口提供英语内容，并有显著的中文入口。地址明确使用 `/en/` 和 `/zh/`；用户选择后保留偏好，不因所在地强制跳走。

每个知识条目使用同一稳定身份关联中英文稿，分别保存正文与审校状态。对中国网文经验可先写中文研究稿，再由英语编辑重写说明；英语来源也可以作为初稿起点。公开版要求含义、案例和模板字段保持同步。

英文内容讲清术语背后的功能与文化语境。例如退婚情节可同时解释关系解除、公开评价、人物自主目标和后续选择；仙侠概念保留中文与拼音，并给出背景说明。Wuxia、Xianxia 等英语表达可参考既有读者语境，但定义由本院编辑结合来源说明。[术语参考](https://www.wuxiaworld.com/page/general-glossary-of-terms)

“黄金三章”作为一种开篇组织经验讲解，说明它要完成的叙事任务及适用条件；不将中文章节字数、更新节奏或具体平台经验直接写成所有英语小说的规则。

语言切换尽量停留在同一条目的译文。尚未完成审校的译文保留草稿；已发布译文因实质修改落后时，提示版本差异，并在可能误导读者时撤下相关内容。术语表记录首选译法、替代表达、容易误解之处和例句。

### 7.5 手机与可访问性

手机采用单列阅读，目录和筛选放入可关闭抽屉，模板在填写和预览之间切换；保留用户阅读位置。主要内容可用键盘访问，表单有标签，图片有替代文字，按钮和高亮满足对比与触控需要。校验 360 像素宽度、长中英文标题与 200% 缩放，避免正文横向滚动。

## 8 一个完整示范单元

首个主题建议选择：**让系统文开篇同时建立人物目标、规则与期待。**它能覆盖用户特别关心的开篇、系统文和可填写模板。

| 产物 | 内容 |
|---|---|
| 方法教程一 | 先让主角遇到具体困难，建立当前目标 |
| 方法教程二 | 通过一次有后果的行动展示系统规则 |
| 方法教程三 | 用第一份奖励与代价连接下一章期待 |
| 案例分析 | 对已核验作品的一段实际开篇做细读，注明版本、范围和定位 |
| 原创示例 | 修复师获得“借用明日技能”的能力，每次使用会损失一段记忆；比较说明式开头与行动式开头 |
| 可填模板 | 当下困难、个人目标、触发事件、能力、限制、代价、首次选择、结果、后续问题 |
| 练习 | 分别写出使用能力与拒绝使用的两种选择，检查人物目标是否仍能推动故事 |
| 术语 | 读者期待、开篇钩子、金手指、代价、奖励、章节推进 |
| 软件交接 | 先提供可复制的角色卡、能力规则与章纲，并链接真实操作指南 |

这个单元同时提供中文与英文稿。邀请试读者根据模板完成自己的版本，检查他们能否解释能力限制、做出人物选择，并带走自己的结果。以完成情况修订内容模板和页面设计，再开始批量生产。

## 9 首发内容与扩展顺序

### 9.1 首发内容预算

| 内容 | 建议数量 | 首发重点 |
|---|---|---|
| 核心教程 | 12 篇 | 期待、一句话故事、人物目标、主动选择、冲突、信息释放、开篇组织、章节钩子、成长代价、系统任务、篇章节奏、伏笔管理 |
| 类型指南 | 4 篇 | 成长与系统、仙侠、武侠、退婚与身份逆转 |
| 拆书分析 | 4 篇 | 每篇限定一个实际阅读范围和研究问题 |
| 可用模板 | 6 份 | 故事一句话、主角目标、前三章、能力与系统、成长阶梯、篇章与伏笔 |
| 学习路线 | 2 条 | 从想法到前三章、成长故事设计 |
| 核心术语 | 20 项 | 中英解释、语境、例子和关联文章 |

合计 48 个知识单元，其中 20 个为术语条目，可集中在术语库展示。练习随教程发布，译文不重复计入原创内容数量。首发核心内容以中英均可用为目标，质量不合格的条目延后发布。

### 9.2 首发后的扩展

根据搜索缺口和练习反馈，逐步补充悬疑、言情、科幻、都市、经营、团队关系和长期修订专题。每新增一个专题，同步准备教程、案例、模板和练习，不只增加类型名称。

待编辑流程和访问需求稳定后，再评估作者客座文章、社区案例选编、订阅通知、视频课程和互动辅导。账号同步、收费、评论与公开投稿分别形成需求和数据契约，不进入首版的阅读前置。

## 10 内容管理与网站技术

### 10.1 仓库与托管建议

建议建立独立的学院内容与站点仓库，工作名 `storyforge-academy`。学院内容库、构建配置和可公开的原创教学材料以该仓库为单一事实源。第三方原始书稿、课程文件和受限取证材料保存在仓库外。

现有 `storyforge-platform` 负责官网导航与品牌连接。其现行入口规则明确禁止存放小说正文；学院的原创示例与编辑出版应有独立规则和 owner。`storyforge` 负责本方案和后续真正需要的客户端模板适配；社区作品集继续使用自己的投稿和审核契约。

学院建议使用 **Astro 静态生成、Markdown/MDX 内容和 Pagefind 搜索**。Astro 的内容集合可通过 schema 校验元数据，适合不同内容类型与关系；它也提供多语言路由能力。[内容集合](https://docs.astro.build/en/guides/content-collections/)、[多语言路由](https://docs.astro.build/en/guides/internationalization/)

Pagefind 可以按语言建立静态搜索，提供中文分词支持；中文构建须选择支持该能力的扩展版本，并用真实中英查询验收。[Pagefind 多语言说明](https://pagefind.app/docs/multilingual/)

学院独立构建和部署，可使用适合当前用途的静态托管。当前官网仓库已有独立海外 Vercel 站点的部署方案，学院可评估沿用同类托管但建立自己的项目与构建输出。具体套餐、域名权限、国内外访问情况和费用在实施时核对，不沿用旧部署记忆配置生产服务。

### 10.2 结构化内容与发布状态

每个内容条目至少保存：稳定编号、类型、语言、标题、摘要、写作阶段、题材/模式/机制标签、难度、先修与关联条目、作者与审校人、版本、日期、来源引用、许可说明、发布状态和翻译对应版本。模板额外记录字段定义、格式版本、填好示例和导出格式。

编辑流程为：选题 → 研究 → 初稿 → 事实复核 → 双语审校 → 预览 → 发布 → 修订或归档。首版可用 Git 审阅和预览站完成；后续若引入可视化 CMS，其写入仍回到同一内容源。

构建检查元数据、有效分类、内容关联、缺失译文、循环先修、来源定位、公开许可和路由冲突。只有发布状态的页面进入站点、目录、搜索索引和 sitemap。草稿预览需访问控制；搜索引擎禁止索引仅是补充措施。

### 10.3 搜索与发现

每篇正文生成可直接读取的 HTML，配置独立标题、摘要、规范地址、中英对应关系与可访问的内部链接。旧地址更名时维护重定向。初期学习路线、类别专题和术语页提供自然的阅读路径。

社交分享图使用自制版式与有使用权的材料。文章作者、来源、实际更新日期和更正入口清楚可见。外部传播围绕具体写作问题和原创样例开展；访问或搜索排名以实际记录衡量。

### 10.4 学习记录与统计

首版无需注册即可阅读、检索和下载。书签、阅读进度和模板草稿默认本地保存，提供导出与清空；提示其不支持跨设备同步。

统计只记录必要的访问与动作，如进入路线、使用模板、下载和点击软件入口。事件不包含模板正文、手稿或私人笔记；搜索词若用于分析，先去除可能包含的私人文本并采用最小化保存。分别观察中英文使用情况，识别无人能找到的内容与学习中断位置。

## 11 与 StoryForge 的衔接

### 11.1 首版可交付路径

教程对应具体创作任务，模板页先支持复制与下载；旁边提供 StoryForge 的下载入口和已经核验的操作指南。写清楚这些材料在人物、世界设定、大纲或章节中如何使用。实际操作与当前客户端版本不一致时更新说明。

### 11.2 后续结构化模板接入

实现“一键在 StoryForge 中使用”前，先冻结版本化模板包契约，声明适用产品、字段、最低版本、来源、许可和校验信息。用户选择目标作品后预览变化，以候选方式确认导入；导入是一次明确复制，后续网站更新不自动改写作品。

学院模板不是可执行插件。模板接入根据实际写入范围登记 `FIELD_REGISTRY`、`AdoptionSchema` 与 `adopt()`；如增加模型读取则登记 `CONTEXT_SOURCES` 并通过 Context Gateway 组装；如新增持久化表则登记 `PROJECT_TABLES` 与全生命周期。纯教学文字的复制不伪装成 AI 采纳。

正式 AI 填写或改编模板时复用已登记的 Agent Skill、Run Contract 与 durable Harness，输出先为候选；作者确认后写回。校验产品不匹配、非法字段、损坏模板、旧版本、来源变化、重复导入、拒绝和失败恢复，保护原稿。

## 12 建设阶段与交付

| 阶段 | 工作 | 可检查的交付物 | 进入下一步的条件 |
|---|---|---|---|
| A 学院定义 | 定位、栏目、术语与内容规范 | 本方案、分类表、编辑模板、首批选题 | 用户确认主要方向，范围可拆分 |
| B 示范单元 | 精读来源、原创示例、模板与双语审校 | 第 8 节完整内容单元与来源记录 | 读者能看懂并完成原创练习 |
| C 网站骨架 | 学院独立仓库、页面、搜索、双语与预览 | 可浏览的预览站和可恢复的内容构建 | 页面与内容关联可用，草稿不公开 |
| D 首发内容 | 扩充核心教程、案例、模板与术语 | 第 9 节的首发集合和编辑记录 | 公开内容通过质量门，搜索覆盖真实查询 |
| E 试用与上线 | 中英试读、手机体验、域名与部署 | 试用问题清单、修订、正式站回读 | 站点与内容均可用，再接通官网导航 |
| F 持续编辑 | 补搜、更新、纠错和专题扩充 | 固定编辑节奏与效果记录 | 根据实际问题决定后续功能 |

建议以一名内容主编、一名可复核自然英语的审校者和一名开发参与的配置估算。AI 可辅助初稿，但无法替代原作阅读与英语编辑。

可先按 4～6 周的小团队建设周期排工作：首周完成定义和示范研究，第 2 周完成双语示范与页面结构，第 3～4 周扩充内容并开发页面，第 5～6 周用于试用、修订和上线。此为工作假设，首个示范单元完成后按实际精读、审校和开发耗时重估；单人兼职需要更长时间。首发内容不足时延长编辑期，或以已完成专题明确范围发布。

费用按来源阅读或授权、英语审校、编辑、模型辅助、托管与域名服务分别记录。子域名继续使用现有主域名；托管和模型预算在选型及首单元测量后确定。

## 13 验收与持续运营

### 13.1 内容与学习验收

- 每篇教程有明确问题、可操作步骤、原创示例、练习和适用条件；可核实的事实有实际来源。
- 拆书有真实阅读范围与位置；原文事实、编辑解释和作者直接表达能够区分。
- 每份模板由编辑实际填写一次；必填项合理、导出可读，刷新恢复、清空与下载行为明确。
- 核心双语页面的意思、关系链接和模板字段一致；英语由能判断自然表达的人审校。
- 组织 5～8 位自愿试读者，覆盖中文与英文读者；先观察能否独立找到内容、解释方法和完成练习，再收集满意度。样本用于发现问题，不推断市场成功。

### 13.2 网站与发布验收

- 教程正文、相关案例、模板、术语和学习路线互相可达；主要链接、下载和语言切换有效。
- 用至少 20 组中英查询检查结果，包括术语、别名、问题句与无结果场景；草稿与私有材料不能被搜到或通过公开 URL 访问。
- 桌面和手机均可完成“搜索 → 阅读 → 填模板 → 下载”；键盘、目录与缩放可用。
- DNS、域名绑定、HTTPS、未知路径、语言地址、sitemap、规范链接与预览隔离分别核对；上线有版本和回滚记录。
- 正式学院先通过回读，再发布官网中英文导航与移动端入口；两次部署各有证据，合并代码不代表站点已经上线。

施工阶段按实际改动执行学院构建、内容校验和定向界面验证。当前方案只做文档与链接检查；不以本轮规划触发产品 CI、作者项目或模型调用。

### 13.3 运营节奏和评价

每周处理读者问题、补搜和小幅修订，按实际编辑能力新增一个完整主题单元；每月整理无结果查询、失效来源、双语差异和模板使用问题。

分别观察内容发现、学习行为、模板使用和软件入口四类结果。点击下载只能证明下载意向，不能直接当作完成写作或长期使用。先记录一轮基线，再设置改进目标；不预设缺少依据的流量、搜索排名、签约或收入承诺。
