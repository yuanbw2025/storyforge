# 社区作品集：拆书分析与原创小说共享开发计划

> 版本：0.5.0 · 2026-11-02 · 权威层级：L2 施工计划 · 状态：专用分支施工中，Vercel Preview 与独立测试后端联调，正式服务未交付。任务归属总纲 §11 阶段 F；本计划不改变 `F-PLATFORM-01` 的 LATER 状态或产品成熟度结论。

## 1. 目标、边界和开工卡

作者可从 StoryForge 本地项目主动选择已完成的小说章节，或从现有“设置 → 文档解析 → 导入项目参考 → 作品分析”选择拆书分析结果，预览公开内容后投稿。审核通过的**指定版本**出现在 Vercel 站新增的“社区作品集”页面；官网增加同名入口。Git 下载的网页版本、桌面客户端和 Android 客户端使用同一投稿协议。作者选择多少章节/分析条目就展示多少，不设人为章数上限；上传字节、速率和存储资源仍需有公开、可解释的运行预算与可续传能力。

- **产品与生命周期**：这是公开共享和浏览能力的产品研发，不是替用户创作具体作品。共享平台只拥有投稿快照、审核记录、公开版本、评论和举报；本地 `Work`、`Chapter`、`ReferenceAnalysisRun` 与原始文件仍由原产品拥有。
- **阶段位置**：小说、拆书分析的本地生产仍在各自原流程；本功能位于完成后显式投稿与展示，不属于世界衍生 S1/S2/S3。没有自动封装世界或回写世界引擎。图片等媒资若后来允许投稿，由共享平台私有暂存和公开派生版本分别持有。
- **入口 → 结果**：本地项目的“分享至社区作品集”选择器 → 只读投影和公开预览 → 作者确认投稿 → 私有待审 → 审核通过后公开作品详情；官网“社区作品集”按钮 → Vercel 作品集。
- **读写治理**：本地投稿不新增 AI 上下文源或 AI 正式写字段；只读取现有领域数据并生成跨服务传输 DTO。独立社区后端按投稿快照执行内容审核，模型只产生审核判定与审计，不回写本地作者字段。不得借投稿写回 `Work`/`Chapter`/`Reference`。若为本地投稿回执新增 Dexie 表，先在 `PROJECT_TABLES` 登记导出、导入、删除、迁移、作用域和重映射生命周期并做正反例；首选将远端投稿 ID 和本地去重记录放在独立、明确归属的客户端设置/同步域，避免污染作者作品数据。
- **现有能力复用**：文档解析是主拆书入口；`项目参考 → 作品分析` 是查看和再次上传 TXT/MD 的次级入口。`ReferenceAnalysisRun` 的 13 维结果、来源和版本可作选择基础。既有 `CommunityPage` 面向世界/游戏等产品，不能与此小说/拆书作品集混用或复制数据库体系。
- **非范围**：云同步整个项目、替用户发布所有手稿、自动抓取第三方小说、在线编辑原稿、商店交易、无审核即时公开、重新实现拆书解析、替换 Vercel 个人项目展示、把官网当投稿数据后端。

## 2. 三仓库职责和确定的技术路径

| 仓库 / 独立分支 | 职责 | 不做的事 |
|---|---|---|
| `yuanbw2025/storyforge` / `feat/community-works-library-20261029` | 本地选择器、纯只读公开投影、预览、认证/投稿客户端、上传恢复与状态回执；网页、Electron、Android 共用 TS 协议 | 不在服务端保存本地浏览器数据库；不自动上传 |
| `yuanbw2025/my-website` / `feat/community-works-library-20261029` | 在现有 Vercel 站**新增** `/community-works/` 独立展示页及必要 BFF，保留首页个人项目展示和其他子应用 | 不直接修改其中旧的 StoryForge subtree；不把 Vercel Functions 当大文件中转 |
| `yuanbw2025/storyforge-platform` / `feat/community-works-link-20261029` | 现有正式官网导航和适当介绍处新增“社区作品集”外链，确保中英文、移动端和可访问性 | 不承载投稿库；不提前暴露空白或未审核站点 |

**前后端选型**：界面沿用 React + TypeScript + Vite；Vercel 负责静态展示与轻量 API/BFF。投稿、身份、数据库和对象存储采用独立 Supabase 项目（PostgreSQL、Auth、Storage、Edge Functions），以可审查的 migration、RLS 策略和服务端权限层承载。共享协议由版本化 JSON Schema + TypeScript 类型定义，StoryForge 与展示端各自从同一契约版本生成或验证；不能靠两边复制而不测兼容。后台审核可先是同一 Vercel 子应用的受保护路由，权限实际在后端判定。搜索先用 PostgreSQL 全文索引与明确的中文分词方案/降级策略；不为首版引入独立搜索集群。限流、队列和异常重试通过后端作业与数据库状态控制；审核服务故障时保留待审，不默认发布。

**部署连接**：Vercel 继续从 `my-website` 的 Git 构建；根构建脚本只增加新子应用构建/复制，`vercel.json` 只增加 `/community-works` 的定向 rewrite，不更改既有 `/storyforge` 和首页路由。先用 Vercel Preview + 独立测试后端验收；生产环境变量仅存在 Vercel/Supabase 控制台。官网按钮指向经核验的生产 `/community-works/` URL，使用标准外链语义与 `rel="noopener noreferrer"`，保留回官网入口。官方仓库近期曾移除过过早的 Vercel 门户链接，因此必须在作品集真实上线并通过回读后才合入官网按钮。

## 3. 内容契约与版权边界

### 3.1 小说快照 `novel.v1`

读取 `Work` 的标题和作者**主动填写的公开笔名**，以及作者勾选的 `Chapter` 正文、章节标题和顺序。章节、作品简介与流派标签分别默认不公开；作者须逐项勾选简介和流派标签后才进入公开预览。支持章节全选、区间、多选、公开预览和逐项排除。形成不可变 `sourceRevision`、章节清单、每章内容 hash、整体 manifest hash；更新作品是新投稿版本且重新审核。不得上传项目备份、隐藏笔记、提示词、AI 原始对话、设置、模型凭据、本地绝对路径或未勾选章节。作者可选择署名/许可范围，声明自己有发布权；标记 AI 辅助与否须基于可核实、用户明确的声明，不能推断。

### 3.2 拆书分析快照 `bookAnalysis.v1`

读取作者明确选择的 `ReferenceAnalysisRun` 版本、13 维结构化分析中被勾选的维度/条目、作者自己写的评论和必要的书目信息。固定格式至少包含：书名/作者/来源说明、分析版本、分析方法与范围、13 维目录（可标“未选”而非伪造结果）、亮点与局限、作者经验/可迁移技法、引用与版权声明。公开 DTO 默认排除 `rawExcerpt`、原文切块、原 TXT/MD/PDF、`referenceAnalysisSources`、导入会话与项目元数据。少量引用必须由作者逐项选择、注明来源并经过版权/长度检查；“我有权在本地解析”不等于“我有权公开原文”。浅分析与深分析都只能发布实际存在的结果，不能把未做的 13 维写成已完成。

### 3.3 通用 DTO 与边界

`SubmissionManifestV1` 含 `schemaVersion`、`kind`、`clientSourceRevision`、作者所选内容的 `items[]`、`contentHash`、`byteSize`、许可/权利声明、语言、内容提示与幂等键；本地内部 ID 只用于投影和去重，不直接公开。服务端重新校验 DTO、大小/hash、编码和选择清单；公开版本只引用审核通过的对象存储版本。上传后修改本地作品不影响已公开快照；撤稿可隐藏公开版本，但审核与法定留存记录按政策保留。上传前提供逐字预览、敏感信息提醒及显式最终确认。

## 4. 服务模型、状态与 API

最小表：`accounts`/`profiles`（公开笔名与最少身份）、`submissions`（类型、owner、当前版本与状态）、`submission_revisions`（不可变 manifest、对象引用与 hash）、`submission_items`（章节/维度顺序和公开元数据）、`moderation_cases`/`moderation_events`（规则命中、人工决定、理由、审计）、`publications`（公开 slug、版本、索引状态）、`comments`/`comment_events`、`reports`/`appeals`、`upload_sessions`/`idempotency_keys`。不在公开表中存邮箱、私有源文件或审核原文。迁移失败在事务内回滚，并有 RLS 正反例；已承接用户行为后通过向前迁移恢复，不删除用户数据或改写审计流水。

状态机：`local_preview → private_uploading → submitted → automated_screening → human_review → approved → published`；支路为 `needs_changes`、`rejected`、`withdrawn`、`taken_down`。只有后端审批角色能作 `approved → published`；新修订从私有待审重新开始，旧公开版本留到新版本批准或作者主动下架。审核记录 append-only，决定需绑定具体 revision hash，避免审核一个版本却发布另一个版本。重复提交由幂等键归并；网络结果未知先查询状态，不盲重试。

API 契约草案：`POST /api/community/v1/upload-sessions`、`PUT/POST` 直传对象存储的有时效签名目标、`POST /api/community/v1/submissions`、`GET /api/community/v1/submissions/:id/status`、`GET /api/community/v1/publications`、`GET /api/community/v1/publications/:slug`、`POST /api/community/v1/reports`、`POST /api/community/v1/comments`、审核专用 `POST /api/community/v1/moderation/:caseId/decision`。大正文走私有存储的分块/可续传直传，Vercel Functions 只收小型控制请求；上传会话须受 owner、配额、类型、hash 和过期时间限制。正文读取通过公开批准后的只读投影，不能用对象路径猜到待审稿。

身份：匿名可读；投稿、评论、举报需要经过实际验证的身份。浏览器可用安全的 OAuth/邮件登录，桌面与 Android 使用系统浏览器授权回跳或设备码等跨端受支持流程；不得把服务角色密钥、长期 token、私有项目 ID 放入公开构建。若邮件登录服务上线配额/投递不足，先替换为可运维方案，不以开发默认 SMTP 投产。未成年人可以使用功能；不设置笼统的“未成年禁止注册/评论”。年龄相关隐私、默认可见度与地区要求要独立评估。

## 5. 审核、举报、版权与治理

公开投稿和评论都实行“先审后显”。禁止针对未成年人的任何性化、性剥削或诱导内容；同时禁止非法性暴力、真实伤害威胁、仇恨煽动、隐私泄露、违法交易等不宜公开的内容。普通未成年角色或普通未成年用户不能仅因年龄被拒绝。规则写成可解释的类别、案例、处置和申诉路径；不能宣称一份屏蔽词表可以保证符合所有国家法律。政策按上线地区与服务商条款由具备当地资质的人复核，记录版本/生效时间。

审核流水：文本清洗/格式校验 → 规则与模型/第三方分类器信号（只作辅助，保留版本和置信）→ 高风险隔离 → 人工逐项审阅及理由 → 批准/要求修改/拒绝/升级处理。关键词命中不是自动定罪；漏检和误报均要采样复盘。涉嫌儿童性剥削材料不得向普通审核员或公开页面二次传播，按适用法律和服务商渠道升级；具体报告义务交法律审核。版权包含原作权利声明、拆书短引文逐项检查、权利人投诉和下架通道。举报、申诉、重复侵权、封禁及误封恢复均要有 SLA、工单与审计；审核员最小权限、双人复核高风险决定、操作留痕。先定义实际值班/响应能力，达不到时暂停接收新稿，不让队列无限堆积或自动通过。

安全与隐私：所有敏感操作服务端鉴权并以 RLS 双重限制；CORS 明确允许官网、Vercel 生产域和经验证预览域，本地客户端使用独立授权流而非任意 `Origin` 通配；输入和 Markdown 渲染防 XSS，CSP 和依赖/文件类型校验；上传频率、账户和存储预算、反机器人挑战、滥用封禁、恶意链接过滤；审计记录与备份加密并设置保留期，提供删除/导出与泄漏应急流程。发布/下架切换要求原子化，缓存失效与索引更新可重试、可核对。

## 6. 用户体验与质量标准

作品集首页提供“原创小说 / 拆书分析”切换、分类、语言、全文/标题搜索、排序、作者/许可标识及审核后的推荐位；不混入个人项目展示。小说详情有目录、连续阅读、阅读进度、本章/整部跳转和移动端排版；拆书详情按固定 13 维与作者点评呈现，未选维度明确为空。投稿端有范围选择、字节估算、预览、版权确认、进度、断线续传、失败恢复、审核状态、修改和撤稿。评论有登录、先审、举报、折叠和作者管理；初期可在投稿/阅读稳定后单独开闸。页面满足键盘导航、语义标题、对比度、屏幕阅读器提示、窄屏布局、错误/空/加载状态。SEO 只索引已公开且允许搜索的版本；待审/后台加 `noindex`，站点地图只含公开作品。

以用户可观察行为验收：任意选中量的内容完整保留顺序和校验 hash；同稿网页、Electron、Android 的结果一致；完全未选不能上传；断线恢复不会重复发布；待审/拒绝稿在匿名搜索、URL、对象存储和缓存均不可读；下架后公开读取和搜索消失；普通角色和普通未成年用户不被误禁，未成年人性剥削内容无公开路径；审核员无法越权读取其他私有账户资料。不能用单元测试声称真人阅读质量或跨地区法律合规已完成。

### 6.1 社区互动范围与现状

社区互动围绕作者主动公开的小说和拆书分析展开。匿名可阅读；评论、点赞、收藏和送花使用同一社区账号。在客户端打开外部浏览器后按该浏览器的登录状态验证，不在链接中传递客户端令牌。本地写作、文档解析及离线客户端不因互动功能而强制登录。互动记录归社区后端所有，不回写本地作品，不新增 AI 读写入口。

截至本版，下列互动已在专用分支实现：稳定作品身份、点赞、私人书架/追更/续读、章节/段落/划线评论、一层回复、免费鲜花、站内通知与屏蔽管理。当前社区定向测试 89 项、桌面/手机隔离浏览器 10 场景及 TypeScript/构建通过。Supabase 测试项目已应用包括 019 在内的 18 个迁移，26 张社区表均启用 RLS；整笔回滚的托管 PostgreSQL 合成事务验证了领取/赠送幂等、余额不足拒绝、私人书架、评论审核与作者标识、屏蔽和下架。测试数据未提交。作品集社交提交 `04d00be` 的 Vercel Preview 已 READY；真实 HTTP 验证私人书架/消息/花篮等 6 个列表读取、身份伪造拒绝、待审外作品互动拒绝、原始表及 actor RPC 权限拒绝、普通账号审核拒绝和停收开关，合成测试账号已删除。真实投稿、人工审核与公开阅读的完整闭环仍未验收，不能标记正式开放。

| 能力 | 用户体验 | 数据与验收边界 |
|---|---|---|
| 作品点赞 | 点赞、取消点赞，查看有效点赞数 | 一个账号对同一社区作品只有一个有效点赞；重复请求和并发不重复计数 |
| 收藏与追更 | 加入私人书架、继续阅读、查看更新提示，可取消收藏 | 收藏列表和阅读进度默认仅本人可读；仅已审核发布的新版本产生站内更新提示 |
| 章节、段落及划线评论 | 在章节末留言，或选中文字后评论；段旁显示讨论入口 | 评论绑定精确公开版本和正文位置，不能错挂到修改后的新文本 |

| 举报、屏蔽与运营管理 | 举报作品/评论、屏蔽骚扰者，审核员处理并留痕 | 作品下架后连同正文摘录、关联评论和通知预览一起停止公开；屏蔽不取代全站审核 |

### 6.2 稳定作品身份与正文定位

社区侧已增加稳定的 `communityWorkId` 与不可变 `publicationRevisionId`。本地作品 ID 不作为公开身份；作者显式选择更新自己的社区作品，服务端验 owner 后关联新修订，禁止按同名标题自动合并。点赞、收藏与累计花数挂在稳定作品身份上，评论和阅读位置另外绑定具体公开修订。现有独立投稿默认按各自作品保留，不根据标题或相似正文批量合并。

划线评论的锚点包含公开修订、章节/分析条目 ID、正文块 ID、块内容哈希、规范化文本中的起止偏移和有限长度选区摘要。网页与服务端共用文本规范化/偏移协议，不能以屏幕像素或 DOM 节点序号定位；服务端从已批准正文验证选区，拒绝越界、伪造和过期锚点。首版限定单正文块选区，触屏长按、键盘选区和段落评论都可用。作者更新后旧评论仍属于原版本；不自动猜测迁移。旧版本不可公开时，其选区摘要也不可公开。跨分页块、重复文字、中文标点、emoji、换行及正文改版必须有反例测试。

### 6.3 花花规则与一致性

花花是免费的鼓励机制，不接充值、交易、提现或现金兑换。首版默认每账号每日领取 3 朵、余额最多 30 朵、单次赠送 1—3 朵；这些默认值已在界面展示，后续调整需体验验证。每日按固定 `Asia/Shanghai` 自然日结算并注明 UTC+8，不按设备时区切换重复发放，不设置连续签到惩罚。余额达到上限时拒绝领取且不占用当日资格，赠送后可在当日再领取。

采用不可变流水与可校验余额：领取以账号和业务日期唯一约束去重，赠送以账号和请求幂等键去重；扣减余额、增加作品有效花数、写流水和生成通知事件必须同事务成功。检查正整数、每次上限、余额、账号状态和作品当前公开状态；禁止给自己的作品送花。网络结果未知时先查原请求结果，不另造请求 ID 重送。作品后续下架保留赠送历史和下架说明，不自动重复退款；若运营更正账目，用有理由的冲正流水而不是改写历史。账号滥用需有限频率、异常检测和封禁处理，不能把“登录过”视为不会刷量。

### 6.4 实现位置与实施顺序

继续使用 React + TypeScript 阅读器、Vercel 同源 API、Supabase PostgreSQL/Auth。点赞、收藏、评论锚点、每日领取、花花流水和站内通知以社区库 migration/RLS/RPC 实现；大正文仍由现有私有 Storage 提供已批准投影，不额外采购存储服务。浏览器不直接改余额、审核状态或聚合计数。后台扩展现有熔炉管理入口及社区审核页；真实权限仍在社区服务端，避免形成第二套账号或把私有稿件复制到官网服务器。

1. **I0 基础可用**：修复预览接口启动问题，完成账号、私有投稿、独立审核、匿名阅读、撤回的真实闭环，冻结稳定作品/修订身份契约。
2. **I1 轻互动**：点赞、私人收藏书架、继续阅读和公开版本更新通知；测试多设备重复操作与私人列表越权拒绝。
3. **I2 阅读讨论**：先章节/段落评论和回复，再选区锚点、讨论侧栏、屏蔽及审核后台；完成移动端选区、键盘操作和下架联动。
4. **I3 免费花花**：每日领取、余额/流水、赠送与作者通知；重点验证并发领取、并发送花、余额不足、跨日、超限和响应丢失后重查。
5. **I4 运营与交付**：通知汇总、分页/索引/限流、容量观测及反滥用；官网入口和三端构建统一接到同一账号与作品身份，再分功能开闸。

点赞、评论、花数均按确定性规则计算，不预置虚假热度。排行榜、关注作者、书单与徽章可在上述闭环验收后另行评估；本轮不以私信、聊天群或付费打赏扩大首版范围。收稿、发布与社交写入分别有服务端开关；`COMMUNITY_SOCIAL_WRITES_PAUSED=1` 暂停新增互动，仍允许撤回评论、移出书架、解除屏蔽和消息已读。失败状态、迁移与最小权限测试、真实 API 读回均需留证，未完成项保持隐藏。
