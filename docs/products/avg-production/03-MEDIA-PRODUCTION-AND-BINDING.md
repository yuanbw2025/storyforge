## 1 需求先于生成

每项需求先声明给谁用、为何用、需要哪些事实与参考，再选择能力和生成/导入路径。通用 `ProductMediaKind` 的九类继续使用；同为 ui 的物品图标与菜单装饰不能因此具有同一消费者。

目标 `AvgMediaRequirementV1` 的逻辑字段：

| 字段组 | 必需语义 |
|---|---|
| identity | requirementKey/revision、familyKey、subjectKey、用途/消费者和准确上游工件 |
| purpose | mediaKind、消费 domain/slot、场景/句/状态/语言，required、允许 fallback 及其艺术影响 |
| content | 公开事实、情绪/行为/信息目的、必要细节、禁止变化和禁止泄露 |
| visual/audio brief | prompt/negative、尺寸/比例/alpha、安全区/锚点，或 duration/loop/channel/混音/配音版本 |
| references | 真实已授权参考的 asset/hash/revision、角色、使用目的和允许变化；非纯文本描述 |
| production policy | generate/import/reuse/edit、所需能力、数量/尝试上限、数据发送政策、权利与费用约束 |
| acceptance | 技术检查、家族一致性、实际消费者尺寸/连续场景、专业/作者审听查看要求 |

系统生成 owner、实际 hash/版本/成本/receipt。需求的 prompt 是生产输入，不能冒充候选图片、配音或已消费证据。

## 2 媒资家族与用途

| 家族 | 典型产物 | 消费者和连续性要求 |
|---|---|---|
| 人物基准参考 | 身份/服装/比例/配色、必要转面或特征基准 | reference-only；被后续生产实际消费，不能默认上舞台 |
| 角色立绘 | 同人同服装的姿态/表情/状态、必要差分与 alpha | stage actor；对齐锚点/尺度/轮廓，换表情不漂移身份 |
| 对话头像 | 指定裁切/朝向/表情与显示身份 | dialogue avatar；不是缩小整张立绘塞进任意框 |
| 物品/证据图标 | 可辨轮廓、状态和选中/不可用视觉 | inventory/case list；按冻结设备实际小尺寸查看 |
| 物件详情 | 与 icon 同物件的细节/可观察状态 | evidence detail；可读文字由合法 UI 数据，图不能发明真相 |
| 场景背景 | 同地点/机位的昼夜/天气/事件状态、角色站位空间 | stage background；地理/消失物与光源保持合法 |
| 关键 CG | 剧情动作关系、视角、人物/物件/环境组合 | stage CG 或 gallery；事后鉴赏按实际解锁 |
| UI/菜单装饰 | 框/面板/按钮皮肤、安全区、状态与主题 | menu/dialogue/inventory 的明确槽；可访问性文字由 UI |
| 地图/档案/关系板 | 正式地点/事实的可视结构与装饰 | archive/location/case-board；只投影当前允许信息 |
| BGM/变奏 | 主题、情绪转折、循环段与静默 | music channel；衔接和循环须在场景中审听 |
| 环境与 SFX | 连续环境、一次性动作/反馈、必要变体 | ambience/sfx channel；持续与瞬时不混，关键事件有准确触发 |
| 配音 | 定稿台词、人物/语言/演法对应 clip 或带可靠对齐的片段 | dialogue voice；实际音频、句匹配、读音/表演与连续对白 |
| 高级层/动作/视频 | 分层角色、特殊特效/视频等能力特定产物 | 后置明确 renderer/恢复合同；不在首场景默认采用 |

封面/商店宣传是 marketing 用途，可以复用授权且信息合法的主体，但不能自动加入 runtime 资产闭包。视觉参考也不因为“被生成器使用”而自动成为作品可公开内容。

家族先冻结主体基准及允许变化，再生产必需变体。每个候选记录 family/subject、参考版本及加工 lineage；作者改身份基准使相关变体 stale，不使无关地点背景全部重生。

## 3 真实参考与 provider 请求

目标 `ProductMediaRequestV2`/AVG 适配扩展保留 V1 文本路径，新增真实参考和 voice 所需类型化输入。公共字段必须有 AVG 与另一真实调用方需求证据；否则留在 AVG adapter，不能扩大中立世界协议。

每个 `ReferenceInput` 指定 assetRef、contentHash、MIME、字节/受控读取句柄、purpose（identity/pose/composition/style/detail）、crop/mask（如能力支持）、授权与数据分类。模型看到的文字“角色 A 基准图”不是参考传输成功。

运行前冻结 capability snapshot：provider/model/endpoint、支持的输入/用途/格式/尺寸/alpha/mask、数量与文件上限、async 状态/查询机制、计费上界、授权/数据政策及实际账号可用性。官方文档能力与当前账号可调用性分别取证。

传输回执保存实际送入参考的 hash/处理版本、参数、operationId、已知费用/用量和实际返回。provider 不支持某参考类型则拒绝或返回作者改路径；不丢参考继续文本生图后称身份受控。

结果未知时先查询既有 operation/receipt；无法判定则停在未知，禁止自动再发一笔。网络瞬断、有界重试、授权/余额/4xx 和单次计费分别按 Harness 处理。收费尝试、参考处理和废弃候选都计入成本；无价格/用量证据不记零。

研究中列出的参考生图/语音接口仅是技术候选，本设计不锁定供应商、报价或商用效果。[研究记录](../../audits/AVG-PROFESSIONAL-METHODS-20261013.md)中的非商用研究代码不能作为商业默认生产底座；外部服务的权利需按实际输入、账户/套餐和输出条款核验。

### 3.5 明确本地加工与衍生来源

实验 AVG V2 可在作者工作区保存独立 `imageProcessing` 配方方案，准备方案/明确开始时与 Brief/Plan 一起冻结；它不进入供应商原始需求。原图 → 本地零调用加工 → 作者视觉评审 → 选择 → 演出是固定依赖。旧 V1 和省略该字段的 V2 不增加任务或改变 JSON/hash；无加工策略不能夹带衍生选择，有冻结加工时不能跳过它选原图。原始请求、响应、账单和原 Blob 保留。

实验图片制作台可在明确停止的批次，或作者选择并保存准确修订基线的冻结预览中，核对同 Work/同冻结世界的已选演出图，准备零模型/图片调用的新组装方案。原始 V4 合同、作者系统/脚本/专业方案、编译、直接图片 producer/HTTP 回执、字节、原视觉评审与选图命令及解码证据均须闭合。没有 Stage 的已选前缀也可核对，但只有已配置到演出的准确图片进入该交接；参考用途不能自动提升为演出。

便携来源使用独立 `generated-reference-source` 版本 2，绑定原 V4 图片 proof 4、编译工件、评审和选图的逻辑版本/hash/作者回执。当前仅供本地演出沿用；旧来源版本 1、外发参考及人物基准的 V1 解析保持严格，不以演出沿用授予新外发或衍生授权。原 PNG、Run、账单、未知费用和原作者改稿保留，不造媒资导入别名或新 HTTP 回执。

“保留专业演出图并准备新方案”只保存可审查的新 V1 组装 Brief 和旧图来源草稿。作者另行明确开始，在新 Build 重新确认系统、对白及演出，当前 Stage 的 typed binding/字节/消费与完整终态证明重新核验；成功原图不重复生成。世界和作品 owner 不变，原预览/存档保留。新版本的媒体生成预算为零，原调用的未知费用仍归原版本。实验关闭时隐藏并拒绝新的沿用准备；已保存的来源可继续只读核对。

先保存来源草稿，再创建演化 Brief。异步核验前捕获 Production/Build revision，在既有草稿事务中再次比较，最终方案命令沿用同一 Production CAS；并发保存的其他方案不能被覆盖。后续保存失败时，刷新后保留明确继续入口，作者对准确相同来源与草稿的重试使用既有命令表中的便携确定性身份续完；完整备份重映射后仍须核对实际命令、当前待开始方案及旧图。本地零调用沿用可核验导入后准确 completed 前缀，但不改变旧 Run 的暂停状态，收费重发检查仍拒绝该 Run。其他待开始方案、版本/草稿/世界变化、缺失选择或评审、坏字节及旧调用未知均拒绝。新当前版本须通过完整生产终态验证；导入后的 V1 沿用既有冻结预览、来源和字节/播放恢复合同，不能由该只读恢复重开旧 Run 或取得旧发布/采用权限。

待开始方案不投影为旧 Build 的当前图片消费或调度；旧图片仍由原始授权 Brief/Plan 的历史来源独立核验。保存中断后刷新和完整导入都必须保留明确继续入口。

该路径保留已采用成功图片，后继继续未选原图的当前候选沿用、加工、版本化外发参考、真实图声和专业质量校准；具体工程结果见工作包 §9.5。

### 3.11 未选原图进入新版本候选

未选用的成功图片不能借上一节的已采用来源进入演出。V4 原图沿用须另冻准确逻辑来源、原编译/需求及原始 provider proof，在新版本执行独立零调用复验任务，再经过本版本视觉评审、作者选图、消费配置和演出采用。原图片/请求/响应/费用与权利保留；复验输出不能冒充新供应商响应，不能用旧选择代签当前决定，也不把 V4 Brief 改写成旧 V2 批次。

共享基础只读证明使用独立 `storyforge.avg.image-revalidation-producer-proof@1`，核对实际单次确定性图片复验 Run、checkpoint、结算 ledger、准确候选与 Work Blob；声明与实测 usage 的文字/媒资调用和费用均须为零，Run 不能含供应商派发或新原始响应。原始 HTTP producer 的 V4 proof4 保持自己的严格入口。该证明可核验导入后准确 completed 前缀，不恢复旧 Run，不创建当前采用、重发或外发权限；原图语义来源、当前准确需求与作者决定仍由 AVG 适配层核对。

新版本保留成功图片与生成失败项是不同任务。即使后继生成选择了其他模型，沿用图片仍须显示和保留其原始模型/请求与原费用；当前复验只证明原字节在当前准确需求下被核对，不伪造一份新模型输出。不同需求、用途或已改变的作者视觉方案不能仅凭同名图片通过。当前 V4 在尚未开始的 Brief 可选冻结 `rawReuse`，最多八项、同制作的准确较早版本、每个需求仅一项；缺省保持旧 JSON/hash，空选择明确删除该字段。保存选择不创建 Run，也不解析当前供应商路由；草稿、父 Build 与 Brief 的版本须再次核对并通过既有命令 CAS。

未选原图的独立便携描述使用 `storyforge.avg.visual-raw-reuse-source@1`，绑定制作身份、原始 proof4、编译引用、世界内容 hash，以及原需求完整/语义 hash；不含主机 ID 或旧选图/评审回执。读取时在当前 Work 以便携身份重新定位原 Build，重验完整已采用视觉闭包、原始 HTTP、原图字节及准确 completed 导入前缀，异步计算后再查原授权/输入/图片行。历史原图列表返回该准确描述，按需预览时用便携身份重验来源，并再次比对所选主机 Build/revision/epoch、需求和工件，不能把另一有效原图误显示为本次所选图。它不能通过旧已选来源或外发参考解析器。

需求兼容性以严格需求 codec 的完整语义为准，只从语义比较中去掉最外层逻辑 `revision`；家族 revision、提示词、参考 hash/权限、消费者、尺寸、透明要求及其它字段继续参与，未知新字段拒绝。返回当前准确需求及 hash 时，原 payload、物理 asset 版本、请求和账单保持原值，不把原图重标为新模型输出。保存和开始前先核对原始证据与非设计参数；当前方案重新采用、确定性编译后再比较完整语义，不兼容即失败，不自动补发收费请求。

明确开始后，沿用项在实际登记的 V4 上下文执行单次 deterministic 任务，依赖本版 compiler，无 Skill/能力绑定，模型、图片和现金预算及实测用量均为零；未保留项仍按实际当前模型有限派发。全部图片与专业岗位均沿用时可无 Key 完成，部分保留时只预检仍需调用的路由。新原图工件保留原 payload/metadata/rights/Blob，外层 capability requirement 为空；独立 quality 绑定当前编译、输入 hash、准确当前需求及原始来源，不产生新 HTTP 回执，也不宣称解码或艺术通过。共享 producer 准入核实真实 Run/候选/checkpoint/ledger/字节，私有准入再核对完整语义和当前 Gateway 输入。

本版必须重新完成实际图像观察、视觉评审、作者选图和演出采用，消费者使用当前准确逻辑需求，原图物理版本不重标。已选复验图的本地来源另用严格 `generated-reference-source` 版本 3：当前零调用 producer、编译/评审/选图回执与平铺原始 proof4 分开保存，不能通过旧 Source1/Source2 或外发参考 V1 解析。该来源可继续显式保留到零生成调用的 V1 演出，仍须当前版本重新采用；完整备份/remap 后核实真实来源和原字节，删除副本不影响原件。加工、版本化外发参考和真实图声质量继续后继。当前受控工程验收见工作包 §9.5，不签真实供应商或艺术/商业质量。

### 3.12 V4 明确配方与本地加工

尚未开始的专业制作方案可逐需求保存、移除准确裁切、等比画布适配、锚点和显式底色配方。配方保存在真实 V4 Brief，编辑草稿不镜像旧媒资批次或配方；保存只创建可审阅的新方案版本，不创建 Build/Run、调用供应商或采用结果。空方案应省略字段，未知需求、重复项、越界裁切、不足尺寸/错误画幅及必需透明用途的不透明填充均拒绝。界面保护未保存修改，其他窗口变更后须明确撤销再核对；父版本、草稿和方案在保存前复查，正式开始后不能修改冻结配方。

明确开始后的加工是同一生产图内单次、无 Skill/供应商能力绑定的确定性任务，依赖准确已采用系统/脚本、实际 compiler 与本版原图。原图可以来自本次 HTTP 或已冻结的零调用沿用；两种来源分别复验，不伪造 V2 Brief。复用已有有界原生画布加工器，输入/输出字节、几何、配方与工具回执单独记录，原图、模型/HTTP、费用和权利保留。原生透明留边不会移除不透明底色，不宣称语义抠图、修脸或艺术提升。加工失败保留原图与失败记录，不自动重发图片请求；坏原字节在加工前拒绝，替换配方/编译来源的候选在密封接收时拒绝并保留准确检查点。

加工 producer 使用独立 `image-processing-producer-proof@1`，真实单次 Run、checkpoint、ledger、候选和 Work Blob 闭合，模型/媒资调用与现金用量均为零。当前作者仍须观察并确认准确加工图的视觉评审，再单独确认衍生选图、配置演出草稿并采用演出，原图评审不能代签加工图。待开始的新方案不用于投影上一 Build 的任务；冻结组装只复核已接收的准确加工检查点，不允许新增加工槽。

已采用加工图另用严格 `generated-reference-source@4`：当前原图 producer 与本地加工证明分开，原图复验另附平铺原始来源，编译、评审与选择均绑定实际回执。来源只供本地演出沿用和只读复验；旧 Source1/2/3、外发参考与人物身份基准入口继续拒绝新版本。明确保留后另行开始下一版 V1，重新采用本版规则、对白与演出，准确衍生字节可进入 Preview。完整备份/remap、导入后完成前缀核验、独立试玩及删除副本留原件沿既有 Work 生命周期，不由导入恢复旧 Run 创作权。

直接原图与零调用沿用原图的实际 Harness 和新增原生像素/Source4 往返路径已有定向证据；完整关联、工程门与准确提交 CI 状态见工作包 §9.5。上述加工和消费验收使用受控工程媒资；账号最小连接探活不代验真实家族图声、可观察专业评审或商业作品质量。

### 3.13 版本化外发参考基础

独立 `storyforge.avg.media-reference@2` 逐项冻结用途、允许取用与明确排除的图内元素、准确字节及本次外发/衍生声明。来源可绑定准确已采用生成来源1～4，包含旧加工图、V4原图、当前零调用复验和加工图；读取复用各自原producer、编译、评审/选择及Work Blob证明，绝不把缺失的生成来源退回同名导入素材。原图或加工图进入下一次生成的权限，仍由本次明确确认承担。

`storyforge.avg.image-request@2` 将目标家族身份与修订纳入输入hash；派发前使用冻结副本，不接受另一个可变家族参数。新旧请求共用既有单次provider适配器与unknown-result门，版本2传输回执保存准确顺序、来源、目标、允许/排除声明和hash，旧版本1的请求字节、hash和拒绝边界不改变。四张/单张8 MiB/合计24 MiB等项目输入上限沿用，原生crop/mask仍拒绝，超限不静默缩放。

用途/排除声明只是发送的指令，不是图内内容隔离或艺术质量保证。[Agnes Image2.5现行文档](https://wiki.agnes-ai.com/en/docs/agnes-image-25-flash)描述了参考字节及尽量保持构图的图生图流程；本项目尚无可核实的参数保证仅取style而完全排除道具，仍须对准确结果逐项观察和返修。此基础尚未进入新版正式专业范围/批次、原图接收、工作台与家族合同；旧V1参考、正式V4和家族V1 parser继续拒绝新输入，不能把传输基础验收写成端到端交付。验收范围见工作包§9.8。

### 3.14 历史专业依赖的同快照批量证明

历史编译读取可在一次原生只读事务内共享已核实依赖，每个请求成员仍须准确key/version/hash、原始Run/模型字节及作者命令/候选/权利证据，任一失败整批拒绝且不写入。旧单项入口保留，不跨调用缓存权限或把历史证明转成当前采用/外发授权。

若Dexie只读子事务共享调用方原生写事务，各成员仍独立证明并保留调用方整体回滚，不另开事务绕过提交边界。准确Build/Brief/Production完成时再核对，Source4原像素/衍生像素、独立试玩和便携恢复继续使用原严格证明；工程验收范围见工作包§9.9，完整CI与真实图声质量另验。

共享producer读取亦可在同一个活动原生只读事务内复用已经完整重放的candidate与原始事件hash，每份Map最多32项，事务结束后不沿用。键包含完整Build指纹、准确作用域、Run/receipt/input与历史完成前缀许可；当前接受和历史恢复不能共用许可。每次调用仍核验准确工件、ledger、作用域、当前指纹与作者/权利证据；OPFS等物理字节始终重读。原生写事务、其中的只读子事务及无外层事务的调用均走原逐次证明，失败不保留证明，采用消耗集合也不共享。分支施工与验收见工作包§9.24。

### 3.15 版本化专业范围、家族与编译输入

独立专业范围/图片批次/人物家族方案及编译提案版本2承接参考@2，复用原结构、主体/消费槽和语义校验。允许/必需参考由作者冻结，岗位只返回逻辑参考键，不能改授权/策略或新增用途；编译合并准确方向/主体方案并绑定规则、文本、参考和目标。请求@2从本次选定需求冻结目标家族，不接受另传可变目标；异步准备前固定输入副本。

`media-production-v2.ts`是明确登记的headless准备API，不读配置、不写表、不调用模型、不生成Run/producer或作者回执。旧V1/V4格式和正式入口保持严格；后继须先串行接通新版正式Brief/Plan、登记Context、producer/原图接收、评审/选用和便携来源，再开放工作台。工程和真实验收边界见工作包§9.10。

### 3.16 新版正式合同与计划基础

同一专业视觉 Brief 字段新增明确 V5 格式，承接范围和参考版本2；旧 V4 的格式、hash、岗位和历史证明保持严格。新合同从实际用途推导有限岗位、图片、确定性编译、可选本地加工、预算和消费门，不能把旧请求重标为已使用新参考策略。作品、世界引用与媒资 owner 沿原生产记录和完整备份生命周期，没有新增表或第二套读写入口。

### 3.17 新参考策略的岗位、原始方案与作者编译

V5 使用独立登记来源和四个模型 Skill@2，另登记图片操作 Skill@2；旧默认 Skill/来源保持原身份。岗位只接收所需公开主体、用途/画布/家族变体、已采用方向及逻辑参考键的允许/排除内容。实际 Work 字节、完整生成来源和许可由系统逐项核验；身份参考按实际目标家族核对；单次投影内，同一身份家族的多个变体共用一次来源核验。缺图、损坏、许可变化及仅有自报来源却无实际 producer，均不能静默回退到同键导入图片。

实际模型请求使用输入@2、原始方案@3和证据@2，保存准确 Skill/路由、登记投影和解析前响应。原采用入口的候选@6继续表达通用模型来源、完整 Brief/Plan、原方案/范围 hash 与作者修改，不把旧请求重标为新策略；方向和主体仍须分别明确采用。确定性编译@2只消费这些采用内容。返回后再次核验来源，若许可等已 stale，保留原响应并记已发生用量，停止接收；未知传输继续沿原保留与有界策略。

### 3.18 新参考策略的原图生产接线

## 4 候选、加工与采用

专业场景工作台后继接入：准备用途时只冻结主体/槽/尺寸/细节与合法参考，复用已有生产记录单次保存 V4 Brief；不会保存第二套需求或合成已开始的 V2 制作。已存参考须重新核对实际字节和本次外发/衍生许可，参考选择失效会报错，不能静默改成无参考。作者可修改尚待确认的方向/地点方案，保存候选与准确版本采用分开；刷新从既有 Brief/工件读取，不重发。采用后使用实际 compiler 工件展示原图、问题单/选择和消费配置。退回是明确结束本批，原方案、原字节、未知费用与依据保留；后继局部修订、停止版本的完整图像消费、专业家族及发布仍另验。双实验开关默认关闭；两个新增原生用例覆盖拟交付的正向参考/修改/消费/原生 Preview/导入复验和退回恢复路径，枚举不算执行通过。

专业家族的准备接缝继续复用原消费声明器：纯计算准确已有物件的 icon/detail 引用，能力/来源预检后先保存可审阅的 V4 Brief，再以原草稿 revision CAS 保存消费槽；正式规则仍须独立采用。Brief 写入失败不留孤立槽；草稿写入失败保留准确 Brief 和原草稿，刷新后明确开始时重新核对完整来源、参考、路由和基线，才可补完该提案。来源已改或路由不可用时不补写、不创建 Run。修订尚未开始的用途只解除本 Production 历史中准确未消费提案所占的槽，已选图片和其他作者绑定保留并阻止冲突替换；能力预检失败不会保存这些新声明。没有创建物件、谓词或第二个图片批次。四岗/五图工程 HTTP 路径已实际运行，原图、用量和未知费用留存；此处不签人物透明度、专业家族评审/消费、真实参考连续性或原生/艺术通过。

专业用途表单继续复用同一 V4 Scope：背景、人物姿态/表情、物件 icon/detail 可组合为最多八图；每个 stage 用途显式指定已存场景/台词，物件图只声明准确已有物件及基础/显示变体槽。人物家族共享画布、档位、透明要求与身份基准；参考可选已有合法导入或经原生成参考选择器核验的已采用原图。同职责替换范围明示，其他职责、可选参考与未改用途的准确参数保留；任何编辑重置本次外发/衍生核对。准备、刷新和撤销均不调用或采用。正式方向/主体候选、图片问题/选用与演出确认仍分开，不能由家族表单签连续性或透明度。

生产阶段：需求冻结 → 主体参考确认 → 能力/预算/数据授权 → 真实生成/导入 → 字节检查 → 有界加工 → 单项/家族/合成评审 → 作者采用 → typed binding → Build 验收。

| 阶段 | 保存证据与失败处理 |
|---|---|
| 返回候选 | 原字节/hash、请求/Run/operation、技术 metadata、权利及成本；空字节/坏格式不转为成功 |
| 加工 | 裁切/缩放/alpha/音频裁段或响度处理的工具/参数、input/output hash；保留原候选，不原地覆盖 Blob |
| 技术审查 | 尺寸/MIME/alpha、可解码、声道/采样/时长/截断/循环；检查结果不等于艺术通过 |
| 专业审查 | 真实图/音与准确参考、身份/比例/轮廓、姿态/光线、读音/表演/混音、实际小尺寸与连续展示 |
| 作者采用 | 看/听准确候选及费用，接受或拒绝；采纳的是版本/hash，不是“以后自动生成的图片” |
| 复用 | 相同合法字节可共享 Blob；用途、可公开信息和绑定仍单独验证 |

图标目标尺寸由设备 Brief 冻结，可先以 32/48 px 为测试点；这只是拟定观察尺寸，不能宣称已达清晰度。立绘透明边缘、脚/视线锚点和文字安全区要在最终舞台中检查，不能只看单图大预览。

无 alpha 的候选只有声明允许背景或经合法处理后才能进入透明立绘用途。当前特定 provider 的抠图路径不自动适用于所有生成器、参考物件或图标。物品可读编号/邮戳/日期等由正式状态与 UI 文本呈现，不能让生图错字修改剧情。

缺观察能力的 reviewer 只能给技术/文本意见，艺术项为 unknown，转交可观察模型或人。身份漂移、知识泄漏、物件状态错误及关键配音错句是 blocking；不能用其他好图/高分抵消。

在完整工厂前，CAL-01 分别查看一个必要人物/物件家族和短对白的真实输入/输出、用/废率、修图/修音/审听与费用。不能只记参考接口“可调用”便扩大，也不能等所有专业岗位/编辑器完成才发现基本身份/演法不可用。若目标需专业人工画图/加工/录音，可作为明确授权的 import/edit 候选，记录实际工作/权利/费用并走同一 typed adopt；人工后的成绩与原始自动生成成绩分别报告。

### 4.1 当前作者视觉观察与问题交接

### 4.3 新版历史 producer 的只读基础

V5 的原始岗位/编译工件和原图各用明确的版本入口核验，沿用同一 Harness、原始 checkpoint/ledger、候选、原始 HTTP 响应和 Work Blob 内核。原图便携 producer proof 明确版本5；V4 入口只接受原始V4，不能把新请求/策略改标为旧来源，反向也不允许。证明不含 Build/Run/Blob 本机定位id，停止和完整备份/remap 后仍核对同一原始证明与准确字节。

此基础只证明实际 producer；不能代签完整编译语义、参考许可、review@2、作者选择或当前消费权限，也不授予恢复后重新采用、carry、重试或请求权限。后继舞台来源必须保留原始版本并另外闭合历史作者评审/选择，不能凭此基础开放配置或新请求；见工作包§9.15。

V5原图的本地舞台来源现使用严格 `generated-reference-source@5`，分别绑定原始producer proof5、实际需求编译、review2和原作者choice/命令回执；不把raw/request2转成旧语义。旧Source2和V4历史reader拒绝新来源，新reader也不读取改标的旧原图。原始编译/作者依赖图和评审/选择回执共用确定性内核，版本化参考许可、原图语义和review2另按实际合同核验。完整备份/remap后必须重新检查原始Run/响应、准确Work字节、原候选及采用命令；缺任一证据或权利声明不一致即拒绝，不借同key导入图补齐。

## 5 配音生产合同与播放交接

配音需求以正式台词绑定：lineKey、speakerKey、locale、textRevision/hash、performanceRevision、voice preset/version、发音词典、言语行动/情绪原因、前后句及速度/停顿/强调边界。演法版本与文本版本分开：改字使旧音频 stale；同字不同演法生成新 clip，不能覆盖旧 release。

voice preset 保存合法来源、可用模型/语言与权利范围；不默认克隆演员、用户或第三方声音。配音主体与字节留在 AVG 产品层，世界只提供人物语义。旁白、别名、部分配音的范围必须在 Brief 中声明，未覆盖句按允许静音政策运行。

| 产物形式 | 采用条件 |
|---|---|
| 单句 clip | 实际音频与准确句/文本匹配；读音/演法/首尾/连续接话审听 |
| 多句/对话片段 | 有实际可验证的逐句 timing/边界和 speaker 对齐，或作者只按整个片段消费；不能根据字数猜切点 |
| 片段裁切 | 保留原音频与裁段工具/边界、真实对齐来源和输出 hash；切错/漏字/串人物拒绝 |
| SSML/情绪参数 | 仅发给该 model/voice/locale 确实支持的能力；不假定所有 voice 支持同一 style |

采用音频记录 duration、codec/声道、必要 timing、文本/演法/音色版本、技术/艺术/人类观察和成本。实际 audio ended/abort/error 交给播放协调器；播放开始回调不等于播放完成。

voice、music、ambience、sfx 分用途音量/混音；BGM/环境循环、一次性 SFX 叠加上限和对白可懂度在连续场景检查。换句、回听、快进、读档及离开播放器取消旧 playback generation；后台政策和失败结果见[系统规格](02-SYSTEMS-AND-RUNTIME.md)。无浏览器声音权限时显示必要操作，不默默等到超时。

### 5.1 已采用配音的跨批沿用（施工中）

## 6 typed 消费绑定与自动配置

目标 `AvgMediaBindingV1` 字段：bindingKey、requirementKey/revision、subjectKey/familyKey/variantKey、consumerDomain/consumerKey/slot、scene/line 或 event（适用时）、locale、state/visibility condition、layout/anchor、required/fallback、assetKey/blobHash、采用/处理/上游 revision。

`consumerDomain` 是 AVG 闭集：stage、dialogue、inventory、evidence、menu、gallery、archive、marketing、reference。各域有独立受校验的 consumerKey/slot，不用通用字符串打开任意组件。

| 示例需求 | 正确自动配置 | 必须拒绝的配置 |
|---|---|---|
| 信封 icon | inventory item 图标槽，状态/可见条件对应正式物件 | 当作 ui 一律 set-overlay，遮住整张舞台 |
| 信封 detail | evidence 详情槽，未开封可观察信息与公开文字 | 详情直接展示尚未获得的信中秘密 |
| 人物表情 | stage actor 指定主体/外观/锚点 | 只按图片数组顺序猜人物和左右站位 |
| 人物头像 | dialogue avatar 指定说话人/显示身份 | 把 reference-only 人物基准当成公开头像 |
| 背景/CG | 指定场景/事件、舞台槽、视角和导演时序 | 绑定不存在 Beat，或每张图都展示一遍假装覆盖 |
| 逐句 voice | 准确 line/text/演法/语言的 dialogue clip | 同 beatKey 但文本已改，仍沿用旧对白 |
| 菜单/鉴赏 | 合法 menu 槽或已解锁 gallery entry | 为消除 orphan 把宣传图/锁定 CG 强塞剧情 |

自动绑定读取已采用需求、目录、导演与实际候选，在确定性 service 生成可预览提案；作者确认后进入 Build。唯一正确映射可自动填充，冲突/缺口必须明确定位，不让模型在 release 阶段猜。自动配置不等于自动发布。

组装覆盖检查从实际 consumer catalog 出发，包括非舞台菜单/库存/详情/鉴赏；stage Cue 的 orphan 检查不能取代全消费覆盖。必需 slot 缺失、wrong kind/MIME、跨 Work、stale 参考/文本、冲突绑定或禁止信息阻止 Build；可选缺失有可见、已批准的 fallback。

reference/marketing 不纳入 runtime 必需闭包；runtime 只冻结实际需要且允许公开的 Blob。未解锁 gallery 的资源访问遵守展示/公开边界；本地离线包不能当作加密防剧透能力，分发时记录可提取边界。
