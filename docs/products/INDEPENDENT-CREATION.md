# 短篇、小说转剧本与小说转漫画产品契约

> 版本：1.2.1 · 生效：2026-10-31 · 权威层级：L2 · 对应总纲：§4.3～§4.5、阶段 C

## 1. 共通原则

三者都是可独立创建、保存、恢复、导出和验收的产品。它们可以复用模型接入、Agent/Harness、记忆、媒资设施和三注册表，但必须分别拥有稳定 owner、状态机、产物和验证，不依附世界引擎才能工作。

跨产品输入通过显式 source manifest 保存来源、版本、内容 hash、范围和用户授权；转换产物不静默改写源作品。

短篇可由作者显式、一键派生世界草稿或封存版本，保存来源和快照且不改变短篇 owner。小说转剧本、小说转漫画当前不提供“封装为世界”入口；它们继续作为独立改编产品。

## 2. 短篇小说

短篇是轻量独立小说产品，默认规模较小、结构层级更少、记忆窗口更短，但仍包含：

```text
创作意图 → 简要规划 → 结构/章节 → 正文 → 审校/修改 → 完整作品版本
```

它可以复用长篇 Skill 和领域类型，但产品配置、推荐流程和完成条件不同；不能只是把长篇目标字数调小。用户可从短篇升级为长篇，升级必须是显式转换，保留来源和既有内容。

完成判据：空项目可创建；目标字数/章节规模有效；规划到正文可完成；刷新、版本、导出和转换不丢数据；短篇 UI 不暴露不必要的百万字管理负担；显式派生世界无需复制粘贴且不与源短篇自动同步。

### 2.1 当前短篇 UI 接入（2026-09-14）

正式入口为 `/short/:pageId?`，作品库、创作意图、故事设计、章节卡、正文、全篇审校、版本与导出、扩展与派生、社区与发行、通用设置均可直接浏览。实际编辑或生成才选择/创建 Work；旧作品入口跳转到同一套页面。社区与发行当前提供派生世界和分享包管理，不宣称已有在线社区运营数据。

创作表单覆盖六阶段闭集字段，候选可编辑并显式确认；正文复用既有编辑器。未确认表单和候选修改存入 Work 所属的对话事件，并参与注册生命周期，不写入正式设定。生成离页取消；结果未知不自动重试，任务可显式结束；已记录采纳意图的任务只能恢复采纳。

章节卡的确认哈希绑定 Brief、故事设计和有序结构摘要。上游修改或结构摘要变化后必须重确认章卡；已有正文保留。旧草稿缺少哈希时同样需重确认，已冻结版本仍可读取。人工 Brief 的章数、目标字数必须与 Work 骨架一致。重新打开草稿会同步 Work 的创作状态。

扩写为长篇保持同一 Work 身份与正文，短篇生产根记录转换时间、原目标字数与生产 revision；未处理短篇运行须先处理。历史短篇 release 保留、可在长篇版本页导出，带转换证据的备份可以往返；缺失合法证据的跨 profile 数据仍拒绝导入。扩写 UI 下载转换前备份。

验证：`R-SHORT2-professional-production` 覆盖六阶段、错误终态、章卡依赖、草稿隔离、版本与转换备份；浏览器用例 `core-workflow`、`shortform-integration`、`approved-product-ui` 覆盖真实表单、编辑、发布导出、刷新恢复和无作品浏览。模型响应使用隔离替身，不代表不同供应商的文学质量验收。

## 3. 小说转剧本

### 3.1 输入

- 本地作品、导入文档或用户选择的章节范围；
- 目标剧本类型、篇幅、媒介、受众、改编自由度和禁改内容；
- 源 manifest、原文证据和用户锁定事实。

### 3.2 生产链

```text
源文解析与范围冻结
→ 事实 / 人物 / 场景 / 动作 / 对白提取
→ 改编 Brief 与删改原则
→ 场次/节奏/视角计划
→ 剧本场景生产
→ 连续性、格式与源文证据审校
→ 作者修改与批准
→ 不可变剧本版本 / 导出
```

系统要区分“忠实保留”“合理改编”“新增假设”，让作者能追溯关键删改。格式校验由确定性代码负责，戏剧改编由模型和作者判断。

### 3.3 完成判据

整部小说可分块处理并保持 source mapping；角色/场景连续；剧本格式可导出；中断可恢复；源文更新会使相关候选 stale；修改源小说不会静默改变已发布剧本。


### 3.4 当前小说转剧本 UI 接入（2026-09-15）

正式入口为 `/script/:pageId?`，以 `work` 查询参数绑定剧本 Work。我的剧本、原作与来源、改编目标、结构与节拍、场次目录、剧本编辑、原作一致性、戏剧性审校、版本与导出均可直接浏览，通用设置保留在产品左侧。创建只在实际操作时进行，旧 ProductHub 与 Workspace 剧本入口跳转到同一组页面；不提供派生世界路径。

来源可选本地小说的全部或指定章节，或使用现有 TXT/Markdown/DOCX/PDF 解析器提取文本。导入原作建立独立长篇 Work，按原始偏移分成约 20,000 字符的连续章段，不截断或叠加原文；再冻结为剧本来源。原作输入上限为 500 万字符，文件解析仍遵守各格式本地大小限制。创建失败后已经建立的源小说保留，避免丢弃作者导入内容。长篇、短篇与剧本作品库分别按 Work 类型读取，不因活动作品切换而隐藏原小说；重命名先绑定所选作品，共用工作区时删除原作只删除该 Work，不连带删除剧本。删除原作会使改编来源不可读取，界面明确提示并要求备份确认。

页面内纵向标签承载来源事实、因果关系、改编 Brief、删改决定、节拍和 Scene Card 的人工阅读、编辑与确认；既有十个 Skill 仍经 Context/Field/Adoption 注册、durable run 生成候选。模型候选和人工工作草稿分别保存，候选修改不会重新全选已排除项目；任务面板显示待确认、结果未知和采纳中断的恢复入口。准备失败有终态，供应商异常不自动重发。已记录采纳意图时恢复同一任务，不重复调用模型。

未确认文本使用已有 Work-owned conversation/event 生命周期；场景草稿按稳定场次键及 revision 保存，不把数据库本地 ID 当作可移植草稿身份。导航先完成草稿写入。作者需先保存场景，才进行生成、审查、锁定或发布；纯审查元数据变化不误判为未保存输入。已完稿/锁定场景只读。

拆分为整体事务，非法块边界不会留下截断的原场景。复制/拆分同步 Scene Card；合并限制同节拍，合并卡片来源并清理被移除场次的审查引用。重做 Beat/Scene Card 必须在保存备份和作者明确确认后替换下游；已发布版本保留。已存在规划时再修改来源分析/删改决定，会要求重新确认 Brief/规划，不静默删除稿件。未处理任务阻断发布。

当前版本页提供不可变发布、历史版本选择、Fountain/FDX/浏览器打印及完整数据备份恢复。历史版本差异与恢复为新草稿尚未作为正式入口开放；社区发行和视频生产不属于本次交付。真模型改编质量、长篇整体戏剧性与外部软件互操作仍需专项验收。

验证入口：`R-SCREEN4-ui-integration` 覆盖拆分原子性、场次卡同步、失败收尾、草稿隔离、长原文分块、取消后的迟到响应、未知结果任务阻断发布及上游规划失效；`screenplay-integration` 覆盖全 UI 人工生产/发布、无作品浏览、候选人工编辑与排除项恢复、改编后长短篇作品库与删除隔离；原有 `screenplay-production` 保留电影/剧集/短剧及导出验证。AI 浏览器用例使用隔离替身。

## 4. 小说转漫画

### 4.1 两阶段语义转换

第一阶段把小说转换为漫画脚本，而不是直接逐段生图：

- 页、格、镜头、景别、构图、动作、表情、节奏；
- 对白、旁白、气泡、拟声、文字强调与阅读顺序；
- 漫画特有的夸张、变形、停顿、反应格和转场。

第二阶段把脚本生产为成品：

```text
视觉圣经与角色/服装/场景锚点
→ 每格媒资需求
→ 生图、候选选择和局部修复
→ 人物/服装/道具/场景连续性检查
→ 气泡、文字、拟声和页面排版
→ 页级审校与导出
```

### 4.2 数据与媒资

漫画拥有 adaptation plan、page、panel、visual subject、media asset、layout、review 和 release。媒体二进制可以放在共享 blob/OPFS 设施，但引用 owner 必须是漫画产品/版本。世界引擎只可提供语义来源，不保存这些资产。

### 4.3 一致性

角色一致性不是只保存一个 Prompt；至少需要稳定 subject identity、参考图/特征锚点、服装状态、场景时间、镜头连续性、模型/seed/工作流溯源和人工选图。无法满足时必须显示风险，不用低质量自动图填满页面冒充完成。

### 4.4 完成判据

从源文范围到漫画脚本、媒资需求、图片、排版和可读成品端到端完成；对白不遮挡关键画面；阅读顺序正确；角色和场景连续性可审查；失败格可单独重做；刷新恢复和导出完整。

### 4.5 漫画页面接入（2026-09-15）

正式入口 `/comic/:pageId?` 使用现有青绿 UI，`work` 选择独立漫画 Work。外侧标签按主要操作排列：作品库、漫画制作台、阅读预览、版本与导出、通用设置。原作与方案、脚本、页格排版、视觉素材与质量审查收进制作台的页内左侧目录，事实、因果、删改等具体内容保留原编辑器。生成、确认、重做、审查、发布和导出是内容页操作。旧作品工作区的漫画入口转到同一实现；预览稿不再承接正式漫画路由。

- 无作品可浏览分类；选择本地小说（整部或指定章节）或导入原作后创建独立改编。源小说和漫画分别保存。
- 原作、事实、因果、改编方案、删改、漫画脚本、分页与视觉设定可人工编辑确认，也可使用既有十二岗位 durable 候选。候选编辑、排除选择、视觉确认及普通作者编辑稿由 Work 所属对话事件保存；采纳中断显示恢复入口，使用冻结作者意图继续，不重新调用模型。
- 原作更新有显式同步入口；上游内容变更使 Brief/分页确认失效。作者确认重做脚本、分页或分镜前下载备份，原子清理相关草稿页格和媒资，提交后按共享 Blob 生命周期回收无引用数据；发布版本的强引用保留。视觉设定编辑保留主体身份、绑定与已有媒资，并撤销视觉审查。
- 页格支持原有布局、排序、拆合、移动和图片裁切；补齐定格瞬间、主体状态、画面保留区、字体、字号、色彩、气泡尾部与图层顺序。文字渲染不静默裁掉长文本，使用实际页面规格检查排字容量，溢出阻止发布并提示调整。
- 图片生成沿用现有 provider 能力检查和媒资回执；新增持久提交记录，阻止同请求并发、刷新或网络结果未知后的隐式重发，需作者明确发起新请求。当前接口仍是文本生图，不声称已传参考图、支持确定性 seed 或局部重绘；AI 连续性审查仍是元数据审查，实际画面需要作者验图。
- 分镜版、视觉版沿用质量门禁及不可变 Release。版本页从校验后的 manifest 与冻结 Blob 读取历史内容，支持指定版本阅读、结构 JSON、脚本、PNG/WebP ZIP、CBZ 和 PDF 打印；工作稿修改或媒资清理不改变旧版。

实现复用已有上下文源、采纳与媒资服务；漫画规格编辑和重规划清理补入既有 `ADOPTION_EXTENSIONS`，没有增加表或修改 schema。验证入口为 `R-COMIC1`、`R-COMIC2`、`R-COMIC4-ui-integration` 与 `comic-production` 浏览器用例，覆盖隔离、刷新、人工生产、采纳中断、重复请求保护、重规划事务回滚、Release Blob 固定与历史导出。模型/图片单元验证使用隔离替身，不代表真实供应商画质验收。

### 4.6 漫画专业文本任务的失败与恢复

十二岗位的文本任务必须从已核验的 Work-owned Run 派生任务记录。没有候选的失败、请求结果未确认和受损记录也应可见；受损证据只读展示，不获得新的执行或采纳权限。准备阶段尚未授权模型请求时的失败应真实结束；存储拒绝终态写入时，应明确显示终态待核验并保留原始错误，不能报告已经成功收尾。

作者的“停止等待”是产品任务控制，保存于既有 Work 对话事件，并绑定实际 Run、代际与操作前缀。它禁止后续模型请求和自动 repair，不能撤销已发出的供应商请求、保证不再计费，或提前终结仍在途的 Run。原运行和晚到证据继续保留；另发请求须由作者明确作为独立请求开始。已冻结的作者采纳意图不能通过停止等待丢弃。

刷新和查看证据不得自动写入候选事件或重发请求。已保存而尚未投影为待确认状态的候选，只能经作者明确的零模型恢复，并继续核验 owner、原 hash、运行前缀及来源 freshness。原响应正文缺失时必须如实标明，不能从候选反造原文。不可移植的本地候选经备份导入后保留为证据；已经结束或不可执行的 Run 不得仅凭残留作者意图重新写入正式内容。合法的采纳中断继续原作者稿和排除项，不重复调用模型。

核验入口为 `R-SFQA001016-creation-task-state`、`R-SFQA001016-creation-task-ui` 和 `quality001016-creation-task-recovery`；执行状态以各固定代码收据为准。工程替身、隔离浏览器、真实供应商行为和作者验收分别取证。

## 5. 共享与隔离

可以共享：provider、Run Contract、Context Gateway、source manifest、CreativeArtifact、blob 存储、通用版本/导出设施。

不得共享为同一数据：短篇正文与长篇正文、剧本场景与小说章节、漫画 panel 与上层产品 scene、漫画媒资与世界引擎、各产品候选和 release。

三项产品可以在不同分支并行开发。分支必须从同一治理基线创建，并只拥有本产品的数据与生产链；若剧本和漫画共同需要改编来源冻结、source manifest 或基础类型，先把确实共享的最小契约做成独立基础提交，再分别实现场次与页格。不得在两个产品分支各自复制并改造一套 adaptation 核心，最终依赖 Git 手工拼接。
