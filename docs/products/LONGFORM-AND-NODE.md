# 分步骤长篇与节点模式产品契约

> 版本：1.3.0 · 生效：2026-09-14 · 对应总纲：§4.1、§4.2、阶段 B

## 1. 产品关系

分步骤长篇是独立核心产品，不以世界引擎为前置。节点模式不是另一款长篇后端，而是把同一生产过程表示为可见、可连接、可替换和可复用的节点图。它在操作表达上比标准步骤更自由、更细粒度、更可视和可调，是同源能力的编排超集。

```text
同一领域能力 / Skill / 数据 / Harness
├── 分步骤 UI：经过设计的标准路径
└── 节点 UI：显式 DAG 与用户自定义组合
```

两种操作表达必须能读写同一个长篇作品，不能分别拥有一套世界观、角色、大纲、正文或记忆。

现行 Phase 5 已完成分步骤长篇的工程主链与验收基线。后续真实作者长期文学研究、模型升级和缺陷修复不把这条主链重新定义为“尚未完成”；官方节点 action 与正式长篇后端的同源约束也已进入机器登记和架构门，完整跨模式 UI/生命周期体验继续作为节点产品维护事项。

## 2. 分步骤长篇范围

完整长篇至少覆盖：

1. 项目名称、创作目标、题材、规模和作者约束；
2. 世界观：起源、自然、人文、种族、势力、地点、历史、规则、多世界关系；
3. 故事：主题、核心冲突、叙事策略、主线和支线；
4. 角色：角色卡、关系、物品、状态、知识和生命周期；
5. 大纲：全书、卷、章；
6. 细纲：场景、目标、节拍、视角、承接和伏笔；
7. 正文：生成、续写、选择编辑、扩写、重写、润色、审校、采纳与版本；
8. 长程工程：事实、事件、关系、时间线、主支线进度、伏笔、原文、摘要、索引、影响分析；
9. durable 运行：候选、刷新恢复、stale、拒绝/采纳、post-state 和下游生效。

用户可以自由决定先写世界、角色或故事；生成时按当前已确认内容适度联动，项目标题只作轻权重创意提示，不能把空白生成变成标题解释。

## 3. 单字段/切片生成合同

以“种族与民族”为代表的所有分步骤字段统一遵守：

```text
保存当前人工输入与补充说明
→ 建立当前作用域和 revision
→ 读取目标字段、相关目录与按需证据
→ 选择 create / expand / rewrite / polish
→ durable 生成候选
→ 展示候选与运行证据
→ 作者编辑、拒绝或采纳
→ stale 检查 + adopt
→ 回读字段、触发索引/事实/下游失效与重建
```

- 空项目：允许 AI 自主创造，标题低权重。
- 有关联内容：作为约束和启发，不要求围绕已有句子重复描述。
- 扩写/润色：展示原版和新版；事实硬验证按风险开启，不以字符 diff 冒充语义。
- 重写：允许整体替换，清楚标为新版候选。
- 非法 JSON：保留原始输出，schema 解析，至多一次定向修复。
- 超长：尊重用户长度合同，仍受模型/运行预算和持久化保护。

同一领域的同类字段共用注册表驱动配置和生成组件/用例族；故事、角色等不同领域可以拥有各自专业 Skill/adapter，但不得让每个面板再维护手写来源清单或绕过共同 Harness。

## 4. 主支线与持续演化

主支线是长篇领域数据，不是上层游戏运行日志。它们与角色、大纲、细纲和正文双向关联：

- 规划阶段可由故事/角色生成主支线；
- 大纲与细纲把故事线分配到卷章场景；
- 正文采纳推进状态、暴露偏差并提出未来影响候选；
- 新角色和新支线可以随故事发展显式加入；
- 影响只向未来传播，已确认历史不被后台静默改写。

持续演化由有限、可恢复的规划/采纳周期组成。每次变更保存来源、影响范围、作者决策和下游 stale。

## 5. 百万字目标

百万字支持依赖分层记忆与检索，不依赖把全文塞进上下文：

- 原文永久可回查；
- 事实/实体/关系/事件/主支线结构化；
- 章节、卷和全局摘要可重建；
- Context Gateway 先目录后详情，长尾事实可按需召回；
- 伏笔、用户锁定和关键约束有高优先级但仍保留原文来源；
- 生成记录实际读取和遗漏，不把裁剪当不存在；
- 规模、召回、时间、预算和真实文学一致性分开验收。

只有基础设施、合成规模门、真实模型纵切面和长期作者项目都提供证据时，才能宣称“真实支持百万字长篇”。

## 6. 显式派生世界

长篇保持独立 owner，但作者可以选择“基于当前作品创建世界草稿”或“将当前作品封存为世界版本”。系统自动选取并投影已确认的世界观、故事、角色、主支线、大纲、细纲、正文和事实，用户不需要复制粘贴。

派生必须保存来源作品、来源 revision、选取范围和 content hash；原长篇继续独立，后续修改只在作者再次发起派生/发布时形成世界新候选或新版本，不自动改写旧世界。

## 7. 节点模式合同

节点至少声明：type/version、owner、输入/输出类型、required sources、allowed writes、作用域、依赖、资源预算和运行证据。图执行前检查循环、缺输入、类型、作用域和未登记权限。

官方分步骤流程应能导出为官方节点模板。节点调用领域 action/Skill，不复制 UI 组件内部逻辑。节点产物通过统一候选/采纳链；运行图和 checkpoint 可以独立保存。

跨模式验收：

1. 分步骤创建的数据可被节点读取；
2. 节点生成并采纳的数据在分步骤 UI 显示；
3. 版本、stale、导入导出和删除一致；
4. 同一动作无第二套 Prompt、AI 请求、DB 表清单或字段映射；
5. 非法连线在调用模型前被阻断。

## 8. 当前完成裁决与持续质量边界

分步骤长篇 Phase 5 工程基线已经满足：

- 世界观、故事、角色、大纲、细纲、正文的代表性纵切面均真实跑通；
- 主支线持续演化进入规划、正文和未来影响链；
- 所有正式 AI 字段由注册表配置，不存在手写来源遗漏；
- 刷新恢复、stale、拒绝/采纳、作用域隔离和下游生效有 E2E；
- 10万/30万/100万字符工程规模门与长尾召回通过。

真实作者长期项目继续记录文学一致性、修改量、召回缺陷和模型差异，但属于质量研究，不是重复建设功能的 backlog。节点正式模板已经禁止通用生成 fallback，实验节点只能产生不可采纳 Canon 的草稿；节点产品仍需以跨模式真实 UI、非法连接、stale、导入导出、删除和恢复 E2E 完成自己的体验验收。


## 9. 长篇工作台与主 Agent 接入

独立长篇生产入口为 `/long` 作品库及 `/workspace/:id`。一级导航为作品库、长篇工作台、版本与导出、派生世界、文档导入、社区与发行、通用设置。工作台内部提供分步骤、节点创作、Agent；分步骤的创作及辅助模块纵向排列于页面内左侧，各模块原有分栏为三级导航。导航切换先提交待保存编辑。未选择作品时，各一级区域、创作模式和分步骤目录仍可从 `/long?section=...` 直接浏览与刷新，展示对应功能和真实空态，不创建占位作品、不自动选中第一部作品。执行编辑、生成、导入、导出等依赖 Work 的操作时才明确选择或创建作品，并保留目标功能页；通用 AI 设置与用量统计直接开放。首页整体改版另行实施。

长篇页面不提供将当前作品切换为短篇的快捷入口。

三种表达读取同一 Work 的正式数据。作品标题等元数据仍归 Work；长篇自身 World 保存其设定和角色，作品不要求选择外部世界引擎。派生世界按第 6 节独立复制并记录来源，社区与发行目前提供真实的派生版本与本地分享包，未实现的在线社区发布、收入和浏览统计不得用样例冒充。

### 9.1 需求会谈与分阶段执行

- 需求会谈读取当前作品状态及当前作用域内的历史对话，仅产生回复或计划预览。作者确认计划才允许执行，计划草案不能直接提交领域生成。
- 长对话可由作者明确保存需求摘要。规划读取最新已确认摘要及其后的对话，原消息和候选完整保留；保存摘要不调用模型，并使旧的待确认计划失效。
- 同一领域可连续承担不同字段任务。任务依赖于前序已采纳内容；同一轮的大纲与正文不会因领域去重而丢失。已有角色补充必须冻结明确角色和字段，指定不存在的章节不得偷偷回退到其他章节。
- 场景细纲复用分步骤的正式 Skill、上下文、CreativeArtifact、固定目标与采纳链，结果回到对应章节细纲。
- 每个持久化阶段至多推进一份正文候选；后续任务保存在会谈中，本阶段终验后恢复为待确认计划。跨章节前检查上一章已创建的章后运行状态。阶段终验不是整本作品完成。
- 正文采纳后复用编辑器同一章后执行器和 Work 的 off / suggest / auto-with-budget 策略，记录真实父 Run、终态 receipt 和正文 hash；整理候选仍由作者采纳。刷新恢复只重建交接或显示既有运行，不自动重发模型请求。
- 全书进度来自实际设定、人物、卷章、细纲和正文，不能由“某次 Agent 运行完成”推算。版本与导出提供明确的全书验收：检查章纲覆盖、空正文、结构异常和待处理运行，作者核对目标、结局与修订后确认完成并备份。此入口不会替作者判断文学质量，概况中的人工状态标签也不等价于验收证据。

### 9.2 精细分块章纲与稳定采纳

精细生成的卷、作用域、revision、章节数、分块数和作者补充约束在启动时固定；方向选项及选定结果持久化，每块正式章纲进入共用 Outline Harness，保存真实模型响应与累积候选之间的可验证关系。刷新可继续已有预览，失败不会用占位章纲或虚构评分伪装完成；恢复和重试由作者显式触发。最终采纳仍经注册字段、固定卷目标与 stale 检查。

方向备选属于已登记的受限创意草稿，不等价于正式 Canon。旧章纲审校固定章节标识及原内容/排序/父级快照；审校期间章节变化时拒绝旧候选，防止写入当前切换后的章节。

### 9.3 验收证据与边界

`R-LONGFORM-*` 覆盖计划边界、作用域、固定目标、错误章节、细纲采纳、章后父子关系及恢复、分块候选恢复/采纳、全书覆盖与内容变化拒绝。`tests/e2e/longform-integration.spec.ts` 验证作品创建/保存/刷新、会谈不启动生产、精细章纲分段刷新恢复及最终采纳；既有核心和节点浏览器回归继续验证同源路径。

模拟模型回归证明工程流程，不证明真实模型的文学质量、整书无人值守生产或在线社区已经可用。节点实验能力继续遵守第 8 节边界，不能因新外壳而被提升为正式能力。

### 9.4 反馈修复边界

世界设定请求中用于说明规则的角色提及，不等价于创建或修改角色的授权；只有明确的角色动作才进入混合领域计划。大纲列表在内部拖动靠近上下边缘时滚动当前所在列表，拖动结束、取消或离开页面时停止；跨卷、章纲与正文仍复用原有排序和 owner。正文列表提示章节增删与排序位于“大纲与章纲”。

文档分块解析保持现有导入会话、来源与写入链。DeepSeek 的结构化抽取显式请求 JSON 对象与非思考模式，避免有限输出预算全部耗在推理中；其他调用保持原有模式。依据 [JSON Output](https://api-docs.deepseek.com/guides/json_mode/) 与 [Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/) 契约，空回答仍可能发生，不能以“已消耗 token”判定解析成功。截断、空回答、非法 JSON、授权/限流或网络结果未知时停止，不自动重发，也不继续收费解析后续块。明确的 503 服务繁忙仍保留最多三次尝试。失败块、已完成块与诊断持久化，作者修正配置或输入后可手动重试并继续未处理块；已成功内容不重复写入。日志提供响应形态和结束原因，不输出私稿、回答全文或推理文本。

连接测试将网络/CORS 与已收到的 HTTP 授权错误区分。自定义中转站须由服务端允许当前网页 Origin、OPTIONS 预检及 Content-Type/Authorization，或由部署者配置同源反向代理；内置本地代理只面向注册的官方目标，不是任意地址转发器。部署站点不承诺开发代理可用，也不建议关闭浏览器安全校验。
