## 1. 一页结论

### 1.1 长期愿景

**愿景**：建立一个由 AI 支撑的文字开放世界叙事基座。玩家可以在完整世界中扮演角色，经历贯穿全局的主线、多个重要故事线、大量普通支线、地域性内容与随机事件，在成长、探索和选择中不断获得新的冒险。

这里借用《巫师 3》《荒野大镖客》《对马岛》等开放世界作品，是为了说明期望的内容层级、世界感和任务生态，不是承诺达到 3A 游戏的叙事密度、手工完成度或制作规模。产品的核心优势应来自文字交互、AI适配和内容供给，而不是画面表现。

最终愿景还包括：玩家通过自由输入创造原计划之外的行动、任务、地点和世界变化，使游戏从“在既定世界中自由行动”逐步演进到“世界能够持续响应并扩展”。

### 1.2 当前阶段目标

**当前决策**：第一阶段先实现“有边界的自由演绎”。

- 游戏创建时，提前规划完整大地图、主线、重要支线与区域内容基础；
- 玩家扮演一个由用户设定或从世界引擎选择的主角；
- 首阶段以系统提供的动作和任务选项推进确定性流程；玩家仍可自由输入文字，AI负责自然回应、解释边界并引导回可执行选项；
- “任务目标固定、玩家提出未预设解法”保留为后续增强，不作为首阶段主路径；
- 主线核心目标和关键世界约束受到保护，当前不允许自由输入把游戏彻底改写成另一款游戏；
- 战斗与局部行动可以失败、读档、复活或换路线，但主线不能因一次非预期输入永久断裂；
- 玩家可以同时持有大量任务，也可以长期搁置主线去体验支线；
- 主线会等待玩家，不以时间压力强迫推进；其他地区、普通任务、限时任务和NPC事件可以随世界时间继续演化；
- 主线首阶段采用严格顺序任务链，但在构建时可以设计多个均符合核心目标的结局；
- 当前不优先支持玩家即时创造新地图、自由创建新任务、无限扩展世界或彻底改变主线阵营；
- 普通任务可以拥有截止期限并在到期后消失；主线和重要支线不可放弃，也不依赖这种期限推动。

### 1.3 最核心的职责原则

**当前决策**：

> 结构化资产保存“游戏里有什么”，确定性代码保存“游戏现在是什么状态”，AI负责“接下来可以怎样创作和怎样演绎”。

模型不是等级、经验值、背包、任务阶段或世界事实的权威来源。AI生成的任务、行动和后果先成为候选，经过结构校验与规则判定后，才冻结成正式可运行内容或写入玩家存档。

## 2. 产品边界

### 2.1 与其他文字游戏的区别

StoryForge 当前至少区分三种不同的文字游戏体验：

- 文字冒险：重点是情境、行动、判定、资源和状态推进；
- AVG：重点是场景、对白、分支、演出和视听呈现；
- 文字开放世界：重点是持续世界状态、探索、任务生态、区域内容、角色反应和开放演化。

文字开放世界可以复用共享的叙事、任务、角色互动、保存和媒资能力，但不能只是给已有文字冒险增加一个 `type` 开关。

### 2.2 与世界引擎的边界

**当前决策**：文字开放世界是独立上层产品，不是世界引擎内部的一个功能页。

- 世界引擎提供冻结、可版本化的世界来源；
- 游戏生产阶段读取该版本中的世界观、地理、历史、角色、组织、规则和故事来源；
- 产品自行拥有游戏 Brief、地图投影、任务内容、数值配置、媒资、Build、ProductRelease 和玩家存档；
- 玩家成长、物品、任务结果、私域关系和运行事件只属于该游戏实例；
- 运行结果不得自动回写或污染世界引擎。

用户也可以创建不依赖既有角色的主角，但正式生成游戏时，仍需把该主角冻结进本游戏实例。

### 2.3 生产阶段与运行阶段

```text
冻结的世界版本 + 用户的游戏设定
                │
                ▼
          游戏生产阶段
  世界投影 / 主线 / 重要故事线 / 区域包
  任务资产 / 成长规则 / 表现与质量检查
                │
                ▼
       Build → 可玩预览 → ProductRelease
                │
                ▼
           游戏运行阶段
 玩家输入 → 行动判定 → 内容调度 → AI演绎
        → 状态结算 → 事件记录 → 存档
```

生产阶段负责把一个世界变成可玩的游戏；运行阶段只能引用冻结发布并产生该玩家自己的运行历史。

## 3. 目标体验

### 3.1 玩家应该感受到什么

**当前决策**：首阶段至少要让玩家感受到：

1. 世界在游戏开始前已经存在，而不是玩家走到哪里才临时编出哪里；
2. 游戏有明确、可长期推进的主线；
3. 重要人物、势力和地区拥有能持续发展的故事；
4. 地图上有足够多与地域相关的活动，而不是只有主线节点；
5. 玩家的等级、装备、技能、物品和历史行动会影响后续内容；
6. 玩家可以用自己的话与系统交流；首阶段由AI自然回应并把玩家引回正式选项；
7. 玩家离开主线一段时间仍有事情可做，主线等待玩家，世界中的其他内容继续前进；
8. 已发生的重要结果在后续会被记住，普通内容不会无限占用上下文。

### 3.2 当前不是要实现什么

**当前决策**：首阶段明确不把以下目标作为验收前提：

- 达到《巫师 3》等大型商业游戏的手工叙事质量和内容规模；
- 允许玩家从一句话即时创造任意新大陆、新规则或完整任务系统；
- 允许玩家永久推翻游戏的主线核心目标；
- 让自由文字直接创造任务表中不存在的新解法并改变正式状态；
- 让全部NPC全天候独立思考和持续运行；
- 让多个常驻Agent各自保存一份世界状态；
- 在创建游戏时写完所有普通NPC、所有地点内部和所有任务正文；
- 把一切人物小传、性格、关系和世界语义拆成独立数据表。

## 4. 叙事内容层级

### 4.1 主线

主线负责给整场游戏提供长期方向、阶段目标、世界展开顺序和最终收束。

当前主线需要同时定义：

- 核心目标：玩家最终必须面对和解决的问题；
- 必经阶段：首阶段采用严格顺序任务链，明确为了形成完整体验必须经过的叙事阶段；
- 可变空间：构建时可以设计多个符合核心目标的结局，并由玩家条件与选择决定最终进入哪一个；
- 保护边界：当前阶段不允许被自由输入永久推翻的事实；
- 关键保护：关键NPC采用中立、不可被玩家杀死等保护；关键道具不可丢弃，暂不设计替代角色或替代线索；
- 时间策略：玩家不推进时主线等待，不通过倒计时、环境恶化或强制提醒施压。

### 4.2 重要故事线

“重要支线”不能只理解为绑定某个配角的个人任务。它至少可以有四种归属：

| 故事线类型 | 主要对象 | 示例性质 |
|---|---|---|
| 角色故事线 | 一个或多个重要角色 | 个人命运、关系、复仇、救赎 |
| 势力故事线 | 组织、阵营、家族或群体 | 权力争夺、战争、改革、分裂 |
| 地区故事线 | 一个地区及其居民 | 灾难、衰败、重建、地方命运 |
| 主题/事件故事线 | 一项跨地区问题或长期事件 | 疫病、贸易危机、宗教运动、异象 |

**讨论假设**：势力和地区故事线不需要持续模拟所有成员。结构化资产保存各方目标、资源、阶段和关键角色；代码保存局势变化；AI选择少量代表人物、传闻、场景和任务，把宏观冲突转化为玩家可参与的具体内容。

### 4.3 区域内容

区域内容负责让不同地区拥有独立主题、矛盾、生活感和任务生态。玩家进入或接近某个地区时，系统根据以下条件选择可发内容：

- 当前区域和具体地点；
- 玩家等级、能力、装备和资源；
- 主线与重要故事线阶段；
- 地区当前局势；
- 近期已玩内容、冷却和重复指纹；
- 当前已有任务和叙事节奏；
- 可用角色、组织、地点和奖励；
- 与其他任务是否冲突。

这就是本轮讨论中的“区域化发牌”。它不是纯随机抽任务，而是在规则约束下从区域内容池选择或组合候选。

### 4.4 普通支线与随机事件

普通内容分为三种来源：

| 来源 | 生成时机 | 主要作用 |
|---|---|---|
| 固定内容 | 游戏创建与正式生产时 | 保证主线、重要故事线和关键探索的质量 |
| 半生成内容 | 提前建立母题和约束，运行时实例化 | 以较低成本形成稳定的大量支线 |
| 即时内容 | 进入场景或发生行动时 | 提供旅途遭遇、路人事件和环境反应 |

完全固定会缺乏体量，完全即时会缺乏连续性。当前方向是让三者共同构成内容供给。

随机任务仍然是大世界中的小型故事：不同NPC提出不同需求，或形成寻宝、资源获取等成长内容。底层玩法可以复用，但每次需要结合地区、人物、时间和玩家状态包装成不同的小故事，避免只更换名称的机械重复。

### 4.5 首阶段任务系统框架

**当前决策**：任务至少需要从四个互不替代的维度分类，不能只用“主线/支线”一个字段承担全部逻辑。

| 维度 | 建议分类 | 决定什么 |
|---|---|---|
| 叙事等级 | 主线、重要故事线、普通支线、随机任务/事件 | 内容质量、保护强度、是否长期记忆 |
| 内容归属 | 全局、角色、势力、地区、地点 | 读取哪些上下文、由谁发放、影响哪里 |
| 时间策略 | 等待玩家、限时、周期性、即时消失 | 是否推进、过期以及何时关闭 |
| 生命周期策略 | 不可放弃、可放弃可重接、永久失败、完成后冷却/不再出现 | 玩家能如何处理任务 |

首阶段约束如下：

- 主线：严格顺序、不可放弃、等待玩家、核心目标受保护、允许多个合规结局；
- 重要故事线：不可由玩家主动放弃，长期保存，由角色、势力、地区或事件持有；它属于会随世界继续演化的非主线内容，具体怎样变化或失败仍需结合故事设计；
- 普通支线：允许放弃、永久失败或限时过期；不限时任务放弃后可以按原途径重新接取；
- 随机任务：根据地区、NPC和玩家成长需求产生，每次有不同故事包装；完成、失败或过期后保留必要回执与去重指纹；
- 随机事件：如果只是一次遭遇，不必进入任务日志；如果产生多步目标，再升级成任务实例。

任务运行建议明确区分以下逻辑对象，但这不代表必须建立同样数量的物理表：

```text
故事线/区域内容意图
        ↓
任务定义：任务为何存在、属于谁、有哪些阶段和结果
        ↓
可用性：何时可见、由什么NPC/地点/事件发出
        ↓
任务实例：某个玩家实际接到的版本、期限和当前阶段
        ↓
目标/步骤：首阶段以预设选项和确定性条件推进
        ↓
结果：完成、失败、放弃、过期及其奖励和世界影响
        ↓
事件回执：永久保存真正产生影响的事实
```

建议任务状态机为：

```text
未开放 → 可接取 → 已接取/进行中 → 已完成
                         ├→ 已失败
                         ├→ 已放弃
                         └→ 已过期
```

代码根据任务等级和策略禁止非法迁移，例如主线不能进入“已放弃”或“已过期”。AI负责生成任务内容和演绎文本，不负责决定任务是否真的完成、发放奖励或修改世界状态。

## 5. 有边界的自由演绎

### 5.1 当前自由度定义

**当前决策**：首阶段是“表达自由、执行受限”。玩家可以自由输入文字，AI应当自然回应；正式推进任务、战斗、移动、交互和状态变化时，仍主要依靠系统给出的可执行选项。

玩家输入至少需要被区分成四类：

| 输入类别 | 当前处理原则 |
|---|---|
| 已有明确动作 | 由代码直接判定和执行 |
| 有合理意图但没有正式选项 | AI承接对话并推荐当前最接近的可执行选项，首阶段不直接创建新规则动作 |
| 当前条件不足 | 明确说明条件不足，并给出已有的前置任务或替代选项 |
| 完全不合理或破坏核心规则 | 系统可以直接说明不能这样做，也可以用简短的世界内理由阻止，再引导回主路径 |

### 5.2 主线保护不是只允许一种解法

例如主线核心目标是“成长后拯救一个国家”：

- 玩家可以长期搁置主线、探索世界和完成支线；
- 玩家可以在已制作的剧情范围内选择不同关系、局部路线和结果；
- 玩家可以在战斗中失败并重试；
- 但首阶段不允许系统把游戏永久演化成“帮助反派毁灭国家并放弃原主线”。

**当前决策**：首阶段不设计拒绝关键NPC、杀死关键角色、丢失关键道具或加入敌对势力后继续主线的复杂恢复体系。关键NPC受保护，关键道具不可丢弃。主线保护可以按以下顺序处理：

1. 承接玩家意图中合理的部分；
2. 优先推荐当前正式存在的任务或行动选项；
3. 用角色和剧情反馈把玩家引导回主线或现有支线；
4. 无法合理承接时直接说明该行为当前不可执行。

### 5.3 非预设解法属于后续增强

**愿景已确认，首阶段暂缓**：长期希望实现“任务目标固定，但玩家可以提出任务表中没有的解决方法”。用户认为这项能力高度依赖模型理解、行动Schema、规则映射和状态安全，当前先把预设流程跑通。

```text
玩家输入：我想从排水渠潜入城堡
        │
        ▼
AI解释为候选行动
潜入目标 / 方法 / 前提 / 风险 / 资源消耗 / 可能效果
        │
        ▼
代码检查
地点是否连通 / 是否有工具 / 能力是否足够 / 是否冲突
        │
        ▼
冻结并执行结果
        │
        ▼
AI根据已确定结果生成演绎文本
```

这仍然是产品未来相对于传统固定选项文字游戏最重要的能力之一。进入后续阶段前，至少需要行动Schema、权限与资源校验、影响预演、可回滚提交和专项Harness；不能仅凭模型的一段自然语言直接修改正式状态。

## 6. 完整世界与渐进展开

### 6.1 “创建时就有完整世界”的含义

**当前决策**：游戏地图不能脱离来源凭空设计。产品的数据基座可能是世界观，也可能是小说；生产流程必须先从冻结来源中拆解事实和故事素材，再把主线、重要故事线、支线与游玩内容设计出来，最后据此编译出服务于游戏的可玩地图。

```text
冻结世界观 / 小说
        ↓
提取地点、角色、势力、事件、规则与故事事实
        ↓
设计游戏主线、重要故事线和内容体量
        ↓
拆解任务、场景、活动、成长与旅行需求
        ↓
形成游戏区域、地点、道路和内容分布
        ↓
检查来源忠实度、故事可达性与预计游玩时长
```

因此，地图既不是照抄世界引擎已有地理，也不是独立于故事的地图生成器产物，而是来源语义经过游戏叙事和玩法需求转换后的“可玩地图投影”。故事内容越完整，地图上需要承载的区域、地点和活动也越明确。

游戏创建完成时，应当已经拥有完整大地图和主要内容规划。主线从其中一个地区开始，随后逐步把世界展现给玩家。

“完整”当前理解为：

- 主要地区及其空间关系已经确定；
- 核心城市、聚落、道路、地标和危险区域已经确定；
- 每个地区的主题、氛围、势力、矛盾和任务潜力已经确定；
- 主线与重要故事线如何穿过世界已经规划；
- 地区之间的内容密度和成长阶段已经规划；
- 未到达地区不是临时从空白中生成的新世界。

但这不要求创建时把每栋建筑、每个路人和每次随机遭遇全部写完。

**当前决策**：首阶段需要用内容时长反向检查生产结果。例如，一个目标为一至两小时的主线段落，连同支线、随机事件和探索，应当能够支撑约定的数小时游玩，而不是只生成一段故事概述和几个地名。具体体量标准将在首个小型验收世界中校准。

### 6.2 建议的分辨率

**讨论假设**：可以把世界内容分成四级分辨率：

| 层级 | 创建时状态 | 玩家接近后 |
|---|---|---|
| 世界图 | 完整存在 | 通常不改变拓扑 |
| 区域包 | 主题、冲突、势力、核心地点和故事钩子完整 | 加载当前区域状态与内容池 |
| 地点内容 | 关键地点详细，普通地点有摘要和功能 | 按需要补齐场景、人物和互动 |
| 当前场景 | 不必提前写正文 | 根据冻结事实和玩家状态即时演绎 |

后续允许用户创造新地区属于长期愿景，不进入首阶段范围。

### 6.3 探索、触发与地图交互

**当前决策**：玩家可以提前前往尚未被主线介绍的地区。因此，主线和重要故事线不能只以“第一次到达某地点”作为唯一触发条件。玩家提前到达时看到该地点的普通状态；只有任务阶段、关键交互、角色状态等条件同时成立时，才进入正式剧情场景。

**讨论方案，待通过原型选择表现形态**：首阶段优先采用分层地图，而不是立即制作完整像素移动游戏。

1. 世界/区域层使用程序生成的 SVG 或节点道路图，展示已知地区、地点、道路和快速旅行点；
2. 玩家点击地点设置旅行目标，系统沿已知路线推进世界时间并有机会触发旅途事件；
3. 到达地点后进入文字场景页，通过地点、角色、任务和功能选项交互；
4. 玩家首次正常到达一个区域后解锁该区域的快速旅行点；
5. WASD控制像素小人、碰撞、建筑内部和逐格探索作为后续表现升级，不作为首阶段完成条件。

这种方案保留了“地图可看、地点可点、旅行有过程”的开放世界感，又不要求在第一阶段同时建设像素美术、寻路、碰撞和空间关卡系统。

### 6.4 时间、天气与旅行

**当前决策**：

- 世界需要昼夜与天气；
- 主线等待玩家；重要故事线、地区局势、普通世界事件、NPC事件和限时任务等非主线内容随世界时间继续演化；
- 普通旅行不设置饥饿、体力或口粮等持续消耗；
- 战斗会消耗生命、技能资源或物品等战斗资源；
- 每个区域设快速旅行点，玩家至少正常到达过一次后解锁；
- 快速旅行是否推进时间、是否触发中间事件仍需在运行规则中确定。

## 7. AI、结构化资产和确定性代码

### 7.1 职责总表

| 系统 | AI负责 | 结构化资产负责 | 确定性代码负责 |
|---|---|---|---|
| 用户设定 | 会谈、理解意图、补充缺口、提出候选方案 | Brief、目标规模、边界、完成条件 | 必填项、预算、版本和确认状态 |
| 世界接入 | 解读冻结世界并提出选材方案 | 来源 Manifest、世界版本、实体映射 | Hash、引用完整性、版本锁定 |
| 主线 | 主题、冲突、阶段、场景和替代路线候选 | 主线骨架、阶段、保护目标、关键事实 | 解锁、推进、恢复、状态迁移 |
| 重要故事线 | 人物、势力和地区故事设计 | 故事线归属、阶段、参与者、交叉节点 | 触发、并发、关闭和后果提交 |
| 区域内容 | 区域故事、任务候选和情境适配 | 区域包、内容池、母题和限制 | 资格过滤、发牌、冷却和去重 |
| 玩家行动 | 首阶段理解自由输入、自然回应并引导到正式选项 | 动作类型、选项、需求、效果和表现模板 | 可达性、数值判定、资源变化和事务 |
| 成长与物品 | 提出体验和奖励语义建议 | 等级、技能、物品和奖励配置 | 经验、属性、库存、装备和结算 |
| 战斗 | 战前/战后叙述、每回合结果演绎 | 敌人、属性、技能、装备、掉落与战斗配置 | 回合、伤害、暴击、技能触发、逃跑和胜负 |
| 制作 | 生成符合世界观的物品说明和配方候选 | 配方、材料、产物、条件与品质规则 | 材料扣除、成功判定、产物入库和防重复提交 |
| 关系与阵营 | 根据当前关系层级生成相符的态度、问候和对白 | NPC阵营、态度文案范围与交互内容 | 道德值、阵营亲合度、关系档位和资格判断 |
| 时间与环境 | 描写昼夜、天气和环境影响 | 时间段、天气类型、地区表现和事件规则 | 世界时钟、天气迁移、期限和事件调度 |
| 对话与场景 | 角色演出、叙述、对白和局部适配 | 风格、知识边界、场景事实、媒资绑定 | 可见信息、轮次、保存和失败恢复 |
| 连续性 | 发现语义冲突、生成修复候选和摘要 | 关键事实、承诺、伏笔、后果记录 | 唯一事实源、事件序列、版本和引用 |

### 7.2 表格不是越多越好

**已修正**：曾把角色外观、性格、社会身份、关系、知识、日程、对话、任务绑定、UI、声音等拆成大量独立角色表。这种做法混淆了“机器必须查询和关联的数据”与“适合存在于人物小传中的创作语义”。

当前原则是：

- AI创建正式游戏内容时，不应只交付一段自然语言，而应形成可校验的结构化候选；
- 只有需要稳定查询、引用、筛选、状态迁移、结算、版本化或媒资绑定的数据，才应成为表或结构化字段；
- 人物性格、社会经历、关系背景等可以集中存在于人物档案或小传中；
- 当某个语义真的参与运行判定时，再提取必要的最小字段，而不是预先为每种语义各建一张表；
- “逻辑对象”不等于“物理表”，多个对象可以在同一聚合、文档或表中表达；
- 最终表清单必须根据产品契约、当前代码、查询路径和生命周期决定，不能根据名词罗列。

当前只能确认需要表达以下逻辑数据，尚不能据此断言需要多少张物理表：

- 游戏与冻结发布；
- 世界地图、区域、地点与连接；
- 主线、重要故事线及阶段；
- 任务定义、任务实例和运行状态；
- 区域内容池、触发与发牌规则；
- 玩家能力、成长、物品和资源；
- 关键事实、选择、后果和事件记录；
- 角色、势力、地区与上述内容的引用绑定；
- UI和媒资在产品中的绑定。

正式数据设计必须等本轮产品问答收敛，并在世界引擎清理完成后重新审计现有实现。

## 8. Agent、Skill与运行调度

### 8.1 从“多个常驻Agent”到“职责化工作流”

早期设想包括：一个Agent负责主线、一个负责重要支线、多个Agent分别绑定地区，以及一个或多个Agent持续统计玩家状态。

当前修正为：

- 主线、重要故事线和区域内容可以由不同专业角色或 Skill 负责；
- 它们不必成为永远在线、分别保存记忆的自治Agent；
- 玩家状态必须由确定性服务和存档维护，不能由状态Agent口头统计；
- 运行时由统一叙事导演读取当前状态，选择需要调用的专业能力；
- 区域可以拥有独立 Context Pack、内容池和生成策略，在玩家接近时按需加载；
- 主线和重要故事线NPC需要由Agent能力持续保持人物一致性和长期经历；这里的“持续保持”首先指档案、记忆、关系和故事状态可持久读取，不要求模型在后台永远运行；
- 普通NPC长期存在，但主要依靠日程、地点、功能、阵营和问候规则进行低成本程式化运行；
- 所有正式生成结果仍需通过同一状态机、引用校验和提交入口。

### 8.2 建议的生产角色

**讨论假设**：

- 产品主Agent：与用户会谈、确认目标、展示计划和最终交付；
- 总体叙事规划：统筹主线、重要故事线、世界展开和内容规模；
- 主线设计 Skill：形成长期骨架、保护目标和恢复路线；
- 重要故事线 Skill：设计角色、势力、地区等长程故事；
- 区域设计 Skill：生成区域包、地点用途、任务母题和在地冲突；
- 任务编排 Skill：把叙事意图转换成可执行任务候选；
- 一致性审查 Skill：检查世界设定、时间、角色知识、引用和因果；
- 修复 Skill：对缺口、冲突、重复和不可玩候选提出有限修复。

### 8.3 建议的运行角色

**讨论假设**：运行时不让多个Agent自行争夺控制权，而是形成单一入口：

```text
玩家选择正式选项 / 输入自由文字
  → 分类为可执行动作或自然语言回应
  → 正式选项进入确定性规则检查；自由文字由AI回应并推荐现有路径
  → 叙事导演选择：主线 / 重要故事线 / 区域任务 / 随机事件
  → 调用对应 Skill 生成候选
  → Schema、事实、预算、重复与可玩性检查
  → 冻结任务或行动结果
  → AI演绎
  → 代码结算并写入事件日志
```

### 8.4 NPC分层运行

**当前决策**：

| NPC层级 | 运行方式 | 当前要求 |
|---|---|---|
| 主线关键NPC | Agent能力 + 持久角色档案 + 主线状态 | 保持人格、知识、关系和长期情节一致；首阶段中立且受剧情保护 |
| 重要故事线NPC | Agent能力 + 持久角色档案 + 故事线状态 | 能承接个人、势力或地区长线内容，离场变化写入正式状态 |
| 普通常驻NPC | 确定性日程和功能规则为主 | 日出而作、日落而息、地点移动、功能服务、按态度档位问候；对话由玩家触发 |
| 临时事件NPC | 事件或任务实例内存在 | 只保留任务所需信息；产生长期影响时再升级保留级别 |

主线之外的世界需要继续前进，但不等于所有NPC都由模型逐回合模拟。普通NPC按规则推进，重要NPC只在相关时间点由调度器调用Agent能力并提交变化，可以在成本可控的前提下形成世界演化。

## 9. 状态、记忆与“玩过就忘”

### 9.1 权威状态

**当前决策**：以下内容必须由代码和结构化数据维护，而不是让模型记忆：

- 等级、经验、生命、能力和技能；
- 装备、材料、物品、货币和奖励；
- 当前地点、旅行状态和必要的世界时间；
- 任务接取、阶段、完成、失败、放弃和关闭；
- 世界、地区、角色和势力的已确认变化；
- 玩家道德值、阵营亲合度和NPC态度档位；
- 已经发放的内容、冷却、重复指纹和领取状态；
- 存档点、检查点、分支和事件序列。

### 9.2 三种保留级别

| 保留级别 | 内容 | 保存方式 |
|---|---|---|
| 长期 | 主线、重要故事线、关键角色命运、重大选择、永久世界变化、未兑现承诺 | 完整结构状态与事实账本 |
| 区域期/任务期 | 当前区域危机、活跃普通任务、本地角色状态、临时传闻和机会 | 活跃实例；阶段结束后压缩 |
| 可丢弃 | 纯气氛遭遇、无长期后果的小互动、具体演绎文本 | 删除正文或仅保留回执、标签、摘要 |

“用过就忘”只适用于没有长期后果的表达细节。只要一次小任务改变了资源、声望、人物关系、地区状态或未来可用内容，就必须保留最小事实残留。

### 9.3 大量任务与有限上下文

**当前决策**：玩家可以同时持有大量任务，但模型每次只读取当前行动需要的关联闭包，例如：

- 当前主线摘要；
- 正在追踪的任务；
- 当前区域内可以推进的任务；
- 与眼前角色或地点相关的任务；
- 最近发生的重要事件；
- 其他任务的压缩状态。

完整任务状态仍保存在存档中，不因本轮没有进入模型上下文而消失。

### 9.4 道德、阵营与NPC态度

**当前决策**：首阶段不建立过度复杂的角色心理模型。NPC先区分中立或带有阵营归属；其对玩家的态度主要由玩家道德值和对应阵营亲合度决定，并折算为三档：

- 态度好；
- 态度一般；
- 态度差。

三档态度可以影响问候、对话语气、是否愿意提供普通功能、部分任务或交易条件，但当前不得阻断主线推进。不同NPC或阵营应配置自己如何解释道德值，不能假设所有阵营都喜欢同一种“高道德”行为。

偷窃、欺骗和犯罪可以进入首阶段，并通过确定性事件修改道德值、阵营亲合度或局部NPC态度。正式加入敌对势力、使主线阵营永久翻转等更高自由度行为留待后续。

## 10. 失败、存档与任务连续性

### 10.1 当前已经确认的失败边界

**当前决策**：

- 等级、装备或战术不足造成的战斗失败是允许的；
- 玩家可以从存档或复活点恢复后重新尝试；
- 局部路线失败可以产生代价、替代目标或新的解决路线；
- 当前阶段不允许主线核心目标因自由输入彻底失败并永久关闭游戏方向；
- 普通支线允许永久失败，普通NPC可以因玩家攻击、自身剧情或随机事件死亡；
- 主线关键NPC首阶段受保护，关键道具不可丢弃；
- 主线和重要故事线不可放弃；普通支线可以放弃，不限时任务可按原途径重接；
- 限时普通任务在截止后自动过期并从可进行内容中关闭。

### 10.2 已由第三轮问卷收口的内容

- 重要故事线不会因玩家长期不参与永久失败，推进到安全点后等待；
- 战斗失败同时提供战前重试和复活点恢复；
- 复活不收取额外货币、时间或消耗品代价；
- 自动存档、战前检查点和有限手动存档并存，分支首版用列表展示。

### 10.3 首阶段战斗与非战斗交互

**当前决策**：战斗采用确定性的逐回合制。系统依据玩家和敌人的属性、技能、装备与状态完成结算；玩家每回合选择普通攻击、技能、道具或逃跑，暂不支持自由描述招式、瞄准部位或即时创造战术。

首阶段战斗需要覆盖：

- 基础属性，例如体质、力量、敏捷；
- 生命、攻击、防御、暴击等派生数值；
- 装备提供的攻击、防御和其他加成；
- 技能伤害、出手时机、多次出手和状态规则；
- 回合顺序、伤害、状态、胜负、逃跑、奖励与战斗失败恢复。

当前不完整照搬《龙与地下城》的属性和技能检定体系。更倾向于MMO式数值主要服务战斗；调查、说服、开锁等非战斗行为以场景交互和任务条件为主，必要时读取道德值、阵营亲合度或已有物品判断能否成功。

制作进入首阶段正常玩法范围，包括装备、药剂等内容。配方、材料、产物和条件属于结构化资产，材料扣除和产物结算由代码完成，AI负责符合世界观的说明和候选设计。

## 11. 阶段路线

### 阶段A：有边界的确定性开放世界

**当前目标**：

- 完整但有层级的大地图；
- 一条严格顺序、不可放弃、可以走向多个合规结局的主线；
- 多种归属的重要故事线；
- 固定任务、半生成区域内容和随机事件共存；
- 选项驱动的正式流程，以及能够自然回应并引导玩家的自由文字输入；
- 主线等待玩家，其他地区、NPC事件和限时任务随世界时间演化；
- 道德值、阵营亲合度和三档NPC态度；
- 确定性的逐回合战斗和基础制作；
- 确定性的移动、任务、成长、物品、判定、结算和存档；
- 统一叙事导演与区域发牌；
- 对主线、事实、重复、奖励和可玩性的质量门。

架构按完整产品设计，但先通过小型验收世界证明生产到运行的完整循环。具体地区数、任务数和目标时长仍需在验收定义中确定。

### 阶段B：更强的响应式世界

**愿景候选**：

- 重要NPC在有限范围内发生离场演化；
- 势力和地区局势根据玩家行为持续变化；
- 任务目标拥有未预设的语义化解法；
- 玩家能够攻击关键角色、拒绝关键路径或加入敌对势力，并由安全的替代路线承接；
- 区域内容能够根据玩家风格和成长缺口适配；
- 新任务链能够在保持既有事实的前提下增量生产。

### 阶段C：可扩展世界

**愿景候选**：

- 用户通过对话新增地区、组织、角色和长期故事线；
- 对已发布世界进行兼容性检查后形成新的游戏版本或实例扩展；
- 旧存档可以显式迁移，不静默改写历史。

### 阶段D：趋近无限自由的文字开放世界

**长期愿景**：

- 玩家能够超出原始设计形成新的目标和身份；
- 世界能够持续生成与既有历史一致的新内容；
- 主线可以被真正改变、替代或自然演化；
- 系统在成本、上下文和一致性边界内维持长期可玩世界。

这一阶段是方向，不是当前工程承诺。

## 12. 方案演进记录

| 阶段 | 当时的想法或问题 | 暴露的问题 | 当前处理 |
|---|---|---|---|
| 产品类型确认 | 先确认多种文字游戏的真实产品差异 | 如果只靠页面名称区分，会共享成一个膨胀模块 | 开放世界作为独立垂直产品，复用底层但拥有自己的生产、发布和运行 |
| 市场参照探索 | 调查 Voyage、类似AI文字游戏和开源项目 | 产品表现相似不等于工程结构可获得，也不等于适合本项目 | 市场和源码调研另建证据报告；本文只记录其对产品思考的影响 |
| 最初愿景表达 | 希望成为类似大型开放世界游戏的叙事基座 | 容易被误读为直接追求《巫师 3》级叙事质量 | 明确：参照的是叙事层级和世界生态，不是3A完成度 |
| Harness构想 | 从内容到字段、Skill、Agent和可玩内容形成完整生产体系 | 如果没有游戏运行数据结构，容易停留在纲要文档 | 保留Harness思想，但必须落到可验证的游戏资产、状态和运行结果 |
| 表格系统讨论 | 曾把角色语义拆成大量角色子表 | 人物小传、性格和关系背景不一定需要独立表；属于过度结构化 | 只结构化运行、查询、引用、结算和版本化真正需要的数据 |
| 游戏工程参照 | 希望研究 Godot、Unity、UE、星火、TapTap及开源游戏的数据组织 | 单个开源包或普通文字游戏结构不能代表开放世界叙事需求 | 后续调研必须以“能否支撑当前目标”为筛选标准，不能机械照搬引擎资源格式 |
| 第一版职责矩阵 | 按游戏阶段区分AI、结构化资产、确定性代码 | 方向有效，但混入旧残留和过早表设计时会显得混乱 | 保留三分法，按本轮重新确认的开放世界目标逐项重写 |
| 多Agent设想 | 主线Agent、重要支线Agent、区域Agent、状态Agent分别负责 | 常驻Agent容易形成多份真相；状态统计不可靠 | 专业职责转成可调度Skill/工作流；统一导演调度；状态由代码维护 |
| 内容保存设想 | 只长期记住主线和重要支线，小任务用过即丢 | 小任务也可能产生资源、关系和地区后果，完全遗忘会破坏连续性 | 小任务正文可丢，但有影响时保存最小事实回执和内容指纹 |
| 目标再次校准 | 不追求AI实现《巫师 3》，先支撑开放世界叙事基座 | 一步实现无限自由不现实，且会妨碍主路径验收 | 当前先做有边界的自由演绎，未来再逐步扩大世界可变范围 |
| 第一轮收敛 | 主线和世界提前确定，同时尽量承接玩家自由输入 | 如果首阶段就让自由输入产生正式新解法，行动和状态系统会过早复杂化 | 首阶段改为选项驱动正式推进；AI回应自由文字并引导回已有路径 |
| 第二轮主线收敛 | 曾考虑主线自由排序、替代角色和失败后继续 | 首个版本需要先证明最基础的完整流程 | 主线采用严格顺序；关键NPC和道具受保护；构建时允许多个合规结局 |
| 世界演化收敛 | 曾考虑用主线压力把离开的玩家拉回 | 用户希望自由探索，不被主线倒计时催促 | 主线等待玩家；非主线地区、NPC事件和限时任务继续演化 |
| 地图认识修正 | 曾先讨论地图需要生成到什么粒度 | 地图不是独立起点，来源可能是世界观或小说 | 先拆来源并设计游戏故事和任务，再反推可玩地图与内容分布 |
| 任务规则细化 | 早期暂不优先考虑限时任务 | 世界继续演化需要任务期限、失败和消失机制 | 普通任务可限时、放弃、重接、失败或过期；主线和重要故事线不可放弃 |
| 战斗范围收敛 | 曾讨论自由描述战术是否影响判定，并一度采用“继续/逃跑”的自动回合 | 自动回合缺少玩家决策感，自由战术又无法可靠计算 | 第三轮收口为确定性逐回合制，每回合选择普通攻击、技能、道具或逃跑 |
| NPC运行收敛 | 曾笼统讨论角色自治与持续模拟 | 所有NPC使用Agent成本高且没有必要 | 重要NPC由Agent能力保持；普通NPC用日程、功能、阵营和问候规则运行 |
| 实施策略确认 | 完整产品设计与小型原型之间尚未选择 | 直接按完整体量生成难以定位质量问题 | 架构设计完整产品，先用小型验收世界证明整个循环 |

### 12.1 本轮最重要的认知变化

1. 从“复刻某款3A游戏”变成“建立开放世界叙事基座”；
2. 从“无限自由”拆成“当前有边界的自由演绎”和“未来无限自由愿景”；
3. 从“AI直接写故事正文”变成“AI生成结构化候选，再由系统冻结和运行”；
4. 从“每种信息都建表”变成“只结构化机器真正需要的数据”；
5. 从“多个Agent分别记忆和运行”变成“统一事实源、按需调用专业能力”；
6. 从“小任务全部预写或全部即兴”变成“固定、半生成、即时内容组合”；
7. 从“完整世界等于全部内容一次写完”变成“完整地图与叙事潜力预建、局部细节渐进展开”；
8. 从“首阶段尝试自由解法”进一步收紧为“正式选项确定推进、自由文字自然回应”；
9. 从“先画地图再填内容”修正为“从世界观/小说到游戏故事、任务，再编译可玩地图”；
10. 从“主线和世界一起推进”细分为“主线等待玩家、其他世界内容继续演化”；
11. 战斗先从抽象讨论收口为自动回合，第三轮再修正为每回合选择普通攻击、技能、道具或逃跑；
12. 从泛化角色自治收口到重要NPC Agent保持、普通NPC程式化运行。
