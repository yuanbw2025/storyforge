# 13 · 首款旗舰游戏生产、实测与展示方案

> 层级：L2 · 版本：1.2.0 · 生效：2026-09-07
> 性质：从来源世界到社区候选的首次真实生产执行合同；不得以夹具、伪造回执或人工拼包替代。

## 1. 目标与边界

本阶段属于独立 `text-adventure` 产品的正式生产、发布、运行和候选展示纵切面。目标是在一个隔离项目中，从来源充分的冻结 `WorldRelease` 出发，经专业 Agent 团队生产一款约 60 分钟、可完整游玩、可保存恢复、可导入导出且有资格交给作者进行社区提交决策的文字冒险。

首款游戏暂定名为《潮钟群岛：最后的灯火》。名称可以在冻结 Brief 前调整；冻结后改名必须形成新 revision。它是新的正式生产，不继承 2026-09-06 失败 Build 的内容、质量结论或回执。旧 Build 只作为反例基线。

- 数据 owner：专用旗舰 Work 拥有 Brief、SourcePlan、生产、Build、媒资、Release、运行会话和存档。
- 世界 owner：专用 World 拥有设定语义与不可变 WorldRelease；不拥有上层媒资或玩家状态。
- 输入：实际世界条目、角色、地点、规则和事件材料，不使用空壳 WorldRelease。
- 输出：同一 lineage 下的正式 Build、ProductRelease、社区候选包和可展示玩家会话。
- 非目标：本阶段不实现调查盘、法庭、开放世界角色自治、AVG 舞台演出、多人和运行期动态出图。
- 外部发布：只生产 `eligible-for-community-submission` 候选；真正上传、公开和申请推荐须作者另行确认。

## 2. 旗舰内容契约

### 2.1 玩家承诺

玩家扮演群岛最后一名见习守灯人，在吞没记忆的雾潮到来前，修复贯穿两座大区的潮钟航路，并决定灯火应当保护谁、由谁承担代价。主线必须有明确开端、升级、逆转、高潮和余韵；三种以上结局必须由玩家实际行动链和持久状态导致，而不是末尾菜单换一句结局。

### 2.2 规模底线

- 目标实测：首轮主路线 45–75 分钟；作者主路线需记录真实起止时间。
- 空间：至少 2 个大区、4 个区域、8 个可到达地点、12 个有正文和行动的场景。
- 叙事：3 幕，至少 12 个非结局主线节点、3 个可解释结局。
- 主线可见内容：任一有效主路线不少于 12,000 中文内容单位；不得把规则说明、物品描述和不可达文本计入路线正文。
- 对话：至少 3 名正式 NPC、24 个对白轮次；任一主路线不少于 12 个对白轮次。
- 交互：任一主路线至少 10 次叙事选择、15 次主线推进动作、4 次持久状态决定；至少一次失败推进和一次同目标替代解法。
- 玩法：角色属性与成长、能力检查、生命/专注等资源、背包、装备、物品使用、主线任务、至少 2 条支线、至少 3 个区域事件、时间代价与任务 UI 均实际参与运行。
- 媒资：关键插图档至少包含封面、2 个大区图、3 个角色锚点、4 个关键场景和 2 个关键物品；纯文字路径仍须完整通关。

若模型产物只达到数量但重复、空泛、无因果或不可玩，质量导演必须判为不合格。规模底线不是质量上限。

## 3. 来源世界施工

世界资料必须先在世界引擎的正式入口建立并冻结，不允许直接向产品 Prompt 塞一份未登记的“设定大全”。最小来源闭包包括：

1. 世界核心命题、基调、禁用设定和玩家可知边界；
2. 两个大区及其区域、地点、通行关系和环境危险；
3. 三名主要角色的目标、恐惧、秘密、相互关系和知识边界；
4. 潮钟、雾潮、灯火、记忆代价等通用实体/规则的确定定义；
5. 开局前历史事件、当前冲突、时间压力和可能结局方向；
6. 可用于任务和物品的至少六个世界实体；
7. 世界 Constitution、来源版本、内容哈希和冻结时间。

`text-adventure-source-editor` 必须对实际 `describe/search/read` 结果判定充分性。若不足，只能暂停等待来源补全，或由作者显式接受产品私域补充候选；不得让下游 Agent 在没有证据时自行发明权威世界事实。

## 4. 专业团队实际生产顺序

每个岗位只运行登记的单一核心 Skill，模型调用分别留存 Run Contract、输入 manifest、候选、验证和 receipt。

1. **`text-adventure-showrunner` / 制作主管**：产出 `production.supervision`，冻结六阶段目标、18 岗位分配、退出证据、停机条件、风险和作者闸门；不写具体故事，也不代替确定性 Scheduler。
2. **`text-adventure-source-editor` / 来源与改编编辑**：核对 WorldRelease 覆盖与风险，形成来源审计；产品私域补充必须经过作者闸门。
3. **`text-adventure-creative-director` / 创意总监**：把来源裁成有限战役，冻结玩家承诺、核心循环、基调和跨部门不变量。
4. **`text-adventure-story-architect` / 故事架构师**：冻结主题、中心冲突、铺垫回收和结局候选。
5. **`text-adventure-cast-director` / 角色总监**：冻结玩家与 NPC 的动机、声音、关系变化、知识边界和视觉锚点。
6. **`text-adventure-space-designer` / 空间设计师**：建立大区、区域、地点、场景空间锚点与移动层级。
7. **`text-adventure-game-designer` / 通用玩法系统设计师**：确定属性、技能、资源、背包、装备、关系、时间和检查语义。
8. **`text-adventure-narrative-designer` / 叙事设计师**：把故事、角色、空间和系统拆成三幕、场景卡、持久决定与后续回响。
9. **`text-adventure-main-quest-designer` / 主线任务设计师**：把叙事弧拆成阶段、目标、条件、替代行动和失败推进。
10. **`text-adventure-side-quest-designer` / 支线任务设计师**：制作映照主线且有独立人物诉求的支线，不阻断主线通关。
11. **`text-adventure-storylet-designer` / 区域事件设计师**：制作有地点、条件、时效和状态回响的 storylet。
12. **`text-adventure-quest-scripter` / 任务脚本工程师**：把主支线和事件设计编译为受控条件、检查、时间成本和结算文本候选。
13. **`text-adventure-scene-writer` / 分场叙事作者**：按三幕启动同 Skill 的三个有界 Run，写玩家可见正文、对白和选择措辞，不能重写冻结结构。
14. **`text-adventure-dialogue-editor` / 独立对白编辑**：按幕逐条审校对白与选择，保证人物声音、潜台词、知识边界和玩家意图清楚。
15. **`text-adventure-continuity-editor` / 连续性与内容审校**：审查因果、知识、时间、物品、状态、铺垫回收、重复和情绪触达；只提交问题，不改原工件。
16. **`text-adventure-art-director` / 美术总监**：建立媒资需求候选；确定性编译器再与角色/空间锚点闭合为视觉圣经。
17. **`text-adventure-visual-qa-director` / 独立视觉质检总监**：检查实际图片的需求匹配、身份一致、风格、构图和技术质量，不改图、不发布。
18. **`text-adventure-playtest-director` / 试玩与发布验证**：基于冻结包生成黄金、替代、失败、恢复、离线和生命周期试玩矩阵，不修改游戏内容。

图片生成或上传由登记的 Provider Adapter / author-import 执行，不伪装成第十九个内容 Agent；结构门、运行状态、自动游玩、装配、调度、暂停和发布判定由确定性系统执行，也不冒充模型岗位。注册表岗位、计划任务、实际 Run 和本清单必须一一对应。

上游工件变化只让依赖图中的下游变 stale；返工必须形成新 revision，禁止原地覆盖已经验收的 Build 或媒资。

## 5. 生产批次和停机条件

### 批次 G1 · 世界与 Brief

建立隔离项目、世界、Work 和实际世界材料；冻结 WorldRelease；创建 `commercial-candidate` Brief，选择关键插图档，目标 60 分钟。来源充分性、改编方向和核心循环未通过前不进入内容生产。

### 批次 G2 · 结构与任务

完成故事圣经、角色圣经、三幕计划、主线、支线、区域事件与任务脚本。确定性检查至少覆盖稳定 key、引用闭合、目标替代行动、结局条件和空间映射。任何主线死路或仅末尾分色的伪分支都必须返工。

### 批次 G3 · 正文与对白

按幕生成场景正文和对白审校。每幕单独有界调用、单独审查、可局部重跑。合并后计算实际可达路线文本和对白，不足时返工具体幕，不允许修改 Brief 目标来放行。

### 批次 G4 · 规则、媒资与装配

编译确定性运行包；生成并逐项绑定图片；完成 Visual QA、媒资三向审计、文本降级和真实解码。缺图不得破坏运行，角色锚点和最终逐图作者确认前不得签发商业候选 Release。

### 批次 G5 · 自动和真人验收

自动游玩覆盖所有结局、替代路线、失败推进、存档往返、分支隔离、AI/媒资离线。浏览器测试必须从开局真实玩到结局，验证属性、任务、背包、装备、状态反馈、刷新恢复和结局回顾。作者主路线试玩记录真实分钟数、选择数、行动数、结局和主观阻断问题。

### 批次 G6 · 发布、上传与展示

发布不可变 ProductRelease；生成候选档案和 `.storyforge-adventure.json`；在全新隔离 Work 上传，核对所有 hash 等价，从导入副本重新完成一条路线，再删除副本验证引用生命周期。保留一个作者可直接打开的正式玩家会话作为展示入口。

任一批次遇到凭据/余额、来源不足、协议错误、结果未知、质量阻断或作者闸门时暂停并展示具体原因；不得隐藏重试、降级为短 Demo 或伪造通过回执。

## 6. 证据与展示清单

最终向作者展示的不是“已经做完”一句话，而是同一 Release/hash 下的：

- WorldRelease 标识、来源清单和充分性决定；
- 18 个岗位及其 Skill、Run、工件和终态；
- 实际路线文本量、对白轮次、选择、行动、持久决定、NPC、任务、区域和结局指标；
- 自动游玩 8 类结果和人工试玩路线；
- 角色属性、任务、背包、装备、地图/地点、状态变化和结局因果 UI 截图或可复现入口；
- 媒资清单、实际图片、Visual QA、作者逐图决定、运行引用和纯文字降级；
- ProductRelease、Build manifest、package、bundle、candidate 和来源世界 hash；
- 导出文件路径、导入副本验证和删除生命周期结果；
- 尚未通过的主观质量问题及其返工 revision。

没有实际可打开玩家入口、没有真实导出文件、没有从导入副本到结局的证据，不得声称“旗舰产品完成”。

- 隔离 Production：`productprod.mtqcyoyo.ae9e63f7`，标题《潮钟群岛：最后的灯火》。

- 来源审查经作者闸门接受五项产品私域补充：弥沙与沉砾档案、支持性 NPC 群、结局触发映射、关键插画场景清单；该决定在后续恢复 epoch 中以 `carried-forward` 复用，不再重复索要确认。

当前状态仍是“生产中的旗舰”，不是可试玩 Build、ProductRelease 或社区推荐候选。下一项唯一合法动作是恢复叙事弧任务；其后必须依次完成主线、支线、区域事件、任务脚本、三幕正文、三幕对白、连续性审查、美术、自动游玩、作者试玩、发布和产品包往返，不能跳级。

### 7.2 完成判据

本阶段完成必须同时满足：

1. 实际 WorldRelease 不是空壳，来源和产品私域补充边界可追踪；
2. 专业 Agent DAG 真实运行，18 个岗位未被合并成一个万能 Agent；
3. 游戏达到第 2 节规模底线并通过第 4、5 节的结构、内容、运行和媒资质量门；
4. 作者完成主路线与逐图确认，没有未解决阻断问题；
5. 同一不可变 ProductRelease 可在本地直接游玩，也可从候选包原子导入到新 Work 后完整游玩；
6. 候选档案为 `eligible-for-community-submission`，但 UI 不冒充已公开或已推荐；
7. 全仓 CI 和隔离浏览器 E2E 通过，工作树干净，方案文档与真实实现一致。

若只完成 1–3 项，应准确称为“工程可试玩 Build”；若完成到第 5 项但作者尚未确认，只能称为“待作者验收的发布候选”。
