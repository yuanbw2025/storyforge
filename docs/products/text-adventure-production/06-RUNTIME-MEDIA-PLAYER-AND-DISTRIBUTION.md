# 06 · 运行、媒资、播放器与分发方案

> 层级：L2 · 版本：1.6.1 · 生效：2026-09-21
> 性质：游戏工程与用户体验目标契约。

## 1. 运行权威

ProductRelease 中冻结内容、确定性规则与不可变事件日志共同构成运行状态权威。玩家命令携带 command id、基线序号和状态 hash，先纯函数预演，再事务追加事件。种子化 RNG、检查公式和结果证据进入事件；AI 只可把自由文本映射成合法行动候选、措辞化已结算结果或提出待规则接纳的事件候选。

正式状态至少包含位置/场景、角色能力与资源、关系、物品与装备、已知事实/flag、任务阶段/目标、叙事节点、storylet、时间、行动历史和结局候选。摘要冲突时由事件重建，不能以摘要覆盖状态。

## 2. 系统 UI

播放器采用文字阅读和行动选择为中心的响应式布局：

- 主区：当前场景标题、正文/对白、插图、结果反馈和可执行行动；长任务目标不能直接冒充按钮标签。
- 状态区：生命/法力/体力、经验/技能点/货币、通用属性与技能，变化有可访问提示。
- 任务区：主线、支线、区域任务分组，显示阶段、当前目标、已完成目标、失败/替代状态和追踪地点。
- 背包与装备区：物品分类、数量、用途、可用/交付/装备动作、槽位和能力修正；不可用原因明确。
- 地图/位置区：大区域 → 区域 → 地点 → 场景层级、已知连接和合法移动；未知内容不泄漏。
- 旅程与因果区：近期行动、关键状态变化、关系/任务回响；结局后显示可解释的行动链回顾。
- 系统区：存档、自动存档状态、读取、从存档创建分支、版本/hash、降级模式和可访问性设置。

首版满足完整键盘操作、语义标签/读屏、字号行距调整、主题与对比度、减少动态效果和图片替代文本。AI 或图片不可用时不得隐藏合法行动。

所有 V2 行动在进入 RuntimePackage 前统一经过玩家可见标签边界：标签不得超过 32 个可见单位，优先保留完整首分句，仍超限时才确定性截断并加省略号；完整任务名、目标和后果继续保存在描述与结算文案中。该约束在行动注册的单一出口实施，不能只修选择按钮而遗漏来源物品、任务准备、支线、区域事件、装备或移动行动；发布质量门再次扫描全部行动作为防线。

## 3. 自由输入

默认始终展示明确合法行动。自由输入经运行期 Agent 转成一个或多个结构化行动候选，展示映射结果、代价和不确定性，由玩家确认后才提交。无法映射时返回结构化原因和可用替代；不得把原文本直接当作规则效果。

## 4. 媒资生产

Art Director 从角色圣经和定稿场景生成媒资需求候选，确定性编译器再生成独立视觉圣经，防止模型用一份松散清单同时自定角色身份和美术约束。首个旗舰包含封面、区域地图、主要角色肖像/设定锚点、关键地点、重要物品、章节图、关键转折 CG 和结局图；商业候选的“关键插图”档不少于 12 张，“丰富插图”档不少于 24 张，数量在 Brief 与预算中冻结。2 张图片只允许作为 prototype 技术验证，不能以单一 media kind 的 100% 覆盖率冒充社区推荐候选。

商业候选前 12 个媒资槽位是确定性的编辑职责，不允许按较短模板取模凑数：1 张封面、2 张相互有区别的大区域/地图环境图、3 张分别绑定冻结角色的角色锚点、三幕各 1 张关键转折图、1 张结局后果图和 2 张互不重复的关键物品图。`artifactKey`、`sceneTag`、`mediaKind`、角色引用与尺寸由计划冻结，Art Director 只负责把每个职责扩写成当前故事的具体画面。任何重复 `sceneTag`、角色槽位回退成同一角色，或用同一事件换措辞补足数量，均在出图前拒绝；角色立绘的最终 prompt 由冻结角色圣经确定性重建，不能沿用模型自造的姓名、发色、伤痕、服饰、肢体或身份。剧情 CG 中逐字出现已登记角色时，系统自动补齐角色引用和硬约束；地图与关键物品则在出图前编译为无字视觉表达。24 图档在此基础上增加支线、区域事件、地点细节、表情与决定回响，不回绕前 12 个职责。

角色图的 provider prompt 必须声明冻结角色约束高于模型补充描述，并保留头部、双手、身份物件与安全边距；细小伤痕等硬锚点只能交给可看清对应区域的构图。只有 `character-pose` / `character-expression` 使用透明背景；绑定角色的剧情 CG 必须把角色融入完整场景，禁止误用透明抠图、角色卡或舞台排布。透明图在冻结前执行只沿真实透明背景连通域扩展的品红键色清理，不能用全图颜色替换破坏服装。Visual QA 每个 Run 同时接收该图的精确需求、角色硬约束、实际 Blob 与 key/hash；未改图片沿用已通过证据，返修目标才重新观察，避免随机审查反复翻转。

资产使用稳定 `assetKey`，记录风格、尺寸、色板、构图、角色锚点、需求来源、provider request/receipt、权利/商用声明、Blob/hash 和引用。商业候选生成前，工作台展示整体风格和每个角色的身份、外观与色板；作者确认后才冻结 `media.anchor-decision` 并开始逐项出图。生成后做格式、构图、角色一致性、内容安全、权利和替代文本检查。清单、素材、场景引用三向不一致阻断推荐候选。

每项媒资独立执行、独立落证据，不用一个批任务掩盖内部进度。纯文字降级以显式省略工件表示；省略项没有 Blob、不会装进 RuntimePackage，也不会增加媒资覆盖率，但必须保留已经有界尝试过的事实，方便作者后续只重做这一项。

连续立绘站位、表情时间轴、口型/配音同步、复杂镜头与路线 CG 画廊仍归 AVG；文字冒险只在阅读和决策节奏中使用静态或轻量插图。

### 4.1 首次可交互与全量媒资必须分开计量

`browser.performance.desktop` 的 `firstInteractiveBytes` 不是发行包总大小。文字冒险的确定性口径为“当前 Build 的完整 Preview manifest UTF-8 字节 + 入口叙事节点在真实播放器阅读面实际选择的首张 background/CG 字节”。入口没有有效 cue 时，按播放器相同规则计入第一张 background/CG 降级图；没有图片时只计 manifest。角色面板立绘、后续幕 CG、地图和结局图不冒充首屏资源，但入口图片本身超过 12 MiB 或完整 manifest 过大时仍必须失败。

真实播放器必须与该口径一致：进入或切换场景只读取当前阅读面需要的插图，打开角色面板时再读取肖像；Resolver 按 `assetKey` 缓存同一 object URL，避免首图与后续核验重复读取 Blob。Build 预览在首个阅读面已经可交互后，仍要单独读取、解码和核对完整冻结媒资目录，生成 `media.runtime.decode` 技术回执；正式 Release 游玩则保持逐场景按需读取。全量解码不计入“首次可交互字节”，但它产生的真实内存占用和缓存场景切换仍进入 30 分钟性能采样，不能借分项口径逃过峰值堆内存或长期增长门。

登记的应用内实验室和 Playwright verifier 必须同时提交 `firstInteractiveBytes` 与有序 `firstInteractiveAssetKeys`。写回前由系统从同一 `previewManifestJson` 重算资源计划并逐项比对；不一致的测量不得生成质量回执。通过后，原始测量、聚合结果、Build 的 package/preview hash 和浏览器环境共同进入不可变 gate receipt。尚未证明渐进加载策略的其他产品继续保守计入全部冻结媒资，不复用文字冒险的窄口径。

## 5. 保存、恢复与分支

- 手动/自动存档绑定 ProductRelease/hash、事件序号和状态 hash。
- 刷新恢复后状态、当前正文、合法行动、任务和媒资引用一致。
- 从存档创建新时间线，父分支不可被子分支污染；重放得到相同 RNG 与状态。
- 损坏 checkpoint 可从上一个有效 checkpoint + 事件恢复；无法恢复时保留证据并停止写入。
- 版本迁移只能通过登记的确定性 migrator；不兼容发布必须明确拒绝。

## 6. 构建、导入导出和发布

Build 装配固定 SourceManifest、内容 Artifact receipts、RuntimePackage、媒资、质量证据和兼容范围。推荐候选导出在隔离副本执行往返验证；导入必须先完整预检，再原子写入新作用域并重映射引用。删除产品时由 `PROJECT_TABLES` 派生清理所有生产、媒资、发布和会话数据，不影响 WorldRelease 或其他产品。

## 7. 当前实现证据（2026-09-08）

播放器已把任务当前阶段/目标地点、背包可用与交付动作、装备/卸下、已知地图与合法移动、人物关系、结局选择链、字号/行距、高对比度和减少动态效果接入正式运行状态；显示偏好保存在浏览器本地配置，不进入游戏状态。相关纵切面由 `R-TEXTADV2-player-ui` 覆盖。商业文字冒险媒资规模已在 Brief 编译、出图前作者闸门和发布质量门三处约束；旧的 2 图商业 Build 不允许继续调用图片 Provider。

任务日志会从冻结任务和正式运行状态投影当前目标的全部玩家可见解法，逐项显示行动说明、判定或资源门槛、追踪地点、当前可执行状态，以及失败推进或任务终止风险；只有通过相同前置检查的路线按钮才能进入正式行动命令。角色成长不再把任务奖励的技能点留成不可消费数字：玩家可在技能面板分配技能点，`adventure.skill-point.allocated` 以单个 CAS 命令原子扣除 1 点并提升一个冻结技能，随后用 `adventure.narrative.synced` 刷新条件投影。重复 command id 幂等返回，过期状态、非技能、余额不足与技能上限均明确拒绝；分配事件可由日志重放并进入损坏检查点恢复。

存档面板会明确显示当前会话绑定的是 ProductRelease 还是 Build 预览、规则版本、不可变来源 hash 与媒资降级状态。检查点快照完整性失败时，运行层保留原损坏记录，校验上一有效检查点或开局基线，并从权威事件日志重建一个新的可验证检查点；播放器随后只从新检查点创建分支。

正式发布进入游戏库详情页时，播放器通过 Release 媒资解析器只读取 `cover-opening` 冻结封面槽位；加载失败保持装饰性纯文字标题页，不把图片故障扩大为不可游玩故障，也不读取未登记的外部 URL。

社区推荐结局门不再只统计正文量。每个可达结局还必须包含正式 NPC 对玩家选择的角色回响，并由至少一个实际可执行行动写入其进入条件所依赖的持久状态；播放器的结局回顾再从权威事件日志投影真实行动链和持久条件。没有状态结算的长尾声、只有模型措辞却没有行动证据的“伪分支”，均不得作为推荐候选发布。
