# 03 · 来源充分性与改编方案

> 层级：L2 · 版本：1.0.0 · 生效：2026-09-06
> 性质：生产入口与来源闸门目标契约。

## 1. 为什么必须先审来源

冻结 WorldRelease 只是版本可靠，不代表内容足以支撑一小时游戏。世界只有地点而缺角色、冲突和事件时，生产链不能偷偷生成占位 NPC，再把“产品角色 1”隐藏后继续发布。它必须给作者看见缺口并取得明确决策。

## 2. `source.sufficiency` 工件

来源编辑 Agent 基于冻结 SourcePlan 和真实 Context Manifest 产出候选；确定性系统复核计数、引用与 hash。工件至少包含：

- `coverage`：世界概述、时间/时代、空间层级、主要角色、组织、冲突、历史、规则/能力、物品、审美锚点、禁区等语义域覆盖。
- `anchors`：每个拟采用事实的 resource key、release/hash、摘录摘要与用途；不复制整份世界 payload。
- `gaps`：缺失项、严重度、对主线/系统/媒资的影响和最低补充量。
- `contradictions`：来源内部冲突、无法裁决原因和需作者选择的问题。
- `recommendedTreatment`：`adapt-rich`、`expand-sparse` 或 `author-outline`，以及建议的生产范围。
- `privateAdditions`：建议只存在产品私域的角色、地点细节或事件，不得伪装成世界 Canon。
- `decision`：`ready`、`ready-with-private-additions` 或 `blocked`；模型只能建议，确定性规则和作者确认共同生效。

## 3. 一小时旗舰最低来源条件

开始故事架构前至少需要：

- 一个清晰时代/环境、一个核心冲突、一个玩家可扮演身份和一个可结算目标。
- 至少两个有结构关系的大区域，或一个足以容纳多个子区域和阶段变化的密集大区域。
- 至少三名可直接采用的主要角色，或作者明确允许在产品私域补足到五名主要 NPC。
- 至少六条可追踪的世界事实锚点，覆盖冲突、角色、地点和限制；纯风格描述不能全部替代事件事实。
- 没有未解决的硬 Canon 冲突；敏感边界、禁止改变项和产品私域补充边界已经确认。

这些是旗舰适配闸门，不是通用 runtime 强制所有题材必须有 NPC。无角色实验游戏可以通过新的版本化玩法配方生产，但不得套用旗舰推荐标准。

## 4. 作者的三种决策

来源不足时必须暂停并给出：

1. 返回世界引擎补充并重新封存；旧 SourcePlan 与下游工件 stale。
2. 缩小产品规模或改变目标体验，重新确认 Brief。
3. 允许指定缺口由产品私域补充；补充事实随 ProductRelease 冻结，不回写 WorldRelease。

默认不替作者选择第三项。作者若导入大纲或完整文本，保留原件及 hash，AI 只生成可比较候选；丰富长篇直接抽取叙事骨架，短或稀疏内容先扩充冲突、角色、事件与节奏材料，不能直接压成几个场景。

## 5. 上下文与 stale

- 每个 Agent 从 SourcePlan 声明必读、选读、条件读取和禁止读取；渐进读取由 Context Gateway 留 manifest。
- 固定条数裁剪只作最终预算保护；摘要与正式来源冲突时摘要失效并重建。
- SourcePlan、WorldRelease/hash、Brief 或已采纳上游工件变化时，由依赖图计算 stale；只重跑受影响闭包。
- 来源改变必须重新确认受影响的故事圣经、角色圣经与视觉锚点，不能用旧 receipt 给新 Build 背书。
