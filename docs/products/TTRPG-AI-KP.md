# 跑团产品：AI KP 生产与游玩契约

> 版本：1.1.0 · 生效：2026-10-12 · 权威层级：L2
> 状态：实施中的产品契约。以下是目标和约束；实际完成状态以能力基线和验证证据为准。
> 本次增量：标准运行格式、局势/事实/知识、授权与恢复契约；施工见 [跑团开发与施工方案](../roadmap/TTRPG-DEVELOPMENT-PLAN.md) 2.1.0。保留全部既有能力与证据，文档修订不代表新功能已实现。

## 产品结果

AI 担任 KP，支持单名真人加 AI 队友、多名真人和混合队伍，在冻结规则、冻结世界语义与作者局势层下分别行动、保守秘密、获得指引，完成有选择与后果的一场游戏。首个社区作品采用原创调查冒险和 StoryForge 2d6；不声称实现某外部规则书的全部内容。

目标标准格式为 `runFormat='open'`：作者准备局势、NPC 动机、压力、规则与开局，玩家可声明未预写行动，经规则、通用检定、受限 Oracle 或无需掷骰的合法计划裁定，世界随游戏内时间演化，以阶段收束和续团代替闭合结局。`runFormat='scripted'` 是已有闭合场景图和结局格式的兼容路径，旧作品、规则、发布包与存档不自动转换；既有人类/AI/混合主持能力保留。两种格式共用规则内核、骰子、信息边界、事件、媒资和发布链路，不新增产品身份。

冻结世界不变量、作者冻结局势层、会话演化事实分层管理；世界初始位置/持有者/关系映射为 session 的机械状态后可按唯一账本合法变化，不等于改写世界来源。会话事实、角色知识与传闻归 session；传闻/信念不能作为规则事实。世界补丁只能导出作者审阅候选，经作者显式创作和确认形成新版本，不能追写旧 WorldRelease。

世界引擎只在 `S1 世界封存`中提供不可变语义。`S2 产品定向`确认规则、模组方向、角色、席位、安全边界和媒资需求后，冻结 Brief / SourcePlan 与开始授权。`S3 产品执行`依次完成生产、验收、发布，并在用户选择游玩后创建绑定 ProductRelease 的 session。生产与运行中新内容、记忆、媒资都归跑团，不自动回写世界。

## 角色与权威

- 模组作者编辑生产候选并批准发布；游玩者不能在运行时修改发布包。
- 房主管理邀请、席位、暂停和退出；管理身份不等于可读取 GM 真相。
- AI KP 决定主持程序、世界响应、规则内裁定提案和节奏；不能代替真人决定其角色的重大行动。
- AI PC 和 NPC 分别获得自己的目标、观察和记忆。NPC 不接收 GM 全文上下文。
- 规则内核负责骰子、数值、消耗、状态、权限、顺序、版本与事件原子提交。
- Oracle 是冻结规则包授权的随机裁定，不是规则询问的建议。内核掷骰并生成可复算回执；已提交结果不覆盖，解释可以重新生成但不能改规则、改世界不变量、追溯改写或替玩家决定。新机械实体与后果须经冻结模板、合法角色/地点/物品绑定及唯一账本，不能仅写自然语言事实。
- 正式多人秘密由权威服务保管，客户端只收相应投影。本地作者预览不承诺防止本机拥有者读取源模组。

## 本桌授权

Session Zero 明确 AI 身份、角色控制权、安全边界、提示程度、暂停方式与允许的自动主持操作。该授权是有限的运行委托：模型输出仍先成为候选，经作用域、规则、版本和信息边界校验后提交。预授权范围内的 AI 行动不逐次要求作者采纳；混合席位、重大含义不清的玩家代价或越界请求需要相应玩家确认。

秘密和背叛以桌面约定为准；默认合作，不允许 AI 队友替真人解谜或未经同意实施不可逆队内攻击。暂停时停止新行动；模型失败或结果未知时保留可见状态，不隐藏重发。

open 的重大意图确认分离行动者与批准者：真人确认自己的具体计划；AI 队友由 Session Zero 指定的真人批准席位授权，AI 不能自批。确认绑定候选/计划哈希、风险、代价、输入与发布版本、授权窗口；关键变化使其 stale。涉及其他真人的资源、秘密或不可逆变化须该真人授权，拒绝/撤销不结算。

## 主持循环

输入区分对白、行动、规则询问和桌外讨论。AI KP 可开场、描述当前局势、澄清意图、提出裁定、安排相关角色反应、提出合规线索发现、切换场景、提供提示、结束或暂停。

每轮有明确的输入 revision、调用预算、候选、验证、事件和终态回执。更新规则状态后再生成玩家可见表达。AI 连续行动有界，遇到真人决定或安全暂停即让出控制权。

open 使用世界时间推进压力，威胁升级前先投放队伍可见的征兆并满足冻结提前时间。世界时间不作为模型预算与队友行动额度的归零开关：持久授权 epoch 控制连续行动及实际 provider 调用，刷新和重复继续不能绕预算。行动后的效果、时间、压力、局势、质量门和叙述形成可恢复 operation；每个因果只消费一次，reducer 只派生状态，后续命令由协调器执行。

自由表达映射到规则内行动或无检定互动；检定方式、风险与资源消耗必须可解释。玩家可选择其他方法、拒绝任务或撤退，不能为回到预设剧情改写事实。

探索、社交与战斗的调度按规则配置。多人同时输入有稳定排序或声明窗口；分队按场景保留各自知情范围，共享后果由同一权威提交。

## 信息边界

区分客观事实、角色观察、角色信念、谎言、私事和信息接收者。信息传播有证据事件和来源；某角色的转述不会让听众自动获得原件全文。

主 Agent 的计划及 GM 真相不直接向玩家发送。关键披露引用已冻结事实与规则条件，经验证后生成按接收者限制的叙述。公开话语、私信、角色决策、摘要、检索、缓存、回放、导出和媒资均遵循相同边界。

字符串检查是补充防线，不是语义绝对保密证明。角色上下文首先排除其未获知的信息。合法揭示和禁止泄密必须同时有测试。

open 的线索/知识以真实发现和传播事件记录接收者、来源及公开字段，局势结束后知识继续存在；私人发现不自动成为全队知识，新席位不自动取得历史秘密。玩家可继续门必须按当前真人投影判断，不用他人的私密出口充数。分支来源同时标记 session 身份和事件序号，不能因子序号归零混淆父子证据。

## 模组、角色与媒资

模组包含可运行局势、关键真相、场景、线索载体和发现途径、NPC 动机、压力、规则挑战、即兴范围和结局条件。检查关键进展是否存在瓶颈，不能将故事摘要机械切片即认定为可玩模组。

上述场景图/结局与穷举可达性属于 scripted 的现行合同。open 冻结作者局势、来源事实索引、规则/Oracle、实体与效果绑定、安全/授权、运行预算及阶段策略；共享 narrative 容器仅作为开场/只读素材，不通过伪造结局或 choice 满足旧图门。open 用运行时四门（当前玩家有出路、可形成假设、征兆齐备、事实一致）及明确发布静态门；可机器判定结构与真实语义体验分别验收。

AI 车卡必须有真实生成证据，并经过规则合法性检查；候选支持确认与修订。角色目标、关系和能力在队伍中互补。世界角色映射保存来源，不创建反向同步。

媒体按玩法需要生产：封面、角色肖像、地图、handout 可独立失败与重试。图片/音频也遵守信息边界。发布媒资与运行媒资 owner 分离。

## 用户路径和社区作品

用户路径：世界编辑与封存 → 跑团入口 → 配置与明确开始 → 内容/角色/媒资生产 → 审查 → 发布 → 选席位与开局 → 实际游玩 → 结局/复盘 → 保存或继续。

制作界面与玩家界面各自清晰，玩家不需要操作开发者或人类 GM 管理面板。替代入口同步收口。

首个作品交付冻结世界来源、产品发布包、必要媒资、玩法说明、许可说明与脱敏生成/试玩证据。导出不得包含 API Key、账户身份或私人测试聊天。用户负责后续 GitHub 集成与社区发布，本实现不替用户发布宣传内容。

测试覆盖规则、权限、角色未知信息、有效披露、stale、重试、同时行动、分队、回放、导出、发布和世界不回写。交付运行完整 CI 及隔离 E2E，并通过真实模型完成世界到跑团的正常用户流程与实际游戏。

## 完成证据

必须区分结构/工程测试、真实模型评测与玩家体验。自动回归不能冒充真人试玩；没有部署证明不能宣传真实公共多人服务完成；试作品可游玩不能代替长期商业运营验证。能力门仅随真实证据更新。

记录整轮与整场调用、tokens、耗时、已知费用、失败恢复和人工干预。未知价格保持未知，不捏造成本或以单次回复成绩代替整场质量。

open 首期必须同时验证正常作者界面的生产/审查/修订/发布和真人加 2–3 队友的连续合作局，不能以手写 fixture 发布代替。四门、授权、恢复与旧包兼容联合验收后才可开放；长局还需真实 provider 连续 30 个 worldTurn 以上、Oracle 复算和征兆前置均 100%、事实矛盾/可继续率基线、分支恢复及一次世界补丁审阅证据。产品整体验收同时覆盖作者工具、角色卡、媒资、分发和续团，不能只凭 open runtime 宣布完成。

## 当前实现边界

截至 2026-10-12，open 标准格式只有本契约和施工方案 2.1.0 的设计约束，尚无该方案实现与验收证据；新内容/状态版本、无场景准入、Oracle、会话事实/角色知识、压力自驱、局势、授权 epoch、可恢复 operation、四门、条件注入和长局记忆均保持待实施。以下记录描述既有 scripted 能力，不因本次修订降级或被新格式覆盖。原始响应与恢复等复用设施缺口须按方案补齐；规则询问仍只给建议，不代替正式行动或 Oracle。

本分支已经接通以下能力：

- 2026-09-15 新跑团入口 `/ttrpg/:pageId?` 接入实际作品库、九步配置、提案比较、制作与检查、发布和团局。一级操作导航与页面内的配置/内容分类分层；未选世界可浏览、填写并保存。旧 `?tab=ttrpg` 普通链接转入新入口，明确 legacy/在线交接保留兼容路径。
- `Work.kind=ttrpg` 与 `ttrpgAuthoringDrafts` 保存产品自己的 S2 草稿、规则引用和世界出口选择；保存配置不触发生成。编译为原有 Brief 后仍需确认提案与明确开始授权，继续走冻结 SourcePlan、既有 Harness 与发布闸门。草稿由 PROJECT_TABLES 统一备份、重映射、删除；schema v8 只加表并调整 Brief 内容 hash 为非唯一索引，版本身份仍由 production/revision 唯一约束，不改写已有记录。
- 战役/场景/角色/地图/手册和媒资页读取实际 Build 产物；内容修订通过新制作轮次或已有失败任务的作者校订入口进行，尚未提供这些对象的通用逐字段可视化编辑器。游玩页重用既有 KP、规则、角色卡、桌面、安全约定、存档和续团功能。

- 已冻结规则与模组下的有界 AI KP 循环：NPC、AI 玩家行动、条件内线索揭示、公开叙述、真人交接、场景与结局选择。
- 本人私密指引及行动前规则询问；询问持久保存，但不扣除角色行动，也不代替真人提交意图。
- 单人加 AI 同伴、同一设备多人交接、独立游玩页、自动保存、检查点分支恢复、可见 API 错误与明确继续。
- 同机多人刷新、切换待回应玩家时先遮住记录与手记，玩家确认后才显示对应桌面；也可手动遮屏。此机制用于防止交接时误看，不代替账户认证或服务端隔离。
- 社区目录与本地存档独立读取，目录失败时仍可打开已有冒险；读取检查点失败保留当前桌面，成功后切换到独立分支，主持期间禁止同时恢复。
- 玩家、NPC、公开叙述采用各自的上下文投影。规则回执保留在运行账本，模型读取结构化观察；被预算截断的 JSON 不得发送。
- 生产模块必须交付真实角色资料、公开场景/GM 真相、线索发现路径和结局条件，并经确定性编译及发布校验。
- 制作失败时可查看原始模型草稿、填写修复要求重试，或提交完整作者校订 JSON。校订绑定当前失败任务及 revision，沿同一 Harness、上下文、解析器和发布闸门验收，保留原模型输出与作者输入的独立证据；不伪造模型调用或绕过秘密与规则校验。
- 社区目录通过校验过的分发包创建独立本地实例，复用 Release / media / 生命周期入口，不伪造市场订单或授权。
- 已有联机协议的 AI NPC 与公开叙述采用最小信息视图；这不等于已经部署可供社区使用的多人服务。

首发目录只有在真实发布包、原创素材许可、完整试玩和脱敏证据就绪后才加入作品条目。`commercialReady` 与产品完成证明不得因本分支自动回归通过而开启。

## Open v2 候选施工：作者采用、发布与备份

Open 候选沿现有生产链完成两次作者内容复核后，仍须校验实际 release-ready Build、完整 producer/root/候选/媒资证明、SourcePlan/真实 Context Manifest 与质量硬门，再原子发布。正式采用和父版本读取显式使用 protocol-2；新 open Release 的兼容谱系标记为 2，旧 scripted 读取默认边界和共享发布事务保留。第一版发布与存档不随第二轮修订改变。

复用内容保留原字节生产来源；本轮零供应商的复用 Run 和 ledger 单独证明当前 epoch 的复验，不替换原 producer/input。跑团使用严格 Artifact owner 校验同 Build、跨 Build 与原来源。恢复中已提交 carry、未提交新 Plan 的间隙可按原身份重入；待提交 Plan 须绑定实际授权 Brief、hash、Build/epoch 及事务 CAS，不跳过作者授权。

完整备份导出时冻结原世界读取的便携证明，导入后先显式复验原候选、历史 producer、当前复用 Run 与 root，再依据同一冻结世界版本聚合来源。原 Context Manifest 和指纹保留；缺失、损坏、换世界或仅复制证明而没有真实导入/复验事件时拒绝发布。该证据属于原作品及 Agent 账本，不能让发行安装副本获得原作者权限。具体边界见 `DATA-GOVERNANCE.md` 的世界资源出口契约。

这里记录候选实现与隔离工程验证，原生浏览器生产使用明确模拟传输；不覆盖上文 scripted 样作的独立真实 provider 证据，也不证明 open 真实玩家、长局、商业或完整产品验收。社区原型分发的旧版读取仍须在后续分发单元升级，当前完整目标与开放入口默认隐藏状态不变。

已发布 open 作品的完整备份使用显式 protocol-2 读取。导入复验只能重建当前机器的验证证明，不得把已发布 Build/Production 改成待发布状态。新作者修订从已重映射的来源记录创建新的 Brief/WorldReference/SourcePlan；原 Brief 字节与 hash、旧发布、旧制作版本和存档不随本地编号变化改写。

仅影响视觉的 open 修订可按真实任务依赖闭包复用来源事实、规则和局势成果，重新执行媒资规划及确定性集成、质量验证。复用必须同时通过未变化的作者输入/世界版本、修订影响范围、当前执行契约、原 producer、每层 carried 来源、本轮 synthetic Run/ledger 和封存证明；初始待提交 Plan 必须绑定实际授权 Brief，并通过原记录事务比对。连续修订按有限深度读取真实父版本证明，循环、损坏、改变输入或未授权计划均拒绝写入。媒资配置变化仍采取保守重建，尚不以这条视觉修订路径声称覆盖全部媒资组合。

## Open v2 候选施工：独立真人主持桌面

真人 GM 从游玩入口单独确认主持席位，不需要认领一个玩家角色，也不因进入主持桌面授予模型读取权限。开团前所有真人分别确认席位、安全约定与 AI 身份；主持不能替尚未确认的玩家完成开团。当前主持授权、席位或来源变化时，旧读取和操作均失效。

主持桌面只按实际团局读取专用投影：世界轮次、当前局势、待处理行动及规则结果、主持有权批准的项目、后果审查、阶段收束、全队叙述和本人叙述回执修复。它不经过某个玩家的私密投影，不返回玩家秘密档案、原始输入、模型消息、随机种子或完整冻结计划。返回身份选择时清除主持桌面和草稿；刷新须重新确认身份。原玩家入口仍保留角色自己的私密视图。

主持可按既有命令暂停、恢复、保存检查点和补写实际结算后的全队叙述，原始骰点、事件和模型记录保持。行动仍由原 epoch 启动者继续结算；主持不能借用玩家身份继续、代签玩家风险，或越过开团时的队友批准关系。保密结果涉及玩家后果时，须按下文的独立知情确认流程处理，不能仅凭主持看到了骰点就自动确认代价。正式连续委托、自由对话、逐 worldTurn 后果交织与 P7–P10 保持后续目标，当前默认预览边界不变。


## Open v2 候选施工：保密裁定后的知情选择

主行动后果和发现线索代价需要选择时，未获主持显式告知前，普通玩家视图继续隐藏结果相关的可选项。主持通过独立审查读取实际未完成步骤，系统依据当前真实 rule receipt、冻结模板、合法参数和机械状态生成将要告知的必要代价。主持不能自写费用、修改结果或替代玩家选择；预览不产生费用、知识授予或重掷。

主持确认后只追加 `ttrpg.open.choice.disclosed` 事件和 operation 的可选 `privateChoiceDisclosures` 历史。玩家只收到有权选择的必要后果、通用选项标签及告知版本标识；不收到骰点、实际成功等级、主持理由、完整机械依据、其他角色秘密或整个冻结计划。选择绑定真实告知 hash、原 plan/risk、当前授权、裁定来源和机械状态，仍由冻结的本人/批准席位确认。实际扣费和知识授予由原业务步骤按一次性账本执行。不能完整向玩家展示的后果继续阻断，不用自然语言承诺覆盖缺失的机械解释。

已有 operation 缺少新属性时保持原序列化形状，历史事件不改写；当前新建和继承 operation 显式启用告知策略，当前命令即使处理旧的未完成操作，也不能跳过告知。记录只使用角色/模板稳定键和限定的 sessionKey+sequence 来源，不引入本地 DB 编号；分支须重新授权和告知，不能复用父告知代签。完整备份保留原证据，异步读取/命令 owner 验证告知 hash，纯回放重建并核验实际后果/来源语义。

此处的告知允许玩家获知自己需要承担的后果，后果本身可能提供叙事线索；不承诺隐藏玩家可由已告知代价作出的推断。正常保密骰点和其他角色信息的边界仍保留。尚未发生裁定时不能用本流程绕过原有风险审查；不能展示的初始风险和未覆盖组合仍需作者/主持按真实契约修复。默认预览入口及真实 provider/真人/长局验收边界不变。


## Open v2 候选施工：不依赖 AI 建议的人工行动

已认领角色的真人可从当前角色有权看到的冻结能力、通用检定和介入提示中选择行动。只列出已知合法对象及冻结模板的绑定参数，不把隐藏线索正文、主持说明或预定结果作为选项展示。玩家拒绝 AI 建议仍可使用此入口；提交后仍走原规则计划、风险展示、本人确认、一次性结算、后果与叙述流程。

人工提交把唯一规范请求及 hash 保存到原 epoch 的可选 `manualAction` 中，授权创建前先调用原规则内核验证。若授权已经保存但 operation 写入失败，原玩家可刷新后继续原请求，完整备份也保留该证据；重复提交不重开窗口、不重掷、不重复后果。同一授权不能更换请求、借用其他角色、接续另一份继承任务或发起新的 AI 行动。KP 叙述仍需原有独立模型许可，人工授权不授予该权限。旧 epoch 缺少此属性时维持原序列化形状。

正常作者发布链验证时发现：冻结发现策略允许全队/公开受众省略接收名单，原运行解析却把空名单判为无合法接收者。现在只在实际发现计划创建时，将这两种空名单确定为本桌已授权角色；显式子名单仍按授权取交集，私密名单不作扩展，发行内容和旧历史不改写。

本单元属于跑团 S3 运行适配，沿用现有 session、ProductRelease、事件与三注册表生命周期；不新增表、AI 来源、正式写入字段或模型入口。候选预览仍默认隐藏。正常制作/发布的浏览器验证使用明确模拟的作者模型传输，不能替代真实 provider、独立玩家或长局验收。连续委托/自由对话、逐 worldTurn 后果与 P7–P10 等剩余目标保持。


## Open v2 候选施工：多轮行动逐轮结算

新建的耗时两轮及以上行动，operation 显式保存 `settlementOrder: per-world-turn-v1`。每次支付一个真实时间 tick 后，先完成该轮压力、征兆/威胁、局势及其受治理后果，才允许推进下一个 tick。需要真人决定的后果保持停机；第一轮授予、消耗或改变的机械状态参与第二轮的实际求值，不能从行动结束时的状态倒推。规则裁定、主效果和发现仍只执行一次，终态、四门、叙述和交棒在全部已授权耗时完成后执行。

压力与局势周期使用原限定规则来源加该轮 operationStepKey 定位；幂等命令、回放、恢复、人工批准和桌面读取均绑定同一 owner 步骤。每一轮不新开 epoch，也不清零 AI 行动/调用预算。子分支继承原结算版本和真实已发生的前缀，备份保留这些稳定键；不能重复支付父分支时间、费用或使用上一轮确认。

旧 operation 没有新标识时，继续保留原来的整批耗时步骤和周期形状，不重排旧事件或伪造历史逐轮证据。已冻结的旧存档由修改前源码生成并纳入回归，实际导入后验证其原三轮耗时和单一批处理压力周期。

连续局势维护现按集合合并已发现证据及已满足障碍；重复维护不制造重复条目，输入自身的重复引用仍拒绝。子分支新建局势周期可引用实际祖先裁定，但须同时具备本地继承回执和真实祖先证据，不能要求尚未生成的子周期预先存在于父分支。该单元没有新增世界写回、表、模型入口或 AI 可写字段。后续完整验证与剩余产品范围见施工方案，默认预览边界不变。


## Open v2 候选施工：真人桌外讨论与规则询问

已开团的真人席位可保存桌外讨论、规则问题和主持答复，不需要开启 AI 建议或支付世界时间；安全暂停期间也可沟通。此处只保存人类文字，不能改变冻结规则、角色资源、事实、知识或已批准行动。游戏内对白/移动/观察仍须绑定正式冻结互动契约，本功能不把任意自然语言作为可执行的 no-roll 行动。

发送者明确选择本次全队或仅提问者与真人主持可见。收件 viewer 在提交时按真实授权冻结，AI 席位不成为本功能接收者。真人 GM 或 AI GM 模式的实际人工主持者可答复自己有权看到的规则问题，答复沿用原问题受众；不能冒充主持或把私密问题扩散给另一位玩家。新增成员或换身份不自动获得旧私密记录。

讨论使用新增的 `ttrpg.open.table-message.posted` 正式事件和可选 `openRun.tableMessages` 保存，首次真实提交才引入字段；旧状态不补空数组。记录绑定实际席位、作者、源事件和授权版本，不含新的本地 DB 引用。完整备份与分支只保留真实切点及祖先证据；重复提交返回原回执，改写原提交拒绝。界面按当前身份分页读取，交接/刷新须重新确认身份，同一身份下刷新保持讨论表单稳定。

这些讨论目前只供真人查看，不加入模型上下文、Agent 来源或事实采纳链，主持答复也不具备规则修改权。AI 规则答复、游戏内冻结互动及连续委托属于后续正式契约，不因本单元通过而开放。公开预览、真实 provider、独立玩家和长局验收边界保持。

## Open v2 候选施工：游戏内无检定互动

作者可在 RulePack V2 中显式冻结对白、观察、移动、协助和撤退。每个互动绑定真实无骰行动、前置条件、耗时及可选的成功后果模板。角色只可执行自己获准的绑定；底层行动不能绕开互动契约。移动和撤退必须实际结算行动者的位置，撤退需要真人决定并增加一次混乱值。原行动费用、能力次数、状态、时间、压力和局势规则继续有效。

手动目录与受治理 AI 候选共用原规则计划。AI 仅从当前角色可见的互动目录选择，method 精确指定互动 key，生成候选后仍须确认具体计划和风险；不把任意“聊天”“观察”等文本直接作为状态变更。模型只看到互动名称、类型、耗时与可用状态，不获得隐藏条件/后果全文。规则与队友预授权仍由确定性系统验证，含后果或越界行为不能借无骰名义自动执行。

费用在授权前按原行动与互动后果合计预检；不可付选项不消费已保存选择，合法方案仍可选。效果提交和回放保留独立校验及一次性账本。观察只有走真实冻结发现路径才获得知识，按指定接收者保存；对白本身不授予知识或创造事实。互动也不自动授权后续模型叙述。

作者在规则页检查并确认导入的规则文件，沿现有规则 owner 保存；同版本不同内容拒绝覆盖。配置保存、Brief 冻结、明确开始制作和正式发布分别校验。局势生产须补齐作者规则引用的真实成功效果，角色卡绑定本次规则版本。旧格式缺少可选绑定时保持旧历史与存档。工程验证与真实模型/玩家/长局的验收独立，连续对话、委托及后续 P7–P10 仍按施工方案推进。

## Open v2 施工中：本轮有限主持委托

连续主持先保存真实人工主持对原 epoch 的明确委托，固定范围为队友建议、原开团约定允许的安全行动与共同视角 KP 叙述；每项实际操作仍由原规则/信息/模型 owner 验证。委托不补充预算、不授予其他真人决定权、不开放 Oracle/事实采用，也不能把人工行动专用授权转为模型授权。

委托绑定原 Session Zero 与真实授予事件，可在暂停或请求未知时停止。每个受委托模型请求把同一来源写入真实契约与调用账本，派发前重新核验。撤销后不发送新的请求；已派发结果照常保存实际用量，迟到候选不能自动采用。新窗口、分支重新授权不自动沿用旧委托，旧请求的原始身份与 hash 保留。

当前仅接通授权、撤销、请求绑定和回放基础；协调器、委托采用与停止/恢复界面尚在施工，公共入口仍默认隐藏。该基础不能单独作为完整连续主持或真实模型/玩家验收证据。

## Open v2 施工中：系统提案与叙述采用

有限委托下的队友系统提案显式标明系统来源，不能冒充真人逐条确认。提案仍进入原规则预检和风险计划；只有原开团约定允许、无额外代价和越界影响的安全行动可以沿已有预授权执行，其他提案交还真人。模型请求、提案和安全执行都绑定同一真实委托，撤销后不能自动提交新的提案或执行决定。

KP 可在同一委托下采用已完成规则结果的共同视角叙述，保留实际候选、模型、输入、接收者、委托及终验来源，不改变知识、事实或机械状态。真人逐条采用入口保持独立，系统采用不虚构真人复核。重复读取/恢复只补原回执，不重新请求模型或扩大原预算；旧历史缺少委托字段时保留原样。

当前 API 已验证一次原真人行动加两名队友、三次 KP 叙述和刷新交棒；测试传输为明确模拟。自动主持协调器、停止/恢复界面和成功响应到候选之间的完整恢复仍在施工，尚不能以这些 API 宣称一键连续主持或产品完成。


## Open v2 施工中：恢复已保存的模型回复

模型已成功保存原始响应与用量、候选尚未整理完整时，玩家桌提供“恢复已保存的回复”。恢复只复用原响应、冻结输入与真实用量，不增加调用、不续授权或预算。已有候选与 Manifest 保持原字节和绑定；缺失的候选回执、上下文回执或检查点按原 Run 补齐。读进度本身不写入，也不自动确认行动或叙述。

暂停、角色权限/机械状态变化或主持委托撤销不会因恢复获得新授权。已派发但结果未知的请求仍等待明确处置，不能借恢复再次发送。该接口与正常成功路径共用候选逻辑，属于有限连续主持的恢复基础；协调器及完整合作体验仍在施工。原生浏览器刷新路径已用明确模拟响应核验，真实 provider、独立玩家、长局与最终发布验收另行完成。


## Open v2 施工中：本轮自动主持界面

玩家可明确委托本轮有限主持，沿原预算推进已批准的行动、安全队友协作与已结算结果的 KP 叙述。系统不代替人类确认风险、后果、私域披露或阶段决定。每次明确继续从原请求、候选和结算账本恢复；刷新和读取进度本身不启动模型。结果未知或预算不足时交回真人，不静默重发或续预算。

处理中可停止：真实撤销回执先保存，再停止本机等待。只取消确实未发送的本轮委托请求、撤销尚无业务结果和新人工批准的系统提案；已经提交的规则、用量和部分进度保留。确定性提交同时检查委托，停止后不能借另一个页面继续自动提交。正式停止的本轮委托不再恢复为有效，新一轮需要真人明确开始。

协调器与界面已接入，联合验证仍按施工方案推进。模型传输的原生界面测试采用本地明确模拟，不能表示真实供应方、独立玩家、30 轮长局、商业或最终发布验收完成。


### P7 情境读取与诊断实现增量（2026-10-15）

### 备份后的未发送请求恢复（2026-10-15）

#### 导入后的原回答复核

完整备份保留历史运行证明时，当前仍有权限的原请求人可在玩家或真人主持桌面明确打开已保存的成功回答，查看原文与原用量。该入口只读，缺少真实费用回执时显示未知；旧候选不会因本地编号一致而重新取得执行资格。原文按纯文本展示，身份或团局改变后关闭。

当前玩家可复核后结束旧授权窗口，按现行冻结规则重新提出人工行动，并亲自确认风险；查看和提案不会触发模型发送或提前结算。未知结果、未发送请求和缺少原文各沿自身恢复边界处理。跨作用域直接复用旧 AI 候选、旧 KP 的替代终验，以及真实长局验收仍须分别完成，不能用历史回答展示替代。
