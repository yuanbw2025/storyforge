# 跑团产品：AI KP 生产与游玩契约

> 版本：1.1.0 · 生效：2026-10-12 · 权威层级：L2
> 状态：实施中的产品契约。以下是目标和约束；实际完成状态以能力基线和验证证据为准。
> 本次增量：标准运行格式、局势/事实/知识、授权与恢复契约；施工见 [跑团开发与施工方案](../roadmap/TTRPG-DEVELOPMENT-PLAN.md) 2.1.0。保留全部既有能力与证据，文档修订不代表新功能已实现。

## 产品结果

AI 担任 KP，支持单名真人加 AI 队友、多名真人和混合队伍，在冻结规则、冻结世界语义与作者局势层下分别行动、保守秘密、获得指引，完成有选择与后果的一场游戏。首个社区作品采用原创调查冒险和 StoryForge 2d6；不声称实现某外部规则书的全部内容。

目标标准格式为 `runFormat='open'`：作者准备局势、NPC 动机、压力、规则与开局，玩家可声明未预写行动，经规则、通用检定、受限 Oracle 或无需掷骰的合法计划裁定，世界随游戏内时间演化，以阶段收束和续团代替闭合结局。`runFormat='scripted'` 是已有闭合场景图和结局格式的兼容路径，旧作品、规则、发布包与存档不自动转换；既有人类/AI/混合主持能力保留。两种格式共用规则内核、骰子、信息边界、事件、媒资和发布链路，不新增产品身份。

冻结世界不变量、作者冻结局势层、会话演化事实分层管理；世界初始位置/持有者/关系映射为 session 的机械状态后可按唯一账本合法变化，不等于改写世界来源。会话事实、角色知识与传闻归 session；传闻/信念不能作为规则事实。世界补丁只能导出作者审阅候选，经作者显式创作和确认形成新版本，不能追写旧 WorldRelease。

世界引擎只在 `S1 世界封存`中提供不可变语义。`S2 产品定向`确认规则、模组方向、角色、席位、安全边界和媒资需求后，冻结 Brief / SourcePlan 与开始授权。`S3 产品执行`依次完成生产、验收、发布，并在用户选择游玩后创建绑定 ProductRelease 的 session。生产与运行中新内容、记忆、媒资都归跑团，不自动回写世界。

## 角色与权威

- 模组作者编辑生产候选并批准发布；游玩者不能在运行时修改发布包。
- 房主管理邀请、席位、暂停和退出；管理身份不等于可读取 GM 真相。
- AI KP 决定主持程序、世界响应、规则内裁定提案和节奏；不能代替真人决定其角色的重大行动。
- AI PC 和 NPC 分别获得自己的目标、观察和记忆。NPC 不接收 GM 全文上下文。
- 规则内核负责骰子、数值、消耗、状态、权限、顺序、版本与事件原子提交。
- Oracle 是冻结规则包授权的随机裁定，不是规则询问的建议。内核掷骰并生成可复算回执；已提交结果不覆盖，解释可以重新生成但不能改规则、改世界不变量、追溯改写或替玩家决定。新机械实体与后果须经冻结模板、合法角色/地点/物品绑定及唯一账本，不能仅写自然语言事实。
- 正式多人秘密由权威服务保管，客户端只收相应投影。本地作者预览不承诺防止本机拥有者读取源模组。

## 本桌授权

Session Zero 明确 AI 身份、角色控制权、安全边界、提示程度、暂停方式与允许的自动主持操作。该授权是有限的运行委托：模型输出仍先成为候选，经作用域、规则、版本和信息边界校验后提交。预授权范围内的 AI 行动不逐次要求作者采纳；混合席位、重大含义不清的玩家代价或越界请求需要相应玩家确认。

秘密和背叛以桌面约定为准；默认合作，不允许 AI 队友替真人解谜或未经同意实施不可逆队内攻击。暂停时停止新行动；模型失败或结果未知时保留可见状态，不隐藏重发。

open 的重大意图确认分离行动者与批准者：真人确认自己的具体计划；AI 队友由 Session Zero 指定的真人批准席位授权，AI 不能自批。确认绑定候选/计划哈希、风险、代价、输入与发布版本、授权窗口；关键变化使其 stale。涉及其他真人的资源、秘密或不可逆变化须该真人授权，拒绝/撤销不结算。

## 主持循环

输入区分对白、行动、规则询问和桌外讨论。AI KP 可开场、描述当前局势、澄清意图、提出裁定、安排相关角色反应、提出合规线索发现、切换场景、提供提示、结束或暂停。

每轮有明确的输入 revision、调用预算、候选、验证、事件和终态回执。更新规则状态后再生成玩家可见表达。AI 连续行动有界，遇到真人决定或安全暂停即让出控制权。

open 使用世界时间推进压力，威胁升级前先投放队伍可见的征兆并满足冻结提前时间。世界时间不作为模型预算与队友行动额度的归零开关：持久授权 epoch 控制连续行动及实际 provider 调用，刷新和重复继续不能绕预算。行动后的效果、时间、压力、局势、质量门和叙述形成可恢复 operation；每个因果只消费一次，reducer 只派生状态，后续命令由协调器执行。

自由表达映射到规则内行动或无检定互动；检定方式、风险与资源消耗必须可解释。玩家可选择其他方法、拒绝任务或撤退，不能为回到预设剧情改写事实。

探索、社交与战斗的调度按规则配置。多人同时输入有稳定排序或声明窗口；分队按场景保留各自知情范围，共享后果由同一权威提交。

## 信息边界

区分客观事实、角色观察、角色信念、谎言、私事和信息接收者。信息传播有证据事件和来源；某角色的转述不会让听众自动获得原件全文。

主 Agent 的计划及 GM 真相不直接向玩家发送。关键披露引用已冻结事实与规则条件，经验证后生成按接收者限制的叙述。公开话语、私信、角色决策、摘要、检索、缓存、回放、导出和媒资均遵循相同边界。

字符串检查是补充防线，不是语义绝对保密证明。角色上下文首先排除其未获知的信息。合法揭示和禁止泄密必须同时有测试。

open 的线索/知识以真实发现和传播事件记录接收者、来源及公开字段，局势结束后知识继续存在；私人发现不自动成为全队知识，新席位不自动取得历史秘密。玩家可继续门必须按当前真人投影判断，不用他人的私密出口充数。分支来源同时标记 session 身份和事件序号，不能因子序号归零混淆父子证据。

## 模组、角色与媒资

模组包含可运行局势、关键真相、场景、线索载体和发现途径、NPC 动机、压力、规则挑战、即兴范围和结局条件。检查关键进展是否存在瓶颈，不能将故事摘要机械切片即认定为可玩模组。

上述场景图/结局与穷举可达性属于 scripted 的现行合同。open 冻结作者局势、来源事实索引、规则/Oracle、实体与效果绑定、安全/授权、运行预算及阶段策略；共享 narrative 容器仅作为开场/只读素材，不通过伪造结局或 choice 满足旧图门。open 用运行时四门（当前玩家有出路、可形成假设、征兆齐备、事实一致）及明确发布静态门；可机器判定结构与真实语义体验分别验收。

AI 车卡必须有真实生成证据，并经过规则合法性检查；候选支持确认与修订。角色目标、关系和能力在队伍中互补。世界角色映射保存来源，不创建反向同步。

媒体按玩法需要生产：封面、角色肖像、地图、handout 可独立失败与重试。图片/音频也遵守信息边界。发布媒资与运行媒资 owner 分离。

## 用户路径和社区作品

用户路径：世界编辑与封存 → 跑团入口 → 配置与明确开始 → 内容/角色/媒资生产 → 审查 → 发布 → 选席位与开局 → 实际游玩 → 结局/复盘 → 保存或继续。

制作界面与玩家界面各自清晰，玩家不需要操作开发者或人类 GM 管理面板。替代入口同步收口。

首个作品交付冻结世界来源、产品发布包、必要媒资、玩法说明、许可说明与脱敏生成/试玩证据。导出不得包含 API Key、账户身份或私人测试聊天。用户负责后续 GitHub 集成与社区发布，本实现不替用户发布宣传内容。

## 工程闭包

复用 CONTEXT_SOURCES / assembleContext、FIELD_REGISTRY / Adoption、PROJECT_TABLES。新增读源、Skill、事件、候选或表先登记并定义 owner、删除、备份、引用重映射、版本及恢复。共享热点变更作为独立基础增量审查，产品逻辑留在跑团边界。

测试覆盖规则、权限、角色未知信息、有效披露、stale、重试、同时行动、分队、回放、导出、发布和世界不回写。交付运行完整 CI 及隔离 E2E，并通过真实模型完成世界到跑团的正常用户流程与实际游戏。

## 完成证据

必须区分结构/工程测试、真实模型评测与玩家体验。自动回归不能冒充真人试玩；没有部署证明不能宣传真实公共多人服务完成；试作品可游玩不能代替长期商业运营验证。能力门仅随真实证据更新。

记录整轮与整场调用、tokens、耗时、已知费用、失败恢复和人工干预。未知价格保持未知，不捏造成本或以单次回复成绩代替整场质量。

open 首期必须同时验证正常作者界面的生产/审查/修订/发布和真人加 2–3 队友的连续合作局，不能以手写 fixture 发布代替。四门、授权、恢复与旧包兼容联合验收后才可开放；长局还需真实 provider 连续 30 个 worldTurn 以上、Oracle 复算和征兆前置均 100%、事实矛盾/可继续率基线、分支恢复及一次世界补丁审阅证据。产品整体验收同时覆盖作者工具、角色卡、媒资、分发和续团，不能只凭 open runtime 宣布完成。

## 当前实现边界

截至 2026-10-12，open 标准格式只有本契约和施工方案 2.1.0 的设计约束，尚无该方案实现与验收证据；新内容/状态版本、无场景准入、Oracle、会话事实/角色知识、压力自驱、局势、授权 epoch、可恢复 operation、四门、条件注入和长局记忆均保持待实施。以下记录描述既有 scripted 能力，不因本次修订降级或被新格式覆盖。原始响应与恢复等复用设施缺口须按方案补齐；规则询问仍只给建议，不代替正式行动或 Oracle。

本分支已经接通以下能力：

- 2026-09-15 新跑团入口 `/ttrpg/:pageId?` 接入实际作品库、九步配置、提案比较、制作与检查、发布和团局。一级操作导航与页面内的配置/内容分类分层；未选世界可浏览、填写并保存。旧 `?tab=ttrpg` 普通链接转入新入口，明确 legacy/在线交接保留兼容路径。
- `Work.kind=ttrpg` 与 `ttrpgAuthoringDrafts` 保存产品自己的 S2 草稿、规则引用和世界出口选择；保存配置不触发生成。编译为原有 Brief 后仍需确认提案与明确开始授权，继续走冻结 SourcePlan、既有 Harness 与发布闸门。草稿由 PROJECT_TABLES 统一备份、重映射、删除；schema v8 只加表并调整 Brief 内容 hash 为非唯一索引，版本身份仍由 production/revision 唯一约束，不改写已有记录。
- 战役/场景/角色/地图/手册和媒资页读取实际 Build 产物；内容修订通过新制作轮次或已有失败任务的作者校订入口进行，尚未提供这些对象的通用逐字段可视化编辑器。游玩页重用既有 KP、规则、角色卡、桌面、安全约定、存档和续团功能。

- 已冻结规则与模组下的有界 AI KP 循环：NPC、AI 玩家行动、条件内线索揭示、公开叙述、真人交接、场景与结局选择。
- 本人私密指引及行动前规则询问；询问持久保存，但不扣除角色行动，也不代替真人提交意图。
- 单人加 AI 同伴、同一设备多人交接、独立游玩页、自动保存、检查点分支恢复、可见 API 错误与明确继续。
- 同机多人刷新、切换待回应玩家时先遮住记录与手记，玩家确认后才显示对应桌面；也可手动遮屏。此机制用于防止交接时误看，不代替账户认证或服务端隔离。
- 社区目录与本地存档独立读取，目录失败时仍可打开已有冒险；读取检查点失败保留当前桌面，成功后切换到独立分支，主持期间禁止同时恢复。
- 玩家、NPC、公开叙述采用各自的上下文投影。规则回执保留在运行账本，模型读取结构化观察；被预算截断的 JSON 不得发送。
- 生产模块必须交付真实角色资料、公开场景/GM 真相、线索发现路径和结局条件，并经确定性编译及发布校验。
- 制作失败时可查看原始模型草稿、填写修复要求重试，或提交完整作者校订 JSON。校订绑定当前失败任务及 revision，沿同一 Harness、上下文、解析器和发布闸门验收，保留原模型输出与作者输入的独立证据；不伪造模型调用或绕过秘密与规则校验。
- 社区目录通过校验过的分发包创建独立本地实例，复用 Release / media / 生命周期入口，不伪造市场订单或授权。
- 已有联机协议的 AI NPC 与公开叙述采用最小信息视图；这不等于已经部署可供社区使用的多人服务。

《雾港：最后一盏灯》已通过真实 provider 的世界生成、正式产品生产和完整试玩，证据见 `examples/ttrpg/fog-harbor/production-status.md`。以下条件仍不能由工程测试替代：真实调用成本与延迟基线、公共多人服务部署及独立玩家测试。完整自由语义裁定、独立分队主持和商业运营保证也尚未完成；当前规则询问给出建议，正式行动仍由玩家从冻结规则中确认。

首发目录只有在真实发布包、原创素材许可、完整试玩和脱敏证据就绪后才加入作品条目。`commercialReady` 与产品完成证明不得因本分支自动回归通过而开启。
