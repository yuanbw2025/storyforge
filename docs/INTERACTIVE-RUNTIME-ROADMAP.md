# StoryForge 互动运行时路线 · SIM-1 / TTRPG-1 / CHATGAME-1

> 状态：SIM-1C、TTRPG-1A/1B/1C、FLOW-3D 与 CHATGAME-1 单角色聊天 MVP 已交付（2026-08-05）；后续进入长期记忆、多角色和冒险扩展。
> 详细 schema、事件闭集和当前实现边界见 `SIM-RUNTIME-DESIGN.md`。

## 1. 为什么先有共同运行时

跑团和“酒馆式”角色聊天冒险表面入口不同，但底层都需要：

- 独立于作者原稿的世界实例和时间推进。
- 角色位置、状态、物品、能力、关系与记忆。
- 玩家行动、规则判定、随机数/骰子和事件日志。
- 可恢复的会话、分支和快照。
- AI 叙事候选、确定性规则结果和用户选择。

如果两条功能各自建立状态、记忆和事件表，会立刻形成两个互不兼容的游戏引擎。因此先由
`SIM-1` 提供共同运行时，再分别建设跑团和角色聊天产品层。

## 2. 层级

```text
创作层：WORLD / CANON / STORY / CHARACTER / INVENTORY
             │ 只读快照或作者明确发布
             ▼
模拟层：SIM-1 世界实例 / 时钟 / 实体状态 / 事件 / 规则判定
             │
             ├── TTRPG-1 战役 / 团队 / GM / 骰子 / 回合
             └── CHATGAME-1 角色聊天 / 场景探索 / 选择 / 冒险
```

- 创作 Canon 是作者作品的权威来源。
- 模拟运行时是一次游戏或会话的派生世界，不得自动反写正文、设定或角色主档。
- 有价值的游戏事件若要进入创作层，必须先形成候选，再由作者逐条确认采纳。
- FLOW-1 可以编排互动过程，Agent 可以主持或扮演角色，但二者都不能绕过模拟规则和状态层。

## 3. SIM-1 · 共同模拟地基

### 目标

提供可复用、可回放、可分支的互动世界实例。

### 当前已交付

- `simulationSessions / simulationEvents / simulationCheckpoints` 三表已进入 DB v48 和
  `PROJECT_TABLES`，覆盖项目/世界删除、父子分支、JSON 导出导入与外键重映射。
- 纯事件 reducer 已覆盖时间、实体、记忆、叙事和确定性骰子；非法事件、事件序号缺口、
  跨作用域数据和直接伪造骰子结果会被拒绝。
- 检查点保存可验证状态 hash；分支从父会话指定序号冻结状态并建立独立事件流。
- 工作区“体验中心 → 互动运行时”可创建沙盒、NPC 演进、跑团、角色聊天四类独立会话，
  推进时间、掷骰、记录叙事、创建检查点、建立/删除分支，并在刷新后恢复。
- 当前状态与本会话事件日志分开展示，因此父会话继承的叙事不会因分支或刷新变成不可见数据。
- 作者创建会话前明确选择世界、角色、地点、物品和规则；来源字段、摘要、更新时间和
  SHA-256 固化到会话，角色/地点/物品成为不反写 Canon 的独立运行时实体。
- 会话列表按世界隔离；来源审计可验证 hash，检查点恢复建立子分支而不截断父事件流。

### 下一阶段

- SIM-1C 已完成：NPC 选择、运行时只读上下文、候选生成、事件持久化、作者确认/拒绝、过期保护、
  事件回放/分支与 Canon 不变性已全部收口。
- 后续运行时实体编辑必须转换为闭集事件；不得直接改写冻结来源或初始状态。

### 红线

- 运行时表必须在 `PROJECT_TABLES` 登记并有项目/世界/会话作用域。
- 创作角色、物品账本和 Canon 只做来源快照或显式引用，不被模拟器直接更新。
- AI 只能提出动作与叙事候选；合法性、骰子与确定性状态变化由代码判定。

## 4. TTRPG-1 · 跑团

### 用户故事

作者或玩家选择一个 StoryForge 世界，建立战役、角色卡和规则集；AI 可担任辅助 GM，
但每次判定、骰子、状态变化和重要事件都有可见依据。

### 阶段

1. ✅ `TTRPG-1A` 单机战役：本地玩家、AI GM、场景、回合顺序、技能检定、成功/失败叙事和事件日志。
2. ✅ `TTRPG-1B` 规则与遭遇：AI 遭遇候选确认、确定性先攻、战斗回合、攻击/伤害、资源上下限、状态效果和回放。
3. ✅ `TTRPG-1C` 长期战役：会话续接、摘要、世界时间、任务、NPC 日程和战役分支。
4. `TTRPG-1D` 多人协作：等 PLATFORM-1 的账号、同步和冲突处理完成后再立项。

### 非范围

- 第一阶段不做联网房间或实时多人。
- 不让 AI 私自改骰子结果或后台改角色卡。
- 不把战役日志冒充小说正文或正式 Canon。

## 5. CHATGAME-1 · 角色聊天与冒险

### 用户故事

用户选择一个或多个已创作角色，在独立的互动世界实例中聊天、探索和做选择；角色保持
身份、知识边界、关系、状态和长期会话记忆，体验可从纯聊天平滑升级为文字冒险。

### 阶段

1. ✅ 单角色聊天 MVP：角色卡、场景卡、用户身份、流式回复、重新生成和分支。
2. 长期记忆：会话摘要、事件记忆、关系变化和知识边界。
3. 多角色房间：发言调度、角色间行动和冲突判定。
4. 冒险模式：地点移动、物品、能力、选择、随机判定和任务。
5. 创作回流：把有价值的事件整理成候选，由作者确认后进入灵感、故事线或大纲。

### 红线

- 角色聊天使用运行时人格快照；角色主档变化只在作者明确同步时发生。
- 角色不能读取其认知边界之外的 Canon 或其它角色私密记忆。
- 回复文本不能直接决定物品获得、死亡、位置或能力变化；状态必须通过模拟规则候选。
- 第三方角色卡导入必须有来源说明、字段沙箱和未知脚本拒绝，不执行任何嵌入脚本。
