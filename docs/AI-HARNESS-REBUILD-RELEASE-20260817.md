> 合并提交：`5021094407a3d71da904564980be1527623ff206`

> 原施工分支：`feat/harness-creative-reliability`

## 一句话说明

StoryForge 已把原来散落在各创作页面里的 AI 调用，收进统一的 Agent + Harness 执行架构：模型只读登记过的上下文，只生成可编辑候选；系统用有界调用、确定性校验、持久化账本和终态回执管理失败与恢复；作者明确确认后，候选才会进入正式设定或正文。

这次更新解决的是“AI 创作过程如何被可靠地执行和交付”，而不是宣称某个模型从此能够稳定写出完美小说。

## 为什么要重构

过去的生成路径虽然已经具备提示词模板、上下文装配和作者确认，但不同功能仍可能各自维护调用、解析、重试和临时候选。模型一旦不遵守结构、网络状态未知或生成质量不足，系统容易出现三类问题：

1. 不知道失败发生在哪一层，也无法准确恢复。
2. 反复重试会继续消耗用户 API，却可能没有可交付结果。
3. 页面级旁路容易绕开统一上下文、作用域、采纳和数据生命周期。

新的架构把创作自由与工程安全分开处理：作用域、引用、结构、写入权限和费用上限保持严格；文学质量、风格和完整度允许分级，以警告、局部修复和作者编辑处理，而不是为了追求机器满分无限重生成。

## 现在的统一主路径

```text
作者请求
  -> Master Agent / 领域 Skill
  -> Run Contract（目标、权限、版本、预算、完成条件）
  -> CONTEXT_SOURCES + assembleContext()
  -> 一次生成
  -> 免费确定性归一化与验证
  -> 必要时最多一次定向修复
  -> CreativeArtifact（草稿、合法片段、问题、假设、用量）
  -> 作者编辑 / 选择 / 接受警告 / 拒绝
  -> FIELD_REGISTRY + AdoptionSchema + adopt()
  -> 终态回读、回执与影响处理
```

贯穿整条路径的 `PROJECT_TABLES` 继续负责表的作用域、导出、导入、删除、迁移、引用重映射和运行记录生命周期。Agent 与 Harness 没有建立第二套数据库或 AI 旁路。

## 本次交付的核心能力

### 1. Agent 不再等于“会聊天的提示词”

- Master Agent 只负责识别意图、选择已登记 Skill、安排依赖和汇总候选。
- 领域 Skill 冻结读源、写目标、提示词版本、工具 schema、上下文策略和回归证据。
- Tool Registry 使用闭集只读工具；模型不能通过自由工具名扩大权限。
- 有限 fan-out 和有限重规划只在明确策略允许时启用，不能变成无边界 Agent 团队。

### 2. Harness 提供可恢复的运行控制面

- 每次运行都有 Run Contract、事件账本、checkpoint、候选 hash、父子 lineage 和终态回执。
- 页面刷新、浏览器中断或长任务恢复时，从同一 ledger 重建状态，不重复已经结算的调用。
- stale 输入、跨 Work/World、错误候选身份、目标变化和采纳前 CAS 漂移会在正式写入前拒绝。
- 下游影响处理以可验证 DAG 展示阻断、就绪、待确认、需人工处理和完成状态，不自动级联重写整本书。

### 3. 创作可靠性采用“严格安全、分级质量”

统一产物状态为：

- `ready`：结构、作用域和硬边界通过，可进入作者确认。
- `usable-with-warnings`：结构可采纳，但存在弱因果、重复、信息倾倒等普通质量问题。
- `manual-repair`：保留原始草稿或合法片段，需要作者手工调整。
- `blocked`：越权、错作用域、错误引用、stale 或不确定正式写入等安全问题。

系统不会因为一个软问题丢掉整批输出，也不会把软质量警告伪装成数据安全失败。

### 4. API 花费被明确限制

- `economy`：一次生成，不自动修复。
- `balanced`：一次生成；只有确定性定位到可修问题时，最多一次定向修复。
- `refine`：仍最多 1+1；额外语义评审必须由作者显式触发。
- 相同失败指纹再次出现立即停止；授权、余额、权限、stale 和网络结果未知不会自动重发。
- 每个候选记录模型、用途、token、延迟、修复与停止原因。模型价格未登记时只展示 token，不虚构金额。

### 5. 部分设定也能推动故事，而不是反复复述世界观

`NarrativeBrief` 把当前任务收束为人物欲望、阻力、代价、必须选择、入口状态、退出变化和下一步压力。资料不足时，模型可以在同一次生成中提出显式临时假设；这些假设随候选存在，不会静默升级为 Canon。

上下文优先级也从“谁的资料最多谁占注意力”改为：作者本轮要求、叙事任务、直接前文和当前状态优先，相关 Canon 次之，世界背景和其它参考只在确实影响行动与结果时进入。

### 6. 核心创作入口统一登记

故事核心、故事线、世界观字段、角色创建/补充/关系、灵感反推、角色驱动、卷章纲、细纲、正文、章后记忆与提取、地点、物品、年表、伏笔、历史、参考分析、文风学习等路径已经迁移到 durable Run，或作为明确的只读/内存草稿/模拟运行时入口登记审计。AI 入口检查会阻止新的页面级直连悄悄出现。

## 对作者意味着什么

完成这次更新后，理想交互不再是“点击生成，然后祈祷一次成功”，而是：

1. 系统明确本轮要生成什么、会读取什么、最多调用几次。
2. 生成结果无论完美与否，都尽量留下可编辑内容和准确问题说明。
3. 作者能修改候选、接受普通警告、只采纳合法部分或直接拒绝。
4. 正式数据只有在作者确认后改变；运行中断后可以继续，不必重新付费生成上游。
5. 后续事实、摘要、检索、章纲和年表影响有可见计划，不会悄悄改稿。

## 数据与兼容性

- 仍是纯前端、本地优先应用，没有新增 StoryForge 云端后端。
- API Key 的保存边界没有改变；运行证据不包含明文 Key。
- 旧项目通过显式 World / Work owner 兼容层进入新作用域，历史候选和旧事件按版本兼容读取。
- 新增运行表已进入 `PROJECT_TABLES` 的导出、导入、删除、迁移和引用重映射生命周期。
- 未确认候选、运行存档和作者私有资料不会自动进入世界发布包。

## 验证结果

合并前最终工程验证：

- `npm run ci` 全绿：387 个测试文件、1,892 项测试。
- required tables、AI Manual、AI 入口登记、架构、来源可达性、路线图、Agent freshness、Canon、生产依赖、lint、TypeScript、覆盖率、构建和 bundle budget 全部通过。
- 独立 Chromium 数据中的 E2E 52/52 通过，没有使用或修改作者当前预览项目。

创作可靠性真实模型评测：

| 评测 | 可编辑 | 可采纳 | 平均调用 | 语义 | 推进 | 结论 |
|---|---:|---:|---:|---:|---:|---|
| Development v6 | 100% | 100% | 1.00 | 85.8% | 100% | 机器门 PASS |
| Sealed held-out v6 | 100% | 100% | 1.00 | 83.3% | 100% | 成本门 FAIL |

封存集唯一失败项是 token/可采纳产物倍率：实际 `1.514404`，预注册门槛 `1.5`，每份产物高约 30.4 tokens。按冻结协议必须判定失败，不能为了得到好看结论重跑或调阈值。

## 社区观察期的诚实边界

- 历史独立真实作者 A/B 仍为 0/6；sealed held-out 成本门仍为 FAIL。2026-08-17 产品决策关闭这两项作为本轮交付阻塞条件，不等于它们已经通过。
- 当前证据不能支持“StoryForge 已经替作者完成 80% 工作”这一宣传。
- 模型仍可能偏题、结构失误、遗漏事实或生成普通文本；Harness 能限制损失、保留结果并解释失败，不能替模型凭空获得文学能力。
- sealed held-out 已经消耗，不得据此调参、放宽门槛或重跑。当前先观察社区作者主动提交的采用结果、修改时间和问题类型；如需新的量化宣传或正式质量门，必须另立新协议与新冻结终验集。
- 社区账号、云发布、发现、协作和治理仍属于后续平台工程，不属于本次 Agent + Harness 更新。

## 后续方向

1. 以实验性入口收集纯本地、可导出的结构化反馈，由作者决定是否主动提交。
2. 按采用结果、修改时间、集中问题、费用与延迟反馈归因，不为旧门槛重复烧费。
3. 只有社区证据显示集中问题时，才建立有明确范围、预算和停止条件的新修复任务。
4. 若未来需要量化质量宣传，再独立建立新的作者研究和冻结评测协议；当前社区观察不能替代该证据。
