# Harness 创作可靠性转入社区观察的产品决策

> 状态：Accepted
>
> 决策日期：2026-08-17
>
> 适用范围：`CREL-0～14`、独立作者 A/B、原预注册社区质量门

## 背景

Agent + Harness 与 CREL 创作可靠性工程已经完成统一执行、可恢复候选、作者确认、受治理采纳、
1+1 调用上限、确定性归一化、失败降级、费用证据和本地结构化反馈入口。

历史评测必须继续如实保留：Development v6 通过机器门；唯一一次 sealed held-out 的
token/可采纳产物倍率为 `1.514404`，高于预注册 `1.5` 门槛，因此该次机器门为 `FAIL`；独立作者
A/B 尚未执行，记录为 `0/6`。这些结果不能改写成通过，也不能用开发者判断代替真实作者反馈。

继续把一次小样本独立 A/B 和原质量门作为工程完成的阻塞条件，会推动为阈值反复调参、重跑和消耗
API，却不能代表社区作者在不同题材、设定完整度和模型配置下的真实体验。现有产物已经具备受控试用
所需的安全、恢复、费用停止、回滚和反馈边界，可以进入社区观察。

## 决策

1. `CREL-0～14` 作为开发任务正式完成，Harness/CREL 本轮工程收口。
2. 独立作者 A/B 与原预注册社区质量门关闭，不再作为本轮开发、合并或社区预览的阻塞项；状态为
   “由产品决策关闭/取代”，不是“评测通过”。
3. 创作可靠性入口进入社区观察期，继续明确标注为实验性/预览能力，不承诺任何模型稳定生成完美文学
   结果，也不宣传“替作者完成 80%”或“全面优于旧路径”。
4. 观察优先使用现有纯本地结构化反馈：环节、采用结果、1～5 分、预计修改时间和问题类型。记录不自动
   上传；作者主动导出并提交后，维护者才能收到。
5. sealed held-out、Development 和 HARNESS-86 的历史协议、hash、用量和失败结论全部冻结，不因本决策
   重新解释、调阈值或重跑。

## 社区观察重点

- 是否基本保留、修改后使用或放弃。
- 从候选到可用稿的预计修改时间。
- 偏离设定、剧情不推进、设定堆砌、结构、连续性、成本和延迟问题。
- 不同环节的集中失败类型，以及是否需要回滚或重新打开专项工程。

社区反馈是产品观察证据，不自动等同于统计学 A/B。当前本地入口不会上传作品文本、提示词、模型输出、
项目标识或 API Key，因此社区结论只能基于作者主动提交的数据形成。

## 后果与重新开启条件

- 路线图不再把独立 A/B 或原质量门列为待开发项；后续工作是社区反馈收集、问题归因和按证据建立新的
  独立任务。
- 如果社区出现集中安全退化、无产出、费用失控或明显不可用，立即使用现有本机开关回退，并重新开启
  有明确样本、预算、门槛和停止条件的修复工程。
- 如果未来需要对外作量化质量宣传，必须另立新的独立评测任务和新冻结协议；本决策及社区观察不能替代
  该证据。
