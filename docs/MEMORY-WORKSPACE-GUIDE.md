# 本地记忆工作区：使用、恢复与隐私

本地记忆工作区把浏览器 IndexedDB 中的确定内容投影为用户硬盘上的可读文件。它是数据库的可核对映像，但不是被动备份：作者可以在项目里修改，也可以在硬盘编辑受支持的文件；任一方向都必须回到“数据管理”由作者手动触发检查和确认。

## 日常使用

1. 在“数据管理 → 本地记忆工作区”选择一个专用文件夹。绑定和重新授权都不会写文件。
2. 点击“检查记忆与本地文件”。系统只做本地读取、解析、哈希、作用域和依赖检查，不调用模型、不修改任一侧。
3. 查看分类和影响：项目内改动、本地改动、同改、双方冲突、缺失、额外或损坏。
4. 项目内改动选择“确认写入项目改动”；本地改动先形成字段候选和影响计划，再选择“确认采纳本地改动”。
5. 冲突必须明确选择项目版本或本地版本。旧文件先进入 `.storyforge/history`；缺失章节只有显式确认后才删除，删除前复制到 `.storyforge/trash`。

支持直接编辑的文件是 Workspace、World、Work 和章节 Markdown。其余已确定项目数据以及 Harness 的 Run、候选、作者决定、采纳和验证证据统一进入只读恢复胶囊；修改只读证据会被隔离，不能反向写入项目。可重建检索块、临时导入状态、统计和本机句柄不会冒充长期记忆。

## Harness 与长期一致性

正式 AI 流程继续由 Harness 记录输入版本、候选、作者决定、采纳和验证。记忆索引只保存对这些原始 ledger 和正式记录的引用，不复制正文。没有作者确认的候选不会升级为 Canon；磁盘尚未同步时会显示 workspace dirty。

生成上下文优先读取已确认事实、角色认知、状态、物品、时间线和依赖关系。本地全文关键词只提供可回链证据；embedding 默认不参与记忆档案，也永远不能裁决事实。生成式语义复核必须由作者另行许可并进入可计费 Harness Run。

## 恢复

- 浏览器数据仍在：重新选择原目录，先检查，再按分类处理。
- 浏览器数据库丢失：选择“从工作区恢复浏览器数据”。系统先验证 workspace identity、manifest、恢复胶囊和逐文件 hash，再创建项目和重映射数值引用；失败会撤销新项目。
- 浏览器不支持 File System Access API：导出或导入自校验的工作区包。
- 同步中断或授权撤销：重新授权后再次检查；pending 事务只补写未完成文件，不重复模型调用或数据库采纳。
- 仍建议在重大迁移或删除前另存完整 JSON 备份。JSON、工作区目录和工作区包是互补恢复路径。

## 隐私、成本和限制

- 文件夹读取、差异检查、结构校验、影响计划、哈希和同步全部在本机完成，不上传内容，模型调用为 0，因此不消耗用户 AI token。
- 只有作者另行启动 AI 生成、文风学习或语义复核时，注册上下文才发送给用户配置的模型服务并计入 token。
- 工作区单文件扫描上限 64 MiB，单次扫描/工作区包总上限 256 MiB；超限文件会先隔离，不读取正文。
- 文件元数据没有变化时复用上次已提交的语义 hash；变化文件才重新读取和解析。
- 不包含云同步、多人协作、Git 自动提交或服务端托管。

## 停用和回滚

数据管理页可随时“停用”记忆工作区。停用后不读取、不检查、不恢复或改写现有目录；IndexedDB、完整 JSON、正文导出和手动 JSON 快照仍可使用。重新启用不会自动同步，仍需作者手动检查。发布回滚只关闭新入口，不删除已有目录、Run ledger、正式内容或恢复证据。
