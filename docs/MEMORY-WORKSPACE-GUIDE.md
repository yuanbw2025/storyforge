# 本地记忆工作区：使用、恢复与隐私

> 当前状态：✅ 已由 PR #66 / #71 完成并合入 `main`。本指南描述的是当前正式能力，不是未来设计稿。

本地记忆工作区把浏览器 IndexedDB 中的确定内容投影为用户硬盘上的可读文件。它是数据库的可核对映像，但不是被动备份：作者可以在项目里修改，也可以在硬盘编辑受支持的文件；任一方向都必须回到“数据管理”由作者手动触发检查和确认。

## 项目位置

- 新建项目时可直接选择“项目存储位置”。所选文件夹就是这个项目的本地根目录；例如选择
  `D:\StoryForge\我的小说\`，项目的可读内容、记忆与恢复证据都位于该目录内。
- 也可先创建项目，再到“设置 → 项目存储工作区”选择或更换任意本地硬盘文件夹。设置页是位置管理的
  唯一入口；“数据管理”只负责核对、同步和恢复。
- 浏览器安全规则要求首次选择、更换位置或权限失效后由作者确认授权。浏览器不会向网页暴露完整盘符路径，
  因此设置页显示文件夹名称，系统选择器负责展示真实位置。
- 选择或更换位置只保存授权句柄，文件写入仍为 0。旧目录不会被删除；进入“数据管理”检查差异并确认后，
  才会在新位置建立当前项目映像。
- 未选择文件夹时，项目仍可使用，但只存在于当前浏览器数据库；设置页会明确显示“尚未设置项目文件夹”。

一个典型项目根目录如下：

```text
我的小说/
├─ storyforge.workspace.json
├─ worlds/
├─ works/
│  └─ <WORK-CODE>/
│     ├─ chapters/
│     └─ memory/
│        ├─ story-core.yaml
│        └─ creative-rules.yaml
└─ .storyforge/
   ├─ manifest.json
   ├─ recovery/
   ├─ runs/
   ├─ history/
   └─ trash/
```

## 日常使用

1. 新建时选择项目文件夹，或在“设置 → 项目存储工作区”设置位置；绑定和重新授权都不会写文件。
2. 点击“检查记忆与本地文件”。系统只做本地读取、解析、哈希、作用域和依赖检查，不调用模型、不修改任一侧。
3. 查看分类和影响：项目内改动、本地改动、同改、双方冲突、缺失、额外或损坏。
4. 项目内改动选择“确认写入项目改动”；本地改动先形成字段候选和影响计划，再选择“确认采纳本地改动”。
5. 冲突必须明确选择项目版本或本地版本。旧文件先进入 `.storyforge/history`；缺失章节只有显式确认后才删除，删除前复制到 `.storyforge/trash`。

支持直接编辑的文件是 Workspace、World、Work、章节 Markdown，以及每个 Work 下的两份中文语义文件：

- `works/<WORK-CODE>/memory/story-core.yaml`：一句话故事、故事概念、主题、核心冲突、情节模式、主线和复线；
- `works/<WORK-CODE>/memory/creative-rules.yaml`：写作风格、叙事视角、基调与氛围、禁止事项、一致性规则和特殊要求。

这些 YAML 不暴露本地数值 ID、时间戳或引用 ID；外部修改仍先变成登记字段候选，经 CAS、Work 作用域和
影响计划校验后才能采纳。故事核心或创作规则缺失时只能从项目恢复文件，不能借“删除章节”入口删除正式
语义。其它已确定项目数据以及 Harness 的 Run、候选、作者决定、采纳和验证证据统一进入只读恢复胶囊；
修改只读证据会被隔离，不能反向写入项目。可重建检索块、临时导入状态、统计和本机句柄不会冒充长期记忆。

## Harness 与长期一致性

正式 AI 流程继续由 Harness 记录输入版本、候选、作者决定、采纳和验证。Run 成功、失败或取消时，
Harness 会在同一浏览器数据库事务内追加显式记忆结算：成功且满足所需采纳时为 `settled`，失败、取消或
缺少所需采纳时为 `incomplete`。这一步只写本地事件账本并标记 workspace dirty，不会绕过作者操作写硬盘。
记忆索引只保存对原始 ledger 和正式记录的引用，不复制正文。没有作者确认的候选不会升级为 Canon；
作者完成手动同步后，工作区索引才显示当前磁盘状态 clean。

生成上下文优先读取已确认事实、角色认知、状态、物品、时间线和依赖关系。本地全文关键词只提供可回链证据；embedding 默认不参与记忆档案，也永远不能裁决事实。生成式语义复核必须由作者另行许可并进入可计费 Harness Run。

章节审校页的 Fast Guard / Deep Audit 也是正式 durable Harness Run：一次点击最多一次模型调用，报告只作为
证据候选，不自动修改正文。正文变化后，旧报告和历史事件仍保留，但当前终态凭据会明确变为 stale；重新
审计会建立新的可区分记录，不覆盖旧证据。

## 恢复

- 浏览器数据仍在：重新选择原目录，先检查，再按分类处理。
- 浏览器数据库丢失：选择“从工作区恢复浏览器数据”。系统先验证 workspace identity、manifest、恢复胶囊和逐文件 hash，再创建项目和重映射数值引用；失败会撤销新项目。
- 恢复时若历史 Harness 的 completed 凭据绑定了原浏览器数值主键，系统会保留全部事件和候选、追加明确的
  “待复核”状态，并重建恢复胶囊与记忆索引；旧文件先进入 `.storyforge/history`，页面会显示受影响数量。
- 浏览器不支持 File System Access API：导出或导入自校验的工作区包。
- 同步中断或授权撤销：重新授权后再次检查；pending 事务只补写未完成文件，不重复模型调用或数据库采纳。
- 仍建议在重大迁移或删除前另存完整 JSON 备份。JSON、工作区目录和工作区包是互补恢复路径。

## 隐私、成本和限制

- 文件夹读取、差异检查、结构校验、影响计划、哈希和同步全部在本机完成，不上传内容，模型调用为 0，因此不消耗用户 AI token。
- 只有作者另行启动 AI 生成、文风学习或语义复核时，注册上下文才发送给用户配置的模型服务并计入 token。
- Fast Guard / Deep Audit 只有作者点击时才计费，每次最多一次调用；发现问题不会自动继续调用模型或改稿。
- 工作区单文件扫描上限 64 MiB，单次扫描/工作区包总上限 256 MiB；超限文件会先隔离，不读取正文。
- 文件元数据没有变化时复用上次已提交的语义 hash；变化文件才重新读取和解析。
- 不包含云同步、多人协作、Git 自动提交或服务端托管。

## 停用和回滚

数据管理页可随时“停用”记忆工作区。停用后不读取、不检查、不恢复或改写现有目录；IndexedDB、完整 JSON、正文导出和手动 JSON 快照仍可使用。重新启用不会自动同步，仍需作者手动检查。发布回滚只关闭新入口，不删除已有目录、Run ledger、正式内容或恢复证据。
