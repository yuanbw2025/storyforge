# StoryForge 本地 API 配置规则

> 版本：1.0.0 · 生效：2026-10-23 · 权威层级：L1
> 上位依据：总纲 §8.2、§12.2；维护职责见 [协作流程 §2.2](./COLLAB-WORKFLOW.md#22-总纲与本地-api-治理分支)。

## 1. 责任与边界

本规则属于共享工程底座和开发协作，供项目级开发、评测、媒资调用和运维任务查找本机 API 配置。治理维护者负责登记服务、配置结构、用途和失效状态；其他分支按任务使用明确的 profile。目录与规则的建立不代表已经登记或验证了任何服务。

交接物是版本化治理文档与本机私有配置索引；不新增作品表、上下文源、AI 可写字段、世界引用或媒资 owner。正式产品调用继续遵守三注册表、Agent Skill / Run Contract / durable Harness；作者在产品设置页中配置的连接仍由现有设置契约管理。本目录不自动读取或替换作者浏览器配置，不复制第三方客户端登录状态。

## 2. 所有工作树的统一入口

解析顺序：

1. 当前任务显式设置了 `STORYFORGE_LOCAL_API_HOME` 时，使用其绝对路径。
2. 未设置时使用当前用户的 `~/.config/storyforge/api/`。
3. 目标不存在、索引为空或所需 profile 不可用时，报告未配置；不得搜索其他分支、日志或浏览器存储猜取凭据。

该变量是本地工具的路径约定；现有脚本不会因本文自动获得加载能力。使用方先读根目录 `README.md` 与 `catalog.json`，再检查其现有入口支持的参数、环境变量或配置文件格式。新增适配必须走正常开发与审查，不建立绕过正式治理的通用 API 调用器。

目录必须位于所有 Git 工作树之外，解析符号链接后也不得落入仓库；不得把目录或其中的文件链接进工作树。macOS/Linux 目录权限为 `0700`，文件为 `0600`；其他平台使用仅当前用户可读写的等价权限。

```text
~/.config/storyforge/api/
  README.md                 本机维护说明及已知配置的发现指引
  catalog.json              profile ID、状态和配置文件相对路径
  profiles/<profile-id>.json 真实端点、模型、凭据引用、用途、预算和使用规则
  credentials/              仅本机保存的密钥文件；也可引用既有安全凭据库
  receipts/                 本机调用验证及变更记录；写入前清除密钥与认证头
```

所有工作树读取同一个索引，不以分支名建立独立密钥副本。现有安全存储可以通过凭据引用接入；维护者核对来源和调用兼容性后再迁移，不删除旧来源或批量搬迁密钥。SSH、客户端签名等独立基础设施凭据保留原有 owner，只在本机说明中按需记录发现指引。

## 3. 本机登记契约

`catalog.json` 至少包含 `schemaVersion` 和 `profiles`。空数组表示尚无可用服务。每项包含稳定 `id`、`status`（`pending` / `ready` / `disabled`）及根目录内的 `configFile` 相对路径；不得使用上级目录跳转。具体 profile 至少记录：

| 内容 | 使用约束 |
|---|---|
| 服务身份、协议、端点、模型或能力 | 真实值仅在本机；不从名称推断模型、额度或兼容性 |
| `credentialRef` | 指向凭据文件或既有安全凭据库；不在索引中重复密钥，不复制 OAuth 会话 |
| `allowedUses` | 明确开发、评测、生产、媒资等允许用途与数据范围 |
| `budget` | 明确调用次数、费用上限和并发等适用限制；缺失不视为无限制 |
| `usageRules` | 入口、环境变量映射、超时、重试、输出位置和已知限制 |
| `verifiedAt` 与验证范围 | 区分未验证、连接验证与具体模型/能力验证；配置变化后重新核对 |

配置只是数据；不得 `source`、`eval` 或执行文件内字符串。新登记默认 `pending`；完成所需信息和任务授权后，按实际验证范围置为 `ready`。发现失效、撤销或漂移时标记 `disabled`，不得隐藏切换其他提供商或模型。

## 4. 调用方的使用顺序

1. 核对所依赖的治理提交、当前任务和实际调用入口；仅选择满足用途的 `ready` profile。
2. 核对端点、模型、凭据来源、预算及本次授权；仅在消费进程内读取所需凭据，按现有入口支持的方式传入。不得将密钥放入命令行参数、shell 历史、调试输出或模型上下文。
3. 需要真实请求时按任务最小范围执行。配置可读不代表已授权外传作品、批量付费生成、修改服务或部署。遵循已有授权，不因读取配置重复索要相同授权。
4. 日志只记录经检查可公开的状态、耗用与错误类别；认证失败、余额不足、非重试型 4xx、结果未知或 stale 不得自动重发。
5. 对外证据只包含必要的脱敏摘要；详细本机配置及私有服务信息留在仓库外。调用方发现配置问题时交回维护者，不在自己的分支复制一份修补。

## 5. Git 与发布边界

| 可以进入仓库 | 必须保留在本机仓库外 |
|---|---|
| 总纲、开发契约、API 使用规则 | API Key、Token、密码、私钥、Cookie、认证头 |
| 配置字段、环境变量名称、通用发现路径 | 真实配置文件、私有端点、账号与私有基础设施信息 |
| 没有真实值的结构示例、脱敏验证摘要 | 含真实配置的日志、截图、备份、导出或录制 |

`.gitignore` 仅是误放时的补充保护，无法移除已跟踪文件，也不能阻止强制添加；它不替代仓库外存储。提交时明确添加文档或代码路径，审阅暂存区，不得使用 `git add -f` 加入本地配置。CI、构建、打包与发布任务不得复制本机私有目录，构建时不得把凭据注入 `VITE_*` 或其他会进入浏览器包的变量。

真实配置不得写入 Issue、PR、远端工具请求、聊天正文、模型上下文或可同步记忆；仅在获授权调用中发送协议所需的凭据到选定服务。若凭据误入 Git，先停止传播并撤销或轮换，再处理历史与远端副本；删除工作区文件不能证明泄漏已经解除。

## 6. 维护与验证

治理维护者串行更新本机索引，保留仓库外的变更与验证记录；轮换通过更新原引用完成，使用方下次执行重新读取。重启、切换分支或同步仓库不会自动复制凭据。

规则文档按文档权威和入口检查验证；本机初始化核对目录位置、权限、JSON 格式和登记状态。只有按任务执行过实际请求并保存脱敏结果后，才能声称对应 API 或模型可用。
