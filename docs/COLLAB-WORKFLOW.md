# StoryForge 分支、PR 与交付协作流程

> 版本：2.1.0 · 生效：2026-08-31 · 权威层级：L1
> 适用于人类与任意编码/审查 Agent，不绑定某两个模型。

## 1. 基本原则

- 一个工作树同一时间只有一个写入者；并行任务使用独立 clone 或 `git worktree`。
- 一个分支承担一个可解释的产品增量，名称使用 `feat/`、`fix/` 或 `refactor/`。
- 不直接 push `main`；不 force push 主干；不覆盖他人未提交改动。
- 交接单元是分支 + commit + PR + 验证证据。临时对话和施工流水不进入现行规范文档。
- `main` 无 staging、可直接发布，因此合并串行进行。

## 2. 开工

1. `git status --short --branch`，确认工作树与 owner。
2. `git fetch --all --prune`，核对目标基线和相关 PR。
3. 从最新 `origin/main` 创建独立分支/工作树。
4. 按总纲和产品契约写开工卡，建立三注册表与测试闭包。
5. 若发现当前分支含另一主题的领先内容，先拆分或明确依赖，不继续堆叠。

### 2.1 并行产品分支的基线与冲突区

并行开发短篇、剧本、漫画、跑团、角色聊天或文字游戏时：

- 先合入或依赖同一个架构治理基线；产品分支不得从治理前的旧身份、旧 WorldRelease 或世界直达 runtime 路线继续扩建。
- 独立产品文件可并行修改；`AGENTS.md`、`CLAUDE.md`、总纲、三注册表、schema、世界网关、跨产品逻辑契约、产品目录、包管理锁文件属于集成热点，不由多个产品分支无协调并改。
- 剧本与漫画若同时需要修改 adaptation 公共来源/Brief/manifest，先拆出一个共享底座提交；剧本场次与漫画页格/媒资继续留在各自分支。
- 跑团、聊天和文字游戏只在各自目录增加 requirement adapter 和产品 owner 数据；若需要改变中立 `describe/search/read` 协议，先以独立共享契约变更证明向后兼容。
- 节点模式与分步骤共用正式领域 action。任何节点分支修改长篇 Skill、Context、Adoption 或 Canon schema 时，必须与长篇调用方一起验证，不能只跑节点测试。

推荐集成顺序是：治理基线 → 必要的共享 schema/契约小提交 → 各产品分支。每个后合并分支先同步最新集成树，再解决真实语义冲突并重跑验证；不能把“Git 能自动合并”当作架构兼容证明。

## 3. 提交

- 提交只包含当前任务的代码、测试和必要文档。
- 提交前查看 `git diff --stat`、`git diff`、`git status` 和 `git diff --check`。
- 不用 `git add -A` 掩盖未知文件；明确添加目标路径。
- 生成文件通过官方脚本重建，不手工解决内容冲突。
- commit message 说明任务/产品、完成边界；验证摘要写入 PR。

## 4. PR 描述

PR 至少包含：

- 总纲章节、产品与用户结果；
- 范围和非范围；
- 数据/AI/表/版本/媒资影响；
- 新旧入口变化；
- 正反例、CI/E2E 命令与结果；
- 风险、迁移、回滚或恢复方式；
- 尚未完成项，不用“完整”“商业级”等超证据措辞。

## 5. 审查

审查者基于最新 head：

1. 先检查产品边界和数据 owner；
2. 再看入口 → 读写 → 生命周期 → 下游 → 测试；
3. 优先报告数据丢失、权限/作用域、stale、恢复、重复入口与错误完成状态；
4. 运行风险相称的验证；
5. 评论应定位文件/行和可复现后果，不用仅表达偏好。

修复进入同一分支或明确 follow-up；未解决的高风险问题不能只写文档后合并。

## 6. 合并 main

1. 获取最新 `origin/main`，确认没有新的生产提交遗漏。
2. 通过普通 merge/rebase 解决冲突；不丢双方功能、注册表、迁移或测试。
3. 在最终合并树运行 `npm run ci`；适用时运行 `npm run ci:e2e`。
4. 确认 PR head 的独有提交是 main 祖先或被有证据地等价重实现。
5. 使用普通 push 更新 `main`；禁止 force。
6. 拉取远端并验证本地/远端 SHA 一致。
7. PR 合并后再删除已合并本地/远程分支与多余工作树。

## 7. 多分支总整合

需要把多个历史分支收敛到主干时：

- 先枚举本地 refs、remote refs、PR heads、worktrees 和 merge-base；
- 为每个分支记录独有提交、文件、与其它分支的重叠和处理结论；
- 逐个正常 merge，冲突按当前总纲、数据安全和最新实现裁决；
- 每个 head 只有在成为整合分支祖先或等价内容有逐项证据后才标记已整合；
- 完整验证、push main、PR 状态确认后才清理 refs；
- 最终断言只剩本地 `main` 和 `origin/main`，SHA 相同且工作树干净。

## 8. 工作树与依赖

- 不把 `node_modules` 符号链接或构建产物提交进 Git。
- 独立 worktree 可共享包缓存，但安装状态和生成缓存不得污染仓库。
- 移除工作树前确认 clean、提交已在目标主干、没有唯一 untracked 文件。
- 分支删除优先 `git branch -d`；若 Git 判断未合并，先调查，不以 `-D` 跳过证据。

## 9. 外部阻塞

外部 provider、依赖审计、GitHub 或部署不可用时，保留本地完整验证和错误证据，明确哪些门未完成。不能把“本地部分通过”写成主干全绿，也不能因外部阻塞扩大未授权远程操作。
