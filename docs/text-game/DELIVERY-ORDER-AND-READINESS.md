# 文字游戏开发顺序与策划成熟度

> 状态：当前施工排序
>
> 裁决：先完成较小、边界清楚的文字游戏，再以其共享能力建设文字开放世界；`TEXTWORLD-1` 放在最后。

## 1. 推荐开发顺序

### 第一阶段：`STORYGAME-1` 分支互动叙事

先完成纯文字、作者预制内容占主导的完整游戏：开局、旁白、对话、条件选择、路线、汇流、结局、存档、
回退与分支。

优先原因：现有 NarrativeModule/Node、WorldRelease、`storygame` 实例、条件/效果和 SIM 回放已经覆盖大部分
底座，最容易形成第一条完整可玩、可发布、可验证的产品链。

### 第二阶段：`CHATGAME-2` 角色互动与关系叙事

在已交付单角色聊天 MVP 上补长期记忆、关系变化、知识边界、多角色场景和剧情目标。

优先原因：已有聊天入口和角色冻结快照；但正式多角色 AI 依赖共享 Harness 的 instance-scope 接口，
所以可先完成确定性记忆/关系合同，再接 AI 表演。

### 第三阶段：`TEXTADV-1` 文字冒险 / 轻 RPG

完成有限区域或场景内的移动、物品、能力、关系、任务、行动判定和成长，不要求整个世界持续自治。

优先原因：可以复用 SIM、TTRPG 的资源/判定/任务能力，以及 STORYGAME 的叙事和选择；它也是后续复杂
模拟与开放世界最重要的可玩子集。

### 第四阶段：`AVG-1` AVG / Galgame 视觉叙事

在 STORYGAME 的稳定内容与播放器之上，独立增加背景、立绘、表情、CG、镜头、转场、音频和演出时间线。

优先原因：游戏逻辑比开放世界简单，但媒资导入、二进制备份、播放器和无障碍是新的技术域。
它不阻塞 TEXTADV/TEXTSIM，可在共享基础稳定后独立排期。

### 第五阶段：`TEXTSIM-1` 复杂叙事模拟

建设多资源、多组织、政策/行动、世界指标、危机、延迟后果、信息差和多结局的长期模拟。

优先原因：它比文字冒险复杂，但范围仍可限定在一个组织、城镇、宗门、殖民地或公司，不需要先解决自由
跨区探索和区域内容调度。

### 最终阶段：`TEXTWORLD-1` 文字开放世界

最后组合前述能力，新增多区域交通、NPC/组织持续行动、区域问题、动态任务导演和跨区域传播。

放在最后的原因：开放世界不是单独的一种 UI，而是把叙事、角色、冒险、模拟、任务和长局一致性连接起来；
只有前面的能力分别成熟后，才不会一次建设一个无法验证的大系统。

## 2. 两条相对独立的建设线

产品顺序不意味着所有能力只能串行：

```text
玩法与世界线：
STORYGAME-1 → CHATGAME-2 → TEXTADV-1 → TEXTSIM-1 → TEXTWORLD-1

表现与演出线：
STORYGAME-1 → AVG-1
```

AVG-1 可以在 STORYGAME-1 稳定后单独推进，不要求先完成复杂模拟；TEXTWORLD-1 也不要求使用 AVG 演出。
两条线只在世界 Canon、叙事内容、存档和媒资引用等明确公共接口处复用。

独立交付单元施工；共享底座变化必须同时保持各产品回归，不授权把产品重新混成一个万能系统。

## 4. “可以开工”的策划门槛

每个类型在编码前必须拥有独立设计文档，并完成以下内容：

1. 一局游戏从创建、游玩到结束的完整玩家流程。
2. 作者如何制作内容、试玩、检查和发布。
3. 首期明确范围、非范围和最小可玩样例。
4. 直接复用的世界引擎、SIM、TTRPG、CHATGAME、Harness 能力。
5. 新增状态、事件、规则和旧存档兼容方式。
6. AI 读什么、能产生什么候选、如何验证和降级。
7. 数据删除、导入导出、发布和引用重映射生命周期。
8. 失败、过期、并发、刷新恢复和恶意输入等反例。
9. 定向测试、E2E、长局测试和明确完成定义。
10. 旧入口如何兼容、迁移或下线，不能留下两套权威。

六份专项方案已经满足这套门槛；实际开工仍要按对应 A/B/C 子阶段建立代码关联闭包，并核对届时能力基线。
类型总览中的几段特点说明不能代替完整功能方案。

## 5. 已交付结果

`STORYGAME-1A/1B/1C` 已于 2026-08-14 完成。玩家可从不可变 GameRelease 新建、继续、选择、自动保存、
通关、回看历史并从检查点 fork；作者可编辑游戏、节点、Beat/Choice，运行内容图诊断，从任意节点进行
不落盘草稿试玩，并通过既有 WorldRevision → WorldRelease → GameRelease 链发布新版本。内置原创样例覆盖
3 章、25 节点、45 Beat、30 Choice、条件显示/禁用、路线汇流与 3 个可达结局。旧 WORLD-2F 存档保持兼容，
通用 SIM 新建入口不再写入 storygame。

`CHATGAME-2A/2B/2C` 与 `HARNESS-RUNTIME-1` 已于 2026-08-14 完成。角色互动现在使用同一
GameDefinition/GameRelease、SIM 事件和实例级 Harness；包含作者端知识/关系/场景配置、上下文检查、
单人/多人回复、固定离线行动、记忆候选、重试/取消/恢复、检查点和 fork。旧 CHATGAME-1 只读保留，
新写入入口已下线。

`TEXTADV-1A/1B/1C` 已于 2026-08-14 完成。文字冒险复用同一不可变发布、Narrative/SIM 事件、
CHATGAME-2 关系状态和 Instance Harness；已交付作者工作台、玩家库与存档、固定行动和自由输入、装备/交付/
成长、确定性判定、三结局、检查点/fork、迁移与完整项目生命周期。

2026-08-16 的路演玩家体验迭代把 STORYGAME 与 TEXTADV 的验收仪表盘收口为各自独立的游戏界面：分支叙事
提供启动书架、阅读舞台、角色对话、选择卡、进度以及历史/存档浮层；文字冒险提供探索地图、场景角色与交互物、
行动结果、角色状态、物品/能力/任务/日志/存档抽屉和玩家化自由行动入口。底层仍是同一 GameRelease、SIM 事件、
检查点和 Instance Harness，没有新增平行运行时；详细基准与剩余差距见
[`ROADSHOW-PLAYER-EXPERIENCE-GAP.md`](./ROADSHOW-PLAYER-EXPERIENCE-GAP.md)。

`AVG-1A/1B/1C` 已于 2026-08-14 完成。视觉叙事直接复用 STORYGAME 的完整三章 Narrative，以 DB v59
版本媒资、白名单 Cue、可恢复舞台和不可变 GameRelease 提供背景、多人立绘、CG、镜头、转场及四类音频；
玩家端支持历史、自动、已读快进、存档/fork、全屏、无障碍偏好和纯文字降级，作者端支持批量导入、
任意 Beat 预览、完整诊断与发布。二进制严格备份、导入 hash/size 回滚、替换/删除保护、缺失诊断事件、
完整路线通关和旧发布不变已有回归。

世界引擎到前三种路演产品的确定性投影和主 Agent AI 演化链已于 2026-08-15 补齐。一个新项目可以先通过
主 Agent 对话和分步骤面板建立正式角色、关系、
重要地点、artifact 道具、主线与视觉媒资，选择内容后冻结 `WorldRelease`，再按分支叙事 → 文字冒险 →
AVG 的顺序让 `outline.world-game` 基于冻结素材继续创作新的可玩剧情，经作者确认、确定性校验、冻结
`GameRelease` 后立即试玩。三种产品共享 `GameDefinition` 来源审计、Narrative、发布、SIM 和同一 Harness；
不配置 AI 时仍可使用明确标注的确定性快速映射备用路径，也没有提前引入复杂模拟或开放世界模块。
雾港演示世界与真实浏览器冷启动流程覆盖了这条完整路径；项目导出再导入仍保留便携来源选择、发布和媒资。
2026-08-16 的路演增强把占位图替换为 17 项可随项目发布、导出和重映射的正式视觉媒资：5 张横屏场景、
9 张透明角色立绘/表情与 3 张结局 CG。AVG 投影按角色和 entry/scene/choice/ending 标签选择立绘版本，
播放器以全景背景、全身角色层和电影式对白框呈现；静态文件加载失败时只降级到原有确定性演示图，不绕过媒资表、
`WorldRelease` 或 `GameRelease`。

`TEXTSIM-1A/1B/1C` 已于 2026-08-14 完成。复杂模拟以 DB v60 作者规则模块接入统一发布和 SIM 事件流，
交付资源/指标、有限主体、行动/政策、modifier、问题/危机、延迟后果、视角报告和多结局；玩家与作者闭环、
四类只读 Instance Harness 表现、30 回合原创样例、四题材映射、100/500 回合确定性验证以及完整生命周期均有
回归。

`TEXTWORLD-1A/1B/1C/1D/1E` 已于 2026-08-14 完成。DB v61 与 `PROJECT_TABLES` 新增唯一的 Work-owned
`openWorldModules` 作者表；GameRelease 同时冻结 Narrative、角色互动、Adventure、NarrativeSimulation 和
OpenWorld 内容。运行状态继续留在既有 SIM 三表，以幂等开放世界命令生成区域旅行、任务发牌、任务生命周期、
主体远端行动、问题传播、Narrative 同步和原子检查点事件。5 区域、20 关键 NPC、5 组织、30 固定任务、
10 模板和一条受保护主线已有作者/玩家闭环、严格导入导出/删除/迁移/重映射、1000 tick 确定性压力与
Instance Harness 只读候选回归；AI 无权修改区域、任务、资源或世界事实。

下一步是保持六种产品的整体回归、真实浏览器 E2E 和性能基线，并把后续增强继续拆回各自产品路线；不再建立
第二套世界、发布、存档、事件流或 Harness。
