# AVG-1 · AVG / Galgame 视觉叙事完整开发方案

> 状态：`IMPLEMENTED · AVG-1A/1B/1C 已于 2026-08-14 交付`
>
> 产品定位：在分支叙事之上增加背景、立绘、CG、音频和 2D 演出
>
> 前置：STORYGAME-1；不依赖 TEXTADV、TEXTSIM 或 TEXTWORLD

## 0. 当前实现结果

- DB v59 新增 `avgMediaAssets / avgMediaBlobs / avgPresentationModules`，全部登记在 `PROJECT_TABLES`，
  严格备份会携带二进制、重映射引用，并在导入事务内复核 byte size 与 SHA-256；损坏输入整体回滚。
- `GameRelease` 的 `avg` manifest 从绑定 `WorldRelease` 冻结实际 Cue、媒资稳定 key、版本和 hash；替换资源只
  生成新版本，旧发布和旧存档保持不变，仍被草稿或发布引用的媒资不能硬删除。
- 演出层使用白名单 Cue、固定舞台层、快照和 `presentation.beat.reached / presentation.media.failed` 事件；
  剧情选择继续只走 `narrative.choice.committed`，演出 reducer 不拥有 Narrative 变量或跳转。
- 玩家端已交付真实本地媒资、多人立绘、CG、四类音频、历史、自动播放、已读快进、存档/fork、全屏、
  隐藏界面、音量/静音、文字速度、减少动态、键盘推进、纯文字和媒资缺失降级。
- 作者端已交付单个/批量导入、稳定版本、来源/授权/替代文本、容量提示、删除保护、声明式时间线、任意
  Beat 演出预览、完整诊断和 `WorldRevision → WorldRelease → GameRelease` 发布。
- 验收样例直接复用 STORYGAME 的 25 节点、45 Beat、30 Choice、三结局故事，并实际冻结 5 个背景、
  3 个角色各 3 套姿势、3 张 CG、4 类音频和 8 种以上 Cue；纯文字完整通关、事件回放、分支恢复、
  媒资替换、缺失降级和完整项目生命周期均有定向回归。
- 玩家运行时不调用模型。作者期 AI 媒资生成仍只允许未来通过统一 Harness/生成任务适配层接入；当前
  `avgAuthoring` 只读上下文和只读演出审查 Skill 已登记，不存在直连 AI 或未经 Adoption 的写入旁路。

## 1. 做成后玩家能玩到什么

玩家体验接近常见 AVG/Galgame：背景与角色立绘随剧情切换，人物拥有表情、位置和进退场，重要场景可以
显示 CG，并配合转场、震动、闪白、淡入淡出、镜头缩放、文字速度和音频形成节奏。剧情选择、条件、存档
和结局仍由 STORYGAME 的稳定逻辑负责。

完整体验包括：

- 对话框、说话者、旁白、历史回看和可配置文字速度；
- 自动播放、快进已读、跳过、隐藏界面和点击继续；
- 背景、前中后景、多人立绘、表情/姿势切换与图层顺序；
- CG、章节卡、选择界面与结局页；
- 淡入、划入、移动、缩放、摇晃、闪白、遮罩等有限 2D 效果；
- BGM、环境音、音效和可选语音；
- 快速存读档、自动存档、缩略图和已读记录；
- 关闭图片、静音、减少动态效果后，剧情仍然完整可玩。

本产品不是开放世界，也不要求运行时 AI。图片和音频在首期以作者导入为主，AI 生成作为后续作者工具。

## 2. 最重要的架构边界

**剧情真相与演出时间线必须分离。**

- Narrative Node/Beat/Choice 决定玩家读到什么、能选什么、状态如何变化和何时结局。
- AVG presentation 只决定同一内容如何显示和播放。
- 演出 cue 不得增加物品、改变关系、完成任务或跳过规则节点。
- 关闭演出、资源缺失或浏览器不支持音频时，纯文字播放器仍能完成整个故事。

这样同一份故事既可作为纯文字 STORYGAME 发布，也可套用 AVG 演出；后续其他游戏可选择性使用演出层，
但不被迫携带媒资字段。

## 3. 演出模型

### 3.1 场景舞台

舞台由固定图层组成：background、environment、actor-back、actor-front、effect、dialogue、overlay。每个图层
只能使用已登记的资源和属性，不能运行任意 HTML、CSS 或脚本。

### 3.2 演出 Cue

Cue 绑定 Narrative Beat 前、期间或结束后执行，使用白名单类型：

- 设置/清除背景、CG 或覆盖层；
- 角色进入、退出、换姿势/表情、移动和改变层级；
- 淡入淡出、交叉溶解、划入、缩放、摇晃、闪白、色调和遮罩；
- 播放、停止或渐变 BGM/环境音/音效/语音；
- 等待固定时长、等待用户继续或与文字同步；
- 恢复到声明过的舞台快照。

Cue 采用声明式参数、持续时间和 easing，不接受代码。动画完成只影响播放器光标；需要改变剧情时必须提交
共享 Narrative Choice/Command。

### 3.3 时间线与恢复

每个 Beat 可以拥有一段 cue 序列。播放器在节点边界和关键 Beat 保存舞台快照引用；读档时恢复最近快照并
快速重放必要 cue，不能逐帧保存动画。

已读、自动播放速度、音量和减少动态是用户偏好，不进入世界规则事件；关键剧情位置、选择和结局仍由 SIM
存档。快进只能跨过已经读过的 Beat，默认停在未读内容、选择和重要提示。

## 4. 媒资系统

### 4.1 资源类型

首期支持 background、character-pose、character-expression、cg、ui、bgm、ambience、sfx、voice。每个资源
记录稳定键、类型、格式、尺寸/时长、内容 hash、来源、授权说明、替代文本和可选角色/场景标签。

角色立绘可采用完整图片，也可使用基础姿势 + 表情叠层；产品声明一种组合方式，播放器不猜测文件名。

### 4.2 本地保存与发布

- 原始二进制继续只保存在浏览器项目中，不上传未知外部服务。
- 内容 hash 用于去重、完整性和缓存；作者替换资源生成新版本，不偷偷改变旧发布。
- GameRelease 冻结实际引用的资源版本与 manifest。
- 项目导出必须包含媒资或明确的轻量导出模式；导入先校验 hash、大小、格式和引用。
- 删除草稿资源前检查发布和存档引用；仍被引用时阻止硬删除。

媒体表和 blob 生命周期必须先登记 `PROJECT_TABLES`。需要在方案实施前用真实大文件做容量、事务失败、导出
中断和恢复验证，不能假定 IndexedDB 永远有足够空间。

### 4.3 缺失资源降级

背景缺失显示主题色和替代文本；立绘缺失显示角色名占位；音频缺失静默继续；效果不支持则立即进入最终
状态。缺失资源必须产生诊断，但不能让剧情存档损坏。

## 5. 玩家界面

桌面和移动端都需要清晰的舞台、文本框、说话者、继续提示和选择。功能菜单包含存读档、历史、自动、快进、
文字速度、音量、全屏、减少动态和返回标题。

无障碍要求：

- 所有剧情文字可由屏幕阅读器顺序读取；
- 图片有作者替代文本，纯装饰图片不重复朗读；
- 不依赖颜色或闪烁传达唯一信息；
- `prefers-reduced-motion` 默认关闭摇晃、闪白和大幅移动；
- 语音不能替代文字；键盘和触摸均能完成全流程。

## 6. 作者工作台

作者可以：

1. 批量导入、查看、标记和替换媒资。
2. 在剧情 Beat 旁配置舞台状态和 cue 时间线。
3. 使用实时预览调整角色位置、图层、持续时间和声音。
4. 从任意 Beat 预览，检查恢复快照和快进效果。
5. 运行缺失资源、孤儿资源、不支持格式、过长等待、不可达 cue 和无替代文本检查。
6. 分别发布纯文字版本和带演出版本，或在同一产品中声明纯文字降级。

首期以表单 + 轻量时间线为主，不建设专业视频编辑器。

## 7. AI 生图、语音与 Harness

AI 媒资生成只作为作者期工具，不允许玩家游玩时临时生成关键图片：

1. 作者从已登记的世界、角色、场景和风格指南组装生成任务。
2. 模型产出候选及生成回执，不能自动覆盖既有资源。
3. 作者比较、裁切、补充授权/来源说明并明确采用。
4. 采用后资源进入本地媒资库，生成稳定 hash 和新版本。
5. 正式发布只引用已采用资源，不依赖生成服务在线。

文本/结构建议可以走 Work-scope Harness；图片、语音等二进制生成通过统一生成任务适配层接入，并保留输入
来源、模型、参数和采用记录。新增世界上下文先登记 `CONTEXT_SOURCES`；可写元数据进入 Adoption 治理。

## 8. 运行状态与事件

AVG 模块主要拥有 presentation cursor、stage snapshot ref、read marks 和可恢复播放状态；用户全局偏好与游戏
规则存档分离。

演出日志不需要把每一帧写成 SIM 事件。只有影响恢复和玩家行为的边界记录，例如：

- `presentation.beat.reached`
- `presentation.checkpoint.created`
- `presentation.media.failed`（诊断日志，不改变世界）

剧情选择继续使用 `narrative.choice.committed`，不得再定义 `avg.choice`。

## 9. 分阶段实现

### AVG-1A · 静态视觉播放器

- 背景、单/多角色立绘、CG、图层、资源库和发布 manifest。
- 对话、旁白、历史、自动、快进、存读档和纯文字降级。
- 作者导入与表单式场景配置。

### AVG-1B · 2D 演出与音频

- 声明式 cue、转场、移动、缩放、摇晃、遮罩和舞台快照。
- BGM、环境音、音效、语音及音量/焦点策略。
- 轻量时间线编辑和从任意 Beat 预览。

### AVG-1C · 生产能力

- 批量资源检查、容量管理、导出恢复、预加载和性能预算。
- 作者期 AI 生图/语音任务、候选采用和来源审计。
- 移动端、无障碍和低性能设备完善。

## 10. 验收样例与完成定义

使用 STORYGAME 验收故事制作一个 20 至 40 分钟的演出版：

- 至少 5 个背景、3 个角色、每人 3 个表情/姿势、3 张 CG 和 4 类音频；
- 至少 8 种 cue，有多人进退场、镜头变化、关键选择和三个结局；
- 任意存档恢复后舞台、BGM 和正文位置正确；快进不会跳过未读选择；
- 删除缓存、静音、减少动态或模拟图片缺失时仍能通关；
- 媒资随项目完整导出导入，旧发布 hash 不变；
- 30 分钟连续播放无明显内存增长，移动端切后台后可恢复。

只有演出层完全不改变叙事规则、纯文字降级可通关、媒资生命周期和无障碍通过，才算 AVG-1 完成。
