# 分支叙事与文字冒险路演体验差距

> 状态：2026-08-16 首轮玩家界面迭代已落地
>
> 范围：只评估 `STORYGAME-1` 与 `TEXTADV-1` 的玩家表现，不改变既定产品分类或底层权威

## 商业产品基准

本轮不以“是否拥有功能字段”作为成品标准，而以玩家能否在首屏理解并使用这些功能作为标准：

- [Choice of Games](https://www.choiceofgames.com/about-us/) 证明纯文字分支游戏不依赖视觉奇观，但必须有
  舒适阅读、清晰选择、角色身份和足够强的重玩路径。
- [80 Days](https://www.inklestudios.com/80days/) 与 [Sorcery!](https://www.inklestudios.com/press/sorcery/)
  把选择放进地图、旅程与持续状态中，而不是只提供一列调试按钮。
- [Roadwarden](https://moralanxietystudio.com/roadwarden) 把地点画面、角色、背包、能力、任务与对话整合为
  同一套文字 RPG 界面。
- [Citizen Sleeper](https://store.steampowered.com/app/1578650/Citizen_Sleeper/) 用技能、关系和可视进度让文字行动
  具有明确的游戏反馈。
- [Fallen London](https://www.failbettergames.com/games/fallen-london) 说明浏览器原生文字冒险同样需要成熟的故事卡、
  物品、品质与角色档案，而不是暴露内部 key 和运行合同。

## 差距与本轮裁决

| 玩家问题 | 原状态 | 路演最低标准 | 本轮结果 |
|---|---|---|---|
| 分支叙事像发布验收页 | 永久书架、正文和存档同屏 | 书架只负责启动；游玩时进入独立阅读舞台 | 已完成 |
| 角色对话不可辨认 | Beat 平铺，`【角色】` 可能显示为旁白，左右位置按条目轮换 | 冻结主角身份明确标注；玩家固定右侧、NPC 固定左侧 | 已完成并补主角歧义反例 |
| 选择缺少决策感 | 节点 Beat 与选项一次性全部展开 | Beat 逐条逐字推进，点击可补全当前句，读完后经独立门槛再显示选择 | 已完成并补阅读光标恢复 |
| 其他产品污染书架 | AVG/TEXTADV GameRelease 显示为错误卡 | 只展示 `productType=storygame` 发布 | 已完成并补反例 |
| 文字冒险像数据仪表盘 | 内部 key、所有模块纵向堆叠 | 地图、场景、行动区和角色状态形成游戏主画面 | 已完成 |
| 看不到角色、物品、技能 | 数据藏在窄列表中 | 场景角色卡、物品卡、能力条与人物关系 | 已完成 |
| 任务和行动没有反馈 | 任务、历史、存档长期占据主页面 | 任务追踪、最近结果、日志和存档抽屉 | 已完成 |
| 自由输入暴露治理术语 | 直接显示 Harness、candidate、base sequence | 玩家只看到“自由行动”；确认后仍走统一 Harness | 已完成 |
| 验收样例暴露英文 key | `notice`、`coin`、`observe` 等直接显示 | 玩家层提供友好名称和说明，原 key 仍留在冻结规则中 | 已完成 |

## 实现边界

本轮没有新增表、AI 可写字段或上下文来源，因此不改动三注册表。玩家界面仍只调用原有 store：

- 分支选择继续写入正式 Narrative Choice 事件，自动检查点、历史与 fork 继续复用 SIM。
- 冒险按钮与自由行动继续汇入同一 Adventure command；AI 只生成候选，确认后才提交。
- 背包、资源、能力、条件、任务与关系全部读取冻结 GameRelease 和可回放 runtime state。
- 友好名称只解决验收样例的玩家呈现，不修改或猜测冻结规则 key。

## 仍需后续增强

首轮已经达到可现场演示的产品原型表现，但与完整商业游戏仍有内容量与专属美术差距：分支叙事尚未配置每场景插画，
文字冒险尚未配置专属地图图块、物品图标包与角色头像包，内容规模也远小于商业作品。这些应作为媒资与内容生产单元继续
迭代，不能通过复制世界、存档、发布或 Harness 来解决。
