# TEXTADV-1 · 文字冒险 / 轻 RPG 完整开发方案

> 状态：`TEXTADV-1A/1B/1C IMPLEMENTED · 2026-08-14`
>
> 产品定位：在有限场景或区域内探索、行动、获取物品、解决任务并成长的规则驱动文字游戏
>
> 前置：STORYGAME-1；建议复用 CHATGAME-2；复用 SIM/TTRPG 规则能力

## 1. 做成后玩家能玩到什么

玩家可以在一个范围明确的冒险中移动、观察、交谈、使用物品和技能、接受任务、进行判定，并由这些真实
结果推进故事。它比纯分支故事自由，但不要求整个世界在玩家看不到的地方持续运行。

完整体验包括：

- 有限地点图与移动条件；
- 场景描述、可交互对象、角色和明显行动；
- 物品获取、携带、消耗、组合或交付；
- 通用能力、状态和有证据的判定；
- 主线、支线和任务目标；
- 固定选项与自由文字行动并存；
- 失败后出现代价、替代路线或结局，而非所有失败都直接 Game Over；
- 角色互动、关系和叙事分支可以影响冒险，但各自由所属模块负责。

首期不做无限地图、全世界 NPC 日程、区域动态发牌、复杂经济或大型组织自治。

## 2. 核心循环

```text
观察当前地点和局势
  → 选择系统行动或输入意图
  → 映射为有限动作
  → 校验位置、物品、能力、目标和成本
  → 确定性判定并追加事件
  → 更新地点/资源/任务状态
  → 由叙事内核呈现结果和下一组机会
```

AI 可以把“我用绳子从侧墙爬进去”解释成 `move/overcome-obstacle` 候选，也可以把规则结果写成自然叙事，
但不能发明玩家没有的绳子、越过锁定地点或自行决定判定成功。

## 3. 冒险能力模块

### 3.1 地点与移动

地点是有限图中的稳定实体，包含说明、可见交互点、出口和环境标签。出口可以有条件、成本和失败说明。
玩家一次只处于一个主要地点；进入/离开均产生事件。位置改变只能通过已验证的移动命令。

地点不会自动成为开放世界区域：首期只计算玩家当前场景以及作者明确触发的远端效果。

### 3.2 物品与资源

物品定义与运行实例分离。定义描述名称、标签、可堆叠性、使用规则和内容引用；实例记录 owner、数量、状态
和来源事件。货币、体力等连续资源可走通用 resource，但不与物品强行合并。

允许的效果是获得、失去、转移、消耗、装备和改变状态。每次变化必须校验数量、owner 和版本，禁止负数、
重复领取和跨存档引用。

### 3.3 能力、状态与判定

能力使用稳定键和等级/加值；状态用于受伤、中毒、鼓舞、通缉等有期限或触发条件的变化。判定复用 SIM 的
确定性 seed 和 TTRPG 已验证的检定思路，但对外使用通用术语，不把骰制和跑团流程写死。

作品选择一种已登记规则配置：固定门槛、随机检定或资源支付。结果至少区分成功、带代价成功、失败和不可
尝试。随机结果必须保存 roll 证据并可重放。

### 3.4 任务

任务由作者定义，包含前置、目标、可选目标、失败条件、奖励和后续叙事入口。目标只使用登记类型，例如：

- 到达地点；
- 获得/交付物品；
- 与角色完成一次指定互动；
- 通过判定或解决威胁；
- 触发/完成叙事节点。

任务状态由事件投影得出，不让 UI 或 AI 直接改为完成。动态任务导演不在本期；TEXTWORLD-1 才负责区域化
生成与发牌。

## 4. 行动体系

首期动作集合保持封闭：look、move、talk、take、give、use、inspect、attempt、rest、quest-action。每个动作
声明所需能力、目标类型、消耗、可能事件和失败原因。

固定操作按钮直接创建命令；自由文字先由 Harness 产生一个或多个动作候选，并向玩家展示解释。高风险、
多义或包含多步效果的输入必须请求确认或拆成多个动作，不能把整段文字当作任意脚本执行。

无法映射的输入返回可理解的建议，例如“你当前可以检查门锁、使用钥匙或寻找其他入口”，不偷偷换成另一个
动作。

## 5. 叙事与角色如何接入

- 地点进入、任务变化和判定结果可以触发 Narrative Node。
- Narrative Choice 可以通过注册 selector 检查地点、物品、能力和任务状态。
- Narrative Effect 只能调用 adventure 模块公开的有限 effect，不能修改内部对象。
- 与角色谈话交给 character-interaction；冒险模块只验证角色是否在场和交互结果产生的结构化事件。
- 纯作者剧情在 AI 不可用时仍可推进；只有自由文字解析和生成式表演降级。

## 6. 玩家与作者界面

玩家主界面应明确显示：当前地点与描述、可见人物/物体、推荐行动、正文结果、状态摘要、背包、任务和历史。
移动与常用行动一键可用，自由输入是增强入口而不是唯一入口。

作者工作台允许：

1. 建立地点图、出口条件与交互点。
2. 定义物品、能力、状态和规则配置。
3. 配置任务目标、奖励、失败与叙事连接。
4. 从任意地点和状态启动草稿试玩。
5. 查看不可达地点、无法完成任务、循环依赖、无来源物品和资源漏洞。
6. 选择 GameRelease 内容并发布不可变版本。

## 7. 运行状态与事件

adventure 模块拥有 location、inventory、resources、abilities、conditions、quests 和 activeInteractions 状态
切片。正式内容仍由发布引用，不复制到状态。

事件至少包括：

- `adventure.location.entered|left`
- `adventure.item.gained|transferred|used|state-changed`
- `adventure.resource.changed`
- `adventure.condition.applied|removed`
- `adventure.check.resolved`
- `adventure.quest.accepted|objective-updated|completed|failed`
- `adventure.action.rejected`

拒绝事件只在需要审计时保存，普通表单校验错误不污染世界时间线。命令必须幂等，资源和物品变化使用事件
前置条件防止双花。

## 8. AI 与 Harness

定义两个实例 Skill：

- `adventure-intent-parser`：把自由文字映射为有限动作候选，引用当前可见目标和物品稳定键。
- `adventure-result-narrator`：根据已完成规则结果生成文字表现，不得改变 result。

输入上下文严格区分玩家可见状态与内部规则数据。解析候选返回后校验 baseSequence/stateHash；叙事生成失败
时显示确定性模板。无 AI 时所有系统按钮、任务、判定和作者正文仍完整可玩。

## 9. 复用与提炼策略

- 直接复用 GameRelease、Narrative、SIM、检查点/fork 和 Harness 实例接口。
- 先审计 TTRPG 的 action/check/resource/condition/quest/schedule，提炼通用规则合同；跑团主持流程、战斗轮次
  和术语留在 TTRPG。
- 真正接入 CHATGAME-2 时提炼关系/记忆的最小共享 selector，不复制第二套关系。
- inventory、ability 和 quest 首次属于 adventure 模块；TEXTSIM/TEXTWORLD 成为第二使用者时再验证抽取，
  不提前为尚不存在的经济系统增加字段。

## 10. 数据治理与兼容

- 地点、物品定义、能力、任务等作者表与实例状态表先登记 `PROJECT_TABLES`，完成完整生命周期和反例。
- AI 上下文进入 `CONTEXT_SOURCES`；AI 不直接采用游戏状态，因此不得为方便绕过命令事件链。
- 发布冻结规则配置、内容定义与引用；旧存档继续使用原版本。
- 导入导出要验证 item instance owner、任务引用、地点引用和 seed；缺内容或版本不兼容时只读恢复。
- 不将 TTRPG 表直接改名复用；先提供兼容适配和双产品回放，再收口权威。

## 11. 分阶段实现

### TEXTADV-1A · 固定行动冒险

- 地点、移动、物品、资源、能力、判定、任务与事件。
- 玩家按钮流程、作者编辑器、规则诊断和发布。
- 不依赖 AI，先打通完整开局到结局。

### TEXTADV-1B · 角色与叙事连接

- 接入 Narrative selector/effect 与 CHATGAME 角色互动。
- 带代价结果、失败路线和任务/剧情相互触发。

### TEXTADV-1C · 自由文字增强

- Harness 意图解析、确认、叙事表达和无 AI 降级。
- 模糊输入、恶意输入、过期结果和成本预算测试。

## 12. 验收样例与完成定义

制作一个 60 至 90 分钟的原创冒险：

- 至少 6 个地点、8 个可交互对象、10 种物品、4 种能力和 3 个状态；
- 1 条主线、3 条支线，至少一个目标可通过交谈、物品或判定三种方式解决；
- 至少一次带代价成功、一次失败后替代路线和三个结局；
- 系统按钮可在完全断网时通关；自由文字与等价按钮得到相同规则结果；
- 重复领取、重复提交、资源双花、坏引用和旧页面提交均被拒绝；
- 1000 步随机合法行动回放一致，导出导入后 seed、任务和背包不变。

只有作者、玩家、规则、存档和发布闭环均完成，且没有复制 Narrative/SIM/TTRPG 权威，才算 TEXTADV-1 完成。

## 13. 实现结果（2026-08-14）

`TEXTADV-1A/1B/1C` 已完整交付。实现使用同一 GameDefinition/GameRelease、WorldRelease、Narrative、SIM
事件流、检查点/fork、CHATGAME-2 角色互动状态和 Instance Harness：固定行动可断网通关，自由输入只产生
受校验候选，结果叙述为只读表现候选。Narrative → Adventure 连接通过带稳定命令 ID 的受限公共行动桥完成，
禁止 Choice 或页面直接改写冒险状态。

内置验收冒险覆盖 6 个地点、8 个交互物、10 种物品、4 种能力、3 个状态、1 条主线与 3 条支线；包含交谈、
物品、判定三种解法，成功/带代价成功/失败，装备、消耗、交付、能力成长和三个结局。回归覆盖 1000 步
确定性回放、重复领取/双花/旧入口拒绝、发布冻结、v57→v58 迁移、导入导出、删除、引用重映射与 Harness
候选持久化恢复。
