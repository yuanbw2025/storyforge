# CHATGAME-2 · 角色互动与关系叙事完整开发方案

> 状态：`IMPLEMENTED · 2026-08-14`
>
> 产品定位：角色能记住共同经历、关系会发展、可进行多人场景的长期文字互动
>
> 前置：CHATGAME-1、STORYGAME-1 共享底座、HARNESS-RUNTIME-1

## 1. 做成后玩家能玩到什么

玩家不再只是和一个“带角色设定的聊天机器人”对话，而是在一个持续的关系中与角色相处：角色知道自己
应该知道的事，记得关键共同经历，对玩家和其他角色形成可解释的关系变化，并能在有目标的多人场景中自然
互动。

完整体验包括：

- 单人或多人会话，选择参与角色和当前场景；
- 自由输入，也可以使用系统给出的固定回复或行动选项；
- 角色短期上下文、长期记忆、承诺、秘密和未解决话题；
- 信任、亲近、戒备、敬重等由作品声明的关系维度；
- 约会、谈判、审问、重逢、争执等带目标的场景；
- 角色会因为证据和共同经历改变观点，但不会读取未获知的世界信息；
- 玩家能查看“角色记得的关键事情”和关系变化原因，而不是面对不可解释的隐藏数值。

首期不包括开放世界 NPC 自治、任意地点旅行、物品战斗和组织模拟。

## 2. 核心循环

```text
选择场景与参与者
  → 玩家说话或选择行动
  → 规则层确定角色可见上下文
  → Harness 生成结构化回复候选
  → 校验口吻、知识、关系和时序
  → 采用回复并追加事件
  → 确定性更新记忆/关系候选
  → 继续、结束场景或进入作者剧情节点
```

AI 负责表演和提出候选，不直接写关系值、长期记忆或剧情完成状态。任何持久变化必须经白名单命令验证并
转成事件。

## 3. 场景与角色互动

每次互动都属于一个 scene，至少包含：

- 场景目的、地点与时间；
- 玩家身份与参与角色；
- 参与者公开知道的事实，以及各自私有知识；
- 可选开始节点、结束条件和安全边界；
- 对话轮次预算和当前说话者策略。

场景可以是纯自由聊天，也可以由 STORYGAME 节点引导。固定剧情选择使用共享 Narrative Choice；自由文字
不伪装成 Choice，而是经过角色互动命令处理。两者可以在同一场景切换，但各自保留明确事件语义。

多人场景由一次“场景导演”调用决定哪些角色需要回应、顺序和意图，再按预算生成实际话语。禁止每回合对
所有角色无上限并行调用，避免成本、延迟和互相看不到刚才发言的问题。

## 4. 记忆、知识与关系

### 4.1 记忆分层

- 当前窗口：最近对话原文，超出预算后滚动移除。
- 场景摘要：已结束场景的事实性摘要，绑定来源事件范围。
- 关键记忆：承诺、冲突、礼物、秘密等长期条目，带重要度和证据。
- 角色设定：来自冻结发布的身份和背景，不属于运行记忆。

AI 可以提出“记住这件事”候选，但只有可追溯到本场景事实、未越权且通过去重的候选才能采用。摘要不得
反向篡改原始事件，玩家可以从记忆查看来源场景。

### 4.2 知识边界

系统为每个角色组装独立 visibility view：公开 Canon、角色初始知识、亲历事件、被告知且可信的信息。
未知秘密、其他角色私聊和系统隐藏数值不得进入该角色上下文。多人对话也不能直接共用一份包含所有秘密的
prompt。

### 4.3 关系

作品可以从受支持维度中启用一部分并设定初值、范围和阈值。关系改变必须来自已采用的互动结果，并记录：

- 哪个事件触发；
- 变化前后；
- 使用的规则或作者覆盖；
- 玩家可见的自然语言原因。

大幅变化需要明确事件或作者规则，不由一次普通模型回复随意决定。关系影响后续选项和角色态度时，通过
注册 selector 暴露给叙事内核。

## 5. 玩家与作者界面

玩家界面包含会话列表、场景标题、参与者、消息流、输入区、可选回复、生成/取消/重试、历史版本、关键
记忆和关系摘要。多人对话必须清楚显示发言者，生成中可以逐条出现，但采用后顺序固定。

作者界面允许：

1. 从世界角色选择可互动人物。
2. 配置角色初始知识、关系维度和绝不能泄露的秘密。
3. 建立场景模板、目标、参与者、入口/退出条件和固定剧情节点。
4. 试玩任意角色视角并查看实际上下文清单，而非完整 prompt 密文。
5. 运行知识泄露、口吻冲突、记忆容量和无结束条件检查。
6. 作为统一 GameRelease 的一种产品发布。

## 6. 运行状态与事件

角色互动模块拥有自己的状态切片：participants、activeScene、conversation、memoryIndex、relationships、
openThreads 和 directorBudget。它不直接持有世界角色全文，而保存发布中的稳定引用。

主要事件包括：

- `interaction.scene.started|ended`
- `interaction.participant.joined|left`
- `interaction.player.message.committed`
- `interaction.character.reply.committed`
- `interaction.memory.proposed|accepted|rejected|superseded`
- `interaction.relationship.changed`
- `interaction.thread.opened|resolved`

CHATGAME-1 现有 message/supersedes 语义应迁入该模块或由兼容适配器读取；新写入不能继续绕过共享命令、
事件和 Harness run。

## 7. AI 与 Harness 合同

CHATGAME-2 是第一个必须使用 Instance-scoped Harness 的产品。至少需要三个 Skill：

1. `character-reply`：生成结构化发言、语气标签和可选非持久表现。
2. `scene-director`：决定回应角色、顺序、意图和场景是否应结束。
3. `memory-curator`：在场景结束时提出摘要、关键记忆和未解决话题。

输入只来自登记后的角色视图；输出 schema 严格限制长度、角色键、引用事件和候选类型。回复返回时检查
baseSequence、stateHash、sceneId 和 participant set；任何一个过期都不得自动采用。

降级策略：

- 无网络/无额度：已发布的固定选择场景可继续；自由聊天明确暂停，不伪造成功。
- 某角色生成失败：保留已采用消息，允许单独重试该角色，不重复提交玩家消息。
- 导演失败：退化为用户指定角色回应一次。
- 记忆整理失败：不影响原始消息与存档，稍后可从事件重新整理。

## 8. 复用与独占边界

直接复用 STORYGAME 的游戏发布、Beat/Choice、播放器文字块、存档/fork 和叙事条件。角色互动只新增
scene、memory、knowledge view、relationship 和多人导演。

第一版关系/记忆实现在 character-interaction 模块中。TEXTADV 真正使用它们时，再对比冒险需要的队友关系、
线索记忆和聊天需要的情感记忆，只提炼共同 selector 和事件证据，不提前统一所有字段。

## 9. 数据治理与兼容

- 场景模板等作者内容及运行记忆/关系涉及的新表都必须登记 `PROJECT_TABLES`，分别声明 world/work/instance
  所有权。
- 新角色视角必须登记 `CONTEXT_SOURCES`；关系、记忆候选如果允许 AI 写入，必须经 Adoption schema 和采用
  权限登记。
- AgentRun owner 扩展到 instance 时需完成恰好一个 owner 的 schema、迁移、导入导出、删除和引用重映射。
- 对话导出需区分作者产品内容与玩家私有存档；诊断导出默认脱敏 prompt 和秘密。
- CHATGAME-1 存档升级要保持消息顺序、supersedes 和冻结角色；不能把旧模型回复重新生成。

## 10. 分阶段实现

### CHATGAME-2A · 确定性角色状态

- 建立 scene、记忆、知识视图、关系模块和事件。
- 迁移 CHATGAME-1 消息读取，完成固定选择场景与无 AI 回放。
- 上下文泄露测试和关系规则测试。

### HARNESS-RUNTIME-1 · 实例调用

- instance run scope、哈希/时序、新上下文源、receipts 和生命周期。
- 将 CHATGAME 生成从组件直调迁到 Harness；旧入口下线。

### CHATGAME-2B · 单角色长期互动

- 场景摘要、关键记忆、关系变化解释、重试/取消/恢复。
- 作者场景配置与上下文检查器。

### CHATGAME-2C · 多角色与剧情连接

- 场景导演、参与者变化、逐角色回复和成本预算。
- 与 Narrative Node/Choice 双向连接，但不直接修改剧情状态。

## 11. 验收样例与完成定义

制作一个三角色、跨五次场景的原创关系故事：

- 一个角色知道秘密，另两个初始不知道；秘密只会通过真实告知事件传播；
- 玩家一次失约和一次补救产生可解释的关系变化；
- 多人场景中三人对同一事件持不同记忆和态度；
- 中途刷新、重试某条回复、从旧检查点 fork 后，原时间线保持不变；
- 断网时固定剧情仍可玩，自由聊天明确暂停；
- 100 轮互动后上下文仍在预算内，关键承诺不因摘要被篡改。

测试必须覆盖知识泄露、伪造记忆、重复采用、过期回复、角色删除、发布升级、导入导出和 Harness 失败。
只有新旧聊天入口完成收口、单人和多人样例均可重放，才算 CHATGAME-2 完成。

## 12. 实施记录

CHATGAME-2A、HARNESS-RUNTIME-1、2B 和 2C 已于 2026-08-14 完成。统一 GameRelease 现在可冻结
`character-interaction` 角色档案、初始知识、关系维度、场景模板和固定行动规则，并以
`chatgame` SIM 实例启动。玩家端的回复、多角色导演、场景结束记忆整理、重试、取消和恢复
全部经 Instance-scoped Harness；固定行动在无 AI 时仍可确定性推进。作者工作台提供角色、秘密、
关系、场景、Narrative 连接、可见上下文检查、诊断与统一发布。CHATGAME-1 事件和快照保持可读，
旧存档在产品页只读呈现，新配置、消息和回复写入已明确禁止。内置确定性验收样例覆盖三个角色、
五个连续场景、一条私密知识、一次失约与一次可解释的关系修复。
