# TEXTWORLD-QUEST-1 · 区域动态任务导演

> 状态：`IMPLEMENTED · QUEST-1A/1B/1C 已随 TEXTWORLD-1 完成（2026-08-14）`
>
> 所属：TEXTWORLD-1 文字开放世界
>
> 参考：开放世界的区域化事件卡组与多渠道任务发现；不复制任何具体游戏内容

## 1. 机制目标

任务导演不是用 AI 无限生成委托，而是根据当前区域、玩家进度、世界资源、人物/组织状态和游戏规则，
受控地决定“现在应该让玩家发现什么内容”。

它应同时做到：

- 关键任务不会因为错过唯一 NPC 而永久丢失。
- 不同玩家可以通过战斗、社交、探索、休息等不同方式发现同一任务。
- 任务类型和强度保持变化，不形成满屏待办事项。
- 玩家成长明显落后或区域危机紧迫时，系统能提高相关任务优先级。
- 玩家已有很多同类任务时，系统暂缓发牌。
- 世界平静或玩家需要休息时，允许抽到“空白牌”。
- 动态任务来自真实世界状态，完成或忽略后会反过来改变世界。

## 2. 五个彼此分离的概念

### 任务定义

作者固定任务或可配置任务模板，说明目标、前置、允许解法、奖励预算、后果和生命周期。

### 任务实例

在某次游戏中已经确定区域、角色、组织、资源、解法和版本的冻结任务。模板以后修改，不改变进行中的实例。

### 区域牌组

当前区域在一轮调度中希望向玩家释放的内容组合，可以包含：

- 固定主线/关键人物牌。
- 区域问题牌。
- 角色请求牌。
- 探索/成长/资源牌。
- 危机或后果牌。
- 空白牌。

牌组不是简单随机列表，而是一个带数量、类别配额、优先级和冷却的释放计划。

### 发牌渠道

任务如何被玩家发现，例如 NPC 对话、敌人口供、酒馆传闻、公告、信件、广播、现场遭遇、物件、梦境。
渠道只负责信息呈现，不决定任务后果。

### 发牌导演

检查所有条件、调整牌序、选择渠道、控制节奏并生成可解释结果的系统。AI 只能参与有限候选和文字表达。

## 3. 一次发牌应该读取什么

- 玩家所在区域、时间、认知和最近行动。
- 已接受、已透露、被拒绝、已完成、失败和过期任务。
- 当前任务数量、类型分布、难度、预计耗时和近期重复情况。
- 玩家能力、资源短板、关系、游玩偏好和近期解决方式。
- 区域资源、指标、问题、危机等级和可用地点。
- 在场且可用的 NPC/组织、日程、关系和知识。
- 主线保护、必要铺垫、关键奖励和禁止冲突。
- 牌组配额、冷却、空白牌和本轮已经发出的内容。

这些必须来自运行时事实与受控上下文，不能由 AI 回忆或猜测。

## 4. 发牌过程

```text
玩家触发一次“可能获知内容”的交互
  → 判断当前是否允许发牌
  → 收集区域牌组中的合法候选
  → 过滤前置不成立、对象不可用、主线冲突和近期重复
  → 根据紧迫度、新鲜度、玩家需要、类别配额和节奏打分
  → 保留一部分确定性随机，选出任务牌或空白牌
  → 选择与玩家当前行为相符的发牌渠道
  → 固定任务直接呈现；动态任务先冻结合法任务实例
  → 可选由 AI 生成渠道文本、任务描述和对话
  → 验证后向玩家透露，记录发牌原因和任务状态
```

同一 seed、状态和触发序列应能复现相同选择；AI 文字可以重生成，但不能改变抽到的任务事实。

## 5. 不是纯随机，而是“受控意外”

任务得分可综合：

- 合法性：硬条件，不满足直接排除。
- 紧迫度：主线窗口、任务期限、危机升级。
- 玩家需要：成长落后、资源短缺、玩法教学。
- 新鲜度：与近期任务类型、角色、地点、冲突和解法的差异。
- 区域相关度：是否来自当前区域真实问题和在场主体。
- 叙事价值：是否铺垫、回收或推进活跃人物线。
- 积压惩罚：同类任务和总任务过多时降低。
- 渠道适配：玩家正在战斗、社交、探索还是休息。
- 随机扰动：只在合法且分数接近的候选之间制造差异。

关键任务可以有保底窗口，但不必每次都硬塞到玩家面前。

## 6. AI 动态配置任务

AI 可以参与，但任务生成应分四步：

1. **系统识别需求**：例如区域药品不足、医生仍在、邻区有药材、玩家最近战斗任务过多。
2. **系统选择模板并冻结硬事实**：资源获取任务；目标、参与者、合法解法、奖励范围和失败后果由代码确定。
3. **AI 填充表达或有限软槽**：标题、传闻、动机表述、对话、场景细节；软槽候选必须来自允许集合。
4. **系统验证并实例化**：检查引用、重复、主线冲突、奖励预算、状态基线和所有后果，失败则降级到模板文本。

AI 不能凭空增加人物、地点、物品、组织资源或可执行效果，也不能以“剧情需要”为理由越过规则。

## 7. 重复控制与问题演化

每个任务实例建立任务指纹，至少包含：

```text
来源问题 + 区域 + 任务族 + 发起者角色/组织
+ 目标对象 + 核心冲突 + 主要解法 + 奖励类型
```

近期指纹过于相似时降低权重或拒绝。同一 NPC、同一地点、同一奖励、同一解决方式也有独立冷却。

但“同一问题继续发展”不应当被误判为重复。例如：

```text
商路遇袭
  → 玩家忽略
  → 运输停摆
  → 粮价上涨
  → 黑市扩张
  → 居民外逃 / 组织争夺
```

每一步都应从上一状态和事件产生新的目标、参与者与后果；如果只是换标题再次要求消灭同一批敌人，则是重复。

## 8. 任务生命周期

至少区分：

- `eligible`：满足条件但玩家尚未知晓。
- `revealed`：通过渠道获知，尚未接受。
- `active`：玩家接受或已通过行动实际介入。
- `resolved`：完成并结算。
- `failed`：明确失败，产生后果。
- `declined`：玩家拒绝，可按定义永久关闭或进入冷却。
- `expired`：时间/世界变化使其失效。
- `superseded`：被问题的下一阶段或另一任务取代。

忽略不是无状态。任务可以在未揭示或揭示后随世界演化，其他主体也可能介入；任何变化都通过事件留下原因。

## 9. 空白牌与节奏

即使存在 AI 无限生成能力，也必须允许不发任务。出现以下情况应提高空白牌权重：

- 玩家活跃任务已经达到上限。
- 最近连续收到多个高强度任务或重大剧情。
- 当前区域问题已经稳定，没有足够相关的新内容。
- 玩家正在旅行、休息或完成长期探索。
- 当前候选都重复、越界或质量不足。

空白牌不是内容缺失，而是给探索、消化、人物日常和环境叙事留出空间。

## 10. 与大型世界的关系

任务导演把世界状态转化为玩家可以理解和介入的行动机会：

```text
区域资源 / 人物目标 / 组织冲突 / 世界问题
  → 动态任务导演
  → 传闻、委托、遭遇、线索和危机
  → 玩家行动
  → 世界事件与长期后果
  → 新的区域状态
```

因此它是文字开放世界的重要驱动器，但不是世界本身。没有区域状态、规则和真实后果，动态发牌只会成为
换皮随机委托生成器。

## 11. 首期结构化合同

任务导演的首期实现不引入任意评分脚本。每个区域牌组声明类别配额、总揭示上限、冷却和空白牌基础权重；
每张牌引用一个固定任务，并提供硬前置、优先级、允许渠道和唯一/可重复策略。

一次调度产生可审计的结果：

- trigger：什么交互触发了发牌检查；
- considered：候选及被过滤原因；
- scores：通过候选各评分项和随机扰动证据；
- selected：任务牌或空白牌；
- channel：实际发现渠道及参与主体；
- baseSequence/stateHash：用于过期拒绝；
- resultingEvent：唯一采用事件。

固定任务、系统配置模板和 AI 表达共享这一结果外壳，但首期只启用固定任务。这样后续增强不会改变“何时
算发出一张牌”的权威语义。

## 12. 状态与事件

任务定义和任务实例严格分离。实例冻结 source definition/template、区域、参与者、目标、解法、奖励预算、
失败后果、生成时世界序号和内容 hash。模板以后修改不影响已生成实例。

已登记的主要事件为：

- `world.quest-card.considered`
- `world.quest-card.dealt|world.quest.blank-dealt`
- `world.quest.instance-created`
- `world.quest.revealed|declined|expired|superseded`
- 接受、完成与失败沿用 `adventure.quest.*` 共享生命周期事件

调度器只在合法触发点运行，同一 trigger/commandId 幂等。牌已经发出但 UI 刷新时从事件恢复，不能再次抽牌。

## 13. 分阶段实施

### ✅ QUEST-1A · 固定任务发牌

- 区域牌组、类别配额、渠道、冷却、积压、空白牌和唯一领取。
- 可解释调度结果、确定性随机、主线保护和发布检查。
- 用真实游玩数据校准节奏，不使用 AI。

### ✅ QUEST-1B · 世界问题与模板配置

- 从 issue、资源缺口、主体目标中识别需求。
- 选择模板、锁定硬槽位、验证解法/奖励/后果并生成冻结实例。
- 指纹、相似度、问题演化和其他主体介入。

### ✅ QUEST-1C · AI 表达与有限建议

- AI 只填写标题、传闻、动机、场景和允许集合内的软槽位。
- Harness instance scope、输出 schema、事实核对、过期拒绝、缓存和模板降级。

## 14. 数据治理、测试与完成定义

- 新定义、牌组、渠道、模板和任务实例先登记 `PROJECT_TABLES` 并完成完整生命周期。
- 运行上下文只从 `CONTEXT_SOURCES` 组装；AI 候选不直接写任务或世界状态。
- 发布冻结牌组、模板、评分配置和规则版本；长局不自动更新。
- 单元覆盖过滤、评分、配额、冷却、空白牌、主线保护、指纹和任务生命周期。
- 反例覆盖重复触发、对象死亡/离开、渠道失效、任务积压、旧页面、坏引用、奖励越界和 AI 幻觉。
- 统计测试覆盖任务类别分布、连续高强度长度、空白牌比例、重复率和关键任务最晚发现窗口。
- E2E 覆盖触发 → 发牌 → 透露 → 接受/拒绝/忽略 → 问题演化 → 后续牌，并验证刷新和 fork。

QUEST-1A 完成的最低标准：同一世界状态下发牌可重放；任务不会重复领取；积压时系统能停止发牌；关键任务
有保底但不破坏渠道合理性；空白牌是真正的合法结果。

## 15. 首期已冻结的实现边界

首期已经冻结并由发布校验或回归覆盖：

- 区域最小状态和世界问题模型。
- 任务模板语法、槽位类型和效果闭集。
- 主线保护与固定任务保底规则。
- 发牌评分、类别配额、轮次重置和随机证据。
- 任务积压上限与空白牌恢复条件。
- 任务指纹和语义相似度的首期算法。
- 拒绝、忽略、过期和其他主体介入的演化规则。
- 作者定义的奖励预算和强度闭集；首期不由 AI 动态估算奖励。
- AI 输出 schema、Harness instance scope 和失败降级。
- 长局重复率、内容密度、主线可达性和世界稳定评测。

验收内容包含 30 张固定牌、10 个模板、20 个区域渠道和受保护主线；同状态/seed 的候选、评分证据、空白牌与
实例完全可复现。任务指纹、来源冷却、积压惩罚、高强度连发限制、关键任务最晚窗口和每次 tick 的传播预算
均为确定性规则。AI 增强只生成引用正式事件与已公开实例的只读表现候选，采用前再次验证实例边界；后续参数
校准不得改变这些治理边界。
