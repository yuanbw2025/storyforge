# 提示词库与功能引用补正

用户指出：生成前已经展示和配置提示词，新增动作的创作指令也应进入提示词库，并由功能配置引用。此前五种准备动作直接在代码内构造指令；原入口的一些内容方法还会在作者模板后追加，造成展示模板与执行内容不一致。

## 当前实现

- 整理、比较、深化、未定定位、明确定位各注册独立PromptModuleKey和内置模板。提示词库可查看、克隆、编辑、激活，并沿原模板导入导出；已有库启动时补齐，用户模板和激活状态保留。
- 灵感面板的功能配置引用当前动作的同一模块。五种准备动作及单/多世界完整反推均传递模板参数、本次System/User修改；生成前按原Prompt执行契约冻结模板、覆盖值、参数和实际消息hash。完整反推规划按工作区模式选择模板。
- 默认世界、历史、规则、文风、研究与词条的本轮创作方法进入可编辑模板正文。目标字段、词条类型、研究动作通过条件变量选择对应段落。运行时使用作者激活模板，不在模板后重新附加同一套隐藏创作方法；自定义模板不会被强行写回或覆盖。
- 输出schema、正式写入目标、作用域、版本、权限、预算与候选确认仍由代码约束。缺少素材变量时，登记读取的完整素材仍通过确定性资料消息送达；模板已包含时不重复追加。
- 输出示例标记也引用当前准备动作模块，避免把定位结果记到完整反推模板。模式间临时修改分别保留在当前页面会话，刷新后的新生成重新使用激活模板；候选刷新沿原冻结请求恢复，不重新调用模型。

本次是长篇产品研发。准备版本归Work，提示词仍使用现有全局promptTemplates表。无新表、迁移、媒资、世界引用或正式写目标；三注册表与原采纳链继续复用。
