# 拆书内容改进与验证

2026-11-19；研发基线 `d2b54226d`。本目录记录内容研发证据，不是新的产品权威或流派已验证声明。

产品：文档解析→项目参考→作品分析，主要服务独立长篇，节点复用。生命周期为产品研发；不适用世界衍生 S1/S2/S3。owner 为当前 Work；输入为作者确认的本机原文和版本化分块，输出为分析及综合候选，作者激活/采纳后才可引用。无新世界引用或媒资。

读取沿 `referenceAnalysisPrivateChunk`、`referenceDerivedBaseline`、`references` 和 Gateway Canon reference provider；写入沿既有 `referenceChunkAnalysis`、`referenceAnalysisRuns.analysisSummary/mergedCharacters` 及 Reference 激活投影，沿原 Field/Adoption 合同；不新增表、迁移、正式写回或 AI 入口旁路。评测明确登记为 eval-only，无数据库和采纳权限。

## 生效路径

- 项目参考的深层作品分析：`chunk-prompt.ts` 调用 `content-skill.ts` 的细读内容包。七领域映射至原 13 小说维度，历史资料保留额外 5 维。原文、事实、解释、方法、原创示例与失效例在原字符串字段内表达；不新建万能“其他技巧”产物。
- 分块视图和综合视图保留各处来源；相似句首不再使后段反证被展示去重隐藏。
- 综合和人物聚合仍是 durable 候选。综合读全部分块的完整分析，不再只读前 3 块的前 200 字；不会凭二手分析认证原作事实。超出已登记来源或模型预算时应明确失败，不以截断材料冒充综合；目前没有自动分层处理任意规模整书的能力。
- 作者可重新生成并审查综合候选，接受前旧综合仍在。历史结果不会被后台重写；要获得新分析需新建分析版本。
- 旧 `references` 来源引用优先使用同一 active run 已采纳综合；未综合维度使用完整分块条目，按维度交错、优先首/末/中，保留块号和未选数量。条目整体适配预算，过长条目整体略过，来源原子化防止 Gateway 再切断条件；可选引用超预算时整段省略并保留trimmed证据，不阻断生成。受保护的正式综合仍拒绝超预算。该选择不保证每维或每本均进入有限预算；完整资料可回作品分析查看。
- 当前正文、章纲等 Gateway 主路径直接读 Canon reference 资源。该资源的 full/focused 展示带原创运用指令，原文证据仍按原规则返回，哈希/预算反映实际呈现内容；没有第二套资料装配。

## 作者使用

1. 导入自己的、获授权或可研究的原文为项目参考，确认来源和使用范围。深层分析按提供的范围细读；残页、节选及连载不得当作完整终局。
2. 在作品分析查看分块证据及综合，检查人物身份、说话者、事件时序、知情差和替代解释。生成综合后审查候选，再采纳；需要时可重新生成候选。
3. 激活要用的分析版本，在创作规则中选择引用参考。当前正文路径沿 Gateway 显式读取选定参考；其他任务必须在其来源清单/实际 Manifest 中出现 reference，不能仅凭有参考书目就声称已经消费。
4. 不需要手工复制全部报告进正文提示词。方法只影响与当前任务有关的创作决定，原作事实、人物、专有设定与情节不能自动移入当前作品。

## 内容覆盖与消费边界

| 内容领域 | 现有维度承载 | 原创应用中的决定 |
|---|---|---|
| 流派/期待 | openingTechnique、emotionalBeats | 处境、阅读承诺、简介兑现 |
| 故事/人物 | characterCraft、dialogueTechnique | 欲望、两难、相处习惯与边界 |
| 剧情/冲突 | plotStructure、conflictEscalation、climaxDesign、foreshadowing | 行动—回应—新条件、揭示顺序 |
| 爽点/情绪 | emotionalBeats、climaxDesign | 成果改变什么、生活回报及余波 |
| 长篇/连载 | plotStructure、pacingControl、foreshadowing | 阶段差异、旧角色意义、中后段与收束 |
| 正文/表达 | narrativeStyle、dialogueTechnique、proseStyle、worldBuilding | 感知、知情、声音、潜台词、生活与意象 |
| 流派专项 | 按实际问题落相应维度 | 机制/背景/活动/体验的组合及代价 |

六种尺度是分析对象：全书、卷/阶段、情节单元、章、场景、句段。机器块不被认证为任何一种。内容包给创意定位、故事核心、人物/关系、主支线、全书/卷纲、章纲、细纲、正文、修改及简介等任务运用建议；没有为14环节逐一新增或冒称已接通专属生成入口。现有 Gateway 消费与旧来源消费须分别检查。

## 复现与证据边界

`node scripts/evaluate-reference-quality.mjs <仓库外新绝对目录> <已登记profile>`：默认固定原创材料的旧新分析、重复与 2×2 资料/指令探索对照。显式 `REFERENCE_EVAL_PUBLIC=1` 包含公开原文与新的留出任务；`REFERENCE_EVAL_SHORT=1` 仅分析。每轮最多28次串行，90秒超时，失败停止，不重试、不自动换服务。真实私有配置位于仓库外；不打印密钥/端点。原答、用量、完整消息和内容哈希保存在指定外部目录，不进入用户数据库。

公开样本来源：鲁迅[《孔乙己》](https://zh.wikisource.org/zh-hans/孔乙己)；[《水浒传》120回本](https://zh.wikisource.org/wiki/水滸傳_(120回本))第001/071/120回的网页段落。公开来源原文按网页 p 段提取，不能证明所有排版块均已抽取；水浒只给选回，不是全书连续阅读，模型可能带有先验名作知识。原创任务用于减少这种泄漏，不是完整长篇代表作研究。

本轮证据与限制见 `review.md`。没有招募真实读者；开发者/模型审读不冒充读者评分。一次准确分析、工程测试和合并均不能证明稳定文学收益、长篇追读或市场结果。

## 拆书内置指令边界（2026-11-20）

拆书属于文档解析内置能力。分块细读、已读范围综合、人物归并和参考方法原创运用统一使用项目代码内置指令，不读取用户提示词模板。此前的细读证据、整单元预算、末段反例和候选采纳质量优化继续保留。

撤下四项拆书模板 seed、库内展示、编辑模块和选用入口；已保存的历史模板原样保留，并继续支持导入导出，但不参与拆书执行。灵感反推与准备模式的模板及配置入口保持现行实现。
