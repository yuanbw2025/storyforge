# 拆书容量专项（2026-11-20）

本分支实现记录，主干合并与发行以交付回执为准。作者决定是无应用层固定长度、数量和调用额度上限，不能以更大的固定数值、极大数或隐藏批数代替旧限制。产品为文档解析→项目参考→作品分析，研发阶段，Work owner；无世界 S1/S2/S3 或媒资 owner 变化。沿现有 CONTEXT_SOURCES、Field/Adoption 和 PROJECT_TABLES，无新表或数据迁移。

## 实现与边界

- referenceDerivedBaseline、referenceAnalysisPrivateChunk 不再有36k/40k来源上限，装配完整任务基线。其 Manifest 表示任务资料完整交付，不声称每次请求都一次读完；每次实际请求另存精确消息、范围、来源根、阶段、服务设置/容量证据与完整原答。
- 参考资料收集不再先按2000-token预算略过长条目；完整保留已选版本的分析。引用来源无固定 per-source 上限，实际生成任务仍按其 Manifest、权限和当次请求容量选读，不声称每次创作都读了整个资料库。
- reference Skill 输出预算为显式 null；RunContract capacityPolicy=service 的调用/输入/输出额度也为显式 null，仅向登记的拆书来源、Skill和既定参考写回字段开放。不用0或极大数充当额度。旧固定预算产品经数值守卫保留原有行为。同步主干时，故事核心节点也沿用主干已确定的serviceCapacityOnly与实际输出设置；冻结Skill支持其已登记的retrievalBudgetMode，未知模式仍拒绝。
- 4096/8192输出覆盖、固定字符块、综合1200字、80张人物卡及字段长度限制撤下。没有可确认人物时可返回空数组，不为满足下界编造角色。依旧验证闭集JSON、必需字段、重复身份、范围与模式。
- 先使用完整资料。实际服务容量与请求估算显示不能承载、服务明确超窗拒绝或返回明确长度未完时，按实际需要划分完整范围；优先句/段边界，必要时保留Unicode边界。没有固定总批数/层数/调用额度。未知能力不据共享fallback预设成小窗口，未知输出限制不发送虚构的max_tokens。
- 跨范围联结层复用唯一内置提示词工厂；压缩目标从本轮服务窗口/已接受请求推导，是派生材料容纳计划，不是作品或字段上限。原始分批分析与反证完整附后，原文和各层原答不被压缩覆盖。若压缩未取得进展，则明确未完成并保留证据，避免无意义循环和假成功。
- 已知完成的分批和联结进度可继续，已完成范围不重发。检查点只放精确证据引用，原文不复制到检查点；派生工作字符串放现有exact artifact中。未知请求、stale、权限、余额和非重试错误不隐藏重发或换服务。确认限流的既有有界重试属于传输恢复，不是任务调用额度。
- 私域分批必须覆盖完整根范围，并校验每批原答根属于原运行；最后一批有效JSON不能冒充整个原文完成。原答与派生组合分开存储，跨层不把原文字符、机器分批或派生层编号认证为原书章节。
- 移除6版本数量限制与自动回收，保留历史、未采用和失败版本。保留引文的完整有效文本；多处引用分别核验并标为非连续原文。删除仍走既有显式作者操作。
- 本机Codex桥不再2MiB拒绝输入或清空大回答；reference-service线协议不受普通文本消息/模型标识长度、待处理/待交接回执数和20分钟生成计时的应用额度约束。仍验证同源/回环、工具禁止、请求身份、当前源与取消信号。原native请求在发送前留绑定并持有回执，原答进入owner存储后才交接缓存；交接失败继续保留。
- 拆书继续使用代码内置指令，不恢复用户模板配置。既有灵感反推配置保持。候选、作者确认、active版本、双投影CAS、来源权限与失败恢复语义继续保留。
